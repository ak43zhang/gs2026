# 盘中异动分析系统 · 完整闭环设计

## 一、系统概述

盘中异动分析系统是整个分析闭环的**盘中信号链**，与盘前预判（领域/新闻/公告分析）和盘后复盘（涨停分析）形成完整的内循环：

```
盘前预判 ──→ 盘中验证 ──→ 盘后复盘 ──→ 反馈预判权重
(领域/新闻/公告)  (异动分析)    (涨停分析)
```

**核心目标**：通过实时监测股票首次涨停异动，结合盘前预判消息，挖掘异动原因及联动板块。

## 二、数据源

### 2.1 三表融合的 watchlist 数据

watchlist 从三张分析结果表中提取关注标的，时间区间与智能报告一致：

| 数据源 | 表名 | 过滤条件 | 时间条件 |
|--------|------|---------|---------|
| 领域分析 | `analysis_domain_detail_2026` | `news_type='利好' AND news_size='重大'` | `event_time >= '{start} 15:00:00' AND event_time < '{end} 09:30:00'` |
| 新闻分析 | `analysis_news_detail_2026` | `news_type='利好' AND composite_score >= 50` | `publish_time >= '{start}' AND publish_time <= '{end}'` |
| 公告分析 | `analysis_notice_detail_2026` | `overnight_score >= 70 AND notice_type='利好'` | `notice_date >= '{start}' AND notice_date <= '{end}'` |

### 2.2 股票代码与消息提取

| 数据源 | 股票代码字段 | 消息字段 | 行业/概念字段 |
|--------|-------------|---------|-------------|
| 领域分析 | `stock_codes` (JSON数组) | `key_event` | `sectors` (JSON), `concepts` (JSON) |
| 新闻分析 | `leading_stocks` (JSON数组) | `title` | `sectors` (JSON), `concepts` (JSON) |
| 公告分析 | `stock_code` (直接字段) | `notice_title` | 无（需通过 stock_code 查 `cache_stock_industry_concept_bond`） |

### 2.3 时间区间获取

使用智能报告相同的工具函数：

```python
from gs2026.analysis.worker.message.huoshanfangzhou.trading_day_util import get_start_end

start_date, end_date = get_start_end(target_date)
# 返回如 ('2026-06-19', '2026-06-23')
```

## 三、MySQL 数据表

```sql
CREATE TABLE stock_anomaly (
    id INT AUTO_INCREMENT PRIMARY KEY,
    trading_date DATE NOT NULL,
    stock_code VARCHAR(10) NOT NULL,
    stock_name VARCHAR(50),
    anomaly_type VARCHAR(20) NOT NULL,     -- zt_hit（暂只做这一种）
    anomaly_time TIME NOT NULL,
    price DECIMAL(10,2),
    change_pct DECIMAL(5,2),
    continuous_zt INT DEFAULT 0,
    ai_analysis TEXT,
    ai_status VARCHAR(20) DEFAULT 'pending',
    ai_started_at DATETIME,
    ai_completed_at DATETIME,
    related_industries JSON,
    related_concepts JSON,
    pre_forecast_messages JSON,
    forecast_match VARCHAR(20) DEFAULT 'pending',
    forecast_note TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_date_type (trading_date, anomaly_type),
    INDEX idx_stock_date (stock_code, trading_date),
    INDEX idx_ai_status (ai_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 四、Redis Key 设计

| Key | 类型 | 说明 | TTL |
|-----|------|------|-----|
| `anomaly:{trading_date}` | Set | 当日已记录异动，member 为 `{stock_code}:{type}` | 86400秒 |
| `anomaly:watchlist:{trading_date}` | Hash | 当日关注清单，field=stock_code，value=JSON | 86400秒 |
| `anomaly_ai_lock:{code}:{date}` | String | AI分析锁 | 900秒 |

## 五、完整流程时序

### T日 盘后（15:05-18:00）—— 领域/新闻/公告分析运行（不动）

已有分析进程自动写入三张结果表：

```
analysis_domain_detail_2026  分析_domain_detail_2026  analysis_news_detail_2026
├── key_event: "工信部集成电路扶持政策2.0"      ├── title: "青松股份净利润增长"     ├── notice_title: "海泰科收购预案"
├── stock_codes: ["002049", "603501"]            ├── leading_stocks: ["300132"]      ├── stock_code: "301022"
├── sectors: ["半导体"]                          ├── sectors: ["化学制品"]            ├── overnight_score: 100
└── concepts: ["芯片"]                           └── concepts: ["化妆品概念"]         └── notice_type: "利好"
```

### T+1日 盘前 08:30 —— watchlist 生成

`realtime/watchlist.py` 通过 cron 自动执行：

1. 使用 `get_start_end()` 获取时间区间
2. 从三张表中分别查询符合条件的记录
3. 提取 stock_codes / leading_stocks / stock_code
4. 合并去重（同一股票代码只保留一条，合并消息列表）
5. 标注数据来源（domain / news / notice）
6. 写入 Redis `anomaly:watchlist:{T+1}`

### T+1日 盘中 09:30-15:00 —— 异动检测 + AI分析

#### 增量涨停检测（monitor_stock.py）

每个 tick 数据写入后：
1. 获取当前 tick 涨停股票集合
2. 与上一 tick 做差集 → 得到增量涨停
3. 对每只增量涨停股票：
   - Redis SADD 去重（确保只记首次）
   - 查 watchlist 获取盘前预判消息
   - 查 stock_name
   - 写入 `stock_anomaly` 表

**覆盖所有涨停方式**：竞价涨停、盘中封板、回封（Redis去重确保只记首次）

#### AI分析（realtime/anomaly_analyzer.py）

独立进程，每3秒轮询：
1. 查询 `ai_status='pending'` 的异动
2. 逐条加分布式锁
3. 构造 Prompt（带盘前预判背景 + 数据来源标注）
4. DeepSeek 分析
5. 更新异动表（分析结果 + forecast_match）
6. 释放锁，处理下一条

### 前端展示（/anomaly 页面）

- 独立页面，导航栏位置：数据监控 → 盘中异动 → 数据采集
- 样式与 monitor.html 一致
- 每5秒轮询 `/api/anomaly/list`
- 显示：异动时间、股票代码/名称、涨跌幅、**数据来源标注**、盘前预判消息、AI分析结果

## 七、内循环关联机制

```
领域分析输出 stock_codes + key_event
    ↓
新闻分析输出 leading_stocks + title
    ↓
公告分析输出 stock_code + notice_title
    ↓
watchlist.py 三表融合 → 同一股票代码合并消息，标注来源
    ↓
Redis anomaly:watchlist:{date}
    ↓
盘中异动检测 → 查 watchlist → 匹配到盘前预判消息
    ↓
AI分析 Prompt 中带入盘前预判背景 + 来源标注
    ↓
分析输出 forecast_match (exact/partial/none)
    ↓
存入 stock_anomaly 表，供下次盘前 watchlist 参考
```

**关联准确性保证**：不是猜测关联，而是三张分析表已经明确输出了股票代码和具体消息，watchlist 直接用代码精确匹配。

## 九、性能影响

| 环节 | 改动点 | 额外开销 | 频率 |
|------|--------|---------|------|
| 增量涨停检测 | monitor_stock.py | Set差集运算 <1ms | 每3秒 |
| Redis 去重 | SADD | <1ms/只 | 仅增量涨停时 |
| MySQL 写入 | INSERT | 5-10ms | 仅首次涨停（最多~20次/日） |
| AI分析轮询 | 独立进程 | 0（不影响监控） | 每3秒 |
| 前端轮询 | 独立页面 | 10-20ms | 每5秒 |
| **监控主循环** | **Set差集+Redis** | **<2ms** | - |
