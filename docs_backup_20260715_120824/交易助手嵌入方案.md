# 交易助手嵌入 Monitor_bond 完整方案

## 一、方案概述

### 1.1 设计目标
- **最快响应**：在数据到达 monitor_bond 时立即处理，无需经过前端
- **完全可插拔**：不影响原有功能，可随时启用/禁用
- **方案过滤**：支持按方案名称白名单/黑名单过滤
- **单次确认**：去掉中间弹窗，只保留华泰软件中的一次人工确认
- **多重通知**：声音 + 3秒快速提示（不阻塞）+ 控制台日志

| 3 | 用户点击"准备委托" | ~~去掉~~ |

**耗时对比**：旧方案需等待用户响应弹窗（0~30秒），新方案直接填充（<1秒）。

## 三、monitor_bond.py 嵌入方案

### 3.1 导入部分（文件顶部，与现有"区间次数缓存导入"格式一致）

```python
# ========== 交易助手适配器（可插拔模块）==========
try:
    from gs2026.monitor.trader_adapter import on_hit as trader_on_hit, get_adapter
    _trader_enabled = True
    logger.info("[trader] 交易助手适配器已加载")
except ImportError as e:
    _trader_enabled = False
    logger.info(f"[trader] 交易助手适配器未启用: {e}")
# 可插拔模块结束
```

### 3.2 配置部分（紧跟导入后）

```python
# ========== 交易助手配置 ==========
TRADER_CONFIG = {
    'enabled': True,
    'trader_api_url': 'http://127.0.0.1:8081',
    'allowed_schemes': [],         # 为空=全部方案允许
    'blocked_schemes': [],         # 黑名单
    'min_interval_seconds': 300,   # 同一债券5分钟间隔
    'max_daily_triggers': 50,      # 单日最多50次
    'default_lots': 1,             # 默认1手
    'price_range': {'min': 50, 'max': 200},
    'notifications': {
        'sound': True,
        'console': True,
        'windows_toast': False,    # 不需要额外弹窗
    },
}

if _trader_enabled:
    get_adapter(TRADER_CONFIG)
```

### 3.3 嵌入调用（在命中检测处）

找到 monitor_bond.py 中产生命中记录的位置，添加一行调用：

```python
# 原有逻辑：检测到命中，准备写入数据库
# ...

# 【新增】触发交易助手（不影响后续写入逻辑）
# 每个新命中直接覆盖前一个，不管前一个是否已操作
if _trader_enabled:
    try:
        trader_on_hit(
            bond_code=bond_code,
            bond_name=bond_name,
            price=current_price,
            scheme_name=scheme_name
        )
    except Exception as e:
        logger.error(f"[trader] 调用失败(不影响主流程): {e}")

# 原有逻辑继续：写入MySQL、推送Redis
# ...
```

**覆盖逻辑**：每次新命中直接调用填充，华泰界面会被新数据覆盖，无论用户是否已对前一个信号操作。仅保留10秒去抖防止同一tick重复。

### 3.4 可选：异步调用（不阻塞主循环）

```python
import threading

if _trader_enabled:
    threading.Thread(
        target=trader_on_hit,
        args=(bond_code, bond_name, current_price, scheme_name),
        daemon=True
    ).start()
```

## 四、trader_adapter.py 核心逻辑

```python
def on_hit(bond_code, bond_name, price, scheme_name, lots=None):
    """
    命中回调入口
    
    过滤链：
    1. enabled检查 → 未启用直接返回
    2. 方案过滤 → 不在白名单或在黑名单中则跳过
    3. 交易时段 → 非交易时段跳过
    4. 风控检查 → 金额/价格/间隔/次数不满足则拦截
    5. HTTP调用 → POST /api/prepare_buy 到8081服务
    """
```

**过滤链示意**：

```
on_hit() 
  → enabled?          (No → return)
  → scheme_filter?    (No → return)
  → trading_time?     (No → return)
  → risk_check?       (No → return + 通知)
  → call_trader_api() → 8081服务 → 填充华泰 → 用户确认
```

## 五、通知方式

| 通知类型 | 触发时机 | 是否阻塞 | 说明 |
|---------|---------|---------|------|
| 声音提示 | 命中通过风控后 | 否 | Windows系统提示音 |
| 3秒快速提示 | 调用8081服务时 | 否 | 屏幕中央，自动消失 |
| 控制台日志 | 全程 | 否 | INFO级别，记录所有操作 |
| 华泰软件界面 | 填充完成后 | 是 | 用户看到已填充的买入界面 |

**无阻塞弹窗**：所有提示都在后台线程执行，不会阻塞 monitor_bond 主循环。

---

## 六、风控机制

| 层级 | 检查项 | 默认值 | 说明 |
|------|--------|--------|------|
| 1 | 方案过滤 | 全部允许 | 白名单/黑名单 |
| 2 | 交易时段 | 09:30-11:30, 13:00-15:00 | 非时段直接跳过 |
| 3 | 价格范围 | 50-200元 | 超出范围拦截 |
| 4 | 单笔金额 | 1000-100000元 | 异常金额拦截 |
| 5 | 同一债券去抖 | 10秒 | 仅防止同一tick重复触发 |
| 6 | 单日次数 | 50次 | 日内熔断 |

## 八、启动流程

```bash
# 1. 启动交易助手服务（保持运行）
cd F:\pyworkspace2026\gs2026
.venv\Scripts\python scripts\huatai_trader\main.py

# 2. 登录华泰证券软件（保持运行）

# 3. 启动 monitor_bond（正常启动即可）
python -m gs2026.monitor.monitor_bond
```

**启动顺序**：交易助手服务 → 华泰软件 → monitor_bond

如果交易助手服务未启动，monitor_bond 正常运行不受影响（适配器捕获连接错误并跳过）。

## 九、故障场景

| 场景 | 系统行为 | 对主流程影响 |
|------|----------|-------------|
| 交易助手服务未启动 | HTTP连接失败，日志记录，跳过 | 无影响 |
| 华泰软件未登录 | 服务返回错误，日志记录 | 无影响 |
| 风控拦截 | 日志记录+声音提示 | 无影响 |
| 适配器模块不存在 | ImportError，`_trader_enabled=False` | 无影响 |
| HTTP超时 | 35秒后返回超时错误 | 如用同步调用会阻塞主循环35秒；建议用异步 |
