## 一、设计背景

### 1.1 问题陈述

原有 DeepSeek 网页自动化方案存在以下痛点：

| 痛点 | 影响 | 根因 |
|------|------|------|
| 账号频繁被封 | 分析中断，需人工干预 | DeepSeek网页版风控严格 |
| 调用延迟高 | 30-120s/条 | 需登录+渲染+等待回复 |
| 单账号串行 | 吞吐受限 | 网页版无法并发 |
| UI变更敏感 | 需频繁修复选择器 | 依赖DOM结构 |
| 验证码干扰 | 自动化失败 | 反爬机制 |

### 1.2 设计目标

1. **稳定性**：消除封号风险，API服务SLA保障
2. **性能**：将调用延迟从30-120s降至5-30s
3. **兼容性**：完全兼容原有接口，零迁移成本
4. **可扩展**：支持多Key轮询，天然并发能力

## 三、核心设计

### 3.1 多Key轮询机制

```python
class StepfunClient:
    """多Key轮询 + 自动重试"""
    
    def __init__(self):
        self.api_keys = ["sk-key1", "sk-key2", "sk-key3"]  # 配置读取
        self.key_index = 0
    
    def _next_key(self) -> str:
        """轮询获取下一个Key"""
        key = self.api_keys[self.key_index % len(self.api_keys)]
        self.key_index += 1
        return key
    
    def analyze(self, prompt, ...):
        for attempt in range(3):
            try:
                headers = {"Authorization": f"Bearer {self._next_key()}"}
                # 发送请求...
            except RateLimit:
                # 自动切换Key重试
                headers["Authorization"] = f"Bearer {self._next_key()}"
```

**优势**：
- 避免单Key触发速率限制
- 某个Key失效时自动切换
- 线性扩展并发能力

### 3.2 强制JSON输出

```python
payload = {

    "messages": messages,
    "response_format": {"type": "json_object"},  # 强制JSON

**效果**：

### 3.3 接口兼容层

## 四、Prompt设计

### 4.1 系统提示词

```
你是一位顶级金融分析师，擅长从全球重要事件中挖掘A股投资机会。

【分析原则】
1. 从短线游资视角评估消息对A股的实质性影响
2. 评分必须客观量化，避免主观臆断
3. 股票代码必须是真实存在的A股6位代码
4. 所有输出必须是合法JSON，不要添加markdown标记

【评分体系】
- 重要程度评分(0-15)：权威性级别 + 新颖性 + 相关性纯度
- 业务影响评分(-60至60)：12个经营维度的综合评估
- 综合评分 = 重要程度×4 + 业务影响

## 八、故障处理

### 8.1 自动重试机制

```python
for attempt in range(3):
    try:
        return self._call_api()
    except Timeout:
        time.sleep(2 ** attempt)  # 指数退避
    except RateLimit:
        self._switch_key()  # 切换Key
        time.sleep(2)
```

### 8.2 降级策略

若阶跃API完全不可用，可快速回退：

```python
# 修改导入即可回退
try:
    from gs2026.analysis.worker.message.stepfun import stepfun_ai
except ImportError:
    from gs2026.analysis.worker.message.deepseek import deepseek_ai as stepfun_ai
```
