## 一、强制规则（必须遵守）

### 规则1：单文件多版本（核心规则）

**禁止行为**：
- ❌ 创建 `xxx-v2.md`, `xxx-v3.md`
- ❌ 创建 `xxx-最终版.md`, `xxx-修订版.md`
- ❌ 创建 `xxx-完整版.md`, `xxx-优化版.md`

**正确做法**：
- ✅ 所有版本合并到 `xxx.md`
- ✅ 使用版本沿革表格
- ✅ 历史版本放入附录

**示例**：
```markdown
# 自动止盈止损设计方案

## 版本沿革
| 版本 | 日期 | 说明 |
|------|------|------|
| v7 | 2026-07-25 | 当前版本 |
| v6 | 2026-07-20 | 优化状态机 |
| v5 | 2026-07-15 | 初始方案 |

## 一、当前版本（v7）
[当前内容]

## 附录：历史版本
<details>
<summary>v6 内容</summary>
[历史内容]
</details>
```

### 规则3：命名规范

**必须**：
- ✅ 使用中文
- ✅ 说明具体功能
- ✅ 简洁明了（<30字）

**禁止**：
- ❌ 英文/拼音（技术名词如Baostock/pytdx除外）
- ❌ 过长名称（>50字）
- ❌ 无意义名称（如"新建文档"）

**示例**：
| ❌ 错误 | ✅ 正确 |
|---------|---------|
| get_bond_tdx优化实施.md | 可转债tdx获取优化.md |
| pytdx数据源接入方案.md | pytdx接入方案.md |
| 量化命中自动止盈止损-最终方案v7.md | 自动止盈止损设计方案.md |

## 三、自动化检查

### 3.1 提交前检查

运行命令：
```bash
python scripts/doc_check.py
```

检查内容：
- [ ] 是否创建了新版本文件（-v2, -最终版等）
- [ ] 目录位置是否正确
- [ ] 文件名是否合规
- [ ] 是否已存在可合并的文档

### 3.2 定期审查

每月运行：
```bash
python scripts/doc_audit.py
```

输出报告：
- 新增的多版本文件
- 位置错误的文档
- 命名不规范的文件
- 建议的合并机会

## 四、违规处理

### 发现违规文档时：

1. **不删除** - 保留内容
2. **合并** - 合并到主文档
3. **更新** - 添加版本沿革
4. **清理** - 删除违规文件

### 处理流程：

```
发现 xxx-v2.md
↓
读取内容
↓
合并到 xxx.md（添加版本沿革）
↓
删除 xxx-v2.md
↓
提交说明："合并版本，符合文档规范v1.2"
```
