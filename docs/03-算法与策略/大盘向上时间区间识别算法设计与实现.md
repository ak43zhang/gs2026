# 大盘向上时间区间识别算法设计与实现

## 1. 背景与需求

### 1.1 业务场景
在量化交易中，需要识别大盘（市场均值）的向上时间区间，用于：
- 验证大盘指标字段（`mkt_weighted_slope_2m`、`mkt_change_1m_pct`、`mkt_price_acceleration`）计算正确性
- 为交易策略提供大盘趋势判断依据
- 过滤噪音，识别真正有效的向上时段

### 1.2 核心挑战
- **数据特性**：大盘涨幅远小于个股/债券（1分钟涨幅通常在±0.1%以内）
- **噪音干扰**：短暂波动导致区间碎片化
- **阈值选择**：过于严格会漏识别，过于宽松会引入噪音

## 2. 算法设计演进

### 2.1 初始方案（三条件判定）

```python
# 初始判定条件
is_up = (
    (mkt_weighted_slope_2m > 0.1) &      # 斜率>0.1
    (mkt_change_1m_pct > 0.05) &         # 涨幅>0.05%
    (mkt_price_acceleration > 0)         # 加速度>0
)
```

**问题发现**：
- 斜率阈值0.1远超实际数据范围（实际最大值0.0035）
- 导致无法识别任何向上区间

### 2.2 方案A：调整阈值

```python
# 调整后阈值
slope_threshold = 0.001      # 从0.1降至0.001
change_threshold = 0.05      # 保持0.05
acceleration_threshold = 0   # 保持>0
```

**问题发现**：
- 加速度条件经常不满足（实际数据正负交替）
- 加速度为负≠方向改变，只是"涨得慢了"
- 过早过滤掉有效向上区间

### 2.3 方案B：移除加速度条件（最终方案）

**业务逻辑分析**：
- 加速度为负只是"劲儿变小了"，方向并未改变
- 作为预判翻转信号会过早退出，错过后半段涨幅
- 等待变盘信号（斜率/涨幅转负）更合理

```python
# 最终判定条件（只用两个核心指标）
is_up = (
    (mkt_weighted_slope_2m > 0.001) &    # 斜率>0.001（趋势向上）
    (mkt_change_1m_pct > 0.02)           # 涨幅>0.02%（有实际涨幅）
)
# 移除：mkt_price_acceleration > 0
```

**涨幅阈值调整**：
- 初始：0.05%（仅25%数据满足，对大盘过严）
- 调整后：0.02%（38%数据满足，更适合大盘特性）

### 3.3 区间合并（关键优化）

**问题**：相邻区间被短暂中断割裂，需要合并

```python
def _merge_close_periods(periods, gap_min=2):
    """
    合并间隔小于gap_min分钟的相近区间
    
    规则：
    1. 计算当前区间结束到下一区间开始的间隔
    2. 间隔<=gap_min则合并
    3. 合并后时长=总时长
    4. 平均斜率=加权平均（按时长）
    5. 最大涨幅=取两者最大值
    """
    merged = []
    current = periods[0].copy()
    
    for next_p in periods[1:]:
        gap = (next_start - current_end).total_seconds() / 60
        
        if gap <= gap_min:
            # 合并区间
            current['up_end_time'] = next_p['up_end_time']
            current['up_duration_min'] = 总时长
            current['avg_slope'] = 加权平均
            current['max_change_pct'] = max(两者)
        else:
            merged.append(current)
            current = next_p.copy()
    
    return merged
```

## 4. 关键修复记录

### 4.1 修复1：持续时间计算

**问题**：`up_duration_min`显示11分钟，实际只有30秒

**原因**：误用记录条数作为分钟数（11条记录≈33秒）

**修复**：
```python
# 修复前
duration_min = len(g)  # 错误：记录条数

# 修复后
start_time = pd.to_datetime(g['time'].iloc[0])
end_time = pd.to_datetime(g['time'].iloc[-1])
duration_min = (end_time - start_time).total_seconds() / 60  # 实际分钟数
```

### 4.2 修复2：min_duration过滤逻辑

**问题**：0.5分钟的区间也能通过过滤

**原因**：用记录条数过滤（3条记录>3就通过）

**修复**：
```python
# 修复前
if len(g) >= min_duration:  # 错误：记录条数

# 修复后  
if duration_min >= min_duration:  # 正确：实际分钟数
```

### 4.3 修复3：数据类型转换

## 9. 总结

### 9.1 核心决策

1. **移除加速度条件**：加速度为负只是涨速放缓，不是方向改变
2. **降低涨幅阈值**：大盘涨幅慢，0.02%比0.05%更适合
3. **保留斜率条件**：趋势方向是核心判断依据
4. **区间合并**：合并相近区间，过滤碎片化噪音

### 9.2 算法价值

- **验证字段正确性**：通过识别结果验证指标计算
- **过滤噪音**：只保留真正有效的向上时段
- **参数可调**：支持大盘/个股/债券不同场景
- **业务合理**：符合"等待变盘而非预判翻转"的交易逻辑
