## 一、背景与目标

### 1.1 当前痛点
- 止盈止损参数靠经验手工调试，效率低
- 入场条件阈值固定，无法适应不同市场环境
- 参数组合空间庞大，穷举计算不可行
- 缺乏科学的参数敏感性分析和稳健性评估

### 1.2 期望目标
- **自动化**：系统自动搜索最优参数组合
- **智能化**：用贝叶斯优化等算法减少计算量
- **多维度**：同时优化收益、风险、胜率、盈亏比等指标
- **可扩展**：支持未来加入市场环境、资金管理等更多维度

## 二、核心指标体系

### 2.1 收益类指标

| 指标 | 计算方式 | 优化方向 | 说明 |
|------|---------|---------|------|
| `total_return_pct` | 累计收益率 | 最大化 | 绝对收益 |
| `annualized_return` | 年化收益率 | 最大化 | 跨周期可比 |
| `daily_return_avg` | 日均收益 | 最大化 | 稳定性参考 |

### 2.2 风险类指标

| 指标 | 计算方式 | 优化方向 | 说明 |
|------|---------|---------|------|
| `max_drawdown_pct` | 最大回撤 | 最小化 | 最坏情况 |
| `volatility` | 收益率标准差 | 最小化 | 波动率 |
| `var_95` | 95% VaR | 最小化 | 风险价值 |

### 2.3 效率类指标

| 指标 | 计算方式 | 优化方向 | 说明 |
|------|---------|---------|------|
| `sharpe_ratio` | (收益-无风险)/波动 | 最大化 | 风险调整后收益 |
| `sortino_ratio` | (收益-无风险)/下行波动 | 最大化 | 只惩罚亏损波动 |
| `calmar_ratio` | 年化收益/最大回撤 | 最大化 | 收益回撤比 |

### 2.4 交易质量指标

| 指标 | 计算方式 | 优化方向 | 说明 |
|------|---------|---------|------|
| `win_rate` | 盈利笔数/总笔数 | 参考 | 胜率 |
| `profit_factor` | 总盈利/总亏损 | 最大化 | 盈亏比 |
| `avg_profit_pct` | 平均盈利 | 最大化 | 单笔质量 |
| `avg_loss_pct` | 平均亏损 | 最小化(绝对值) | 单笔风险 |
| `expectancy` | 期望收益 | 最大化 | 长期价值 |
| `trade_count` | 交易次数 | 约束条件 | 样本量充足性 |

### 2.5 综合评分公式（建议）

```python
# 多目标加权评分（可配置权重）
score = (
    w1 * sharpe_ratio +
    w2 * (1 - max_drawdown_pct / 100) * 10 +  # 归一化
    w3 * calmar_ratio +
    w4 * np.log1p(trade_count) / 10  # 交易次数奖励（边际递减）
)

# 硬约束（不满足直接淘汰）
if trade_count < min_trades: score = -999
if win_rate < min_win_rate: score = -999
if max_drawdown_pct > max_dd: score = -999
```

## 三、分层参数体系

### 3.1 L1: 出场参数（最优先优化）

| 参数 | 类型 | 搜索空间 | 说明 |
|------|------|---------|------|
| `tp_pct` | 连续 | [0.1, 3.0] | 止盈百分比 |
| `sl_pct` | 连续 | [0.1, 3.0] | 止损百分比 |
| `window_minutes` | 离散 | [5, 10, 15, 20, 30, 45, 60] | 持有窗口 |
| `trailing_stop` | 连续 | [0, 0.5, 1.0] | 移动止损（可选） |

**特点**：与入场条件解耦，可独立优化

### 3.2 L2: 入场条件阈值

| 参数 | 类型 | 搜索空间 | 说明 |
|------|------|---------|------|
| `slope_short_threshold` | 连续 | [-1.0, 2.0] | 短周期斜率阈值 |
| `slope_long_threshold` | 连续 | [-0.5, 1.0] | 长周期斜率阈值 |
| `change_pct_threshold` | 连续 | [-2.0, 5.0] | 涨跌幅阈值 |
| `amount_rank_threshold` | 离散 | [1, 5, 10, 20, 50] | 金额排名阈值 |
| `peak_vol_bias_threshold` | 连续 | [-5, 10] | 放量偏离阈值 |
| `high_distance_threshold` | 连续 | [-10, 5] | 高点距离阈值 |

**特点**：每个条件字段都可参数化，支持动态阈值

### 3.3 L3: 市场环境维度

| 参数 | 类型 | 取值 | 说明 |
|------|------|------|------|
| `market_regime` | 分类 | up/down/sideways | 市场状态 |
| `mkt_slope_threshold` | 连续 | [-0.01, 0.01] | 大盘斜率阈值 |
| `mkt_change_threshold` | 连续 | [-0.5, 0.5] | 大盘变化阈值 |

**特点**：分环境优化，动态参数切换

### 3.4 L4: 资金与仓位管理

| 参数 | 类型 | 搜索空间 | 说明 |
|------|------|---------|------|
| `position_pct` | 连续 | [10, 100] | 单笔仓位% |
| `max_positions` | 离散 | [1, 2, 3, 5] | 最大同时持仓 |
| `pyramiding` | 离散 | [0, 1, 2] | 加仓次数 |

### 3.5 L5: 条件组合结构（高阶）

| 参数 | 类型 | 说明 |
|------|------|------|
| `condition_logic` | 树结构 | AND/OR/NOT 组合 |
| `condition_weights` | 连续 | 各条件权重（投票机制） |

**示例**：
```python
# 从固定组合优化到动态组合
(slope_short > A AND change_pct > B) OR (amount_rank < C AND peak_vol_bias > D)
# 其中 A, B, C, D 都是待优化参数
```

## 四、优化算法选择

### 4.1 算法对比

| 算法 | 适用场景 | 优点 | 缺点 | 推荐度 |
|------|---------|------|------|--------|
| **网格搜索** | 参数少(<3)、离散值 | 简单、可复现 | 维度灾难 | ⭐⭐ |
| **随机搜索** | 基准对比 | 实现简单 | 效率低 | ⭐⭐ |
| **贝叶斯优化** | 10-30维连续参数 | 样本效率高 | 离散参数弱 | ⭐⭐⭐⭐⭐ |
| **遗传算法** | 混合类型、组合优化 | 发现非直观解 | 计算量大 | ⭐⭐⭐⭐ |
| **强化学习** | 在线自适应 | 动态优化 | 复杂、需大量数据 | ⭐⭐⭐ |

### 4.2 推荐方案：分层优化策略

```
Phase 1: 贝叶斯优化（粗筛）
    └─ 目标：快速定位优势区域
    └─ 采样：100-200次
    └─ 维度：L1 + 关键L2参数

Phase 2: 遗传算法（精筛+组合发现）
    └─ 目标：发现复杂条件组合
    └─ 种群：50-100代
    └─ 维度：L2 + L5条件结构

Phase 3: 分环境优化（L3）
    └─ 目标：不同市场环境各自最优
    └─ 方法：对每个regime重复Phase1-2
```

## 五、计算效率解决方案

### 5.1 多保真度优化（Multi-Fidelity）

```python
# 粗粒度：1天数据快速评估 → 淘汰90%
# 中粒度：5天数据验证 → 淘汰5%
# 细粒度：30天数据精算 → 最终排序

def evaluate(params, fidelity='coarse'):
    if fidelity == 'coarse':
        return run_backtest(date='latest', **params)
    elif fidelity == 'fine':
        return run_backtest(date_range='last_30_days', **params)
```

### 5.2 结果缓存池

```python
# 缓存键：(日期, 条件哈希, 参数哈希)

# 持久化到Redis/MySQL，跨会话可用
```

### 5.3 并行计算架构

```
单机多核：ProcessPoolExecutor（8核）
    └─ 适合Phase 1快速扫描

分布式：Ray Tune / Optuna Distributed
    └─ 适合Phase 2大规模遗传算法
```

```sql
-- 优化任务表
CREATE TABLE optimization_tasks (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100),
    status ENUM('pending', 'running', 'completed', 'failed'),
    algorithm ENUM('bayesian', 'genetic', 'grid'),
    param_space JSON,           -- 参数空间定义

    constraints JSON,           -- 约束条件

    completed_at TIMESTAMP

-- 优化结果表
CREATE TABLE optimization_results (
    id INT PRIMARY KEY AUTO_INCREMENT,
    task_id INT,
    iteration INT,
    params JSON,                -- 参数组合
    metrics JSON,               -- 各项指标
    score FLOAT,                -- 综合评分
    rank INT,                   -- 帕累托排名
    is_pareto BOOLEAN           -- 是否帕累托前沿
);

-- 结果缓存表
CREATE TABLE backtest_cache (
    cache_key VARCHAR(64) PRIMARY KEY,
    params_hash VARCHAR(64),
    conditions_hash VARCHAR(64),
    date_range VARCHAR(20),
    result JSON,
    created_at TIMESTAMP
);
```

## 九、风险与注意事项

### 9.1 过拟合风险
- **问题**：在历史数据上优化过度，实盘失效
- **对策**：
  - 滚动窗口验证（Walk-forward）
  - 训练集/验证集分离
  - 参数稳定性分析（不同周期参数变化小）

### 9.2 计算资源
- **问题**：大规模优化耗时过长
- **对策**：
  - 多保真度优化
  - 结果缓存复用
  - 异步任务队列

### 9.3 结果解释性
- **问题**：黑箱优化结果难以解释
- **对策**：
  - 参数重要性分析
  - 可视化展示
  - 提供"为什么这个参数好"的解释
