## 差异分析

### 文档1：交易流程Web面板方案-替代热键.md

```markdown
﻿# 交易流程管理 - Web面板方案设计

> 版本: v2.0 (替代热键方案)
```

**问题**：文件开头有**BOM字符（﻿）**！

- BOM (Byte Order Mark) 是UTF-8文件的标识字符
- 正则表达式 `^#\s*(.+)$` 无法匹配，因为行首是BOM字符而非`#`
- 导致匹配失败，继续向下查找，匹配到了`## 一、需求变更`

### 文档2：离线数据验证工具设计方案.md

```markdown
# 离线数据验证工具设计方案

---
```

**正常**：
- 没有BOM字符
- 正则表达式 `^#\s*(.+)$` 正常匹配到第一行标题

---

## 根本原因

**BOM字符导致正则表达式匹配失败**

| 项目 | 有BOM的文件 | 无BOM的文件 |
|------|-------------|-------------|
| 实际内容 | `﻿# 标题` | `# 标题` |
| 正则匹配 | ❌ 失败 | ✅ 成功 |
| 识别结果 | 第二级标题 | 第一级标题 |

---

## 修复方案

### 方案A：读取时去除BOM（推荐）

修改读取逻辑，在读取文件内容时自动去除BOM字符：

```python
def read_first_title(file_path):
    try:
        with open(file_path, 'r', encoding='utf-8', errors='ignore') as f:
            content = f.read(5000)
            # 去除BOM字符
            if content.startswith('\ufeff'):
                content = content[1:]
            # 查找第一个#标题
            match = re.search(r'^#\s*(.+)$', content, re.MULTILINE)
            if match:
                return match.group(1).strip()
    except:
        pass
    return None
```

### 方案B：使用更宽松的正则

匹配时允许BOM字符：

```python
# 允许行首有BOM字符或空格
match = re.search(r'^[\s\ufeff]*#\s*(.+)$', content, re.MULTILINE)
```

### 方案C：统一文件编码

批量去除所有文件的BOM字符：

```python
def remove_bom_from_file(file_path):
    with open(file_path, 'r', encoding='utf-8', errors='ignore') as f:
        content = f.read()
    
    if content.startswith('\ufeff'):
        content = content[1:]
        with open(file_path, 'w', encoding='utf-8') as f:
            f.write(content)
        return True
    return False
```
