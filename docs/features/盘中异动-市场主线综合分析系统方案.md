> 日期：2026-07-12  
> 状态：已通过审核  
> 涉及模块：analysis/worker/realtime、dashboard2/routes、dashboard2/templates

## 一、问题背景

### 当前实现的缺陷

盘中异动的「市场主线」展示中，分析结论来源有误：

**前端 `calcMainlinesFromData()` 中的逻辑（anomaly.html 第1590行）**：

```javascript
// 提取催化事件（从第一只归属该主线的股票的异动原因中取）
if (!mainlineMap[name].catalyst && item.ai_analysis) {
    mainlineMap[name].catalyst = item.ai_analysis['异动原因'] || '';
}
```

- 主线的「分析展示」= 第一只归入该主线的股票的 `异动原因`
- `异动原因` 是针对个股的分析（如"某公司获华为大单，短期催化"）
- 展示出来就是：主线名"华为产业链" → 分析内容却是"XX公司获华为大单导致涨停"
- **结论太依赖某只个股，不是主线本身的分析**

### 已有但未利用的数据

每只股票的 `ai_analysis['主线归属']` 中包含主线级字段：

```json
{
    "mainline_name": "华为产业链",
    "mainline_reason": "华为Mate70供应链备货需求爆发，带动核心供应商集体异动",
    "catalyst": "华为宣布Mate70提前量产，供应链开始大规模备货",
    "evidence": "该公司是华为核心光学模组供应商，订单直接受益"
}
```

`mainline_reason` 和 `catalyst` 是主线级描述，`evidence` 是个股级。但前端没用这些字段。

## 三、核心设计理念

### 分离静态分析与动态追踪

```
┌─────────────────────────────────────────────┐
│ 静态层（AI合成，里程碑触发，最多2次/主线）       │
│   · 核心驱动逻辑                              │
│   · 催化事件解读                              │
│   · 市场意义与持续性判断                       │
└─────────────────────────────────────────────┘
┌─────────────────────────────────────────────┐
│ 动态层（算法生成，每只新增追加，无AI成本）       │
│   · 发展阶段：发酵→扩散→高潮→分歧              │
│   · 发展动态：时间线式追踪                      │
│   · 实时指标：成员数/置信度变化                  │
└─────────────────────────────────────────────┘
```

**为什么这样拆分？**
- 核心分析应该稳定，不因每只新股加入而反复变动
- 动态状态应该实时，用户能看到主线最新发展
- AI成本可控：每条主线每天最多2次合成调用

## 四、里程碑触发策略

### 触发条件

| 里程碑 | 触发条件 | AI操作 | 合成级别 |
|--------|----------|--------|----------|
| **形成** (formation) | 首次达到 2 只成员 | ✅ 首次合成 | formation |
| **确认** (confirmed) | 首次达到 5 只 OR 置信度首次≥85% | ✅ 升级合成 | confirmed |
| **中间状态** (3-4只) | 非里程碑 | ❌ 不触发AI | - |
| **后续加入** (6只+) | 非里程碑 | ❌ 不触发AI | - |

### 为什么选这两个节点？

- **2只**：主线首次被确认为真实存在（从"独立个股"变为"有主线"），此时需要建立核心定性
- **5只**：置信度达85%+，数据充足，可以做更深入的综合分析
- **不选3只**：3只时主线仍在发展中，核心逻辑在2只时已建立，无需重新分析
- **不选每只**：频繁重做会导致结论不断漂移，用户体验差

### 防重复触发

- `synthesis_level` 字段记录已完成的合成级别
- formation 只触发一次（`synthesis_level` 从 NULL → 'formation'）
- confirmed 只触发一次（`synthesis_level` 从 'formation' → 'confirmed'）

## 六、阶段判定算法

```python
def calc_market_stage(stock_count, confidence, last_join_minutes_ago):
    """根据规则计算主线当前阶段（无AI成本）"""
    if stock_count <= 2 and confidence < 50:
        return '发酵期'
    elif stock_count <= 4 and confidence < 80:
        return '扩散期'
    elif last_join_minutes_ago <= 20:
        return '高潮期'   # 仍有新成员快速加入
    else:
        return '分歧期'   # 扩散放缓，可能见顶
```

### 阶段含义

| 阶段 | 特征 | 操作建议 |
|------|------|----------|
| 发酵期 | 2只，置信度低，刚形成 | 观察，等待确认 |
| 扩散期 | 3-4只，置信度中等 | 关注龙头表现 |
| 高潮期 | 5只+，仍有新成员快速加入 | 短线活跃，注意高位风险 |
| 分歧期 | 扩散放缓，超过20分钟无新成员 | 谨慎，可能见顶 |

## 七、AI 合成 Prompt 设计

### Formation 级别（2只时触发）

```
【任务】对以下市场主线进行综合定性分析。要求从主线整体视角分析，不要分析某只个股。

主线名称：{mainline_name}

成员股票：
1. {time_1} | {code_1} {name_1}（{role_1}）| 归属证据：{evidence_1}
2. {time_2} | {code_2} {name_2}（{role_2}）| 归属证据：{evidence_2}

各股票的异动原因：
- {name_1}：{reason_1}
- {name_2}：{reason_2}

请输出JSON（严格按格式）：
{
    "core_analysis": "200字以内，分析该主线的核心驱动力、为什么形成板块效应、资金逻辑",
    "catalyst_event": "一句话，触发该主线的核心催化事件",
    "sustainability": "一句话，持续性判断（短期情绪驱动/中期产业逻辑/长期趋势）"
}

注意：
- core_analysis 必须是对主线整体的分析，不是对某只个股的分析
- 如果两只股票的驱动原因不同，需要找到它们的共同主线逻辑
- sustainability 要给出明确判断，不要模棱两可
```

### Confirmed 级别（5只时触发）

```
【任务】该市场主线已有5+只股票确认，请基于全部数据进行深度综合分析。

主线名称：{mainline_name}
当前状态：{stock_count}只成员，置信度{confidence}%
当前阶段：{market_stage}

全部成员（按时间排序）：
{all_stocks_detail}

发展时间线：
{developments_text}

请输出JSON（严格按格式）：
{
    "core_analysis": "300字以内，深度分析：主线核心逻辑、为什么多只股票共振、资金行为特征、板块内部传导路径",
    "catalyst_event": "核心催化事件（可能比初次分析时更明确）",
    "sustainability": "持续性与风险判断（结合当前扩散速度和市场阶段）"
}

注意：
- 重点分析主线整体，不是罗列个股情况
- 需要归纳共性：这些股票为什么被同一逻辑驱动
- sustainability 要结合当前扩散速度给出明确预判
```

## 八、动态追踪条目生成（模板化，无AI）

每只新股加入时自动追加 `developments` 条目：

```python
def build_development_entry(stock_name, role, evidence, stock_count, confidence, is_milestone=False):
    """生成动态追踪条目"""
    # 截取证据关键部分
    evidence_brief = evidence[:30] + '...' if len(evidence) > 30 else evidence
    
    entry_text = f"{stock_name}加入（{role}），{evidence_brief}"
    
    entries = [{"time": current_time_str, "text": entry_text}]
    
    # 里程碑标记
    if is_milestone == 'formation':
        entries.append({"time": current_time_str, "text": f"【主线形成】2只成员，开始追踪"})
    elif is_milestone == 'confirmed':
        entries.append({"time": current_time_str, "text": f"【主线确认】{stock_count}只成员，置信度{confidence}%"})
    
    return entries
```

## 十一、成本与风险评估

### AI 调用成本
- 每条主线每天最多 2 次合成（formation + confirmed）
- 典型交易日 3-8 条主线 → 6-16 次额外 AI 调用
- 相比现有 Phase 2 每只股票 1 次调用（日均 20-50 次），增加约 30%

### 风险点
- 合成时主线成员可能还未全部分析完 → 解决：formation 在 2 只时触发，信息足够做初步定性
- AI 返回格式异常 → 解决：复用现有 `repair_llm_json` + fallback 到前端聚合模式
- 合成耗时影响 Phase 2 流速 → 解决：合成可异步执行，不阻塞主流程

### 回退策略
- 前端做双层 fallback：优先用 `mainline_summary` → 退而用 `主线归属.mainline_reason` → 最后用 `异动原因`
- 合成失败不影响现有功能，只是展示退回旧模式
