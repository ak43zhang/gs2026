# 大盘趋势指标设计 — 基于全市场平均涨跌幅的市场级趋势判断

## 文档信息
- **创建日期**: 2026-07-09
- **功能位置**: 监控采集（monitor_bond.py）+ 量化回测入场条件
- **数据表**: `monitor_zq_sssj_{date}`

---

## 一、需求背景

### 目标
在债券sssj表中增加**大盘级趋势指标**，用于量化回测时作为入场条件的环境过滤器：
- 大盘趋势向上时才入场（顺势交易）
- 大盘冲高回落时规避（逆势保护）
- 与个股指标组合实现"大盘+个股"双维度筛选

### 与个股指标的关系

| 维度 | 个股指标 | 大盘指标 |
|------|---------|---------|
| 数据源 | 单只bond的change_pct/amount | 全市场 avg(change_pct) / sum(amount) |
| 粒度 | 每bond不同值 | 同一tick所有bond共享 |
| 用途 | 筛选个股特征 | 筛选市场环境 |
| 组合 | 个股向上 + 大盘向上 = 真正顺势 | |

---

## 二、数据源

`monitor_bond.py` 每tick已有的计算：
```python
avg_change_pct = df_now['change_pct'].mean()   # 全市场平均涨跌幅
total_amount = df_now['amount'].sum()           # 全市场总成交额
```

这两个值作为大盘指标的输入，**无需额外IO**。

## 三、新增字段

| 字段名 | 类型 | 含义 | 每tick存储 |
|--------|------|------|-----------|
| `mkt_slope_short` | DOUBLE | 大盘3分钟滚动斜率 | 同一tick所有bond相同 |
| `mkt_slope_long` | DOUBLE | 大盘15分钟滚动斜率 | 同一tick所有bond相同 |
| `mkt_peak_vol_bias` | DOUBLE | 大盘放量高点偏离(百分点) | 同一tick所有bond相同 |
| `mkt_high_distance` | DOUBLE | 大盘日内高点距离(百分点) | 同一tick所有bond相同 |

---

## 四、计算逻辑

### 4.1 `mkt_slope_short` — 大盘3分钟斜率

**输入**: avg_change_pct（全市场平均涨跌幅）的滚动窗口（60 tick = 3分钟）

**计算**: 最小二乘线性回归斜率

**含义**:
- 正值: 大盘近3分钟在上涨
- 负值: 大盘近3分钟在下跌
- 绝对值越大: 趋势越强

### 4.2 `mkt_slope_long` — 大盘15分钟斜率

**输入**: avg_change_pct 的滚动窗口（300 tick = 15分钟）

**含义**: 大盘中期趋势方向。用于过滤短期波动噪声。

### 4.3 `mkt_peak_vol_bias` — 大盘放量高点偏离

**公式**:
```
mkt_peak_vol_bias = avg_change_pct_当前 - avg_change_pct_在总成交额最大时刻
```

**含义**:
- = 0: 当前就在大盘放量最大的位置
- < 0: 大盘已从放量高点回落
- > 0: 放量发生在低位，大盘继续上行

### 4.4 `mkt_high_distance` — 大盘日内高点距离

**公式**:
```
mkt_high_distance = avg_change_pct_当前 - max(所有历史tick的avg_change_pct)
```

**含义**:
- = 0: 大盘正在创日内新高
- < 0: 大盘已从日内最高点回落（值越负回落越深）

## 五、实现代码

```python
from collections import deque

WINDOW_SHORT = 60    # 3分钟
WINDOW_LONG = 300    # 15分钟

# 进程级缓存（只需各一个，非per-bond）
_mkt_slope_buf_short = deque(maxlen=WINDOW_SHORT)
_mkt_slope_buf_long = deque(maxlen=WINDOW_LONG)
_mkt_peak_vol = {'max_total_amt': 0, 'pct_at_max': 0.0}
_mkt_high = {'max_avg_pct': -999.0}
_mkt_date = None


def compute_market_indicators(df_now, current_date):
    """
    计算大盘趋势指标（基于全市场平均涨跌幅）
    每tick调用一次，O(1)，零IO
    结果广播到df_now所有行（同tick所有bond共享）
    """
    global _mkt_slope_buf_short, _mkt_slope_buf_long
    global _mkt_peak_vol, _mkt_high, _mkt_date

    # 日期切换 → 清空
    if _mkt_date != current_date:
        _mkt_slope_buf_short = deque(maxlen=WINDOW_SHORT)
        _mkt_slope_buf_long = deque(maxlen=WINDOW_LONG)
        _mkt_peak_vol = {'max_total_amt': 0, 'pct_at_max': 0.0}
        _mkt_high = {'max_avg_pct': -999.0}
        _mkt_date = current_date

    # 计算大盘数据
    avg_pct = float(df_now['change_pct'].mean())
    total_amt = float(df_now['amount'].sum())

    # slope_short
    _mkt_slope_buf_short.append(avg_pct)
    mkt_ss = round(_calc_slope(_mkt_slope_buf_short), 6)

    # slope_long
    _mkt_slope_buf_long.append(avg_pct)
    mkt_sl = round(_calc_slope(_mkt_slope_buf_long), 6)

    # peak_vol_bias
    if total_amt > _mkt_peak_vol['max_total_amt']:
        _mkt_peak_vol['max_total_amt'] = total_amt
        _mkt_peak_vol['pct_at_max'] = avg_pct
    mkt_pvb = round(avg_pct - _mkt_peak_vol['pct_at_max'], 4)

    # high_distance
    if avg_pct > _mkt_high['max_avg_pct']:
        _mkt_high['max_avg_pct'] = avg_pct
    mkt_hd = round(avg_pct - _mkt_high['max_avg_pct'], 4)

    # 广播到所有行
    df_now['mkt_slope_short'] = mkt_ss
    df_now['mkt_slope_long'] = mkt_sl
    df_now['mkt_peak_vol_bias'] = mkt_pvb
    df_now['mkt_high_distance'] = mkt_hd
    return df_now
```

### 与个股指标完全一致的策略

| 场景 | 行为 | 恢复时间 |
|------|------|---------|
| 冷启动（开盘） | 从0开始积累 | slope_short 3分钟 / slope_long 15分钟 |
| 宕机重启 | 滚动窗口自愈 | 同上 |
| Redis不可用 | **完全不依赖Redis** | 无影响 |
| MySQL不可用 | 降级运行（peak_vol/high从当前开始） | 无影响 |

## 八、回测使用示例

### 场景A: 顺势交易（大盘+个股同向）
```json
{"field": "mkt_slope_short", "op": ">", "value": 0.001},
{"field": "mkt_high_distance", "op": ">=", "value": -0.05},
{"field": "slope_short", "op": ">", "value": 0.005},
{"field": "amount_rank", "op": "<=", "value": 30}
```
含义: 大盘在涨 + 大盘接近日高 + 个股也在涨 + 放量前30

### 场景B: 环境过滤（只在大盘好的时候操作）
```json
{"field": "mkt_slope_long", "op": ">", "value": 0}
```
含义: 只在大盘15分钟趋势向上时入场

### 场景C: 大盘强势突破
```json
{"field": "mkt_slope_short", "op": ">", "value": 0.002},
{"field": "mkt_slope_long", "op": ">", "value": 0.001},
{"field": "mkt_high_distance", "op": "=", "value": 0}
```
含义: 大盘短期和中期都在涨 + 正在创日内新高

### 场景D: 规避大盘下跌环境
```json
{"field": "mkt_peak_vol_bias", "op": ">=", "value": -0.1}
```
含义: 大盘尚未明显冲高回落（偏离放量高点不超过0.1个百分点）

## 九、存储策略

**方案选择**: 直接写入sssj表（同tick所有bond共享相同值）

| 对比 | 写入sssj表（当前方案） | 单独market表 |
|------|---------------------|-------------|
| 回测兼容 | ✅ 条件直接使用，无需改引擎 | ❌ 需JOIN |
| 存储开销 | ~320行×4字段×8bytes≈10KB/tick | 更小 |
| 实现复杂度 | 低（广播赋值） | 高（额外表+JOIN） |
| 一致性 | 天然一致（同表同事务） | 需保证跨表一致 |

选择写入sssj表，以回测引擎零改动为优先。
