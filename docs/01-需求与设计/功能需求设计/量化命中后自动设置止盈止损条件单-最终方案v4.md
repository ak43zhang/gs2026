## 一、方案总览

### 1.1 一句话描述

**量化命中 → 自动填充买入表单 → 你点买入 → 系统检测成交弹窗 → 自动设置止盈止损条件单。全程你只做1件事: 点买入。**

### 1.2 架构图

```
monitor_bond.py (采集+ETL, 每3秒一个tick)
    │
    │  ← 绝不因交易模块异常而中断
    │
    └── trade_hook.on_hit()  [try/except全包裹, 可插拔]
              │
              └── AutoTrader (独立模块)
                    ├── 活跃列表 (多命中并行跟踪)
                    ├── 弹窗检测 (成交确认)
                    ├── 超时撤单 (30秒兜底)
                    └── 止盈止损自动化 (纯Win32 API, 已验证)
```

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 采集不中断 | 交易模块任何异常 = 只打日志, 采集继续 |
| 可插拔 | 一个开关关掉, 采集照跑; 后期可迁移为独立服务 |
| 你只点买入 | 其余全自动(成交检测/TP-SL设置/超时撤单) |
| 无面板 | 不依赖浏览器, 不需要额外窗口 |
| 活跃列表 | 多个命中并行跟踪, 成交哪个处理哪个 |

### 2.1 时间线(典型场景)

```
[t+0s]   tick1: 量化命中 127045 @105.0
         系统: 加入活跃列表 {127045}
         系统: 填充xiadan买入表单(127045 @105.3)
         系统: 播放命中提示音

[t+3s]   tick2: 量化命中 127011 @110.5
         系统: 加入活跃列表 {127045, 127011}
         系统: 填充xiadan买入表单(覆盖为 127011 @111.0)

[t+6s]   tick3: 量化命中 127123 @98.0
         系统: 加入活跃列表 {127045, 127011, 127123}
         系统: 填充xiadan买入表单(覆盖为 127123 @98.5)
         
[t+7s]   你: 看到127123不错, 点击[买入]!
         xiadan: 委托提交

[t+7.5s] xiadan: 弹出成交回报窗口 "127123 成交 10股 @98.5"
         系统: 检测到弹窗 → 匹配活跃列表中的127123 ✓
         系统: 状态标记127123=FILLED

[t+8~13s] 系统: 自动设置止盈止损
          → 打开条件单弹窗(华泰理财通)
          → 导航: 卖出条件单 → 止盈止损
          → 填充: 代码=127123, 基准价=98.5, 止盈=3%, 止损=2%, 数量=10
          → 滚动 → 提交
          → 完成! 127123从活跃列表移除

[t+30s]  127045超时 → 尝试撤单 → "无此委托"(没买过) → 正常清除
[t+33s]  127011超时 → 尝试撤单 → "无此委托"(没买过) → 正常清除
[t+33s]  活跃列表清空 → 恢复正常
```

## 三、状态设计

### 3.1 系统状态(极简)

```
IDLE ←──→ ACTIVE
```

| 状态 | 含义 | 触发 |
|------|------|------|
| IDLE | 无活跃订单, 正常接收命中 | 活跃列表清空 |
| ACTIVE | 有活跃订单, 监控线程运行中 | 第一个命中到达 |

### 3.2 单个订单状态

```
WATCHING → FILLED → TP_SL_SET
              ↗
WATCHING → TIMEOUT_CANCEL_FILLED (撤单时发现已成交)
              
WATCHING → EXPIRED (超时, 未买/撤单成功)
```

| 状态 | 含义 |
|------|------|
| WATCHING | 在活跃列表中, 等待弹窗或超时 |
| FILLED | 成交确认(弹窗匹配 或 撤单返回已成交) |
| TP_SL_SET | 止盈止损已提交 ✓ |
| EXPIRED | 30秒超时, 已清理 |

## 四、活跃列表设计

### 4.1 数据结构

```python
active_orders = {
    "127045": {
        "bond_name": "凯中转债",
        "buy_price": 105.3,          # 计算后的买入价(hit_price + offset)
        "tp_pct": 3.0,               # 止盈百分比
        "sl_pct": 2.0,               # 止损百分比
        "quantity": 10,              # 股数
        "hit_time": 1721150400.0,    # 命中时间戳
        "scheme_name": "强势反弹",
    },
    "127011": { ... },
    "127123": { ... },
}
```

### 4.2 操作规则

| 操作 | 逻辑 |
|------|------|
| 新命中(同code) | 覆盖(保留最新参数) |
| 新命中(新code) | 新增 |
| 弹窗匹配 | 移除该code, 触发设TP/SL |
| 30秒超时 | 移除该code, 尝试撤单 |
| 撤单返回"已成交" | 视为成交, 补设TP/SL |
| 列表清空 | 停止监控线程, 状态→IDLE |

### 4.3 为何不限制列表大小

- 每个tick最多命中1个最优(现有逻辑best_match)
- 30秒超时自动清理
- 实际同时在列表中的不会超过10个(30秒/3秒tick=最多10个)
- 内存消耗可忽略

## 五、弹窗检测设计

### 5.1 检测逻辑

```python
def detect_fill_popup():
    """检测xiadan成交弹窗, 返回成交的code或None"""
    # 1. FindWindow查找标题含"成交"的窗口
    popup_hwnd = find_window_by_title(keyword)
    if not popup_hwnd:
        return None
    
    # 2. 读取弹窗内容(窗口文本/子控件文本)
    text = get_all_text(popup_hwnd)
    
    # 3. 在活跃列表中匹配code
    for code in active_orders:
        if code in text:
            return code
    
    return None  # 不是我们的单(或别的委托)
```

### 5.2 检测频率

- 每100ms轮询一次(0.1秒)
- 成交弹窗通常停留数秒, 100ms足够捕获
- CPU消耗极低(单次FindWindow调用)

### 5.3 需要实测确认

| 项目 | 需确认 | 如何确认 |
|------|--------|---------|
| 弹窗窗口标题 | "成交回报"? "委托成交"? | 写探测脚本, 成交时自动抓取 |
| 弹窗内容是否含code | 是否显示证券代码 | 同上 |
| 弹窗停留时间 | 几秒? 需手动关闭? | 观察 |
| 弹窗类型 | 独立窗口? MessageBox? | 探测脚本 |

```python
def handle_timeout(code, order_info):
    """30秒超时处理"""
    result = try_cancel_order(code)
    
    if result == "cancelled":
        # 有委托且撤成功 → 你买了但没成交
        log(f"[TIMEOUT] {code} 撤单成功(买了未成交)")
    
    elif result == "not_found":
        # 无此委托 → 你根本没买
        log(f"[TIMEOUT] {code} 无委托(未买入)")
    
    elif result == "already_filled":
        # 已成交! 弹窗可能漏检了 → 补设TP/SL
        log(f"[TIMEOUT] {code} 发现已成交! 补设止盈止损")
        set_tp_sl(code, order_info)
    
    # 无论如何, 从活跃列表移除
    del active_orders[code]
```

## 七、止盈止损自动化(已验证)

### 7.1 技术方案

- 纯Win32 API (ctypes.windll)
- 相对坐标 + 校准文件(tp_sl_positions.json)
- 窗口移动不影响

### 7.2 操作序列(已验证通过)

```
1. 找到xiadan.exe → 激活
2. 点击[条件单] → 弹出"华泰理财通(专业版)"窗口
3. 弹窗中点击: 卖出条件单 → 止盈止损
4. 填充表单(Tab模式):
   点击代码框 → 输入code
   → Tab → 输入基准价(买入成交价)
   → Tab → 输入止盈百分比
   → Tab → 输入止损百分比
   → Tab → 输入数量
5. 向下滚动1次 → 点击[提交条件单] → 确认
```

### 7.3 表单字段

| 字段 | 填入值 | 说明 |
|------|--------|------|
| 证券代码 | bond_code | 直接输入,无需下拉 |
| 基准价 | buy_price (元) | 实际成交价 |
| 止盈条件 | tp_pct (百分比) | 如3.0 |
| 止损条件 | sl_pct (百分比) | 如2.0 |
| 委托数量 | quantity (股) | lots × 10 |
| 委托价 | 默认(即时买三价) | 不修改 |
| 截止时间 | 默认 | 不修改 |

### 7.4 Tab顺序(已验证)

```
证券代码 → Tab → 基准价 → Tab → 止盈% → Tab → 止损% → Tab → 数量
```

## 八、可插拔接入设计

### 8.1 trade_hook.py (monitor_bond.py的唯一接口)

```python
class TradeHook:
    """可插拔交易钩子 — 所有异常内部消化"""
    
    def __init__(self, config):
        self.enabled = config.get('auto_trader_enabled', False)
        self._trader = None
    
    def on_hit(self, bond_code, bond_name, hit_price, scheme_detail, lots=1):
        """命中时调用 — 保证: 绝不抛异常, 绝不阻塞"""
        if not self.enabled:
            return
        try:
            trader = self._get_trader()
            trader.on_hit(bond_code, bond_name, hit_price, scheme_detail, lots)
        except Exception as e:
            logger.warning(f"[TradeHook] 异常(不影响采集): {e}")
    
    def tick(self):
        """每tick调用 — 保证: 绝不抛异常"""
        pass  # 超时检查在监控线程中自动执行,不需要tick驱动
```

### 8.2 monitor_bond.py 改动(仅3行)

```python
# 文件顶部:
from trade_hook import TradeHook
_trade_hook = TradeHook(config)

# 命中触发处(现有trader_on_hit旁边加一行):
_trade_hook.on_hit(bond_code, bond_name, hit_price, scheme_detail, lots)
```

### 8.3 可迁移性

## 十、错误处理

| 场景 | 处理 | 影响范围 |
|------|------|---------|
| trade_hook异常 | log.warning, 采集继续 | 仅交易 |
| 弹窗检测失败 | 30秒超时撤单时兜底发现 | 延迟但不丢 |
| 止盈止损设置失败 | 重试3次 → 声音告警 | 需人工补设 |
| 撤单失败 | log.error + 告警 | 可能残留委托 |
| xiadan未打开 | on_hit直接返回 | 本次命中丢失 |
| 校准文件不存在 | 启动时warning, TP/SL功能禁用 | 只能买不能自动设TP/SL |
| monitor_bond主循环 | **绝不受影响** | 无 |
