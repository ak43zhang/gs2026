## 1. 项目背景

### 1.1 问题描述

当前股票分时图查询存在严重性能瓶颈：

| 问题 | 现状 | 影响 |
|------|------|------|
| 查询延迟高 | 50-200ms | 悬浮分时图卡顿，用户体验差 |
| 数据库压力大 | 每次查询扫描4800条tick | MySQL CPU/IO负载高 |
| 并发能力差 | 高并发时响应恶化 | 影响大盘监控功能 |

### 1.2 优化目标

- **查询延迟**: 50-200ms → 1-3ms
- **并发能力**: 支持1000+并发查询
- **数据库负载**: 降低MySQL当日查询90%+
- **用户体验**: 悬浮分时图秒开

---

## 2. 方案概述

### 2.1 架构设计

采用**Redis缓存当日实时 + MySQL持久化历史**的混合架构：

```
┌─────────────────────────────────────────────────────────┐
│                         前端页面                          │
│                    (悬浮分时图/详情页)                      │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                      API Gateway                         │
│              (优先Redis，miss则回源MySQL)                   │
└─────────────────────────────────────────────────────────┘
                            │
            ┌───────────────┴───────────────┐
            ▼                               ▼
┌─────────────────────┐         ┌─────────────────────┐
│      Redis          │         │      MySQL          │
│  ├─ 当日实时数据     │         │  ├─ 历史全量数据     │
│  └─ 昨日数据(可选)   │         │  └─ 持久化存储       │
│     (热数据)         │         │     (冷数据)         │
└─────────────────────┘         └─────────────────────┘
```

### 2.2 数据分层策略

| 数据层 | 存储介质 | 保留时间 | 查询延迟 | 适用场景 |
|--------|----------|----------|----------|----------|
| 热数据 | Redis | 当日 | 1-3ms | 当日分时图查询 |
| 温数据 | Redis | 昨日(可选) | 1-3ms | 昨日对比查询 |
| 冷数据 | MySQL | 永久 | 50-200ms | 历史数据分析 |

## 3. 详细设计

### 3.1 Redis Key设计

**Key格式**: `stock:ticks:{股票代码}:{日期}`

**Field**: 时间戳 `HHMMSS`（如 093015）

**Value**: 压缩JSON，短字段名
```json
{
    "p": 10.50,   // price: 当前价
    "c": 1.20,    // change_pct: 涨跌幅%
    "v": 10000,   // volume: 成交量
    "a": 105000   // amount: 成交额
}
```

**示例**:
```
HSET stock:ticks:000001:20250703 093015 {"p":10.5,"c":1.2,"v":10000}
HSET stock:ticks:000001:20250703 093018 {"p":10.6,"c":1.3,"v":12000}
... 全天约4800个field
```

### 3.2 数据写入流程

**触发时机**: 每3秒采集tick数据时

**写入步骤**:

1. **数据收集**
   - 收集5000+股票最新tick数据
   - 内存中按股票代码聚合

2. **Redis批量写入**
   ```python
   pipe = redis.pipeline()
   for code, data in stock_data_dict.items():
       key = f"stock:ticks:{code}:{date}"
       field = time_str.replace(":", "")  # 093015
       value = json.dumps({
           "p": data["price"],
           "c": data["change_pct"],
           "v": data["volume"],
           "a": data["amount"]
       }, separators=(",", ":"))  # 压缩JSON
       
       pipe.hset(key, field, value)
       pipe.expire(key, ttl)  # 设置次日09:30过期
   
   pipe.execute()  # 批量执行
   ```

3. **MySQL异步写入**
   - 异步批量写入MySQL（不阻塞主流程）
   - 保持原有数据持久化逻辑

**性能指标**:
- 写入耗时: <0.5秒（在3秒采集窗口内）
- Redis命令数: 5000条打包为1个pipeline
- 网络RTT: 1次往返

### 3.3 数据查询流程

#### 当日分时图查询

```python
def query_today_ticks(code, date):
    """查询当日分时图数据"""
    key = f"stock:ticks:{code}:{date}"
    
    # 1. 查Redis
    data = redis.hgetall(key)
    
    if data:
        # 2. 解析并排序
        result = []
        for time_str, value in data.items():
            item = json.loads(value)
            item["time"] = time_str
            result.append(item)
        result.sort(key=lambda x: x["time"])
        return result
    
    # 3. Miss则查MySQL并回填
    return query_mysql_and_backfill(code, date)
```

**查询延迟**: 1-3ms（内存操作）

#### 历史分时图查询

```python
def query_history_ticks(code, date):
    """查询历史分时图数据"""
    key = f"stock:ticks:{code}:{date}"
    
    # 1. 尝试查Redis（可能命中昨日缓存）
    data = redis.hgetall(key)
    if data:
        return parse_and_sort(data)
    
    # 2. 查MySQL
    result = mysql.query(f"""
        SELECT time, price, change_pct, volume, amount
        FROM stock_ticks WHERE code=%s AND date=%s
    """, (code, date))
    
    # 3. 可选：回填Redis（带短TTL）
    if result:
        backfill_to_redis(key, result, ttl=3600)  # 1小时缓存
    
    return result
```

**查询延迟**: 50-200ms（仅历史）

### 4.1 内存占用

**基础参数**:
- 股票数量: 5,100
- 每天tick数: 4,800 (4小时交易/3秒间隔)


## 6. 代码实现

### 6.1 Redis写入模块

```python
# src/gs2026/utils/redis_tick_writer.py

import json
import redis
from datetime import datetime, timedelta
from typing import Dict, Any, Optional

class TickRedisWriter:
    """股票tick数据Redis写入器"""
    
    def __init__(self, redis_client: redis.Redis, pipeline_size: int = 100):
        """
        Args:
            redis_client: Redis连接
            pipeline_size: Pipeline批量大小
        """
        self.redis = redis_client
        self.pipeline_size = pipeline_size
    
    def write_ticks(self, date: str, time_str: str, 
                    stock_data_dict: Dict[str, Dict]) -> bool:
        """
        批量写入tick数据到Redis
        
        Args:
            date: 日期 (YYYYMMDD)
            time_str: 时间 (HH:MM:SS)
            stock_data_dict: {code: {price, change_pct, volume, amount}}
        
        Returns:
            bool: 是否成功
        """
        pipe = self.redis.pipeline()
        count = 0
        
        # 计算TTL（到次日09:30）
        ttl = self._calculate_ttl(date)
        
        for code, data in stock_data_dict.items():
            key = f"stock:ticks:{code}:{date}"
            field = time_str.replace(":", "")  # 093015
            
            # 压缩JSON，短字段名
            value = json.dumps({
                "p": data.get("price", 0),
                "c": data.get("change_pct", 0),
                "v": data.get("volume", 0),
                "a": data.get("amount", 0)
            }, separators=(",", ":"))
            
            pipe.hset(key, field, value)
            pipe.expire(key, ttl)
            
            count += 1
            if count >= self.pipeline_size:
                pipe.execute()
                pipe = self.redis.pipeline()
                count = 0
        
        # 执行剩余
        if count > 0:
            pipe.execute()
        
        return True
    
    def query_ticks(self, code: str, date: str) -> Optional[list]:
        """
        查询单股票全天分时数据
        
        Args:
            code: 股票代码
            date: 日期 (YYYYMMDD)
        
        Returns:
            list: 排序后的tick数据，None表示miss
        """
        key = f"stock:ticks:{code}:{date}"
        data = self.redis.hgetall(key)
        
        if not data:
            return None  # Miss，需查MySQL
        
        # 解析并排序
        result = []
        for time_str, value in data.items():
            item = json.loads(value)
            item["time"] = time_str.decode() if isinstance(time_str, bytes) else time_str
            result.append(item)
        
        result.sort(key=lambda x: x["time"])
        return result
    
    def _calculate_ttl(self, date: str) -> int:
        """计算到次日09:30的秒数"""
        now = datetime.now()
        target_date = datetime.strptime(date, "%Y%m%d") + timedelta(days=1)
        target = target_date.replace(hour=9, minute=30, second=0)
        ttl = int((target - now).total_seconds())
        return max(ttl, 3600)  # 至少1小时


class TickRedisReader:
    """股票tick数据Redis读取器（查询接口）"""
    
    def __init__(self, redis_client: redis.Redis, mysql_fallback=None):
        self.redis = redis_client
        self.mysql = mysql_fallback
    
    def get_intraday_data(self, code: str, date: str) -> list:
        """
        获取当日分时图数据（优先Redis，miss则MySQL）
        """
        # 1. 尝试Redis
        writer = TickRedisWriter(self.redis)
        data = writer.query_ticks(code, date)
        
        if data is not None:
            return data
        
        # 2. Miss，查MySQL
        if self.mysql:
            data = self._query_mysql(code, date)
            # 可选：回填Redis
            if data:
                self._backfill_to_redis(code, date, data)
            return data
        
        return []
    
    def _query_mysql(self, code: str, date: str) -> list:
```

### 6.2 集成到现有采集流程

```python
# 在 monitor_stock.py 的 tick 采集逻辑中集成

from gs2026.utils.redis_tick_writer import TickRedisWriter

# 初始化（全局单例）
redis_writer = None

def init_redis_writer(redis_client):
    global redis_writer
    redis_writer = TickRedisWriter(redis_client)

# 在 tick 采集后调用
def on_tick_collected(date: str, time_str: str, stock_data: dict):
    """每3秒tick采集完成后调用"""
    
    # 原有逻辑：写入MySQL
    write_to_mysql(date, time_str, stock_data)
    
    # 新增：写入Redis（异步，不阻塞）
    if redis_writer:
        try:
            redis_writer.write_ticks(date, time_str, stock_data)
        except Exception as e:
            # Redis写入失败不影响主流程
            logger.warning(f"Redis写入失败: {e}")
```

## 8. 风险评估

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| Redis故障 | 低 | 高 | 降级到MySQL，服务可用，延迟增加 |
| 内存不足 | 低 | 中 | 设置allkeys-lru策略，自动淘汰 |
| 写入超时 | 低 | 中 | 调大pipeline_size，或分多批 |
| 冷启动 | 中 | 低 | 首次查MySQL，自动回填Redis |
| 双写不一致 | 低 | 低 | Redis为准，MySQL仅持久化 |
