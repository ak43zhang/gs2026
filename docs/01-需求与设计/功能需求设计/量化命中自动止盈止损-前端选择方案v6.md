## 一、所有方案回顾

### v1: 热键确认
```
命中→填表→你点买入→按Ctrl+Shift+Y确认→设TP/SL
```
❌ 淘汰原因: 热键冲突,看不到状态

### v2: Web面板+队列
```
命中→入队→面板展示→你点[已买入]→点[确认成交]→设TP/SL
```
❌ 淘汰原因: 操作步骤多,切窗口多

### v3: Web面板一步确认
```
命中→面板展示→你点买入→面板点[确认]→设TP/SL
```
❌ 淘汰原因: 还是要切窗口确认

### v4: 全自动(弹窗检测)
```
命中→自动填表→你点买入→弹窗检测成交→自动设TP/SL
```
⚠️ 问题: 每次只跟踪1个,其他命中丢失;你无法选择买哪个

### v5: 全自动极简(单笔全仓)
```
命中→填表(最新一个)→你点买入→弹窗→设TP/SL
WATCHING期间新命中全部跳过
```
⚠️ 问题: 看不到其他命中信号,选择权受限

## 二、新方案(v6): 前端命中列表 + 你选择 + 独立执行

### 2.1 核心思路

```
┌─────────── 前端面板(实时) ─────────────┐
│                                        │
│  命中列表(实时刷新):                    │
│  ┌──────────────────────────────────┐  │
│  │ 10:30:01 127045 凯中 @105.3 [买] │  │
│  │ 10:30:04 127011 国城 @110.2 [买] │  │
│  │ 10:30:07 127123 华锐 @98.5  [买] │  │
│  │ 10:30:10 128096 众兴 @112.8 [买] │  │
│  │ ...实时滚动...                    │  │
│  └──────────────────────────────────┘  │
│                                        │
│  当前交易: 无 (等待选择)                 │
│                                        │
└────────────────────────────────────────┘

你看到列表 → 点某一行的[买]按钮 → 系统自动:
  1. 填充买入表单
  2. 等你在xiadan点买入
  3. 检测成交弹窗
  4. 设止盈止损
  5. 完成 → 清空列表 → 等新命中
```

### 2.2 与v5对比

| | v5(全自动) | v6(前端选择) |
|---|---|---|
| 你看到什么 | 只看到xiadan的最新表单 | **所有命中列表,一目了然** |
| 谁决定买哪个 | 系统填最新的,你只能买最新的 | **你自己选,哪个好买哪个** |
| 命中信号利用 | WATCHING期间全丢 | **全部保留在列表中** |
| 操作 | 只点xiadan买入 | 面板点[买] → xiadan点买入 |
| 切窗口 | 0次(但看不到选择) | 1次(面板→xiadan) |
| 信息量 | 低(只知道有命中) | **高(所有命中+价格+方案)** |
| 控制感 | 低(被动) | **高(主动选择)** |

### 2.3 流程详细

```
阶段1: 收集命中(持续)
─────────────────────
tick1: 命中127045 → 加入面板列表(展示)
tick2: 命中127011 → 加入面板列表(展示)
tick3: 命中127123 → 加入面板列表(展示)
...

你: 浏览列表, 选择最想买的那个

阶段2: 买入(你触发)
─────────────────────
你: 点了127123那行的[买]按钮
面板: 127123高亮, 显示"执行中..."
系统: 
  → 填充xiadan买入表单(127123 @98.5)
  → state = TRADING(面板锁定, 其他[买]按钮灰掉)
  → 清空命中列表(这批信号作废, 因为你已经选了)

你: 切到xiadan, 看表单, 点[买入]

阶段3: 自动完成(不需要你操作)
─────────────────────
系统: 检测成交弹窗...
  ├── 弹窗匹配127123 → 设止盈止损 → 完成!
  └── 30秒超时 → 撤单 → 完成

阶段4: 结束
─────────────────────
系统: state = IDLE
面板: 显示"交易完成 ✓ 127123 止盈3% 止损2%"
      或 "超时撤单 / 止盈止损触发"
面板: 清空, 开始接收新命中

新的tick命中 → 重新进入阶段1
```

## 三、v6方案深度分析

### 3.1 优势

| 优势 | 说明 |
|------|------|
| **全局视野** | 所有命中一览无余,不错过好机会 |
| **主动选择** | 你决定买哪个(不是系统强塞最新的) |
| **信息充分** | 每行显示代码/名称/价格/方案/止盈止损,决策有据 |
| **买入后全自动** | 选完之后不需要再操作面板 |
| **清晰的交易边界** | 一笔交易从"点[买]"到"完成提醒",界限分明 |
| **不丢信号** | 命中信号持续积累到列表,直到你选择 |

### 3.2 潜在问题与解决

**问题A: 命中列表越来越长?**
```
解决: 30秒信号过期自动移除
  - 超过30秒的命中从列表消失(信号过时)
  - 列表只保留最新30秒内的命中
  - 随着旧的过期、新的加入,列表自然滚动
```

**问题B: 你点[买]时,那条命中的价格可能已经变了?**
```
解决: 点[买]时用当前实时价格(不是命中时的价格)
  - 或: 保持命中时的计算价格(你看到什么买什么)
  - 建议: 用命中时的价格(你是基于这个价格做的决策)
  - 面板上可以同时显示"命中价"和"当前价"的对比
```

**问题C: 还是要切窗口(面板→xiadan)?**
```
对比:
  v5: 0次切窗口,但你不知道有什么命中,无法选择
  v6: 1次切窗口(面板→xiadan),但你有完整选择权

权衡: 1次切窗口换来全面信息+选择权, 值得
```

**问题D: 面板和采集的关系?**
```
面板是独立服务(Flask 8081端口)
monitor_bond.py只负责:
  1. 命中时调用 on_hit() 投递信号(非阻塞)
  2. 不管面板是否运行,采集不受影响
```

## 四、最终推荐: v6(前端选择 + 后端全自动)

### 4.1 为什么v6最好

```
v5的问题: "你只能被动等最新命中填入表单"
  → 如果最好的机会是5秒前那个,你没法选它

v6的解决: "所有命中都给你看,你选最好的"
  → 然后系统接管,全自动完成
  
v6 = v5的执行效率 + 面板的信息优势 + 你的主动选择权
```

### 4.2 架构

```
monitor_bond.py (主线程, 3秒tick, 不阻塞)
    │
    └── trade_hook.on_hit() → 投递命中信号到内存列表(<1ms)
              │
              ▼
┌─────────────────────────────────────────────────┐
│  AutoTrader (独立模块)                            │
│                                                 │
│  hit_list: [最近30秒内的命中信号]                  │
│  state: IDLE / TRADING                           │
│                                                 │
│  Flask API:                                      │
│    GET /api/hits → 返回命中列表                    │
│    POST /api/buy/{code} → 你点了[买] → 触发交易   │
│    GET /api/status → 当前交易状态                  │
│                                                 │
│  交易线程(state=TRADING时):                       │
│    填表 → 等弹窗 → 设TP/SL → 完成 → IDLE        │
└─────────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────────┐
│  前端面板 (浏览器, localhost:8081/panel)           │
│                                                 │
│  每秒刷新:                                       │
│    state=IDLE → 显示命中列表 + [买]按钮           │
│    state=TRADING → 显示当前交易进度               │
│    交易完成 → 提醒 → 清空 → 等新命中              │
└─────────────────────────────────────────────────┘
```

### 4.4 状态机

```
IDLE ──── on_hit() ────→ IDLE (命中只加列表,不改状态)
  │
  │ 你点面板[买] (POST /api/buy/127123)
  ▼
TRADING ──→ 填表 → 等弹窗 → 设TP/SL → 完成
  │                                      │
  │ (期间命中列表冻结,不接收新的)          │
  │                                      │
  └──────────── state=IDLE ←─────────────┘
                清空命中列表
                开始接收新命中
```

### 4.5 关键改变: 命中不再触发任何自动操作

```
之前(v5): on_hit → 自动填表 → 自动等弹窗 (你是被动的)
现在(v6): on_hit → 只加入列表 (等你主动选择点[买])

"买哪个"的决定权完全在你手上
```

## 五、v5 vs v6 最终对比

| 维度 | v5(全自动) | v6(前端选择) | 胜 |
|------|-----------|------------|---|
| 操作次数 | 1次(xiadan点买入) | 2次(面板点[买]+xiadan点买入) | v5 |
| 信息量 | 只知道最新1个 | 看到所有命中 | **v6** |
| 选择权 | 无(系统决定) | 有(你决定) | **v6** |
| 错过信号 | 多(WATCHING期间全丢) | 少(30秒内都保留) | **v6** |
| 切窗口 | 0次 | 1次(面板→xiadan) | v5 |
| 决策质量 | 低(最新≠最好) | 高(你选最好的) | **v6** |
| 实现复杂度 | 低(150行) | 中(250行+面板HTML) | v5 |
| 心理压力 | 高(来一个买一个,被动) | 低(看清楚再选,主动) | **v6** |

**推荐v6。多1次点击换来: 全面信息+主动选择+不丢信号。**
