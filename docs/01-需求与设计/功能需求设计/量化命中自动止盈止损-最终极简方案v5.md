# 单笔全仓交易模式 - 极简方案

> 版本: v5.0
> 日期: 2026-07-17
> 核心: 每次只有一笔交易,要么买到了要么没买到,不存在并行

---

## 一、核心洞察

**你的交易模式:**
- 全仓操作 → 同一时间最多只有1笔买入委托
- 买到了 → 不可能再买(没钱了)
- 没买到 → 必须撤单后才能买下一个
- 不存在"同时有两笔买入委托在跑"的情况

**这意味着:**
- 不需要多线程
- 不需要并行监听多个code
- 不需要优先级队列
- 不需要UI操作串行化(因为本来就只有一个在执行)

---

## 二、极简状态机

```
IDLE ──→ WATCHING ──→ SETTING_TP_SL ──→ IDLE
              │                            ↑
              │ 弹窗成交                    │
              │────────────────────────────┘
              │
              │ 30秒超时
              ↓
         CANCELLING ──→ IDLE
              │
              │ 撤单返回"已成交"
              ↓
         SETTING_TP_SL ──→ IDLE
```

**只有4个状态, 单线程顺序执行, 零并发问题。**

## 三、完整逻辑(单线程)

```python
class AutoTrader:
    """
    极简版: 单笔全仓交易
    
    规则:
    - state=IDLE时接受命中, 其他状态全部跳过
    - 同一时间只有1个活跃交易
    - 无多线程, 无队列, 无锁
    """
    
    state = "IDLE"           # IDLE / WATCHING / SETTING_TP_SL / CANCELLING
    current = None           # 当前活跃订单信息
    last_fill_time = None    # 上次填充表单的时间
    
    def on_hit(self, code, name, price, scheme, lots):
        """
        命中回调 — 每个tick可能调用
        
        逻辑:
        - IDLE → 接受, 填充表单, 进入WATCHING
        - 非IDLE → 但如果是新code且比当前更优, 可以覆盖表单
          (因为反正只有一笔委托, 表单覆盖不影响已提交的)
        """
        if self.state == "IDLE":
            # 新交易开始
            self._start_new_trade(code, name, price, scheme, lots)
        
        elif self.state == "WATCHING":
            # 已经在等成交了, 但新命中可以覆盖表单
            # (用户还没点买入的话, 看到新的可能更想买新的)
            self._update_form(code, name, price, scheme, lots)
    
    def tick(self):
        """
        每3秒tick调用(或独立线程每100ms调用)
        
        在WATCHING状态下:
        1. 检测弹窗 → 成交 → 设TP/SL
        2. 检查超时 → 撤单
        """
        if self.state == "WATCHING":
            # 检测成交弹窗
            filled_code = detect_popup()
            if filled_code == self.current['code']:
                self._on_filled()
                return
            
            # 检查超时(从命中时间算30秒)
            if time.time() - self.current['hit_time'] >= 30:
                self._on_timeout()
    
    def _start_new_trade(self, code, name, price, scheme, lots):
        """开始新交易"""
        buy_price = self._calc_buy_price(price, scheme)
        self.current = {
            'code': code,
            'name': name,
            'buy_price': buy_price,
            'tp_pct': scheme['take_profit'],
            'sl_pct': scheme['stop_loss'],
            'quantity': lots * 10,
            'hit_time': time.time(),
        }
        self.state = "WATCHING"
        
        # 填充买入表单
        fill_buy_form(code, buy_price, lots)
        play_sound("hit")
    
    def _update_form(self, code, name, price, scheme, lots):
        """
        WATCHING状态下新命中: 覆盖当前跟踪目标+表单
        
        为什么可以覆盖?
        - 如果用户还没点买入 → 表单覆盖,看新的
        - 如果用户已点买入 → 表单覆盖没关系(委托已提交,表单显示什么不影响)
          → 弹窗检测用的是current['code'], 改了code后会匹配新的
          → 但旧的委托还在! 需要处理...
        
        处理方式:
        - 覆盖current信息
        - 旧委托如果成交,弹窗code不匹配新current → 30秒后超时撤单时发现"已成交"→补设
        - 或者: 不覆盖code(只覆盖表单显示),弹窗还是匹配旧code
        
        简化决策: WATCHING状态下不更换跟踪目标!
        原因: 用户可能已经点了买入, 更换会导致混乱
        只更新表单显示(让用户看到最新的), 但系统跟踪的还是第一个
        
        等等, 这样也有问题... 
        
        最简方案: WATCHING状态下不覆盖, 新命中直接丢弃
        理由: 你正在决定要不要买当前这个, 新的等下一轮
        """
        pass  # WATCHING状态: 跳过新命中(最简)
    
    def _on_filled(self):
        """成交确认 → 设止盈止损"""
        self.state = "SETTING_TP_SL"
        play_sound("filled")
        
        # 直接设TP/SL(同一线程,无并发)
        result = set_tp_sl(
            self.current['code'],
            self.current['buy_price'],
            self.current['tp_pct'],
            self.current['sl_pct'],
            self.current['quantity'],
        )
        
        if result['success']:
            play_sound("done")
        else:
            play_sound("error")
        
        # 完成,回到IDLE
        self.state = "IDLE"
        self.current = None
    
    def _on_timeout(self):
        """超时 → 撤单"""
        self.state = "CANCELLING"
        
        result = cancel_order(self.current['code'])
        
        if result == "already_filled":
            # 撤单发现已成交(弹窗漏了) → 补设TP/SL
            self._on_filled()
        else:
            # 撤成功或无此委托 → 回IDLE
            play_sound("timeout")
            self.state = "IDLE"
            self.current = None
```

## 四、为什么不需要多线程

| 多线程方案的问题 | 单线程方案的优势 |
|---|---|
| UI操作冲突 | **不存在** — 只有1个操作在执行 |
| 需要锁/队列 | **不需要** — 顺序执行 |
| 需要优先级排序 | **不需要** — 没有并行任务 |
| 弹窗检测和UI操作冲突 | **不存在** — 检测和操作在同一线程交替 |
| 状态同步问题 | **不存在** — 单线程无竞态 |

**关键推导:**
```
全仓 → 只有1笔委托 → 只需要跟踪1个code → 只有1个可能的弹窗需要匹配
→ 不需要"活跃列表" → 只需要1个current变量
→ 成交/撤单/设TP_SL不可能同时发生 → 不需要串行化(本来就是串行的)
```

## 五、线程模型

**只需要1个额外线程(监控+执行合一):**

```
主线程 (monitor_bond.py, 每3秒tick)
    │
    │ on_hit()(state==IDLE时才接受)
    │
    ▼
监控+执行线程 (1个, 做所有事)
    │
    │ 循环(每100ms):
    │   if state == WATCHING:
    │       检测弹窗 → 找到? → _on_filled()(在本线程直接设TP/SL)
    │       检查超时 → 到了? → _on_timeout()(在本线程直接撤单)
    │   elif state == IDLE:
    │       sleep(等待下一次on_hit触发)
    │
    无并发, 无冲突, 无队列
```

**或者更简单: 连额外线程都不需要!**

```python
# 方案B: 完全靠tick驱动(无额外线程)

def tick(self):
    """monitor_bond.py每3秒调用一次"""
    if self.state == "WATCHING":
        # 在tick中做快速弹窗检测(每tick查一次)
        filled = detect_popup()
        if filled == self.current['code']:
            self._on_filled()  # 同步执行TP/SL(阻塞几秒)
            return
        # 超时检查
        if time.time() - self.current['hit_time'] >= 30:
            self._on_timeout()  # 同步执行撤单
```

**但tick间隔3秒太慢(弹窗可能消失)。所以还是用1个100ms轮询的线程。**

## 六、最终确定: 单监控线程方案

```python
class AutoTrader:
    state = "IDLE"
    current = None
    _thread = None
    
    def on_hit(self, code, name, price, scheme, lots):
        """只在IDLE时接受"""
        if self.state != "IDLE":
            return  # 正在交易中,跳过
        
        self.state = "WATCHING"
        self.current = {...}
        fill_buy_form(code, price, lots)
        
        # 启动监控线程
        self._thread = Thread(target=self._watch_loop, daemon=True)
        self._thread.start()
    
    def _watch_loop(self):
        """监控线程: 等弹窗或超时, 然后直接执行后续"""
        while self.state == "WATCHING":
            # 检测弹窗
            if detect_popup(self.current['code']):
                self.state = "SETTING_TP_SL"
                set_tp_sl(...)        # 直接执行,无冲突
                self.state = "IDLE"
                self.current = None
                return
            
            # 检测超时
            if time.time() - self.current['hit_time'] >= 30:
                self.state = "CANCELLING"
                result = cancel_order(...)  # 直接执行
                if result == "already_filled":
                    self.state = "SETTING_TP_SL"
                    set_tp_sl(...)    # 补设
                self.state = "IDLE"
                self.current = None
                return
            
            time.sleep(0.1)
```

**整个模块的线程模型:**
```
主线程(tick): on_hit() → 改state + 启动监控线程
监控线程(1个): 等弹窗/超时 → 执行TP/SL或撤单 → 完成 → 线程结束

不可能冲突:
- on_hit()只在state==IDLE时修改state(此时无监控线程)
- 监控线程运行时state!=IDLE → on_hit()不会执行任何操作
- 监控线程结束前设state=IDLE → 下次on_hit才能进入
```

## 八、WATCHING状态下新命中如何处理

两种策略:

### 策略A: 全部跳过(最简,推荐)
```
state != IDLE → return  # 一行代码,新命中直接丢弃
```
理由: 你正在决定当前这个,专注一个
缺点: 如果你犹豫了30秒没点买入,期间所有信号丢失

### 策略B: 允许覆盖表单(但不换跟踪目标)
```
state == WATCHING:
    fill_buy_form(new_code)     # 表单覆盖为新的
    self.current = new_info     # 跟踪也更新为新的
    self.current['hit_time'] = time.time()  # 超时重置
```
理由: 你还没买(表单还在),看到新的更好的可以直接买
缺点: 如果你刚点了旧的买入,但系统覆盖了current → 弹窗匹配可能出问题

### 策略C: 覆盖表单但不更换code跟踪
```
state == WATCHING:
    fill_buy_form(new_code)     # 表单覆盖(让你看到新的)
    # 但current不变! 系统还是在等旧code的弹窗
    # 如果你买了新的 → 弹窗code不匹配 → 超时撤单时发现已成交 → 补设
```
这太复杂了,放弃。

**结论: 用策略A(最简)。WATCHING期间新命中全部跳过。**

如果30秒内你没买 → 超时 → 回IDLE → 下一个tick的命中就能接收了。
最多损失30秒的信号,换来逻辑的绝对简单。
