# 可插拔式交易扩展 - 集成方案设计

> 版本: v3.0
> 日期: 2026-07-16
> 核心原则: 交易扩展不得影响采集主流程

---

## 一、架构原则

### 1.1 隔离要求

```
monitor_bond.py (采集+ETL, 生命线)
    │
    │  ← 绝对不能因为交易模块出错而中断
    │
    └─── trade_hook (可插拔扩展, try/except全包裹)
              │
              │  ← 这里面炸了=只打日志, 主流程不受影响
              │
              └─── TradeFlowManager (独立模块)
                        ├── Web面板 (Flask, 独立线程)
                        ├── 止盈止损 (Win32 API)
                        └── 撤单 (15秒未成交自动撤)
```

### 1.2 三个不可妥协

| 原则 | 说明 |
|------|------|
| 采集不中断 | 交易模块任何异常 = warning日志, 主循环继续 |
| 可插拔 | 一个开关关掉交易扩展, 采集照跑 |
| 可迁移 | 后期可整体搬到独立服务, 改动最小 |

## 二、两层超时设计

| 超时 | 时间 | 含义 | 触发动作 |
|------|------|------|---------|
| **命中信号过期** | 30秒 | 从命中瞬间算,超时=信号过时不值得买 | 丢弃(队列移除) |
| **买入未成交撤单** | 15秒 | 从点击"已买入"算,15秒没确认成交=可能没成交 | 自动撤单(F3) |

```
命中时刻 ──────────── 30秒 ────────────→ 信号作废
         │
         ├── 面板显示订单
         │
         ├── 你点买入(xiadan)
         │
         ├── 回面板点[已买入]
         │        │
         │        └──── 15秒 ────→ 未确认成交 → 自动撤单
         │              │
         │              ├── 你确认成交 → 设止盈止损 ✓
         │              └── 超时 → 撤单 → 下一个
         │
         └── 一直没操作 → 30秒到 → 信号丢弃 → 下一个
```

## 三、可插拔Hook设计

### 3.1 接口定义

```python
# trade_hook.py — 可插拔交易钩子

class TradeHook:
    """
    monitor_bond.py 的交易扩展接口
    
    设计目标:
    - 所有方法绝不抛异常(内部全try/except)
    - enable/disable一键切换
    - 后期可替换为远程调用(HTTP/MQ)
    """
    
    def __init__(self, config: dict):
        self.enabled = config.get('trade_hook_enabled', False)
        self._manager = None  # 延迟初始化
    
    def on_hit(self, bond_code, bond_name, hit_price, scheme_detail, lots=1):
        """
        命中时调用 — monitor_bond.py唯一需要调用的方法
        
        保证: 绝不抛异常, 绝不阻塞(异步处理)
        """
        if not self.enabled:
            return
        try:
            manager = self._get_manager()
            if manager:
                manager.on_hit(bond_code, bond_name, hit_price, scheme_detail, lots)
        except Exception as e:
            logger.warning(f"[TradeHook] on_hit异常(不影响采集): {e}")
    
    def tick(self):
        """
        每tick调用(3秒) — 检查超时
        保证: 绝不抛异常
        """
        if not self.enabled:
            return
        try:
            manager = self._get_manager()
            if manager:
                manager.check_timeout()
        except Exception as e:
            logger.warning(f"[TradeHook] tick异常: {e}")
```

### 3.2 monitor_bond.py中的使用(改动极小)

```python
# monitor_bond.py 中只需加这几行:

# === 初始化(文件顶部) ===
from trade_hook import TradeHook
_trade_hook = TradeHook(config)  # config里有trade_hook_enabled开关

# === 命中时(在现有trader_on_hit调用旁边) ===
# 原有逻辑不动,新增一行:
_trade_hook.on_hit(bond_code, bond_name, hit_price, scheme_detail, lots)

# === 每tick末尾 ===
_trade_hook.tick()
```

**关键: 即使TradeHook内部全炸了,monitor_bond.py照跑不误。**

### 3.3 可迁移设计

```python
# 当前: 进程内直接调用
class TradeHook:
    def on_hit(self, ...):
        self._manager.on_hit(...)  # 本地调用

# 未来: 独立服务(只改实现,接口不变)
class TradeHookRemote:
    def on_hit(self, ...):
        requests.post("http://trade-service:9000/hit", json={...})  # 远程调用
```

## 四、撤单接口设计

### 4.1 撤单场景

```
用户点了[已买入] → 15秒倒计时开始
    │
    ├── 15秒内点[确认成交] → 正常流程(设TP/SL)
    │
    └── 15秒超时 → 自动撤单:
         ├── 调用 /api/cancel_order
         ├── xiadan.exe中: 撤销该委托
         └── 面板显示: "15秒未成交,已自动撤单"
```

### 4.2 xiadan.exe撤单操作

华泰xiadan.exe撤单方式:
- **F3** 切换到撤单面板
- 显示当日未成交委托列表
- 选中目标委托 → 点撤单/双击

自动化方式(与买入填充相同技术):
```python
def cancel_order(bond_code):
    """在xiadan.exe中撤销指定委托"""
    # 1. 激活xiadan窗口
    # 2. 按F3切到撤单面板
    # 3. 在委托列表中找到bond_code对应的行
    # 4. 双击/选中后按撤单
    # 5. 确认弹窗
```

### 4.3 API接口

```
POST /api/cancel_order
{
    "code": "127045",
    "price": 105.3    // 可选,用于精确匹配
}

Response:
{
    "success": true/false,
    "message": "撤单成功/失败原因"
}
```

## 五、面板状态机(修订版)

```
WAIT_BUY ──→ CONFIRMING ──→ FILLED ──→ TP_SL_SET ✓
    │              │
    │              └──→ AUTO_CANCELLED (15秒未成交,自动撤单)
    │
    └──→ EXPIRED (30秒信号过期,从未操作)
```

### 面板按钮:

| 状态 | 显示 | 按钮 |
|------|------|------|
| WAIT_BUY | "127045 @105.3 TP:3% SL:2%" + 30秒倒计时 | [已买入] [跳过] |
| CONFIRMING | "等待成交确认" + 15秒倒计时 | [确认成交→设止盈止损] [撤单] |
| FILLED | "正在设置止盈止损..." | 无 |
| TP_SL_SET | "✓ 完成" | 无 |
| AUTO_CANCELLED | "15秒未成交,已撤单" | 无 |
| EXPIRED | "信号过期" | 无 |

## 六、完整操作时间线(最佳情况)

```
[10:30:00.000] 量化命中 → on_hit() → 计算买入价
[10:30:00.100] 买入表单填充(xiadan.exe自动)
[10:30:00.200] Web面板出现订单(30秒信号倒计时开始)
[10:30:01.000] 你看到面板 → 切到xiadan → 点买入
[10:30:02.000] 切回面板 → 点[已买入](15秒成交倒计时开始)
[10:30:02.500] 你看到价格已成交 → 点[确认成交→设止盈止损]
[10:30:02.600] 系统开始设置止盈止损(约5秒)
[10:30:07.500] 止盈止损条件单提交完成 ✓
[10:30:07.600] 面板显示✓, 处理队列下一个

总耗时: ~7.5秒(其中你操作~2秒, 系统自动~5.5秒)
```

## 八、错误处理矩阵

| 错误场景 | 影响范围 | 处理方式 |
|---------|---------|---------|
| trade_hook.on_hit()异常 | 仅交易 | log.warning, 采集继续 |
| Flask服务崩溃 | 仅面板 | 面板不可用,命中信号仍在队列 |
| 止盈止损填充失败 | 仅TP/SL | 重试3次→告警,订单标记failed |
| 撤单API失败 | 仅撤单 | log.error+告警,面板显示手动撤 |
| xiadan.exe未打开 | 所有交易 | 直接跳过,log.error |
| 校准文件不存在 | 止盈止损 | 启动时warning,TP/SL功能禁用 |
| monitor_bond.py主循环 | **绝不受影响** | 所有外部调用都在try/except中 |
