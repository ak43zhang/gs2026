# 完整交易闭环分析 — 从买入到止盈止损触发

> 日期: 2026-07-17
> 核心: 一笔交易的完整生命周期 = 买入 → 持有监控 → 卖出(TP/SL/强平) → 结束

---

## 一、完整闭环流程

```
┌─────────────────────────────────────────────────────────────┐
│                    一笔交易的完整生命周期                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  阶段1: 选择买入                                             │
│    命中列表实时展示 → 你选一个点[买] → 填表 → 你点买入         │
│                                                             │
│  阶段2: 等待成交                                             │
│    弹窗检测 → 成交 → 设止盈止损条件单                         │
│    或: 30秒超时 → 撤单 → 交易结束                            │
│                                                             │
│  阶段3: 持仓监控 ← 新增!                                     │
│    每tick检查当前价格 vs TP/SL水平                            │
│    ├── 价格 >= 止盈价 → 止盈触发! → 交易结束                  │
│    ├── 价格 <= 止损价 → 止损触发! → 交易结束                  │
│    └── 持仓时间 >= max_hold_time → 强制卖出 → 交易结束        │
│                                                             │
│  交易结束:                                                   │
│    清空命中列表 → state=IDLE → 等待新命中                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、状态机(完整版)

```
IDLE ──→ TRADING ──→ MONITORING ──→ IDLE
           │              │
           │ 超时撤单      ├── 止盈触发 → 提醒 → IDLE
           └── IDLE        ├── 止损触发 → 提醒 → IDLE
                           └── 超时强平 → 卖出 → IDLE
```

| 状态 | 含义 | 持续时间 |
|------|------|---------|
| IDLE | 等待,接收命中 | 不定 |
| TRADING | 买入执行中(填表→等弹窗→设TP/SL) | ~10-40秒 |
| MONITORING | 持仓中,监控价格 | 数分钟~数十分钟 |

## 三、阶段3(持仓监控)详细设计

### 3.1 监控方式: 利用已有的tick价格数据

```python
def tick(self, df_now):
    """monitor_bond.py每3秒调用,传入最新行情"""
    if self.state != "MONITORING":
        return
    
    # 获取当前持仓债券的价格
    price = get_price_from_df(df_now, self.current['code'])
    if not price:
        return
    
    # 检查止盈
    if price >= self.tp_level:
        self._on_exit("tp", price)
        return
    
    # 检查止损
    if price <= self.sl_level:
        self._on_exit("sl", price)
        return
    
    # 检查持仓超时(强平)
    hold_seconds = time.time() - self.fill_time
    if hold_seconds >= self.max_hold_seconds:
        self._on_force_sell(price)
```

### 3.2 为什么用价格监控而不是弹窗?

| | 用价格判断(推荐) | 用卖出弹窗 |
|---|---|---|
| 数据来源 | monitor_bond已有的行情数据 | 需要检测xiadan卖出弹窗 |
| 额外开发 | 0(只是比较数字) | 需要新的弹窗检测逻辑 |
| 准确性 | 高(价格过线=条件单必触发) | 弹窗可能漏检 |
| 时效 | 3秒延迟(tick间隔) | 未知 |
| 复杂度 | 极低(3行if) | 中 |

**价格监控的本质:** 券商的条件单在价格到达时触发卖出,我们看到同样的价格数据,就知道条件单已经/即将触发。不需要等卖出确认弹窗。

### 3.3 止盈止损价计算

```python
# 进入MONITORING时计算:
self.tp_level = self.current['buy_price'] * (1 + self.current['tp_pct'] / 100)
self.sl_level = self.current['buy_price'] * (1 - self.current['sl_pct'] / 100)
self.max_hold_seconds = scheme['max_hold_time'] * 60  # 分钟→秒

# 示例:
# buy_price = 105.3, tp=3%, sl=2%, max_hold=30min
# tp_level = 105.3 * 1.03 = 108.459
# sl_level = 105.3 * 0.98 = 103.194
# max_hold = 30 * 60 = 1800秒
```

### 3.4 强制卖出(超时强平)

```python
def _on_force_sell(self, current_price):
    """持仓时间超过max_hold_time → 强制卖出"""
    # 填充xiadan卖出表单(F2)
    fill_sell_form(
        code=self.current['code'],
        price=current_price,  # 当前价卖出(尽快成交)
        quantity=self.current['quantity'],
    )
    play_sound("force_sell")
    # 提示你在xiadan点卖出
    # 或: 自动提交卖出(更激进)
    
    self._end_trade("force_sell", current_price)
```

**强平的卖出方式选择:**

| 方式 | 描述 | 风险 |
|------|------|------|
| A. 填表等你点 | 系统填F2表单,你手动点卖出 | 你可能没注意到 |
| B. 自动卖出 | 系统填表+自动点击卖出 | 全自动,但万一误判? |
| C. 不卖,只告警 | 提示你手动处理 | 可能延误 |

**建议: 方式A(填表等你点) — 与买入保持一致的操作模式。**
如果你希望更激进(完全不用管),可以用方式B。

## 四、可行性分析

### 4.1 ✅ 可行的部分

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 价格监控 | ✅ 完全可行 | monitor_bond每3秒已有价格,只需比较 |
| 判断TP/SL触发 | ✅ 完全可行 | 价格过线=触发,逻辑简单 |
| max_hold超时 | ✅ 完全可行 | 时间比较 |
| 强平填表 | ✅ 可行 | 与买入填表相同技术(F2+keyboard) |
| 交易结束清空 | ✅ 可行 | 清列表+state=IDLE |
| 结束提醒 | ✅ 可行 | 声音/日志 |

### 4.2 ⚠️ 需注意的点

**注意1: 3秒延迟**
```
价格监控每3秒一次(tick间隔)
极端情况: 价格在tick间隙闪过TP/SL线又回来
  → 券商条件单可能已触发(毫秒级) 
  → 但我们3秒后才看到,此时价格已回落
  → 我们判断"未触发" → 继续监控 → 实际已卖出
  
影响: 可能多等几个tick才意识到已触发
解决: 无大碍(最终max_hold会兜底; 或下次tick价格又过线)
```

**注意2: 强平时机的精确性**
```
max_hold_time=30min
实际检测: 每3秒检查 → 最多延迟3秒触发强平
影响: 可接受(3秒误差对30分钟持仓无影响)
```

**注意3: MONITORING期间不接收新命中**
```
如果max_hold_time=60分钟 → 60分钟内无法做新交易
这是"全仓单笔"模式的固有特性
如果觉得太长 → 减小max_hold_time
```

## 六、完整伪代码

```python
class AutoTrader:
    state = "IDLE"         # IDLE / TRADING / MONITORING
    current = None
    hit_list = []          # 面板展示的命中列表
    
    # === 阶段1: 命中收集 ===
    def on_hit(self, code, name, price, scheme, lots):
        """命中信号投递(非阻塞)"""
        if self.state != "IDLE":
            return  # 交易中/监控中,不收新命中
        self.hit_list.append({
            'code': code, 'name': name, 'price': price,
            'scheme': scheme, 'lots': lots,
            'time': time.time(),
        })
        # 清理30秒前的过期命中
        self.hit_list = [h for h in self.hit_list if time.time()-h['time'] < 30]
    
    # === 阶段2: 用户选择买入 ===
    def on_buy_click(self, code):
        """面板[买]按钮(API调用)"""
        if self.state != "IDLE":
            return
        hit = find_in_list(code)
        if not hit:
            return
        
        self.state = "TRADING"
        self.current = build_order(hit)
        self.hit_list = []  # 清空命中列表
        
        # 启动交易线程
        Thread(target=self._execute_trade, daemon=True).start()
    
    # === 阶段2: 交易执行(独立线程) ===
    def _execute_trade(self):
        """填表 → 等弹窗 → 设TP/SL → 进入监控"""
        # 填买入表单
        fill_buy_form(self.current)
        
        # 等弹窗
        filled = wait_for_popup(self.current['code'], timeout=30)
        
        if not filled:
            # 超时撤单
            try_cancel(self.current['code'])
            self._end_trade("timeout_cancel")
            return
        
        # 设止盈止损
        result = set_tp_sl(self.current)
        if not result['success']:
            play_sound("error")
            # 设失败了但已经买了 → 进入监控(靠价格监控+强平保护)
        
        # 进入监控阶段
        self.state = "MONITORING"
        self.fill_time = time.time()
        self.tp_level = self.current['buy_price'] * (1 + self.current['tp_pct']/100)
        self.sl_level = self.current['buy_price'] * (1 - self.current['sl_pct']/100)
        self.max_hold_seconds = self.current['max_hold_minutes'] * 60
        
        play_sound("monitoring")  # 提示: 已设好TP/SL,开始监控
    
    # === 阶段3: 持仓监控(tick驱动) ===
    def on_tick(self, df_now):
        """每3秒tick调用"""
        if self.state != "MONITORING":
            return
        
        price = get_price(df_now, self.current['code'])
        if not price:
            return
        
        # 止盈触发
        if price >= self.tp_level:
            self._end_trade("tp", price)
            return
        
        # 止损触发
        if price <= self.sl_level:
            self._end_trade("sl", price)
            return
        
        # 持仓超时强平
        if time.time() - self.fill_time >= self.max_hold_seconds:
            self._force_sell(price)
            return
    
    # === 强制卖出 ===
    def _force_sell(self, price):
        """超时强平: 填卖出表单"""
        Thread(target=self._do_force_sell, args=(price,), daemon=True).start()
    
    def _do_force_sell(self, price):
        fill_sell_form(self.current['code'], price, self.current['quantity'])
        play_sound("force_sell")
        # 等卖出弹窗? 或直接视为完成?
        # 建议: 填表后直接结束(你去点卖出,系统认为交易结束)
        self._end_trade("force_sell", price)
    
    # === 交易结束 ===
    def _end_trade(self, reason, price=None):
        """统一结束: 清空状态,回到IDLE"""
        log_trade(reason, self.current, price)
        play_sound("trade_end")
        
        self.current = None
        self.hit_list = []  # 清空旧命中
        self.state = "IDLE"  # 可以接收新命中了
```

## 八、优化建议

| 建议 | 说明 | 优先级 |
|------|------|--------|
| 价格监控用tick数据(已有) | 不需要额外获取价格,零开销 | 必做 |
| 强平用填表模式(你点卖出) | 与买入一致,你保留控制权 | 推荐 |
| TP/SL设置失败时仍进MONITORING | 靠价格监控+强平兜底 | 推荐 |
| 面板显示持仓进度条 | 直观看到当前位置和TP/SL距离 | 可选 |
| 交易结束后短暂冷却(如3秒) | 防止结束瞬间的命中质量差 | 可选 |

## 九、风险与兜底

| 风险 | 兜底 |
|------|------|
| 条件单设失败了(没TP/SL保护) | 仍进入MONITORING,靠价格监控+强平 |
| 价格闪过TP/SL线太快(3秒没检到) | 大概率下个tick能检到;最终有强平兜底 |
| 强平时你没点卖出 | 至少表单已填好,下次强平会再填一次 |
| MONITORING太久(60min) | 可配置max_hold缩短;全仓模式的固有特性 |

## 十、结论

**这个思路完全可行,形成了真正的闭环:**

```
命中 → 选择 → 买入 → 设TP/SL → 监控 → 退出(TP/SL/强平) → 结束 → 新一轮
```

**每一步都有明确的结束条件,不会"卡住":**
- 买入阶段: 成交弹窗 或 30秒超时
- 监控阶段: 价格触达TP/SL 或 max_hold超时强平
- 强平: 填卖出表单(最终你点卖出)

**对系统的额外负担几乎为零:**
- MONITORING阶段只是每tick做3个数字比较(<1ms)
- 不需要额外线程/弹窗检测/UI操作
- 直到强平才需要操作xiadan(独立线程)
