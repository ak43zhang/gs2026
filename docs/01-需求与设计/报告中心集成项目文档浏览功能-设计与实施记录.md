## 安全设计

1. **路径穿越防护**：`doc-content` API 中使用 `resolve().relative_to()` 确保路径不超出 `G:/report`
2. **只读访问**：所有API只提供读取功能，不支持修改/删除
3. **联接隔离**：Windows Junction 只映射目录，不影响源文件权限

## 问题排查记录

### 问题1：点击文档显示"加载失败：非法路径"

**发现时间**：2026-07-15 22:32

**现象**：在报告中心点击"项目文档"分类下的 .md 文件（如"文档中心Web浏览器设计方案"），弹出查看器后显示"加载失败：非法路径"。

**根因分析**：

`/api/reports/doc-content` 路由中的路径安全检查使用了 `Path.resolve()`：

```python
full_path = Path("G:/report") / file_path
full_path.resolve().relative_to(Path("G:/report").resolve())
```

`resolve()` 会**跟随 Windows Junction 解析为真实路径**：
```
G:\report\项目文档\00-项目说明\文档.md
    ↓ resolve() 跟随Junction
F:\pyworkspace2026\gs2026\docs\00-项目说明\文档.md
    ↓ relative_to(G:\report)
ValueError → "非法路径"
```

Junction 映射的文件真实路径不在 `G:\report` 下，导致安全检查误判。

**修复方案**：

将 `resolve()` 安全检查替换为**防路径穿越检查**（不跟随Junction）：

```python
# 修复前
full_path = Path("G:/report") / file_path
try:
    full_path.resolve().relative_to(Path("G:/report").resolve())
except ValueError:
    return jsonify({"success": False, "error": "非法路径"}), 403

# 修复后
if '..' in file_path or file_path.startswith('/') or file_path.startswith('\\'):
    return jsonify({"success": False, "error": "非法路径"}), 403
full_path = Path("G:/report") / file_path
```

**修改文件**：`src/gs2026/dashboard2/routes/report.py` 第750-755行

**修复原理**：
- 防穿越：检查路径中不含 `..`、不以 `/` 或 `\` 开头
- 不跟随Junction：不使用 `resolve()`，直接拼接路径
- 文件存在性由后续 `full_path.exists()` 检查保证

**经验教训**：
> Windows Junction/Symbolic Link 场景下，`Path.resolve()` 会将虚拟路径解析为真实路径，不适合用于安全边界检查。应使用逻辑层面的路径穿越检查替代。
