# 多命中并行问题分析与解决方案

> 日期: 2026-07-17
> 问题: 连续tick命中不同code,用户只买其中一个,如何处理?

---

## 一、问题还原

```
tick1 (t+0s):  命中 127045 → 填充买入表单 → 你没买
tick2 (t+3s):  命中 127011 → 填充买入表单(覆盖了127045) → 你没买
tick3 (t+6s):  命中 127123 → 填充买入表单(覆盖了127011) → 你买了!

问题:
  - 三个都启动了线程监听弹窗?
  - 127045和127011的超时是"没买"的超时,127123是"买了等成交"的超时
  - 系统如何区分?
```

---

## 二、核心矛盾

**系统不知道你买没买。** 

它只知道:
1. 填充了买入表单(但填充不等于你点了买入)
2. 弹窗出现了(说明某笔成交了)

**它不知道:**
- 你有没有点买入按钮
- 你看了表单后是决定买还是放弃

---

## 三、解决方案: 覆盖模式(不并行)

### 3.1 核心思路: 新命中覆盖旧命中,只跟踪最新一笔

```
tick1: 命中127045 → 填充表单 → 监听目标="127045" → 30秒超时开始
tick2: 命中127011 → 填充表单(覆盖) → 监听目标改为"127011" → 超时重置30秒
tick3: 命中127123 → 填充表单(覆盖) → 监听目标改为"127123" → 超时重置30秒

你在tick3后买了127123 → 弹窗"127123" → 匹配当前目标 → 设TP/SL
```

**逻辑:**
- **永远只跟踪最新一笔命中**
- 新命中覆盖旧命中(旧的自动作废,不需要撤单因为根本没提交)
- 弹窗只匹配最新target_code
- 超时只算最新命中的30秒

**为什么旧命中不需要撤单?**
```
tick1填充127045 → tick2填充127011(覆盖了表单) → xiadan表单里现在是127011
→ 127045从未被提交过(你没点买入) → 不存在委托 → 不需要撤
```

**表单覆盖 = 旧命中自动失效**

### 3.2 但有个问题: 如果你买了旧的呢?

```
tick1: 命中127045 → 填充表单
你: 看到127045,快速点了买入! (在tick2到来之前)
tick2: 命中127011 → 填充表单(但127045已经提交了,表单显示新的127011)
系统: 监听目标="127011"

弹窗: "127045成交!" → 但系统在等127011 → 不匹配 → 忽略!!
```

**问题: 你买了旧的,但系统跟踪的是新的,导致弹窗不匹配!**

### 3.3 解决: 监听所有活跃code(有限集合)

```python
class AutoTrader:
    state = "IDLE"  # IDLE / ACTIVE
    active_orders = {}  # code → {scheme_detail, hit_time, buy_price}
    
    def on_hit(self, code, name, price, scheme, lots):
        """每次命中: 记录到活跃列表 + 填充最新表单"""
        if self.state != "ACTIVE":
            self.state = "ACTIVE"
            self._start_monitor_thread()
        
        # 记录这笔命中(如果同code覆盖)
        self.active_orders[code] = {
            'bond_name': name,
            'buy_price': price + scheme['price_offset'],
            'tp_pct': scheme['take_profit'],
            'sl_pct': scheme['stop_loss'],
            'quantity': lots * 10,
            'hit_time': time.time(),
        }
        
        # 填充最新的表单(xiadan显示最新一笔)
        fill_buy_form(code, self.active_orders[code]['buy_price'], lots)
    
    def _monitor_thread(self):
        """统一监控线程(只有1个)"""
        while self.state == "ACTIVE":
            # 1. 检测弹窗
            popup_code = self._detect_popup()
            if popup_code and popup_code in self.active_orders:
                # 匹配到! 这笔成交了
                order = self.active_orders.pop(popup_code)
                self._set_tp_sl(popup_code, order)
                # 设完TP/SL后如果没有其他活跃单了,回到IDLE
                if not self.active_orders:
                    self.state = "IDLE"
                continue
            
            # 2. 清理超时的(从命中时间算30秒)
            now = time.time()
            expired = [code for code, info in self.active_orders.items()
                       if now - info['hit_time'] >= 30]
            for code in expired:
                del self.active_orders[code]
                # 注意: 超时的可能需要撤单(如果用户买了但没成交)
                # 但我们不确定用户是否买了... 见下文分析
            
            # 3. 全部超时 → 回IDLE
            if not self.active_orders:
                self.state = "IDLE"
                return
            
            time.sleep(0.1)
```

### 3.4 超时撤单问题: "没买"和"买了没成交"如何区分?

```
活跃列表: {127045, 127011, 127123}
30秒后:
  127045 超时 — 你没买它(未提交委托) — 不需要撤单
  127011 超时 — 你没买它(未提交委托) — 不需要撤单  
  127123 超时 — 你买了但没成交(有委托) — 需要撤单!
  
但系统不知道哪个你买了哪个你没买!
```

**解决方案: 超时后统一尝试撤单,撤不到就算了**

```python
for code in expired_codes:
    result = try_cancel(code)
    # result可能是:
    # "cancelled" → 有委托且撤成功了
    # "not_found" → 没有这个委托(你根本没买) → 正常,忽略
    # "already_filled" → 已成交(弹窗漏检了?) → 补设TP/SL!
```

| 撤单结果 | 含义 | 处理 |
|---------|------|------|
| 撤单成功 | 你买了但没成交,已撤 | 清理,继续 |
| 无此委托 | 你没买,不存在委托 | 正常,忽略 |
| 已成交 | 弹窗漏检了,其实成交了 | **补设TP/SL!** |

**这是一个完美的兜底: 不管弹窗检没检到,超时撤单时都能发现真实状态。**

## 四、最终方案: 活跃列表 + 统一监听 + 超时撤单兜底

### 4.1 状态图

```
IDLE ─── on_hit ───→ ACTIVE
  ↑                     │
  │                     ├── 弹窗匹配code → 设TP/SL → 该code移出列表
  │                     ├── 超时 → 尝试撤单 → 该code移出列表  
  │                     │       └── 撤单返回"已成交" → 补设TP/SL
  │                     │
  └── 列表清空 ─────────┘
```

### 4.2 不是多线程,是单线程监控

```
只有1个监控线程:
  └── 循环(每100ms):
        ├── 检测弹窗 → 匹配活跃列表中的code
        └── 检查超时 → 清理过期的code
        
不需要每个code一个线程!
```

### 4.3 完整逻辑

```python
class AutoTrader:
    """
    状态: IDLE / ACTIVE
    active_orders: dict[code] → {buy_price, tp_pct, sl_pct, quantity, hit_time}
    
    规则:
    - 每次命中: 加入active_orders + 填充最新表单
    - 弹窗检测: 匹配code → 成交 → 设TP/SL → 从列表移除
    - 30秒超时: 从列表移除 + 尝试撤单(兜底)
    - 列表清空: 回到IDLE
    - ACTIVE期间新命中: 正常加入列表(不跳过!)
    """
```

### 4.4 对比之前的"全跳过"方案

| | 之前(全跳过) | 现在(活跃列表) |
|---|---|---|
| 命中处理 | 处理中全丢 | **全部记录,哪个成交处理哪个** |
| 信号利用率 | 低(只处理第1个) | **高(N个里成交哪个就处理哪个)** |
| 并行处理 | 不支持 | **天然支持(列表中任一成交即响应)** |
| 复杂度 | 极简 | 稍高(但逻辑清晰) |
| 符合实际 | 部分(丢信号) | **完全(你自己选择买哪个)** |

## 五、你的操作流程(最终版)

```
tick1: 命中127045 → xiadan显示买入表单(127045 @105.3)
       你: 看了一眼,不想买,不操作

tick2: 命中127011 → xiadan表单覆盖为(127011 @110.2)
       你: 还是不想买

tick3: 命中127123 → xiadan表单覆盖为(127123 @98.5)
       你: 这个好! 点[买入]!

[系统后台]
  活跃列表: {127045(t+0), 127011(t+3), 127123(t+6)}
  监听弹窗...
  
[t+7s] 弹窗出现: "127123 成交 10股 @98.5"
  → 匹配127123 ✓
  → 自动设止盈止损(TP=3%, SL=2%, 基准=98.5)
  → 127123从列表移除

[t+30s] 127045超时 → 尝试撤单 → "无此委托"(你没买) → 正常移除
[t+33s] 127011超时 → 尝试撤单 → "无此委托"(你没买) → 正常移除
[t+36s] 列表清空 → 状态=IDLE
```

**你只做了1次操作: 点买入。系统自动完成了TP/SL设置和超时清理。**

## 六、边界情况处理

| 场景 | 处理 |
|------|------|
| 你同时买了2个(快速操作) | 两个弹窗都会被匹配,各自设TP/SL ✓ |
| 弹窗漏检(成交但没检测到) | 30秒超时撤单时发现"已成交"→ 补设TP/SL ✓ |
| 别的手动委托弹窗 | code不在活跃列表 → 忽略 ✓ |
| 同一tick命中同code | active_orders[code]覆盖(保留最新参数) ✓ |
| 超时后才成交(31秒成交) | 已撤单成功→不会成交; 或撤单返回"已成交"→补设 ✓ |
