# 日志系统 — 周期任务（挑战）功能设计方案

> **版本**: V1.0  
> **日期**: 2026-05-11  
> **状态**: 待用户审核  
> **基于**: 当前日志+待办系统现状

---

## 一、需求理解

用户在日志体系中增加**周期性任务/挑战**能力。

典型场景：
- 🏃 **锻炼21天挑战** — 在21天内每天打卡运动
- 📚 **阅读30天计划** — 连续阅读打卡
- 💊 **按时吃药提醒** — 每日固定时间事项
- 💧 **喝8杯水** — 每日重复习惯

核心特征区别于现有「待办」：
- **有持续周期**：不是单次任务，有开始/结束或持续天数目标
- **每日打卡**：每天记录是否完成，看连续进度
- **一个挑战跨多天**：1个挑战对象 → 对应N天的完成状态
- **注重连续性**：显示连续打卡天数、完成率

## 二、当前系统分析

### 2.1 数据库现状

`user_journals` 表（主体日志表）：

```sql
id, username, journal_date, content, todo_items, 
remarks, tags, mood, is_deleted
```

- 日志按**天**存储，一条记录 = 一天
- `todo_items` 是 JSON 字段，存该日期下的待办事项
- 已有 27 条有效记录（testadmin 用户）

### 2.2 有待改进

| 维度 | 现状 | 挑战系统需求 |
|------|------|------------|
| 周期定义 | ❌ 无 | 需要挑战定义（名称/目标天数/频率） |
| 跨天关联 | ❌ 日志天与天无关联 | 挑战跨N天，每天打卡关联回挑战 |
| 连续打卡 | ❌ 无 | 连续天数、最长连续、完成率 |
| 挑战进度 | ❌ 无 | 图形化进度环/条形 |
| 挑战列表 | ❌ 无 | 用户的所有挑战列表+状态 |

## 三、架构设计

### 3.1 数据模型

#### 表1：`user_challenges`（挑战主表）

```sql
CREATE TABLE user_challenges (
    id              INT AUTO_INCREMENT PRIMARY KEY,
    username        VARCHAR(100)    NOT NULL COMMENT '用户名',
    name            VARCHAR(200)    NOT NULL COMMENT '挑战名称',
    target_days     INT             DEFAULT 21 COMMENT '目标天数(0=无限期)',
    description     VARCHAR(500)    DEFAULT '' COMMENT '挑战描述',
    color           VARCHAR(16)     DEFAULT '#667eea' COMMENT '卡片颜色',
    icon            VARCHAR(32)     DEFAULT '🎯' COMMENT 'emoji图标',
    status          TINYINT         DEFAULT 1 COMMENT '0=暂停,1=进行中,2=已完成',
    created_at      DATETIME        DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    is_deleted      TINYINT         DEFAULT 0,
    KEY idx_user     (username),
    KEY idx_status   (username, status),
    UNIQUE KEY uk_name (username, name, is_deleted)
);
```

**字段说明**：

| 字段 | 说明 | 示例 |
|------|------|------|
| `name` | 挑战名称 | "锻炼21天" |
| `target_days` | 目标天数，21 | `21`（周 为 7，月为 30） |
| `status` | 状态 | `1(进行中)` |
| `color` | 主题色（影响卡片UI） | `#667eea` |
| `icon` | Emoji 图标 | `🏃` |

#### 表2：`user_challenge_logs`（打卡记录）

```sql
CREATE TABLE user_challenge_logs (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(100)    NOT NULL,
    challenge_id INT            NOT NULL,
    log_date    DATE            NOT NULL COMMENT '打卡日期',
    notes      VARCHAR(500)    DEFAULT '' COMMENT '当日打卡备注',
    created_at  DATETIME        DEFAULT CURRENT_TIMESTAMP,
    is_deleted  TINYINT         DEFAULT 0,
    UNIQUE KEY uk_challenge_date (username, challenge_id, log_date, is_deleted),
    KEY idx_challenge (username, challenge_id),
    KEY idx_date (username, log_date),
    FOREIGN KEY (challenge_id) REFERENCES user_challenges(id)
);
```

**字段说明**：

| 字段 | 说明 |
|------|------|
| `challenge_id` | 关联挑战主表 |
| `log_date` | 打卡的日期 |
| `notes` | 当日简短备注（打卡时填写） |

**唯一约束**：同一挑战同一日期只能打卡一次（防止重复）。

#### 表3：扩展 `user_journals`（可选，懒打卡关联）

在 `user_journals` 增加字段用于展示当天的挑战完成情况（可选，Phase 2考虑）：

```sql
ALTER TABLE user_journals ADD COLUMN challenge_progress VARCHAR(2000) DEFAULT '' COMMENT '当日完成挑战列表JSON';
```

> ⚠️ 此字段为 v1.1➕，第一阶段可暂不引入，用单独查询即可。

### 3.2 数据关系

```
用户
 └── user_challenges（1个用户的多挑战，N记录）
      └── user_challenge_logs（1个挑战的N天打卡，按天1×N记录）
```

## 四、功能规格

### 4.1 挑战管理（CRUD）

| 操作 | 方法 | 说明 |
|------|------|------|
| **列表** | `GET /api/challenges/list` | 按状态筛选（全部/进行中/已完成/暂停） |
| **详情** | `GET /api/challenges/detail/<id>` | 包含打卡统计（计入总数、连续等） |
| **创建** | `POST /api/challenges/create` | name, target_days, description, icon, color |
| **更新** | `POST /api/challenges/update/<id>` | 修改名称/目标天数/描述/颜色/状态 |
| **删除** | `POST /api/challenges/delete/<id>` | 软删除（级联删除打卡记录） |
| **完成** | `POST /api/challenges/complete/<id>` | 提前完成挑战 |

### 4.2 打卡操作

| 操作 | 方法 | 说明 |
|------|------|------|
| **当日打卡** | `POST /api/challenge/checkin/<id>` | log_date=今天，幂等 |
| **取消打卡** | `POST /api/challenge/uncheckin/<id>` | 删除当日记录 |
| **编辑备注** | `POST /api/challenge/notes/<id>` | 更新 log_date 的 notes |

### 4.3 统计 API

打卡为例，卡片展示需要：
```json
{
    "challenge_id": 1,
    "name": "锻炼21天",
    "icon": "🏃",
    "color": "#667eea",
    "target_days": 21,
    "status": 1,
    "created_at": "2026-05-01",
    "total_checked": 8,
    "current_streak": 3,
    "longest_streak": 5,
    "progress": 8,
    "progress_pct": 38,
    "remaining_days": 13
}
```

### 4.4 列表+详情页

**列表页卡片（类似待办卡片风格）**：
```
┌─ 🏃 锻炼21天 ─────────────────────────────────────────┐
│  ████████████░░░░░░░░  8/21天 · 连续3天              │
│  当前进度 38%，还需13天，今日✅ 已打卡               │
└───────────────────────────────────────────────────────┘
```

状态色彩：
| 状态 | 描述 | 色彩 |
|------|------|------|
| 进行中 | `status=1, total<target` | 主题色（用户自定义） |
| 已完成 | `status=2 或 total>=target` | `#22c55e` 绿色 + ✅图标 |
| 暂停 | `status=0` | `#9ca3af` 灰色 + ⏸图标 |
| 逾期 | `status=1, 当前日期>目标天数` | `#f97316` 橙色 + ⚠️ |

**详情页（打卡日历视图）**：

│  │ 12    13    14    15    16    17    18                          │  │
│  └───────────────────────────────────────────────────────────────┘  │
│                                                                      │
│  ████████████░░░░░░░░  8/21天 · 连续3天 · 已完成38%               │

**📝当日打卡备注**（可选必填）：
- 点击日历某天 → 弹出备注框或直接打卡
- 支持日期判断（仅今天或历史日期都可补卡）

## 六、API 一览

### 6.1 挑战管理

```
GET  /api/challenges/list              → 列表（可选 status=1/2/0）
GET  /api/challenges/detail/<id>       → 详情+统计
POST /api/challenges/create            → 创建（name, target_days, description, icon, color）
POST /api/challenges/update/<id>       → 更新
POST /api/challenges/delete/<id>       → 软删除
POST /api/challenges/complete/<id>     → 完成挑战
```

### 6.2 打卡

```
POST /api/challenge/checkin/<id>       → 当日打卡（幂等）
POST /api/challenge/uncheckin/<id>     → 取消打卡
POST /api/challenge/notes/<id>         → 更新打卡备注
```

### 6.3 日历详情

```
GET  /api/challenge/cal/<id>?month=2026-05  → 月度打卡日历[{date, has_checkin, notes}]
```

### 6.4 嵌套在日志页？

> **思考**：是否需要挑战进度同步到日志的 Daily View？  
> **结论**：Phase 1 暂不嵌入，保持独立页面。Phase 2 可在日历视图中叠加打卡状态。

## 八、数据模型详细对比

### 现有 vs. 新增

| | 现有待办 | 新增挑战 |
|---|---|---|
| 粒度 | 单条待办（日期+文+优先级） | 多个打卡日（关联到挑战） |
| 关联 | 按天分散在不同日志中 | 1对多：挑战→N天记录 |
| 周期 | ❌ 无 | ✅ 有目标持续天数 |
| 连续性 | ❌ 无 | ✅ 连续天数统计 |
| 进度可视化 | ❌ 无 | ✅ 进度条+完成率 |
| 重复 | 需要每天手动录入 | 创建后每天显示+打卡 |
| 完结自动化 | ❌ 无 | ✅ 达成目标标记完成 |
