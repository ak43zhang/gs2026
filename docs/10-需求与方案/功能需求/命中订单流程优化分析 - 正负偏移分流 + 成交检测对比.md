## 一、正负偏移分流设计

### 1.1 两条路径

```
量化命中 → 计算买入价
    │
    ├── offset >= 0 (买入价 >= 市价)
    │       │
    │       │  [快速路径] 秒成交,无需等待
    │       │
    │       ├── 自动填充买入表单
    │       ├── 面板: 1个按钮 [买入成功,设止盈止损]
    │       ├── 你点买入 → 回面板点这个按钮 → 立刻设TP/SL
    │       └── 30秒信号过期仍未操作 → 丢弃
    │
    └── offset < 0 (买入价 < 市价)
            │
            │  [等待路径] 挂单等成交
            │
            ├── 自动填充买入表单
            ├── 面板: [已挂单] → 开始等待倒计时
            ├── 成交了 → 点[确认成交,设止盈止损] → 设TP/SL
            └── N秒未成交 → 自动撤单(N=方案配置,15-30秒)
```

### 1.2 两条路径对比

| | 快速路径(offset>=0) | 等待路径(offset<0) |
|---|---|---|
| 成交预期 | 秒成交 | 不确定,可能不成交 |
| 面板按钮 | 1个: [买入成功,设TP/SL] | 2步: [已挂单] → [确认成交] |
| 等待时间 | 不等(立刻设TP/SL) | 等N秒看是否成交 |
| 超时处理 | 30秒信号过期丢弃 | N秒未成交自动撤单 |
| 你的操作 | 1次点击 | 2次点击(挂单+确认) |

### 1.3 配置

```yaml
trade_hook:
  signal_expire_seconds: 30        # 信号过期(通用)
  fill_timeout_seconds: 20         # 负偏移挂单未成交撤单时间(可按方案配)
  # 也可以在scheme中单独配:
  # schemes:
  #   强势反弹: { fill_timeout: 15 }
  #   低吸: { fill_timeout: 30 }
```

## 二、成交检测方式对比

### 2.1 方案对比

| | 方式A: 监控当日成交 | 方式B: 人为确认(面板点击) | 方式C: 检测成交弹窗 |
|---|---|---|---|
| **原理** | 定时切到xiadan"当日成交"面板查看 | 你看到xiadan成交通知后点面板按钮 | 检测xiadan弹出的"成交回报"窗口 |
| **时效性** | 慢(轮询3-5秒间隔) | 快(你看到立刻点,1-2秒) | 快(弹窗出现即检测) |
| **可靠性** | 中(需解析列表/OCR) | 高(人判断最准) | 低(弹窗可能瞬间消失) |
| **复杂度** | 高(切面板+读取+切回) | 低(只需面板按钮) | 中(FindWindow轮询) |
| **干扰性** | 高(切换xiadan面板会打断你操作) | 无(面板独立) | 无 |
| **自动化** | 全自动 | 需1次点击 | 全自动 |

### 2.2 逐项分析

#### 方式A: 监控当日成交(不推荐)

```
操作序列:
1. 切到xiadan → F4(当日成交面板)
2. 读取列表找匹配(code+price+time)
3. 判断是否成交
4. 切回F1(买入面板)准备下一单

问题:
- 切面板会打断你正在做的事(比如你正在看另一只的买入)
- 读取列表需要OCR或剪贴板操作,不稳定
- 来回切换面板 = 慢 + 干扰
- 如果成交列表很长,查找耗时

结论: ❌ 干扰大,实现复杂,不值得
```

#### 方式B: 人为确认(推荐)

```
流程:
1. xiadan弹出成交通知(你看到了)
2. 你切到面板点[确认成交]
3. 系统设TP/SL

优势:
- 最可靠(人的判断不会错)
- 不干扰xiadan操作
- 实现最简单
- 你本来就要看面板(管理队列)

劣势:
- 需要1次点击(~1秒)
- 如果正在忙可能延迟几秒

结论: ✅ 推荐,可靠+简单+不干扰
```

#### 方式C: 检测成交弹窗(备选)

```
原理:
- xiadan成交后会弹出一个通知窗口
- 用FindWindow轮询检测标题含"成交"的弹窗
- 检测到 → 自动确认 → 自动设TP/SL

代码:
    # 每秒检测
    hwnd = find_window_by_title("成交")  # 或"委托成交"/"成交回报"
    if hwnd:
        # 读取弹窗内容确认是我们的单
        auto_confirm()

优势:
- 全自动(0次点击)
- 时效高(弹窗出现即检测)

劣势:
- 弹窗标题不确定(需实测)
- 弹窗可能很快消失(1-2秒)
- 多笔委托同时有弹窗时难区分
- 可能误判(别的委托的成交)

结论: ⚠️ 有潜力但需实测弹窗行为
```

### 2.3 建议方案: B为主 + C为辅(后期)

```
当前实施: 方式B(人为确认)
- 稳定可靠,立即可用
- 你只需1次点击,不影响效率

后期优化: 加入方式C(检测弹窗)
- 实测xiadan成交弹窗的窗口标题和持续时间
- 如果可检测 → 作为自动确认的加速手段
- B和C并行: 弹窗检测到=自动确认, 没检测到=等你手动确认
```
