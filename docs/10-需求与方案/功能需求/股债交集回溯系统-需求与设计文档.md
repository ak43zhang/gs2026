## 1. 需求概述

### 1.1 背景

当前系统中，股票上攻排行和债券上攻排行分别展示，用户需要手动对比才能发现股债联动机会。为提高效率，需要自动化回溯功能，遍历历史时间轴，自动筛选符合条件的股债组合并持久化存储。

### 1.2 目标

构建一个股债交集回溯系统，能够：
- 遍历指定日期的完整时间轴（tick 级别）
- 对股票和债券分别应用过滤条件
- 计算股债交集（有映射关系的股票-债券对）
- 将结果幂等保存到 MySQL
- 支持后续查询和分析

### 1.3 范围

**包含范围**:
- 时间轴遍历（tick 级别）
- 股票过滤管道（复用前端逻辑）
- 债券过滤管道（复用前端逻辑）
- 股债交集计算
- 结果持久化（MySQL）
- 查询 API

**不包含范围**:
- 实时流式计算
- 分布式并行处理
- 复杂关联规则（除 bond_code 外）

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| **Tick** | 系统数据采集的最小时间粒度，通常为 3 秒（债券）或 5 秒（股票） |
| **时间轴** | 一个交易日内所有 tick 时间点的有序集合 |
| **过滤管道** | 由多个过滤器组成的链式处理结构，数据依次经过每个过滤器 |
| **股债交集** | 同时满足股票过滤条件和债券过滤条件的股票-债券对 |
| **幂等性** | 重复执行相同操作，结果一致，不会产生重复数据 |
| **过滤快照** | 执行回溯时的完整过滤配置，用于追溯和复现 |

### 3.2 详细需求

#### F001 时间轴遍历

**需求描述**: 系统需要能够遍历指定交易日的完整时间轴。
**输入**:
- 日期（YYYYMMDD）
**输出**:
- 时间列表（["09:30:00", "09:30:03", ..., "15:00:00"]）
**规则**:
- 只遍历 tick 级别时间点（根据实际存储的时间戳）
- 从 09:30:00 到 15:00:00（交易时间）
- 只遍历有数据的时间点（从 Redis 时间戳列表获取）

#### F002/F003 数据获取

**需求描述**: 获取指定时间点的股票/债券上攻排行数据。
**输入**:
- 日期（YYYYMMDD）
- 时间（HH:MM:SS）
**输出**:
- 股票/债券数据列表（使用现有 API）

#### F004/F005 过滤管道

**需求描述**: 复用前端过滤逻辑，在后端实现相同的过滤管道。

**股票过滤器**:
| 过滤器 | 类型 | 说明 |
|--------|------|------|
| industry | predicate | 行业筛选 |
| topn_sectors | predicate | 仅前N行业（次数） |
| topn_sectors_pct | predicate | 仅前N行业（涨幅） |
| topn_window | ranking | 仅前N区间次数 |
| topn_count | ranking | 仅前N累计次数 |
| bond_filter | predicate | 仅显示有债券 |

**债券过滤器**:
| 过滤器 | 类型 | 说明 |
|--------|------|------|
| industry | predicate | 行业筛选 |
| topn_sectors | predicate | 仅前N行业（次数） |
| topn_sectors_pct | predicate | 仅前N行业（涨幅） |
| topn_amount | ranking | 仅前N金额 |
| topn_window | ranking | 仅前N区间次数 |
| topn_count | ranking | 仅前N累计次数 |
| green_list | predicate | 排除绿名单 |

**过滤管道执行逻辑**:
1. Phase 1: 谓词型过滤器串行执行，生成候选池 S
2. Phase 2: 排名型过滤器各自基于 S 计算，取交集

#### F006 交集计算

**需求描述**: 计算股票和债券的交集。
**关联规则**:
```
股票字段 bond_code == 债券字段 code
```

**交集结果**:
- 对于每只股票，如果其 bond_code 在过滤后的债券列表中，则形成一个股债对

#### F007 结果保存

**需求描述**: 将交集结果幂等保存到 MySQL。
**幂等保证**:
- 唯一索引: (trade_date, trade_time, stock_code, bond_code)
- 写入方式: INSERT ... ON DUPLICATE KEY UPDATE

#### F009 结果查询

**需求描述**: 支持多维度查询回溯结果。
**查询条件**:
- 日期范围
- 时间范围
- 股票代码
- 债券代码
- 行业

## 8. 模块详细设计

### 8.1 BacktraceRunner（回溯运行器）

```python
class BacktraceRunner:
    """股债交集回溯运行器"""
    
    def __init__(self, config: BacktraceConfig):
        self.config = config
        self.time_axis = TimeAxisIterator(config.date)
        self.stock_filter = StockFilter(config.stock_filters)
        self.bond_filter = BondFilter(config.bond_filters)
        self.intersection_calc = IntersectionCalculator()
        self.repository = BacktraceRepository()
    
    def run(self) -> BacktraceResult:
        """执行回溯任务"""
        records = []
        
        for time_str in self.time_axis:
            stock_data = self._fetch_stock_data(time_str)
            bond_data = self._fetch_bond_data(time_str)
            
            filtered_stocks = self.stock_filter.apply(stock_data)
            filtered_bonds = self.bond_filter.apply(bond_data)
            
            intersections = self.intersection_calc.calculate(
                filtered_stocks, filtered_bonds
            )
            
            records.extend(self._build_records(time_str, intersections))
        
        return self.repository.save_batch(records)
```

### 8.2 过滤器实现

```python
class Pipeline:
    """过滤管道"""
    
    def execute(self, data: List[Dict]) -> List[Dict]:
        # Phase 1: 谓词型
        S = data
        for f in self.filters:
            if f.kind == 'predicate':
                S = f.apply(S)
        
        # Phase 2: 排名型
        ranking_sets = []
        for f in self.filters:
            if f.kind == 'ranking':
                subset = f.apply(S)
                ranking_sets.append(set(item['code'] for item in subset))
        
        # 取交集
        if ranking_sets:
            intersection = ranking_sets[0]
            for s in ranking_sets[1:]:
                intersection &= s
            S = [item for item in S if item['code'] in intersection]
        
        return S
```

## 14. 10分钟窗口汇总展示设计（2026-08-04新增）

### 14.1 需求背景

当前系统返回每个tick的明细数据，存在以下问题：
- 数据量大，难以快速识别趋势
- 无法直观看到股票-债券对在时间窗口内的表现演变
- 缺乏关键分析指标（如从首次命中到最高涨幅的时间差、涨幅差）

### 14.2 设计目标

将明细数据按**10分钟时间窗口聚合汇总**，提供分析友好的展示方式，帮助分析人员快速识别：
- 哪些股债对在哪个时间段表现突出
- 拉升速度（时间差）和力度（涨幅差）
- 持续性（出现次数、连续性评分）

### 14.3 窗口定义

- **窗口大小**: 固定10分钟
- **窗口边界**: 09:30, 09:40, 09:50, 10:00, 10:10...
- **窗口标识**: `09:30-09:40`, `09:40-09:50`, `14:20-14:30`...
- **聚合维度**: 按 **股票代码+债券代码** 唯一对聚合

### 14.4 汇总表字段（11列）

| 序号 | 字段名 | 类型 | 说明 | 示例 | 分析意义 |
|------|--------|------|------|------|----------|
| 1 | `window` | string | 窗口标识 | `14:20-14:30` | 定位时间段 |
| 2 | `stock_code_name` | string | 股票代码+名称 | `000703 恒逸石化` | 快速识别标的 |
| 3 | `bond_code_name` | string | 债券代码+名称 | `127067 恒逸转2` | 关联转债信息 |
| 4 | `industry_name` | string | 行业名称 | `化学纤维` | 行业维度分析 |
| 5 | `appear_count` | int | 窗口内出现次数 | `5` | **持续性指标**：出现次数越多，说明该对在该窗口持续活跃 |
| 6 | `first_change_pct` | float | 首次命中涨幅 | `0.37` | 入场参考：首次出现时的涨幅水平 |
| 7 | `max_change_pct` | float | 窗口内最高涨幅 | `1.25` | 峰值参考：该窗口内达到的最高涨幅 |
| 8 | `time_to_max_display` | string | **时间差（显示）** | `4分27秒` | **速度指标**：从首次到最高所用时间，判断拉升速度 |
| 9 | `gain_to_max` | float | **涨幅差** | `0.88` | **力度指标**：最高-首次，判断拉升力度 |
| 10 | `last_change_pct` | float | 窗口结束涨幅 | `1.10` | 离场参考：窗口结束时的涨幅水平 |
| 11 | `window_count_avg` | float | 平均window_count | `3.2` | 强度指标：平均上榜强度，值越大说明越强 |

### 14.5 派生计算字段

| 字段名 | 类型 | 计算方式 | 说明 |
|--------|------|----------|------|
| `time_to_max_seconds` | int | `max_time - first_time`（秒） | 时间差原始值，用于排序和颜色判断 |
| `time_to_max_display` | string | `format_duration(seconds)` | 人性化显示：`4分27秒` |
| `gain_to_max` | float | `max_change_pct - first_change_pct` | 涨幅差，保留2位小数 |
| `continuity_score` | float | `appear_count / 窗口总tick数` | **连续度评分**：0-1之间，值越大说明连续性越好 |
| `avg_change_pct` | float | `sum(change_pct) / appear_count` | 平均涨幅水平 |
| `min_change_pct` | float | `min(change_pct)` | 窗口内最低涨幅 |

### 14.6 明细字段（展开后）

| 序号 | 字段名 | 类型 | 说明 | 示例 |
|------|--------|------|------|------|
| 1 | `time` | string | 精确时间点 | `14:23:15` |
| 2 | `change_pct` | float | 当时涨幅 | `0.37` |
| 3 | `window_count` | int | 当时window_count | `3` |
| 4 | `rank` | int | 当时排名 | `5` |
| 5 | `main_net_amount` | float | 主力净流入金额 | `12500000` |
| 6 | `amount` | float | 成交金额 | `250000000` |
| 7 | `mark` | string | 特殊标记 | `first`/`max`/`last` |

### 14.7 关键字段详细说明

#### 14.7.1 时间差（time_to_max）

**定义**: 从首次命中该对，到达到窗口内最高涨幅所用的时间。

**计算**:
```
time_to_max_seconds = max_change_time - first_appear_time
time_to_max_display = format_to_human_readable(time_to_max_seconds)
```

**分析意义**:
| 时间差 | 解读 | 策略建议 |
|--------|------|----------|
| < 2分钟 | 极速拉升，资金抢筹明显 | 追涨风险高，适合短线快进快出 |
| 2-5分钟 | 正常拉升，资金持续流入 | 可跟随，设置止损 |
| > 5分钟 | 缓慢爬升，资金稳健进入 | 适合稳健持有，波动小 |

**颜色编码**:
- 🔴 **红色** (< 2分钟): 快速拉升，注意追高风险
- 🟡 **黄色** (2-5分钟): 正常拉升
- 🟢 **绿色** (> 5分钟): 缓慢爬升，稳健

#### 14.7.2 涨幅差（gain_to_max）

**定义**: 窗口内最高涨幅与首次涨幅的差值，代表该窗口内的拉升力度。

**计算**:
```
gain_to_max = max_change_pct - first_change_pct
```

**分析意义**:
| 涨幅差 | 解读 | 策略建议 |
|--------|------|----------|
| > 2% | 强势拉升，资金力度大 | 关注，可能延续 |
| 1-2% | 正常拉升 | 观察 |
| < 1% | 弱势，或已高位 | 谨慎 |

**颜色编码**:
- 深红色: > 2%
- 浅红色: 1-2%
- 灰色: < 1%
