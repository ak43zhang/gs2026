# 股票交集命中音效功能 - 需求与方案

**版本**: v1.0
**制定日期**: 2026-08-05
**状态**: 待审核
**关联页面**: `dashboard2/templates/monitor.html`（数据监控）
**关联规范**: `docs/20-开发规范/音效开发统一规范.md`

---

## 一、需求背景

数据监控页「📈 股票上攻排行」标题栏有一个 🔗「仅显示与债券榜的交集」按钮（`stock-intersect-btn`）。开启后，股票榜只展示与债券榜按 `bond_code` 关联的交集结果。

用户诉求：**开启交集后，当交集结果"从无到有"或"出现新成员"时，自动播放"萌宝高兴说中啦中啦"的语音提示**，以便盯盘时不用一直用眼睛盯着榜单变化。

---

## 二、现状分析（代码实证）

### 2.1 交集按钮链路

```
🔗 stock-intersect-btn (onclick=toggleIntersection)
  → _intersectionMode = true
  → refreshBothWithIntersection()
      → 股票榜跑 STOCK_PIPELINE → stockFiltered
      → 债券榜跑 BOND_PIPELINE → bondFiltered
      → applyIntersection(stockFiltered, bondFiltered) → { stockResult, bondResult }
      → renderRanking('stock-ranking', stockResult)
```

### 2.2 交集算法（`applyIntersection`）

股票交集结果 = 股票中 `bond_code` 存在且落在债券榜 code 集合里的行。**`stockResult` 就是我们要监听的目标。**

### 2.3 刷新时机

- 手动开启/关闭交集：`toggleIntersection`
- 切时间点 / 自动刷新数据：`rerenderStockRanking()` → 若 `_intersectionMode` 则调 `refreshBothWithIntersection()`
- 数据 tick：**3 秒一次**（用户明确，故无需额外节流）

### 2.4 现有音效

页面已有 Web Audio 合成蜂鸣音（`play2StarBeep`/`play3StarBeep`），用于买点 2星/3星提示，开关为 🔔（`_bpSoundEnabled`）。**本功能不复用此开关，单独加一个交集音效开关**，两者互不干扰。

## 三、方案设计

### 3.1 音效方式：前端播放（遵循音效规范 方案A）

- 判断逻辑（交集从无到有）在**前端 JS**，故按《音效开发统一规范》**前端方式**实施。
- 音频文件放 `dashboard2/static/sounds/zhongla.mp3`，`new Audio('/static/sounds/zhongla.mp3').play()`。
- 失败降级到 Web Audio 蜂鸣。

> 说明：借鉴华泰 `auto_trader.py` 的"文件+配置+开关+降级"思路，但播放 API 用浏览器原生 Audio（非 winmm），因为监控是 Web 场景，声音应从看页面的机器发出。

### 3.2 音效文件

- 用 `edge_tts`（`zh-CN-XiaoyiNeural` 小艺女声 + 提高 pitch/rate）生成"萌宝高兴说中啦中啦"童声。
- 已生成 3 个候选：`static/sounds/zhongla_v1/v2/v3.mp3`，用户选定后重命名为 `zhongla.mp3`。

### 3.3 触发逻辑：交集结果"出现新成员"

维护状态变量 `_prevIntersectStockCodes`（上一次交集股票代码 Set）。

在 `refreshBothWithIntersection()` 算出 `stockResult` 之后插入：

```javascript
// 交集命中音效检测
const curCodes = new Set(stockResult.map(s => String(s.code)));
// 本次存在、上次没有的新代码
let hasNew = false;
for (const c of curCodes) {
    if (!_prevIntersectStockCodes.has(c)) { hasNew = true; break; }
}
if (_intersectionMode && hasNew) {
    playSound('zhongla', 'intersect_sound_enabled');
}
_prevIntersectStockCodes = curCodes;
```

### 3.4 触发真值表

| 场景 | 上次 → 本次 | 是否触发 | 依据 |
|------|------------|----------|------|
| 从无到有 | ∅ → {a} | ✅ | a 是新成员 |
| 从无到有(多) | ∅ → {a,b} | ✅ | 有新成员 |
| 出现新成员 | {a} → {a,b} | ✅ | b 是新成员 |
| 换成员 | {a} → {b} | ✅ | b 是新成员 |
| 完全不变 | {a,b} → {a,b} | ❌ | 无新成员 |
| 变少 | {a,b} → {a} | ❌ | 无新成员 |
| 清空 | {a,b} → ∅ | ❌ | 无新成员 |

**判定规则**：`本次 − 上次 ≠ ∅`（出现任一新代码）即触发。完整覆盖用户描述的两种情况（无→有、a→a,b/仅b）。

### 3.5 已确认的细节

| # | 细节 | 决定 |
|---|------|------|
| 1 | 刚点开🔗按钮时若立即有交集 | **触发一次**（点开时 `_prevIntersectStockCodes` 为空集，符合"从无到有"） |
| 2 | 关闭交集再打开 | 关闭时**清空** `_prevIntersectStockCodes`，下次点开重新按"从无到有"判定 |
| 3 | 静音开关 | **单独新增**交集音效开关（localStorage 键 `intersect_sound_enabled`），不复用买点 🔔 |
| 4 | 节流 | **不加节流**（tick 3 秒一次，频率本身可控 —— 用户明确要求） |
| 5 | 音频文件 | 用户从 3 个候选中选定，重命名为 `zhongla.mp3` |

| 项 | 方法 | 预期 |
|----|------|------|
| 从无到有 | 构造交集从 0 → ≥1 条 | 播放"中啦" |

## 六、风险与边界

- **浏览器自动播放限制**：本功能由用户点击 🔗 开启，点击已完成交互授权，`play()` 不会被拦截。
- **性能**：`Audio` 对象预加载缓存，`stockResult` 通常几到几十条，Set 比对开销可忽略。
- **不影响交集本身逻辑**：音效为旁路检测，即使音效代码异常也用 try/catch 隔离，不影响榜单渲染。
