# 开发文档：如何为过滤系统新增一个过滤条件

**版本**: v1.0
**日期**: 2026-08-05
**适用范围**: 债券上攻监控页 + 股债交集回溯页

---

## 一、架构总览

### 1.1 系统中的"过滤"分布

| 场景 | 入口 | 过滤实现 | 是否走后端统一管道 |
|------|------|----------|-------------------|
| **监控页-前端过滤**（默认） | `monitor.html` 内联 `BOND_PIPELINE`/`runPipeline` | **前端 JS** | ❌ 独立实现 |
| **监控页-后端过滤**（开关开启） | `backend_filter.js` → `/api/filter/bond` | 后端 `UnifiedPipeline` | ✅ |
| **股债交集回溯** | `backtrace.js` → `/api/backtrace/run-stream` | 后端 `UnifiedPipeline` | ✅ |

> ⚠️ **关键认知**：监控页有一个"前端过滤/后端过滤"切换开关（`backend-filter-toggle`，默认前端）。
> 因此**存在两套过滤器实现**：
> - **后端**：`src/gs2026/common/pipeline/`（Python）
> - **前端**：`monitor.html` 内联的 `BOND_PIPELINE` + `applyToggleableFilter`（JS）
>
> 两者语义完全一致（两阶段模型：谓词取交集 → 排名基于候选池取交集），但代码是**各自独立的**。

### 1.2 数据流

```
monitor_bond.py（采集/计算字段）
    ↓ 写入 Redis / MySQL
data_service / monitor.py（取数 + 补充字段）
    ↓
    ├─ 监控页：_rankRawData['bond-ranking'] → runPipeline(BOND_PIPELINE) → 渲染
    └─ 回溯页：/api/backtrace/run-stream → UnifiedPipeline → 交集 → 渲染
```

### 1.3 两阶段过滤模型（前后端一致）

```
Phase 1（谓词型 predicate）：每个过滤器从"全部原始数据"独立计算 → 结果取交集 = 候选池 S
Phase 2（排名型 ranking）：每个过滤器基于候选池 S 计算 → 结果取交集 = 最终结果
```

- **谓词型**（`predicate`）：布尔判断，如"行业==银行"、"隐藏绿名单"、"1分钟涨幅>N"
- **排名型**（`ranking`）：取前N，如"金额前10"、"次数前20"
  - `ranking` 模式：基于候选池 S 取前N
  - `predicate` 模式：从全部原始数据取前N（前端叫"谓词"下拉）

## 二、新增过滤条件的完整步骤

新增一个条件，需要改动 **5 个位置**（后端 3 + 前端 2）。

### 前置检查：数据字段是否存在

先确认过滤所需字段在数据里已存在（否则要先在 `monitor_bond.py`/`monitor_stock.py` 计算并透传）。

```powershell

```

已有字段示例（债券）：`change_pct`、`amount`、`count`、`window_count`、`min1_change_pct`、`min1_amount`、`min1_amount_rank`、`industry_name`、`is_green`。

### 步骤 1：后端 - 配置类 `config.py`

**文件**：`src/gs2026/common/pipeline/config.py`

**1a. 加字段**（`@dataclass` 内，债券区）：
```python
    bond_min1_amount_topn: int = 0             # 仅1分钟金额前N
    bond_min1_change_min: float = 0.0          # 1分钟涨幅 > N
```

**1b. 在 `from_dict` 注册**（兼容前端字段名）：
```python
    # 需要 float 解析的辅助函数（若无则新增）
    def _float(*keys):
        for k in keys:
            if k in data and data[k] is not None:
                try:
                    return float(data[k])
                except (ValueError, TypeError):
                    return 0.0
        return 0.0

    # cls(...) 内债券部分追加：
        bond_min1_amount_topn=_int('bond_min1_amount_topn', 'min1_amount_topn'),
        bond_min1_change_min=_float('bond_min1_change_min', 'min1_change_min'),
```

**1c. 在 `to_dict` 追加**（保持序列化完整）：
```python
        'bond_min1_amount_topn': self.bond_min1_amount_topn,
        'bond_min1_change_min': self.bond_min1_change_min,
```

**1d. 在 `is_bond_filter_active` 追加**（让过滤生效判断包含新条件）：
```python
    def is_bond_filter_active(self) -> bool:
        return any([
            ...,
            self.bond_min1_amount_topn > 0,
            self.bond_min1_change_min > 0,
        ])
```

### 步骤 2：后端 - 过滤器 `filters.py`

**文件**：`src/gs2026/common/pipeline/filters.py`

**排名型**（前N金额）→ 复用现成的 `RankingFilter`，只需指定 field：
```python
class TopNMin1AmountFilter(RankingFilter):
    """仅1分钟金额前N过滤器（债券用）"""
    def __init__(self, n: int, mode: str = 'ranking'):
        super().__init__(n, 'min1_amount', mode)
```

**谓词型**（1分钟涨幅 > N）→ 新建 `PredicateFilter`：
```python
class Min1ChangeGtFilter(PredicateFilter):
    """1分钟涨幅大于阈值过滤器"""
    def __init__(self, threshold: float = 0.0):
        self.threshold = threshold

    def is_active(self) -> bool:
        return self.threshold > 0

    def apply(self, data):
        if self.threshold <= 0:
            return data
        return [d for d in data if _to_float(d.get('min1_change_pct', 0)) > self.threshold]
```

> **要点**：
> - 排名型继承 `RankingFilter(n, field, mode)`，自动获得 ranking/predicate 双模式
> - 谓词型继承 `PredicateFilter`，实现 `is_active()` + `apply()`
> - 数值转换统一用模块内 `_to_float()`

### 步骤 3：后端 - 管道装配 `pipeline.py`

**文件**：`src/gs2026/common/pipeline/pipeline.py`

**3a. import 新过滤器**：
```python
from .filters import (
    ...,
    TopNMin1AmountFilter,
    Min1ChangeGtFilter,
)
```

**3b. 在 `_build_bond_pipeline()` 挂载**：
```python
    def _build_bond_pipeline(self) -> List[Filter]:
        filters = []
        # 谓词型（先挂）
        ...
        if self.config.bond_min1_change_min > 0:
            filters.append(Min1ChangeGtFilter(self.config.bond_min1_change_min))
        # 排名型
        ...
        if self.config.bond_min1_amount_topn > 0:
            filters.append(TopNMin1AmountFilter(
                self.config.bond_min1_amount_topn,
                'ranking'))  # 或从 config 读 mode
        return filters
```

> **执行顺序不影响结果**（两阶段模型内部按 kind 自动分组），但建议谓词型写前面便于阅读。

## 三、字段命名一致性（重要）

后端 `from_dict` 通过多别名兼容前端。**新增条件时务必让前端传的 key 命中后端别名之一**：

| 后端字段 | 前端传的 key（回溯/监控） | 后端 `from_dict` 别名 |
|----------|--------------------------|----------------------|
| `bond_min1_amount_topn` | `bond_min1_amount_topn` | `'bond_min1_amount_topn', 'min1_amount_topn'` |
| `bond_min1_change_min` | `bond_min1_change_min` | `'bond_min1_change_min', 'min1_change_min'` |

前端两个页面尽量传**同一个 key**，减少别名维护成本。

## 五、常见坑

1. **只改了后端，监控页默认前端过滤不生效** —— 监控页默认走前端 `BOND_PIPELINE`，必须同步改 monitor.html。
2. **字段名不匹配** —— 前端传 key 未命中后端 `from_dict` 别名，导致后端读到默认值 0。
3. **忘记 `is_bond_filter_active`** —— 后端管道在 `filter_bonds` 开头判断 `is_bond_filter_active()`，未加则整个过滤被跳过。
4. **float vs int** —— 涨幅阈值是 float，若用 `_int` 解析会截断（0.5→0），必须用 `_float`。
5. **数据字段缺失** —— `min1_change_pct`/`min1_amount` 可能为 None，过滤时用 `_to_float` 兜底。
