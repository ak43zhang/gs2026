# 量化选债实时信号跟踪与历史回填功能设计文档

## 一、功能概述

### 1.1 目标
- **历史回填**：用今日已采集数据测试验证量化选债功能，回填命中记录
- **实时信号**：命中后根据方案止盈止损参数实时跟踪信号状态
- **完整展示**：历史命中按时间倒序展示，含方案名称、收益、状态等

### 1.2 核心特性
- 每个命中记录绑定具体方案，支持多方案同时命中同一债券
- 信号状态实时计算：entry → holding → stopped/profited
- 5分钟或平仓后锁定状态，不再更新
- 历史命中按入场时间倒序排列

```sql
    trade_date VARCHAR(8) NOT NULL,          -- 交易日期 20260709
    tick_time VARCHAR(6) NOT NULL,             -- 入场时间点 143025

    bond_code VARCHAR(10) NOT NULL,
    bond_name VARCHAR(50),
    
    -- 入场信息（固定）
    entry_price DECIMAL(10,3) NOT NULL,
    entry_change_pct DECIMAL(6,2),
    entry_amount DECIMAL(15,2),
    
    -- 方案参数（固定）
    stop_loss_pct DECIMAL(5,2),
    take_profit_pct DECIMAL(5,2),
    stop_loss_price DECIMAL(10,3),
    take_profit_price DECIMAL(10,3),
    
    -- 当前状态（每tick更新）
    current_price DECIMAL(10,3),
    current_return_pct DECIMAL(6,2),
    signal_status VARCHAR(20),                 -- entry/holding/stopped/profited
    
    -- 平仓信息（确定后不再更新）
    exit_price DECIMAL(10,3),
    exit_time VARCHAR(6),
    final_return_pct DECIMAL(6,2),
    
    -- 状态锁定（5分钟后或已平仓则锁定）

    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_date_scheme_time (trade_date, scheme_name, tick_time),
    INDEX idx_bond_date (bond_code, trade_date),
    INDEX idx_status (signal_status, is_locked)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 三、状态流转规则

### 3.1 状态机

```
                    ┌─→ stopped (价格 ≤ 止损价)
entry → holding ────┤
                    └─→ profited (价格 ≥ 止盈价)
```

### 3.2 状态定义

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| entry | 首次命中 | 新记录插入时 |
| holding | 持仓中 | 价格介于止损止盈之间 |
| stopped | 已止损 | 当前价格 ≤ 止损价 |
| profited | 已止盈 | 当前价格 ≥ 止盈价 |

### 3.3 锁定规则

满足任一条件即锁定，锁定后不再更新：
1. `signal_status IN ('stopped', 'profited')`（已平仓）
2. `TIMESTAMPDIFF(MINUTE, created_at, NOW()) >= 5`（入场超过5分钟）

## 四、后端API设计

### 4.1 筛选命中API（已有，扩展写入逻辑）

**POST** `/api/monitor/quant-screen`

**扩展逻辑**：
1. 执行筛选逻辑，获取命中列表
2. 对每个命中：
   - 检查是否已存在 `(date, scheme, bond, time)` 记录
   - 不存在则插入新记录（状态=entry）
   - 存在则更新 `current_price`, `current_return_pct`, `signal_status`
3. 返回命中结果

## 六、回填脚本设计

### 6.1 功能
遍历指定日期的所有tick数据，执行量化筛选，生成命中记录。

### 6.2 逻辑流程

```python
def backfill_quant_hits(trade_date: str):
    """
    回填指定日期的量化选债命中记录
    
    Args:
        trade_date: 交易日期，如 '20260709'
    """
    # 1. 读取当日所有方案
    schemes = load_schemes_from_localstorage()
    
    # 2. 读取当日所有tick的sssj数据
    ticks = load_sssj_by_date(trade_date)
    
    # 3. 按时间顺序遍历每个tick
    for tick in ticks:
        tick_time = tick['time']
        market_data = tick['data']  # 该tick的所有债券数据
        
        # 4. 对每个方案执行筛选
        for scheme in schemes:
            hits = run_screen(scheme, market_data)
            
            # 5. 对每个命中写入/更新记录
            for hit in hits:
                save_or_update_hit(
                    trade_date=trade_date
                    tick_time=tick_time
                    scheme_name=scheme['name']
                    bond_code=hit['code']
                    bond_name=hit['name']
                    entry_price=hit['price']
                    # ...其他字段
                )
        
        # 6. 更新所有未锁定记录的状态
        update_all_hits_status(trade_date, tick_time, market_data)
    
    print(f"回填完成：{trade_date}")
```

### 6.3 使用方式

```bash

# 回填历史数据
```

## 八、风险与注意事项

1. **数据一致性**：回填时需确保方案定义与当时一致
2. **性能**：大量命中记录时，每tick更新需优化批量操作
3. **时区**：所有时间字段使用统一时区（Asia/Shanghai）
4. **并发**：实时更新和回填不要同时进行，避免冲突
