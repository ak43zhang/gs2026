## 三、状态机

```
IDLE ──→ TRADING ──→ MONITORING ──→ IDLE
              │                        ↑
              │ 30秒无弹窗              │ 止盈/止损/强平
              ↓                        │
          撤单 → IDLE                  │
                                       │
              MONITORING:              │
                价格>=止盈价 ───────────┘
                价格<=止损价 ───────────┘
                持仓>=max_hold_time ────┘(强平)
```

| 状态 | 含义 | 进入条件 | 退出条件 |
|------|------|---------|---------|
| IDLE | 等待,收集命中,展示列表 | 交易结束/初始 | 你点[买] |
| TRADING | 买入执行中 | 你点[买] | 成交/超时撤单 |
| MONITORING | 持仓中,监控价格 | 成交且TP/SL已设 | TP/SL触发/强平 |

### 4.1 阶段①: 命中收集(IDLE状态)

```python
def on_hit(self, code, name, price, scheme, lots):
    """monitor_bond每tick调用, 非阻塞(<1ms)"""
    if self.state != "IDLE":
        return  # 交易中不收新命中
    
    self.hit_list.append({
        'code': code,
        'name': name,
        'buy_price': calc_buy_price(price, scheme),
        'tp_pct': scheme['take_profit'],
        'sl_pct': scheme['stop_loss'],
        'max_hold_minutes': scheme.get('max_hold_time', 30),
        'quantity': lots * 10,
        'hit_time': time.time(),
    })
    
    # 移除30秒前过期的
    self.hit_list = [h for h in self.hit_list if time.time() - h['hit_time'] < 30]
```

```python
def on_buy_click(self, code):
    """前端点[买]触发(API调用)"""
    if self.state != "IDLE":
        return {'success': False, 'message': '交易进行中'}
    
    # 从列表找到这条命中
    hit = next((h for h in self.hit_list if h['code'] == code), None)
    if not hit:
        return {'success': False, 'message': '信号已过期'}
    
    # 进入交易状态
    self.state = "TRADING"
    self.current = hit
    self.hit_list = []  # 清空列表(本轮结束)
    
    # 启动交易线程(不阻塞)
    Thread(target=self._trade_thread, daemon=True).start()
    
    return {'success': True, 'message': f'开始交易 {code}'}
```

### 4.3 阶段③路径A: 买到了 → 设TP/SL → 监控

```python
def _trade_thread(self):
    """独立线程: 填表→等弹窗→设TP/SL或撤单"""
    
    # 1. 填充买入表单
    fill_buy_form(self.current['code'], self.current['buy_price'], 
                  self.current['quantity'] // 10)
    play_sound("hit")
    
    # 2. 等待成交弹窗(30秒)
    filled = False
    start = time.time()
    while time.time() - start < 30:
        popup_code = detect_fill_popup()
        if popup_code == self.current['code']:
            filled = True
            break
        time.sleep(0.1)
    
    if filled:
        # === 路径A: 买到了 ===
        play_sound("filled")
        
        # 设止盈止损
        result = tp_sl_placer.place(
            code=self.current['code'],
            base_price=self.current['buy_price'],
            tp_pct=self.current['tp_pct'],
            sl_pct=self.current['sl_pct'],
            quantity=self.current['quantity'],
        )
        
        if result['success']:
            play_sound("tp_sl_set")
        else:
            play_sound("error")
            # TP/SL设失败,仍进入监控(靠价格监控+强平保护)
        
        # 进入持仓监控
        self.fill_time = time.time()
        self.tp_level = self.current['buy_price'] * (1 + self.current['tp_pct'] / 100)
        self.sl_level = self.current['buy_price'] * (1 - self.current['sl_pct'] / 100)
        self.max_hold_seconds = self.current['max_hold_minutes'] * 60
        self.state = "MONITORING"
    
    else:
        # === 路径B: 没买到 ===
        self._handle_not_filled()
```

### 4.4 阶段③路径B: 没买到 → 撤单

```python
def _handle_not_filled(self):
    """30秒未检测到成交弹窗 → 撤单 → 结束"""
    cancelled = try_cancel_order(self.current['code'])
    
    if cancelled:
        # 撤成功 → 确实没成交
        play_sound("timeout")
        self._end_trade("timeout_cancelled")
    else:
        # 撤不掉(可能已成交但弹窗漏了)
        # 告警,让你手动检查
        play_sound("alert")
        self._end_trade("alert_check_manually")
```

### 4.5 阶段③持仓监控(MONITORING)

```python
def on_tick(self, df_now):
    """monitor_bond每tick调用,传入当前行情"""
    if self.state != "MONITORING":
        return
    
    price = get_price(df_now, self.current['code'])
    if not price:
        return
    
    # 止盈触发
    if price >= self.tp_level:
        play_sound("tp_triggered")
        self._end_trade("take_profit", price)
        return
    
    # 止损触发
    if price <= self.sl_level:
        play_sound("sl_triggered")
        self._end_trade("stop_loss", price)
        return
    
    # 持仓超时 → 强平
    if time.time() - self.fill_time >= self.max_hold_seconds:
        self._force_sell(price)
```

### 4.6 强制卖出

```python
def _force_sell(self, price):
    """持仓超时强平: 填充卖出表单"""
    def _do_sell():
        fill_sell_form(self.current['code'], price, self.current['quantity'])
        play_sound("force_sell")
        self._end_trade("force_sell", price)
    
    Thread(target=_do_sell, daemon=True).start()
```

### 4.7 交易结束(统一出口)

```python
def _end_trade(self, reason, price=None):
    """所有路径的统一结束点"""
    # 记录日志
    log_trade(reason, self.current, price)
    
    # 记录到历史(面板展示)
    self.trade_history.append({
        'code': self.current['code'],
        'name': self.current['name'],
        'reason': reason,
        'time': datetime.now().isoformat(),
    })
    
    # 清空状态
    self.current = None
    self.hit_list = []     # 确保旧命中清空
    self.state = "IDLE"    # 回到IDLE, 开始新一轮
    
    # 提醒
    play_sound("trade_end")
```

## 七、线程模型

```
主线程 (monitor_bond.py, 每3秒tick)
    │
    ├── on_hit(): 往hit_list追加1条 (<1ms, 不阻塞)
    ├── on_tick(df): 价格比较3个数字 (<1ms, 不阻塞)
    │
    └── (采集+ETL正常运行, 完全不受影响)

交易线程 (daemon, 按需启动)
    │
    ├── 你点[买]时启动
    ├── 填表(2-3秒) → 等弹窗(最多30秒) → 设TP/SL(5-7秒)
    ├── 完成后: state=MONITORING (交给tick监控)
    └── 线程结束
    
强平线程 (daemon, 按需启动)
    │
    ├── on_tick检测到超时时启动
    ├── 填卖出表单(2-3秒)
    ├── _end_trade()
    └── 线程结束

Flask线程 (daemon, 常驻)
    │
    └── 提供面板和API (独立于主线程)
```

**并发安全:**
- 主线程: 只读/追加hit_list + 数字比较(无UI操作)
- 交易线程: 独占UI操作(state=TRADING时启动,完成前不会有第二个)
- 强平线程: 独占UI操作(state=MONITORING时才可能启动,启动后state立刻变IDLE)
- 任何时刻最多1个线程在操作UI → 零冲突

## 问题1: 无效条件单是否影响下次同code交易?

### 分析

```
场景:
t=0s  命中127045 → 你没买 → 30秒超时 → 保守设了TP/SL条件单
      条件单内容: 127045 基准价=105.3 止盈3% 止损2%
      
t=5min 再次命中127045 → 你买了! 成交价=108.0
      系统设新条件单: 127045 基准价=108.0 止盈3% 止损2%

现在存在两个条件单:
  旧(无效): 基准价=105.3 → 止盈>=108.459, 止损<=103.194
  新(有效): 基准价=108.0 → 止盈>=111.24, 止损<=105.84

问题: 旧条件单的止盈价108.459 可能接近当前价格!
     如果价格涨到108.459 → 旧条件单触发卖出!
     但你是在108.0买的,108.459才涨了0.4% → 不是你想要的止盈!
```

### 结论: ⚠️ 无效条件单会干扰! 不能保守设置!

**旧条件单不会"自动消失"——它一直有效直到触发或手动删除或到期。**

如果下次买了同一只,旧条件单的止盈/止损价可能先触发,导致被错误卖出。

### 解决: 放弃"保守设TP/SL"策略

```
超时后F3找不到的处理:
  ✗ 旧方案: 保守假设成交 → 设TP/SL (会留下垃圾条件单!)
  ✓ 新方案: 不设TP/SL, 只告警(声音+日志)
  
  如果真的成交了但没设TP/SL → 你听到告警 → 手动检查 → 手动设
  如果没买过 → 告警提示但无影响
```

这是概率极低的场景(弹窗漏检), 用告警替代自动操作更安全。

## 问题3: 交易操作会不会阻塞monitor_bond.py的3秒tick?

### 分析

```
monitor_bond.py 主循环:
  while True:
      df = fetch_data()        # 采集(必须3秒完成)
      process(df)              # ETL转换
      check_hits(df)           # 命中检测
      trade_hook.on_hit(...)   # ← 这里如果阻塞,tick就延迟了!
      sleep(remaining)
```

**如果on_hit()内部做了耗时操作(如fill_buy_form 2-3秒), 会直接阻塞tick!**

### 解决: on_hit()必须是非阻塞的

```python
# trade_hook.py
def on_hit(self, code, name, price, scheme, lots):
    """保证: 绝不阻塞, 瞬间返回"""
    if not self.enabled:
        return
    try:
        self._trader.on_hit_async(code, name, price, scheme, lots)
    except Exception as e:
        logger.warning(f"[TradeHook] {e}")

# auto_trader.py  
def on_hit_async(self, code, name, price, scheme, lots):
    """非阻塞: 只设状态+启动线程"""
    if self.state != "IDLE":
        return
    
    self.state = "WATCHING"
    self.current = {... }
    
    # 所有耗时操作都在独立线程
    Thread(target=self._trade_loop, daemon=True).start()

def _trade_loop(self):
    """独立线程: 填表 → 等弹窗 → 设TP/SL 或 撤单"""
    # 1. 填充买入表单(2-3秒, 不阻塞主线程)
    fill_buy_form(...)
    
    # 2. 监听弹窗(每100ms)
    while ...:
        if detect_popup(): ...
        if timeout: ...
        sleep(0.1)
    
    # 3. 设TP/SL或撤单(5-7秒)
    ...
    
    # 4. 完成
    self.state = "IDLE"
```

### 线程模型(最终版)

```
┌──────────────────────────────────────┐
│  主线程 (monitor_bond.py)             │
│  每3秒tick: 采集 → ETL → 命中检测    │
│  on_hit(): 只改state + 启动线程       │
│  耗时: <1ms (瞬间返回)               │
│  绝不阻塞 ✓                          │
└──────────────────────┬───────────────┘
                       │ 启动(state=IDLE时)
                       ▼
┌──────────────────────────────────────┐
│  交易线程 (1个, daemon)               │
│  顺序执行:                            │
│    1. fill_buy_form (2-3秒)          │
│    2. 监听弹窗 (每100ms, 最多30秒)    │
│    3. set_tp_sl (5-7秒) 或 cancel    │
│    4. state=IDLE → 线程结束           │
│                                      │
│  下次命中时启动新线程                  │
└──────────────────────────────────────┘

并发安全:
- 主线程只读state(判断是否IDLE)
- 交易线程写state
- state只有两个写入点:
  · on_hit_async中 IDLE→WATCHING (主线程, 只在IDLE时)
  · _trade_loop末尾 →IDLE (交易线程)
- 不会同时写 → 无竞态 ✓
```

## 最终修正方案(完整版)

### 状态机

```
IDLE ──→ WATCHING ──→ FILLED ──→ SETTING_TP_SL ──→ IDLE
              │                                      ↑
              └──→ TIMEOUT ──→ 撤单                  │
                      ├── 撤成功 → IDLE              │
                      └── 找不到 → 告警 → IDLE       │
                            (不设TP/SL,避免垃圾条件单)│
```

### 完整代码逻辑

```python
class AutoTrader:
    """
    极简全仓交易: 单线程执行, 非阻塞接入
    
    规则:
    - state=IDLE时才接受命中
    - 同一时间只有1笔交易在处理
    - 所有UI操作在独立线程(不阻塞tick)
    - 超时后不盲设TP/SL(避免垃圾条件单)
    """
    
    def __init__(self, config):
        self.state = "IDLE"
        self.current = None
        self.config = config
        self.timeout_seconds = config.get('timeout_seconds', 30)
        self.tp_sl_placer = TpSlPlacer(config['positions_file'])
    
    def on_hit_async(self, code, name, price, scheme, lots):
        """
        主线程调用(非阻塞, <1ms返回)
        state!=IDLE → 直接跳过
        """
        if self.state != "IDLE":
            return
        
        # 计算买入价
        offset = scheme.get('price_offset', 0)
        mode = scheme.get('offset_mode', 'fixed')
        if mode == 'percent':
            buy_price = round(price * (1 + offset / 100), 3)
        else:
            buy_price = round(price + offset, 3)
        
        # 设置状态(主线程写, 此时无交易线程)
        self.state = "WATCHING"
        self.current = {
            'code': code,
            'name': name,
            'buy_price': buy_price,
            'tp_pct': scheme.get('take_profit', 3.0),
            'sl_pct': scheme.get('stop_loss', 2.0),
            'quantity': lots * 10,
            'hit_time': time.time(),
        }
        
        # 启动交易线程(所有耗时操作在这里)
        Thread(target=self._trade_loop, daemon=True).start()
    
    def _trade_loop(self):
        """交易线程: 填表→等弹窗→设TP/SL或撤单→结束"""
        try:
            # 阶段1: 填充买入表单(2-3秒)
            fill_buy_form(
                self.current['code'],
                self.current['buy_price'],
                self.current['quantity'] // 10,  # lots
            )
            play_sound("hit")
            
            # 阶段2: 监听成交弹窗(每100ms, 最多30秒)
            start = time.time()
            filled = False
            
            while time.time() - start < self.timeout_seconds:
                popup_code = detect_fill_popup()
                if popup_code == self.current['code']:
                    filled = True
                    break
                time.sleep(0.1)
            
            # 阶段3: 根据结果处理
            if filled:
                # 成交了! 设止盈止损
                self.state = "SETTING_TP_SL"
                play_sound("filled")
                
                result = self.tp_sl_placer.place(
                    bond_code=self.current['code'],
                    base_price=self.current['buy_price'],
                    tp_pct=self.current['tp_pct'],
                    sl_pct=self.current['sl_pct'],
                    quantity=self.current['quantity'],
                )
                
                if result['success']:
                    play_sound("done")
                    log_trade("TP_SL_SET", self.current)
                else:
                    play_sound("error")
                    log_trade("TP_SL_FAILED", self.current, result['message'])
            
            else:
                # 超时! 尝试撤单
                self.state = "CANCELLING"
                cancelled = try_cancel_order(self.current['code'])
                
                if cancelled:
                    # 撤成功 → 买了但没成交 → 正常结束
                    play_sound("timeout")
                    log_trade("CANCELLED", self.current)
                else:
                    # F3找不到 → 可能没买过, 也可能已成交(弹窗漏了)
                    # 不盲设TP/SL(避免垃圾条件单), 只告警
                    play_sound("alert")
                    log_trade("ALERT_CHECK", self.current, 
                             "超时且无法撤单,请手动检查是否已成交")
        
        except Exception as e:
            logger.error(f"[AutoTrader] 交易线程异常: {e}")
            play_sound("error")
        
        finally:
            # 无论如何, 恢复IDLE
            self.state = "IDLE"
            self.current = None
```

## 5. 量化命中自动止盈止损-最终极简方案v5

﻿# 单笔全仓交易模式 - 极简方案

> 版本: v5.0
> 日期: 2026-07-17
> 核心: 每次只有一笔交易,要么买到了要么没买到,不存在并行

---

## 一、核心洞察

**你的交易模式:**
- 全仓操作 → 同一时间最多只有1笔买入委托
- 买到了 → 不可能再买(没钱了)
- 没买到 → 必须撤单后才能买下一个
- 不存在"同时有两笔买入委托在跑"的情况

**这意味着:**
- 不需要多线程
- 不需要并行监听多个code
- 不需要优先级队列
- 不需要UI操作串行化(因为本来就只有一个在执行)

---

## 二、极简状态机

```
IDLE ──→ WATCHING ──→ SETTING_TP_SL ──→ IDLE
              │                            ↑
              │ 弹窗成交                    │
              │────────────────────────────┘
              │
              │ 30秒超时
              ↓
         CANCELLING ──→ IDLE
              │
              │ 撤单返回"已成交"
              ↓
         SETTING_TP_SL ──→ IDLE
```

**只有4个状态, 单线程顺序执行, 零并发问题。**

---

## 三、完整逻辑(单线程)

```python
class AutoTrader:
    """
    极简版: 单笔全仓交易
    
    规则:
    - state=IDLE时接受命中, 其他状态全部跳过
    - 同一时间只有1个活跃交易
    - 无多线程, 无队列, 无锁
    """
    
    state = "IDLE"           # IDLE / WATCHING / SETTING_TP_SL / CANCELLING
    current = None           # 当前活跃订单信息
    last_fill_time = None    # 上次填充表单的时间
    
    def on_hit(self, code, name, price, scheme, lots):
        """
        命中回调 — 每个tick可能调用
        
        逻辑:
        - IDLE → 接受, 填充表单, 进入WATCHING
        - 非IDLE → 但如果是新code且比当前更优, 可以覆盖表单
          (因为反正只有一笔委托, 表单覆盖不影响已提交的)
        """
        if self.state == "IDLE":
            # 新交易开始
            self._start_new_trade(code, name, price, scheme, lots)
        
        elif self.state == "WATCHING":
            # 已经在等成交了, 但新命中可以覆盖表单
            # (用户还没点买入的话, 看到新的可能更想买新的)
            self._update_form(code, name, price, scheme, lots)
    
    def tick(self):
        """
        每3秒tick调用(或独立线程每100ms调用)
        
        在WATCHING状态下:
        1. 检测弹窗 → 成交 → 设TP/SL
        2. 检查超时 → 撤单
        """
        if self.state == "WATCHING":
            # 检测成交弹窗
            filled_code = detect_popup()
            if filled_code == self.current['code']:
                self._on_filled()
                return
            
            # 检查超时(从命中时间算30秒)
            if time.time() - self.current['hit_time'] >= 30:
                self._on_timeout()
    
    def _start_new_trade(self, code, name, price, scheme, lots):
        """开始新交易"""
        buy_price = self._calc_buy_price(price, scheme)
        self.current = {
            'code': code,
            'name': name,
            'buy_price': buy_price,
            'tp_pct': scheme['take_profit'],
            'sl_pct': scheme['stop_loss'],
            'quantity': lots * 10,
            'hit_time': time.time(),
        }
        self.state = "WATCHING"
        
        # 填充买入表单
        fill_buy_form(code, buy_price, lots)
        play_sound("hit")
    
    def _update_form(self, code, name, price, scheme, lots):
        """
        WATCHING状态下新命中: 覆盖当前跟踪目标+表单
        
        为什么可以覆盖?
        - 如果用户还没点买入 → 表单覆盖,看新的
        - 如果用户已点买入 → 表单覆盖没关系(委托已提交,表单显示什么不影响)
          → 弹窗检测用的是current['code'], 改了code后会匹配新的
          → 但旧的委托还在! 需要处理...
        
        处理方式:
        - 覆盖current信息
        - 旧委托如果成交,弹窗code不匹配新current → 30秒后超时撤单时发现"已成交"→补设
        - 或者: 不覆盖code(只覆盖表单显示),弹窗还是匹配旧code
        
        简化决策: WATCHING状态下不更换跟踪目标!
        原因: 用户可能已经点了买入, 更换会导致混乱
        只更新表单显示(让用户看到最新的), 但系统跟踪的还是第一个
        
        等等, 这样也有问题... 
        
        最简方案: WATCHING状态下不覆盖, 新命中直接丢弃
        理由: 你正在决定要不要买当前这个, 新的等下一轮
        """
        pass  # WATCHING状态: 跳过新命中(最简)
    
    def _on_filled(self):
        """成交确认 → 设止盈止损"""
        self.state = "SETTING_TP_SL"
        play_sound("filled")
        
        # 直接设TP/SL(同一线程,无并发)
        result = set_tp_sl(
            self.current['code'],
            self.current['buy_price'],
            self.current['tp_pct'],
            self.current['sl_pct'],
            self.current['quantity'],
        )
        
        if result['success']:
            play_sound("done")
        else:
            play_sound("error")
        
        # 完成,回到IDLE
        self.state = "IDLE"
        self.current = None
    
    def _on_timeout(self):
        """超时 → 撤单"""
        self.state = "CANCELLING"
        
        result = cancel_order(self.current['code'])
        
        if result == "already_filled":
            # 撤单发现已成交(弹窗漏了) → 补设TP/SL
            self._on_filled()
        else:
            # 撤成功或无此委托 → 回IDLE
            play_sound("timeout")
            self.state = "IDLE"
            self.current = None
```

## 四、为什么不需要多线程

| 多线程方案的问题 | 单线程方案的优势 |
|---|---|
| UI操作冲突 | **不存在** — 只有1个操作在执行 |
| 需要锁/队列 | **不需要** — 顺序执行 |
| 需要优先级排序 | **不需要** — 没有并行任务 |
| 弹窗检测和UI操作冲突 | **不存在** — 检测和操作在同一线程交替 |
| 状态同步问题 | **不存在** — 单线程无竞态 |

**关键推导:**
```
全仓 → 只有1笔委托 → 只需要跟踪1个code → 只有1个可能的弹窗需要匹配
→ 不需要"活跃列表" → 只需要1个current变量
→ 成交/撤单/设TP_SL不可能同时发生 → 不需要串行化(本来就是串行的)
```

## 五、线程模型

**只需要1个额外线程(监控+执行合一):**

```
主线程 (monitor_bond.py, 每3秒tick)
    │
    │ on_hit()(state==IDLE时才接受)
    │
    ▼
监控+执行线程 (1个, 做所有事)
    │
    │ 循环(每100ms):
    │   if state == WATCHING:
    │       检测弹窗 → 找到? → _on_filled()(在本线程直接设TP/SL)
    │       检查超时 → 到了? → _on_timeout()(在本线程直接撤单)
    │   elif state == IDLE:
    │       sleep(等待下一次on_hit触发)
    │
    无并发, 无冲突, 无队列
```

**或者更简单: 连额外线程都不需要!**

```python
# 方案B: 完全靠tick驱动(无额外线程)

def tick(self):
    """monitor_bond.py每3秒调用一次"""
    if self.state == "WATCHING":
        # 在tick中做快速弹窗检测(每tick查一次)
        filled = detect_popup()
        if filled == self.current['code']:
            self._on_filled()  # 同步执行TP/SL(阻塞几秒)
            return
        # 超时检查
        if time.time() - self.current['hit_time'] >= 30:
            self._on_timeout()  # 同步执行撤单
```

**但tick间隔3秒太慢(弹窗可能消失)。所以还是用1个100ms轮询的线程。**

## 六、最终确定: 单监控线程方案

```python
class AutoTrader:
    state = "IDLE"
    current = None
    _thread = None
    
    def on_hit(self, code, name, price, scheme, lots):
        """只在IDLE时接受"""
        if self.state != "IDLE":
            return  # 正在交易中,跳过
        
        self.state = "WATCHING"
        self.current = {...}
        fill_buy_form(code, price, lots)
        
        # 启动监控线程
        self._thread = Thread(target=self._watch_loop, daemon=True)
        self._thread.start()
    
    def _watch_loop(self):
        """监控线程: 等弹窗或超时, 然后直接执行后续"""
        while self.state == "WATCHING":
            # 检测弹窗
            if detect_popup(self.current['code']):
                self.state = "SETTING_TP_SL"
                set_tp_sl(...)        # 直接执行,无冲突
                self.state = "IDLE"
                self.current = None
                return
            
            # 检测超时
            if time.time() - self.current['hit_time'] >= 30:
                self.state = "CANCELLING"
                result = cancel_order(...)  # 直接执行
                if result == "already_filled":
                    self.state = "SETTING_TP_SL"
                    set_tp_sl(...)    # 补设
                self.state = "IDLE"
                self.current = None
                return
            
            time.sleep(0.1)
```

**整个模块的线程模型:**
```
主线程(tick): on_hit() → 改state + 启动监控线程
监控线程(1个): 等弹窗/超时 → 执行TP/SL或撤单 → 完成 → 线程结束

不可能冲突:
- on_hit()只在state==IDLE时修改state(此时无监控线程)
- 监控线程运行时state!=IDLE → on_hit()不会执行任何操作
- 监控线程结束前设state=IDLE → 下次on_hit才能进入
```

两种策略:

### 策略A: 全部跳过(最简,推荐)

### 策略C: 覆盖表单但不更换code跟踪

这太复杂了,放弃。

**结论: 用策略A(最简)。WATCHING期间新命中全部跳过。**

如果30秒内你没买 → 超时 → 回IDLE → 下一个tick的命中就能接收了。

```python
        self.enabled = config.get('auto_trader_enabled', False)
        self._trader = None

        """每tick调用 — 保证: 绝不抛异常"""
```

## 一、方案概述

```

  → 系统自动检测成交弹窗

  → 持有债券时: 同一债券命中跳过
```

**极简: 你只需做一件事 — 点买入。其余全自动。**


### 漏洞1: 成交弹窗检测不可靠 ⚠️ 核心风险

| 问题 | 影响 | 严重度 |
|------|------|--------|
| 弹窗标题不确定 | 找不到窗口 | 高 |
| 弹窗停留时间短(1-2秒就消失) | 来不及检测 | 高 |
| 你手动关了弹窗 | 系统漏检 | 中 |
| 别的委托也弹窗 | 误判为当前单成交 | 中 |
| 华泰版本更新改了弹窗 | 检测失效 | 低 |

**解决方案:**
```

备选: 如果弹窗不可靠,改用"提交后N秒自动视为成交"策略
```

### 漏洞2: "你决定不买"的情况

```

系统: 30秒后超时撤单

问题: 这30秒内所有新命中都丢了!
      但你根本没买,本应可以接收新命中

解决: 
  方案A: 接受(30秒内丢信号是可接受的代价)
  方案B: 加一个"放弃"快捷键(如Esc),你按了立刻恢复
  方案C: 如果检测到xiadan买入表单被手动清空→恢复
```

**建议: 方案A即可(30秒丢信号影响小,简化设计)**

### 漏洞3: 撤单时发现已成交

```
场景: 30秒超时 → 系统去撤单 → 但其实刚好在29.9秒成交了

这不是bug,是正常情况!

处理: 
  撤单失败(已成交) → 视为成交 → 继续设TP/SL
  撤单成功 → 确实没成交 → 状态恢复IDLE
```


### 漏洞5: 持仓检测的准确性

```
"实时监听是否持有" — 怎么实现?

方式A: 内部状态跟踪
  - 成交 → 标记holding[127045]=True
  - 条件单触发卖出(止盈/止损) → holding[127045]=False
  - 问题: 条件单触发是券商服务器执行的,本地不知道什么时候卖了

  - 问题: 干扰操作,实现复杂
```

### 漏洞6: 弹窗检测 vs 正偏移秒成交

```
正偏移(买入价>=市价): 几乎100%秒成交
  → 弹窗在你点买入后0.x秒就出现
  → 系统能检测到(只要轮询够快,如100ms一次)

  → 可能5秒,可能20秒,可能不成交
  → 弹窗在某个时刻出现(或不出现)
  → 超时撤单是安全网

两种情况都能用同一套弹窗检测逻辑 ✓
不需要分两条路径了!
```

### 7.2 完整逻辑(伪代码)

```python
class AutoTrader:
    state = "IDLE"
    current_code = None
    today_traded = set()  # 当日已交易代码
    
    def on_hit(self, bond_code, bond_name, hit_price, scheme_detail, lots):
        """monitor_bond.py调用"""
        # 跳过条件
        if self.state != "IDLE":
            return  # 正在处理中,跳过
        if bond_code in self.today_traded:
            return  # 今天已买过,跳过
        
        # 开始处理
        self.state = "TRADING"
        self.current_code = bond_code
        
        # 计算买入价
        buy_price = hit_price + offset
        
        # 1. 填充买入表单
        fill_buy_form(bond_code, buy_price, lots)
        play_sound("hit")  # 提示音:有新单
        
        # 2. 启动异步监控线程
        Thread(target=self._monitor_fill, args=(
            bond_code, buy_price, scheme_detail, lots, timeout
        )).start()
    
    def _monitor_fill(self, code, price, scheme, lots, timeout):
        """后台: 等待成交或超时"""
        start = time.time()
        
        while time.time() - start < timeout:
            # 检测成交弹窗
            if detect_fill_popup(code):
                # 成交了!
                self._on_filled(code, price, scheme, lots)
                return
            time.sleep(0.1)  # 100ms轮询
        
        # 超时,尝试撤单
        cancel_result = cancel_order(code)
        if cancel_result == "already_filled":
            # 撤单失败=其实成交了
            self._on_filled(code, price, scheme, lots)
        else:
            # 确实没成交
            self.state = "IDLE"
            play_sound("timeout")
            log("[TIMEOUT] 撤单完成")
    
    def _on_filled(self, code, price, scheme, lots):
        """成交后: 设置止盈止损"""
        self.state = "SETTING_TP_SL"
        self.today_traded.add(code)
        
        # 设置止盈止损
        result = tp_sl_placer.place(
            code, base_price=price,
            tp_pct=scheme['take_profit'],
            sl_pct=scheme['stop_loss'],
            quantity=lots*10
        )
        
        if result['success']:
            play_sound("success")
            log(f"[TP_SL] 设置成功")
        else:
            play_sound("alert")
            log(f"[FAIL] TP/SL设置失败: {result['message']}")
        
        self.state = "IDLE"
```

```
|                                                                    |
+------------------------------------------------------------------+
```

### 2.2 核心设计: 串行订单管道

**解决的核心问题:** 多个命中信号时,系统如何确定用户实际操作了哪一单?

**方案: 任何时刻只有一个订单处于PENDING状态**

```
命中队列: [hitA, hitB, hitC, ...]
      | (每次只取1个处理)
      v
+-------------------------------+
| 当前活跃单 (PENDING)           |
| 123456 某转债 @105.5 买入已填充 |
+-------------------------------+
      |
      | <- 用户确认(热键/自动扫描)
      v
确认成交 -> 计算TP/SL -> 提交条件单 -> DONE
      |
      v (处理下一个)
从队列取下一个命中 -> 填充买入表单 -> 等待确认...
```

**规则:**
- 任何时刻最多1个订单处于PENDING状态
- 新命中信号进入队列排队,不立刻填充表单
- 用户确认/跳过当前订单后,才处理下一个
- 队列上限5个,满时丢弃最旧的
- 超时30秒未确认自动跳过,处理下一个

### 2.3 成交确认方式(双通道)

同时支持两种确认方式,任一触发即确认:

| 方式 | 触发条件 | 优先级 |
|------|---------|--------|
| **全局热键** | Ctrl+Shift+Y = 确认成交, Ctrl+Shift+N = 跳过 | 主(最快) |
| **HTTP面板** | 浏览器小面板点击[已成交]/[跳过] | 辅(直观) |
| **自动扫描** | 扫描当日成交,三元组匹配(code+price+time) | 兜底(自动) |

**三元组匹配策略(解决同一转债多次交易的区分问题):**

```
匹配条件 = (证券代码 完全匹配)
         AND (委托价格 与 target_buy_price 差值 <= 0.01元)
         AND (委托时间 在 提交时间后 0~30秒内)
```

```python
class OrderPipeline:
    """
    串行订单管道
    
    设计原则:
    - 任何时刻最多1个PENDING订单
    - 队列上限5个,满时丢弃最旧
    - 超时30秒自动跳过
    - 状态持久化到JSON(防重启丢单)
    """
    
    MAX_QUEUE_SIZE = 5
    PENDING_TIMEOUT_SECONDS = 30
    STATE_FILE = "pipeline_state.json"
    
    def __init__(self, config, trader, cond_placer):
        self.queue = []              # 等待处理的命中信号
        self.current = None          # 当前PENDING订单(最多1个)
        self.history = []            # 已完成订单(用于当日统计)
        self.trader = trader         # HuaTaiTrader实例
        self.cond_placer = cond_placer  # 条件单提交器
    
    def on_new_hit(self, hit_info: dict):
        """
        新命中到达
        
        Args:
            hit_info: {
                'bond_code': str,
                'bond_name': str,
                'hit_price': float,    # 命中时市场价
                'scheme_name': str,
                'scheme_detail': {
                    'price_offset': float,
                    'offset_mode': str,     # 'fixed' / 'percent'
                    'stop_loss': float,     # 止损百分比
                    'take_profit': float,   # 止盈百分比
                    'max_hold_time': int,   # 最大持仓分钟(条件单截止时间参考)
                },
                'lots': int,
            }
        """
        if self.current is None:
            # 无等待中的订单,立即处理
            self._process_hit(hit_info)
        else:
            # 有订单在等确认,入队
            if len(self.queue) >= self.MAX_QUEUE_SIZE:
                dropped = self.queue.pop(0)  # 丢弃最旧的
                logger.info(f"[Pipeline] 队列满,丢弃最旧: {dropped['bond_name']}")
            self.queue.append(hit_info)
            logger.info(f"[Pipeline] 入队: {hit_info['bond_name']} (队列={len(self.queue)})")
    
    def on_confirm(self, actual_price: float = None):
        """
        用户确认成交(热键或HTTP面板触发)

        """
        if not self.current:
            return
        
        order = self.current
        order.actual_buy_price = actual_price or order.target_buy_price
        order.status = "filled"
        order.filled_at = datetime.now().isoformat()
        
        # 提交止盈止损条件单
        self._submit_tp_sl(order)
        
        # 处理下一个
        self.current = None
        self._process_next()
    
    def on_skip(self):
        """用户跳过当前订单"""
        if self.current:
            self.current.status = "skipped"
            self.history.append(self.current)
            self.current = None
            self._process_next()
    
    def check_timeout(self):
        """每tick调用: 检查当前PENDING订单是否超时"""
        if self.current and self.current.status == "pending":
```

```python
    """

    RETRY_INTERVAL = 2

    POPUP_TITLE = "华泰理财通"
    POPUP_CLASS = "Chrome_WidgetWin_1"

        """
        Args:
            positions_file: 校准文件路径(tp_sl_positions.json)
                包含所有元素相对于窗口左上角的坐标偏移
        """

                    tp_pct: float, sl_pct: float, 
                    quantity: int) -> dict:
        """
        提交止盈止损条件单
        
        Args:
            bond_code: 证券代码
            base_price: 基准价(买入成交价,元)
            tp_pct: 止盈百分比(如3.0表示涨3%触发)
            sl_pct: 止损百分比(如2.0表示跌2%触发)
            quantity: 委托数量(股/张)
        
        Returns:
            {'success': bool, 'message': str, 'retries': int}
        """
        for attempt in range(self.MAX_RETRIES):
            try:
                result = self._execute(bond_code, base_price, tp_pct, sl_pct, quantity)
                if result['success']:
                    result['retries'] = attempt
                    return result
            except Exception as e:
                logger.warning(f"[条件单] 第{attempt+1}次失败: {e}")
            
            if attempt < self.MAX_RETRIES - 1:
                time.sleep(self.RETRY_INTERVAL)
        
        self._alert_manual_intervention(bond_code, base_price, tp_pct, sl_pct)
        return {'success': False, 'message': f'重试{self.MAX_RETRIES}次失败', 'retries': self.MAX_RETRIES}
```

```python
        """启动热键监听(独立线程)"""
        import keyboard  # pip install keyboard
        
        keyboard.add_hotkey('ctrl+shift+y', self._on_confirm)
        keyboard.add_hotkey('ctrl+shift+n', self._on_skip)
        keyboard.add_hotkey('ctrl+shift+i', self._on_info)
        
        self._running = True
        logger.info("[Hotkey] 热键监听已启动: Ctrl+Shift+Y=确认 N=跳过 I=信息")
    
    def stop(self):
        """停止监听"""
        import keyboard
        keyboard.unhook_all()
        self._running = False
    
    def _on_confirm(self):
        """确认成交"""
        if self.pipeline.current:
            logger.info(f"[Hotkey] 用户确认成交: {self.pipeline.current.bond_name}")
            self.pipeline.on_confirm()
            # 播放确认音
            self._play_confirm_sound()
    
    def _on_skip(self):
        """跳过当前"""
        if self.pipeline.current:
            logger.info(f"[Hotkey] 用户跳过: {self.pipeline.current.bond_name}")
            self.pipeline.on_skip()
    
    def _on_info(self):
        """打印当前订单信息"""
        if self.pipeline.current:
            o = self.pipeline.current
            print(f"\n{'='*50}")
            print(f"当前订单: {o.bond_name}({o.bond_code})")
            print(f"目标买入价: {o.target_buy_price}")
            print(f"止盈: +{o.take_profit_pct}% = {o.tp_price_preview}")
            print(f"止损: -{o.stop_loss_pct}% = {o.sl_price_preview}")
            print(f"等待时间: {o.pending_elapsed:.0f}秒 / 30秒超时")
            print(f"队列中: {len(self.pipeline.queue)}个")
            print(f"{'='*50}\n")
        else:
            print("[Pipeline] 当前无活跃订单")
```

### 6.2 trader_adapter.py 修改

**修改内容:** on_hit() 方法改为接收完整信息并转发给Pipeline

```python
def on_hit(self, bond_code: str, bond_name: str, price: float = None,
           scheme_name: str = '', lots: int = None,
           scheme_detail: dict = None, **extra) -> bool:
    """
    命中回调 - 转发给OrderPipeline
    (保留原有过滤逻辑: 方案过滤/风控/去重)
    """
    if not self.config['enabled']:
        return False
    
    self._reset_daily_count_if_needed()
    
    # 方案过滤(不变)
    if not self._check_scheme_filter(scheme_name):
        return False
    
    # 交易时段检查(不变)
    if self.config.get('check_trading_time', True):
        if not self._is_trading_time():
            return False
    
    # 风控检查(不变)
    passed, reason = self._check_risk_limits(bond_code, price, lots)
    if not passed:
        self._send_notification("风控拦截", reason, success=False)
        return False
    
    # 转发给Pipeline
    from gs2026.monitor.order_pipeline import get_pipeline
    pipeline = get_pipeline()
    pipeline.on_new_hit({
        'bond_code': bond_code,
        'bond_name': bond_name,
        'hit_price': price or 0,
        'scheme_name': scheme_name,
        'scheme_detail': scheme_detail or {},
        'lots': lots or self.config.get('default_lots', 1),
    })
    
    self._daily_count += 1
    return True
```

## 八、错误处理与容错

### 8.1 条件单提交失败处理流程

```
条件单提交
    |
    v
第1次尝试 ──失败──> 等待2秒 ──> 第2次尝试 ──失败──> 等待2秒 ──> 第3次尝试
    |                                   |                              |
    成功                                成功                          失败
    |                                   |                              |
    v                                   v                              v
  完成                                完成                      触发告警流程
                                                                       |
                                                         +-------------+-------------+
                                                         |                           |
                                                    声音告警x3                  控制台红色警告
                                                    (急促蜂鸣)              "[!!! 需要人工干预 !!!]"
                                                         |                           |
                                                         +-------------+-------------+
                                                                       |
                                                                       v
                                                              订单标记为 TP_SL_FAILED
                                                              (不自动重试,等待人工处理)
```

### 8.2 各环节容错策略

| 环节 | 可能的错误 | 处理方式 |
|------|-----------|---------|
| 买入表单填充 | 华泰窗口未连接 | 自动重连1次,失败则跳过此单 |
| 华泰Web页面 | 未登录/session过期 | 告警提示重新登录 |
| 条件单提交 | 网络超时/页面卡顿 | 重试3次,间隔2秒 |
| 条件单提交 | 证券代码不存在 | 记录错误,跳过(数据异常) |
| 条件单提交 | 数量超过持仓 | 告警,需人工确认 |
| 热键监听 | 库冲突/权限不足 | 降级为仅HTTP面板模式 |
| 状态文件 | JSON损坏 | 备份损坏文件,从空状态重启 |
| 进程重启 | 有未完成的PENDING单 | 从state文件恢复,继续倒计时 |

### 8.3 进程重启恢复策略

```
启动时:
1. 读取 pipeline_state.json
2. 检查是否有 status="pending" 的订单
   - 有: 检查创建时间
     - 已超过30秒: 自动标记skipped
     - 未超过30秒: 恢复为PENDING,继续倒计时
3. 检查是否有 status="filled" 但 tp_sl未提交 的订单
   - 有: 重新执行条件单提交
4. 队列中的订单: 保留,继续处理
```

## 9. 债券量化回测功能-基于sssj表的条件回测与止盈止损判定


## 文档信息
- **创建日期**: 2026-07-08
- **功能位置**: 分析中心 → 回溯分析 下方
- **数据源**: `monitor_zq_sssj_{date}` 表

---

## 一、需求概述

选择某天的债券sssj表，配置入场条件（支持sssj表所有字段，动态增删），执行回测后输出：
1. 命中信号清单（满足条件的债券+时间点）
2. 每笔信号在N分钟内的止盈/止损判定结果
3. 整体统计（胜率、盈亏比、总收益等）

---

## 二、核心数据流（两阶段查询）

### 关键设计：条件筛选与止盈止损判定是两次独立查询

```
┌─────────────────────────────────────────────────────────────────────┐
│                        第一阶段：信号筛选                              │
│                                                                     │
│  SQL条件下推 → 获取满足入场条件的 tick（信号点）                        │
│                                                                     │
│  SELECT bond_code, bond_name, time, price                           │
│  FROM monitor_zq_sssj_20260708                                      │
│  WHERE min1_change_pct > 0.2                                        │
│    AND min1_change_pct < 0.8                                        │
│    AND min1_amount > 10000000                                       │
│    AND time >= '09:30:00' AND time <= '15:00:00'                    │
│                                                                     │
│  结果：命中信号列表（几十~几百条）                                      │
│  内容：哪些债券、在什么时间点、以什么价格触发了入场条件                    │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                                │ 提取：bond_codes[] + time范围
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                     第二阶段：止盈止损判定                              │
│                                                                     │
│  根据信号点的bond_code列表 + 时间窗口，查询这些债券的全量价格数据         │
│                                                                     │
│  SELECT bond_code, time, price                                      │
│  FROM monitor_zq_sssj_20260708                                      │
│  WHERE bond_code IN ('123456','789012',...)      ← 信号中的债券       │
│    AND time >= '09:32:06'                        ← 最早信号时间       │
│    AND time <= '15:05:00'                        ← 最晚信号+窗口      │
│  ORDER BY bond_code, time                                           │
│                                                                     │
│  结果：信号债券在观察窗口内的完整价格序列（几千~几万条）                   │
│  用途：逐tick扫描判定止盈/止损/超时                                     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                     第三阶段：逐信号判定                               │
│                                                                     │
│  对每个信号点：                                                       │
│    entry_price = 信号时刻价格                                         │
│    tp_price = entry_price × (1 + 止盈%)                              │
│    sl_price = entry_price × (1 - 止损%)                              │
│                                                                     │
│    从信号时刻起，逐tick扫描该bond后续N分钟内价格：                       │
│      if price >= tp_price → 止盈命中（先到），记录盈利，退出              │
│      if price <= sl_price → 止损命中（先到），记录亏损，退出              │
│      if 超过N分钟         → 超时，按末tick价格计算浮盈/浮亏              │
│                                                                     │
│  关键：逐tick遍历保证时间顺序 → 谁先到谁生效                            │
└─────────────────────────────────────────────────────────────────────┘
```

### 为什么分两阶段

| 对比 | 单次全量加载（旧方案） | 两阶段查询（本方案） |
|------|---------------------|-------------------|
| 数据量 | 150万行全部加载 | 阶段1: 几百行 + 阶段2: 几万行 |
| 耗时 | 5-10秒 | < 2秒 |
| 内存 | ~500MB | ~20MB |
| SQL优化 | 无法利用索引 | 条件下推 + IN查询，命中索引 |

### 5.2 核心引擎 `backtest_bond.py`

```python
"""
债券量化回测引擎

两阶段查询策略：
  阶段1：条件下推SQL → 获取信号点（几十~几百条）
  阶段2：按信号bond_code + 时间窗口 → 获取价格序列（几千~几万条）
  阶段3：逐信号逐tick判定止盈/止损/超时
"""

import pandas as pd
import numpy as np
from datetime import timedelta
from sqlalchemy import text


# ====== 字段配置（扩展点）======
BACKTEST_FIELDS = [
    {'name': 'price', 'label': '现价', 'group': '价格类', 'type': 'float'},
    {'name': 'open', 'label': '开盘价', 'group': '价格类', 'type': 'float'},
    {'name': 'high', 'label': '最高价', 'group': '价格类', 'type': 'float'},
    {'name': 'low', 'label': '最低价', 'group': '价格类', 'type': 'float'},
    {'name': 'pre_close', 'label': '昨收', 'group': '价格类', 'type': 'float'},
    {'name': 'change', 'label': '涨跌额', 'group': '涨跌类', 'type': 'float'},
    {'name': 'change_pct', 'label': '涨跌幅(%)', 'group': '涨跌类', 'type': 'float'},
    {'name': 'volume', 'label': '成交量', 'group': '成交类', 'type': 'float'},
    {'name': 'amount', 'label': '成交金额', 'group': '成交类', 'type': 'float'},
    {'name': 'min1_change_pct', 'label': '1分钟涨幅(%)', 'group': '1分钟类', 'type': 'float'},
    {'name': 'min1_amount', 'label': '1分钟金额', 'group': '1分钟类', 'type': 'float'},
    {'name': 'is_body_up', 'label': '实体阳', 'group': '形态类', 'type': 'int'},
    {'name': 'is_body_down', 'label': '实体阴', 'group': '形态类', 'type': 'int'},
    {'name': 'is_body_flat', 'label': '实体平', 'group': '形态类', 'type': 'int'},
]

VALID_FIELDS = {f['name'] for f in BACKTEST_FIELDS}
VALID_OPS = {'>', '>=', '<', '<=', '=', '!=', 'between'}


def _build_sql_where(conditions):
    """
    将条件列表转为 SQL WHERE 子句（参数化，防注入）
    返回: (where_clause_str, params_dict)
    """
    clauses = []
    params = {}
    for i, c in enumerate(conditions):
        field = c['field']
        op = c['op']
        param_key = f"cond_{i}"

        if op == 'between':
            clauses.append(f"`{field}` >= :{param_key}_lo AND `{field}` <= :{param_key}_hi")
            params[f"{param_key}_lo"] = float(c['value'])
            params[f"{param_key}_hi"] = float(c['value2'])
        elif op == '=':
            clauses.append(f"`{field}` = :{param_key}")
            params[param_key] = float(c['value'])
        elif op == '!=':
            clauses.append(f"`{field}` != :{param_key}")
            params[param_key] = float(c['value'])
        else:
            # >, >=, <, <=
            clauses.append(f"`{field}` {op} :{param_key}")
            params[param_key] = float(c['value'])

    return ' AND '.join(clauses), params


def run_bond_backtest(engine, date, conditions, tp_pct, sl_pct,
                      window_minutes, dedup='first_per_minute',
                      time_start='09:30:00', time_end='15:00:00'):
    """
    执行债券量化回测（两阶段查询）

    Args:
        engine: SQLAlchemy engine（共享引擎）
        date: 日期 YYYYMMDD
        conditions: [{'field', 'op', 'value', 'value2'(optional)}]
        tp_pct: 止盈百分比（如0.5表示+0.5%）
        sl_pct: 止损百分比（如0.3表示-0.3%）
        window_minutes: 观察窗口（分钟）
        dedup: 去重模式 'first_per_minute' | 'none'
        time_start: 信号时间范围开始
        time_end: 信号时间范围结束

    Returns:
        (summary_dict, trades_list)
    """

    # ====== 0. 校验 ======
    for c in conditions:
        if c['field'] not in VALID_FIELDS:
            raise ValueError(f"非法字段: {c['field']}")
        if c['op'] not in VALID_OPS:
            raise ValueError(f"非法操作符: {c['op']}")

    if not conditions:
        raise ValueError("至少需要一个入场条件")

    table = f"monitor_zq_sssj_{date}"

    # ====== 阶段1：条件下推 → 获取信号点 ======
    where_clause, params = _build_sql_where(conditions)
    params['time_start'] = time_start
    params['time_end'] = time_end

    signal_sql = text(f"""
        SELECT bond_code, bond_name, time, price
        FROM {table}
        WHERE {where_clause}
          AND time >= :time_start AND time <= :time_end
        ORDER BY bond_code, time
    """)

    with engine.connect() as conn:
        df_signals = pd.read_sql(signal_sql, conn, params=params)

    if df_signals.empty:
        return {'total_signals': 0, 'tp_count': 0, 'sl_count': 0,
                'timeout_count': 0, 'win_rate': 0}, []

    # 去重：每分钟每债券只取第一个信号
    df_signals['time_td'] = pd.to_timedelta(df_signals['time'].astype(str))
    if dedup == 'first_per_minute':
        df_signals['minute_key'] = df_signals['time_td'].dt.components['hours'].astype(str).str.zfill(2) + ':' + \
                                   df_signals['time_td'].dt.components['minutes'].astype(str).str.zfill(2)
        df_signals = df_signals.groupby(['bond_code', 'minute_key']).first().reset_index()

    # ====== 阶段2：查询信号债券的完整价格序列 ======
    signal_codes = df_signals['bond_code'].unique().tolist()
    earliest_time = df_signals['time_td'].min()
    latest_time = df_signals['time_td'].max() + pd.Timedelta(minutes=window_minutes)

    # 分批查询防止 IN 列表过长
    BATCH_SIZE = 200
    price_dfs = []
    for i in range(0, len(signal_codes), BATCH_SIZE):
        batch_codes = signal_codes[i:i+BATCH_SIZE]
        codes_str = ','.join([f"'{c}'" for c in batch_codes])
        price_sql = text(f"""
            SELECT bond_code, time, price
            FROM {table}
            WHERE bond_code IN ({codes_str})
              AND time >= :earliest AND time <= :latest
            ORDER BY bond_code, time
        """)
        with engine.connect() as conn:
            batch_df = pd.read_sql(price_sql, conn, params={
                'earliest': str(earliest_time).split(' ')[-1] if ' ' in str(earliest_time) else str(earliest_time),
                'latest': str(latest_time).split(' ')[-1] if ' ' in str(latest_time) else str(latest_time),
            })
        price_dfs.append(batch_df)

    df_prices = pd.concat(price_dfs, ignore_index=True) if price_dfs else pd.DataFrame()

    if df_prices.empty:
        return {'total_signals': len(df_signals), 'tp_count': 0, 'sl_count': 0,
                'timeout_count': len(df_signals), 'win_rate': 0}, []

    df_prices['time_td'] = pd.to_timedelta(df_prices['time'].astype(str))

    # ====== 阶段3：逐信号判定止盈止损 ======
    window_td = pd.Timedelta(minutes=window_minutes)
    trades = []

    # 按bond_code分组价格数据，避免重复切片
    price_grouped = {code: group.sort_values('time_td') for code, group in df_prices.groupby('bond_code')}

    for _, sig in df_signals.iterrows():
        code = sig['bond_code']
        entry_time = sig['time_td']
        entry_price = float(sig['price'])

        if entry_price <= 0:
            continue

        tp_price = entry_price * (1 + tp_pct / 100)
        sl_price = entry_price * (1 - sl_pct / 100)
        deadline = entry_time + window_td

        # 获取该bond在信号后的价格序列
        bond_prices = price_grouped.get(code)
        if bond_prices is None:
            continue

        future = bond_prices[(bond_prices['time_td'] > entry_time) & (bond_prices['time_td'] <= deadline)]

        exit_type = 'timeout'
        exit_price = entry_price
        exit_time = entry_time
        max_price = entry_price
        min_price = entry_price

        if not future.empty:
            prices = future['price'].values.astype(float)
            times = future['time_td'].values
            max_price = float(np.max(prices))
            min_price = float(np.min(prices))

            # 向量化查找首次触达
            tp_hits = np.where(prices >= tp_price)[0]
            sl_hits = np.where(prices <= sl_price)[0]

            tp_idx = tp_hits[0] if len(tp_hits) > 0 else len(prices) + 1
            sl_idx = sl_hits[0] if len(sl_hits) > 0 else len(prices) + 1

            if tp_idx <= sl_idx and tp_idx < len(prices) + 1:
                # 止盈先到
                exit_type = 'tp'
                exit_price = float(prices[tp_idx])
                exit_time = times[tp_idx]
            elif sl_idx < tp_idx and sl_idx < len(prices) + 1:
                # 止损先到
                exit_type = 'sl'
                exit_price = float(prices[sl_idx])
                exit_time = times[sl_idx]
            else:
                # 都未触达 → 超时
                exit_price = float(prices[-1])
                exit_time = times[-1]

        profit_pct = round((exit_price - entry_price) / entry_price * 100, 4)
        duration_sec = int(pd.Timedelta(exit_time - entry_time).total_seconds()) if exit_time != entry_time else 0

        def _format_time(td):
            """timedelta → HH:MM:SS"""
            total_sec = int(pd.Timedelta(td).total_seconds())
            h, rem = divmod(total_sec, 3600)
            m, s = divmod(rem, 60)
            return f"{h:02d}:{m:02d}:{s:02d}"

        trades.append({
            'bond_code': code,
            'bond_name': sig.get('bond_name', ''),
            'signal_time': _format_time(entry_time),
            'entry_price': round(entry_price, 3),
            'exit_price': round(exit_price, 3),
            'exit_time': _format_time(exit_time),
            'exit_type': exit_type,
            'profit_pct': profit_pct,
            'duration_sec': duration_sec,
            'max_price': round(max_price, 3),
            'min_price': round(min_price, 3),
        })

    # ====== 统计汇总 ======
    if not trades:
        return {'total_signals': 0, 'tp_count': 0, 'sl_count': 0,
                'timeout_count': 0, 'win_rate': 0}, []

    tp_trades = [t for t in trades if t['exit_type'] == 'tp']
    sl_trades = [t for t in trades if t['exit_type'] == 'sl']
    timeout_trades = [t for t in trades if t['exit_type'] == 'timeout']
    all_profits = [t['profit_pct'] for t in trades]

    avg_profit = float(np.mean([t['profit_pct'] for t in tp_trades])) if tp_trades else 0
    avg_loss = float(np.mean([t['profit_pct'] for t in sl_trades])) if sl_trades else 0

    summary = {
        'total_signals': len(trades),
        'tp_count': len(tp_trades),
        'sl_count': len(sl_trades),
        'timeout_count': len(timeout_trades),
        'win_rate': round(len(tp_trades) / len(trades) * 100, 2),
        'avg_profit_pct': round(avg_profit, 4),
        'avg_loss_pct': round(avg_loss, 4),
        'profit_factor': round(abs(avg_profit / avg_loss), 2) if avg_loss != 0 else 999,
        'max_profit_pct': round(max(all_profits), 4) if all_profits else 0,
        'max_loss_pct': round(min(all_profits), 4) if all_profits else 0,
        'total_return_pct': round(sum(all_profits), 2),
        'avg_duration_sec': int(np.mean([t['duration_sec'] for t in trades])),
    }

    return summary, trades
```

## 一、需求概述

选择某天的债券sssj表，配置入场条件（支持sssj表所有字段，动态增删），执行回测后输出：
1. 命中信号清单（满足条件的债券+时间点）
2. 每笔信号在N分钟内的止盈/止损判定结果
3. 整体统计（胜率、盈亏比、总收益等）

---

## 二、核心数据流（两阶段查询）

### 关键设计：条件筛选与止盈止损判定是两次独立查询

```
┌─────────────────────────────────────────────────────────────────────┐
│                        第一阶段：信号筛选                              │
│                                                                     │
│  SQL条件下推 → 获取满足入场条件的 tick（信号点）                        │
│                                                                     │
│  SELECT bond_code, bond_name, time, price                           │
│  FROM monitor_zq_sssj_20260708                                      │
│  WHERE min1_change_pct > 0.2                                        │
│    AND min1_change_pct < 0.8                                        │
│    AND min1_amount > 10000000                                       │
│    AND time >= '09:30:00' AND time <= '15:00:00'                    │
│                                                                     │
│  结果：命中信号列表（几十~几百条）                                      │
│  内容：哪些债券、在什么时间点、以什么价格触发了入场条件                    │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                                │ 提取：bond_codes[] + time范围
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                     第二阶段：止盈止损判定                              │
│                                                                     │
│  根据信号点的bond_code列表 + 时间窗口，查询这些债券的全量价格数据         │
│                                                                     │
│  SELECT bond_code, time, price                                      │
│  FROM monitor_zq_sssj_20260708                                      │
│  WHERE bond_code IN ('123456','789012',...)      ← 信号中的债券       │
│    AND time >= '09:32:06'                        ← 最早信号时间       │
│    AND time <= '15:05:00'                        ← 最晚信号+窗口      │
│  ORDER BY bond_code, time                                           │
│                                                                     │
│  结果：信号债券在观察窗口内的完整价格序列（几千~几万条）                   │
│  用途：逐tick扫描判定止盈/止损/超时                                     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│                     第三阶段：逐信号判定                               │
│                                                                     │
│  对每个信号点：                                                       │
│    entry_price = 信号时刻价格                                         │
│    tp_price = entry_price × (1 + 止盈%)                              │
│    sl_price = entry_price × (1 - 止损%)                              │
│                                                                     │
│    从信号时刻起，逐tick扫描该bond后续N分钟内价格：                       │
│      if price >= tp_price → 止盈命中（先到），记录盈利，退出              │
│      if price <= sl_price → 止损命中（先到），记录亏损，退出              │
│      if 超过N分钟         → 超时，按末tick价格计算浮盈/浮亏              │
│                                                                     │
│  关键：逐tick遍历保证时间顺序 → 谁先到谁生效                            │
└─────────────────────────────────────────────────────────────────────┘
```

### 为什么分两阶段

| 对比 | 单次全量加载（旧方案） | 两阶段查询（本方案） |
|------|---------------------|-------------------|
| 数据量 | 150万行全部加载 | 阶段1: 几百行 + 阶段2: 几万行 |
| 耗时 | 5-10秒 | < 2秒 |
| 内存 | ~500MB | ~20MB |
| SQL优化 | 无法利用索引 | 条件下推 + IN查询，命中索引 |

### 5.2 核心引擎 `backtest_bond.py`

```python
"""
债券量化回测引擎

两阶段查询策略：
  阶段1：条件下推SQL → 获取信号点（几十~几百条）
  阶段2：按信号bond_code + 时间窗口 → 获取价格序列（几千~几万条）
  阶段3：逐信号逐tick判定止盈/止损/超时
"""

import pandas as pd
import numpy as np
from datetime import timedelta
from sqlalchemy import text


# ====== 字段配置（扩展点）======
BACKTEST_FIELDS = [
    {'name': 'price', 'label': '现价', 'group': '价格类', 'type': 'float'},
    {'name': 'open', 'label': '开盘价', 'group': '价格类', 'type': 'float'},
    {'name': 'high', 'label': '最高价', 'group': '价格类', 'type': 'float'},
    {'name': 'low', 'label': '最低价', 'group': '价格类', 'type': 'float'},
    {'name': 'pre_close', 'label': '昨收', 'group': '价格类', 'type': 'float'},
    {'name': 'change', 'label': '涨跌额', 'group': '涨跌类', 'type': 'float'},
    {'name': 'change_pct', 'label': '涨跌幅(%)', 'group': '涨跌类', 'type': 'float'},
    {'name': 'volume', 'label': '成交量', 'group': '成交类', 'type': 'float'},
    {'name': 'amount', 'label': '成交金额', 'group': '成交类', 'type': 'float'},
    {'name': 'min1_change_pct', 'label': '1分钟涨幅(%)', 'group': '1分钟类', 'type': 'float'},
    {'name': 'min1_amount', 'label': '1分钟金额', 'group': '1分钟类', 'type': 'float'},
    {'name': 'is_body_up', 'label': '实体阳', 'group': '形态类', 'type': 'int'},
    {'name': 'is_body_down', 'label': '实体阴', 'group': '形态类', 'type': 'int'},
    {'name': 'is_body_flat', 'label': '实体平', 'group': '形态类', 'type': 'int'},
]

VALID_FIELDS = {f['name'] for f in BACKTEST_FIELDS}
VALID_OPS = {'>', '>=', '<', '<=', '=', '!=', 'between'}


def _build_sql_where(conditions):
    """
    将条件列表转为 SQL WHERE 子句（参数化，防注入）
    返回: (where_clause_str, params_dict)
    """
    clauses = []
    params = {}
    for i, c in enumerate(conditions):
        field = c['field']
        op = c['op']
        param_key = f"cond_{i}"

        if op == 'between':
            clauses.append(f"`{field}` >= :{param_key}_lo AND `{field}` <= :{param_key}_hi")
            params[f"{param_key}_lo"] = float(c['value'])
            params[f"{param_key}_hi"] = float(c['value2'])
        elif op == '=':
            clauses.append(f"`{field}` = :{param_key}")
            params[param_key] = float(c['value'])
        elif op == '!=':
            clauses.append(f"`{field}` != :{param_key}")
            params[param_key] = float(c['value'])
        else:
            # >, >=, <, <=
            clauses.append(f"`{field}` {op} :{param_key}")
            params[param_key] = float(c['value'])

    return ' AND '.join(clauses), params


def run_bond_backtest(engine, date, conditions, tp_pct, sl_pct,
                      window_minutes, dedup='first_per_minute',
                      time_start='09:30:00', time_end='15:00:00'):
    """
    执行债券量化回测（两阶段查询）

    Args:
        engine: SQLAlchemy engine（共享引擎）
        date: 日期 YYYYMMDD
        conditions: [{'field', 'op', 'value', 'value2'(optional)}]
        tp_pct: 止盈百分比（如0.5表示+0.5%）
        sl_pct: 止损百分比（如0.3表示-0.3%）
        window_minutes: 观察窗口（分钟）
        dedup: 去重模式 'first_per_minute' | 'none'
        time_start: 信号时间范围开始
        time_end: 信号时间范围结束

    Returns:
        (summary_dict, trades_list)
    """

    # ====== 0. 校验 ======
    for c in conditions:
        if c['field'] not in VALID_FIELDS:
            raise ValueError(f"非法字段: {c['field']}")
        if c['op'] not in VALID_OPS:
            raise ValueError(f"非法操作符: {c['op']}")

    if not conditions:
        raise ValueError("至少需要一个入场条件")

    table = f"monitor_zq_sssj_{date}"

    # ====== 阶段1：条件下推 → 获取信号点 ======
    where_clause, params = _build_sql_where(conditions)
    params['time_start'] = time_start
    params['time_end'] = time_end

    signal_sql = text(f"""
        SELECT bond_code, bond_name, time, price
        FROM {table}
        WHERE {where_clause}
          AND time >= :time_start AND time <= :time_end
        ORDER BY bond_code, time
    """)

    with engine.connect() as conn:
        df_signals = pd.read_sql(signal_sql, conn, params=params)

    if df_signals.empty:
        return {'total_signals': 0, 'tp_count': 0, 'sl_count': 0,
                'timeout_count': 0, 'win_rate': 0}, []

    # 去重：每分钟每债券只取第一个信号
    df_signals['time_td'] = pd.to_timedelta(df_signals['time'].astype(str))
    if dedup == 'first_per_minute':
        df_signals['minute_key'] = df_signals['time_td'].dt.components['hours'].astype(str).str.zfill(2) + ':' + \
                                   df_signals['time_td'].dt.components['minutes'].astype(str).str.zfill(2)
        df_signals = df_signals.groupby(['bond_code', 'minute_key']).first().reset_index()

    # ====== 阶段2：查询信号债券的完整价格序列 ======
    signal_codes = df_signals['bond_code'].unique().tolist()
    earliest_time = df_signals['time_td'].min()
    latest_time = df_signals['time_td'].max() + pd.Timedelta(minutes=window_minutes)

    # 分批查询防止 IN 列表过长
    BATCH_SIZE = 200
    price_dfs = []
    for i in range(0, len(signal_codes), BATCH_SIZE):
        batch_codes = signal_codes[i:i+BATCH_SIZE]
        codes_str = ','.join([f"'{c}'" for c in batch_codes])
        price_sql = text(f"""
            SELECT bond_code, time, price
            FROM {table}
            WHERE bond_code IN ({codes_str})
              AND time >= :earliest AND time <= :latest
            ORDER BY bond_code, time
        """)
        with engine.connect() as conn:
            batch_df = pd.read_sql(price_sql, conn, params={
                'earliest': str(earliest_time).split(' ')[-1] if ' ' in str(earliest_time) else str(earliest_time),
                'latest': str(latest_time).split(' ')[-1] if ' ' in str(latest_time) else str(latest_time),
            })
        price_dfs.append(batch_df)

    df_prices = pd.concat(price_dfs, ignore_index=True) if price_dfs else pd.DataFrame()

    if df_prices.empty:
        return {'total_signals': len(df_signals), 'tp_count': 0, 'sl_count': 0,
                'timeout_count': len(df_signals), 'win_rate': 0}, []

    df_prices['time_td'] = pd.to_timedelta(df_prices['time'].astype(str))

    # ====== 阶段3：逐信号判定止盈止损 ======
    window_td = pd.Timedelta(minutes=window_minutes)
    trades = []

    # 按bond_code分组价格数据，避免重复切片
    price_grouped = {code: group.sort_values('time_td') for code, group in df_prices.groupby('bond_code')}

    for _, sig in df_signals.iterrows():
        code = sig['bond_code']
        entry_time = sig['time_td']
        entry_price = float(sig['price'])

        if entry_price <= 0:
            continue

        tp_price = entry_price * (1 + tp_pct / 100)
        sl_price = entry_price * (1 - sl_pct / 100)
        deadline = entry_time + window_td

        # 获取该bond在信号后的价格序列
        bond_prices = price_grouped.get(code)
        if bond_prices is None:
            continue

        future = bond_prices[(bond_prices['time_td'] > entry_time) & (bond_prices['time_td'] <= deadline)]

        exit_type = 'timeout'
        exit_price = entry_price
        exit_time = entry_time
        max_price = entry_price
        min_price = entry_price

        if not future.empty:
            prices = future['price'].values.astype(float)
            times = future['time_td'].values
            max_price = float(np.max(prices))
            min_price = float(np.min(prices))

            # 向量化查找首次触达
            tp_hits = np.where(prices >= tp_price)[0]
            sl_hits = np.where(prices <= sl_price)[0]

            tp_idx = tp_hits[0] if len(tp_hits) > 0 else len(prices) + 1
            sl_idx = sl_hits[0] if len(sl_hits) > 0 else len(prices) + 1

            if tp_idx <= sl_idx and tp_idx < len(prices) + 1:
                # 止盈先到
                exit_type = 'tp'
                exit_price = float(prices[tp_idx])
                exit_time = times[tp_idx]
            elif sl_idx < tp_idx and sl_idx < len(prices) + 1:
                # 止损先到
                exit_type = 'sl'
                exit_price = float(prices[sl_idx])
                exit_time = times[sl_idx]
            else:
                # 都未触达 → 超时
                exit_price = float(prices[-1])
                exit_time = times[-1]

        profit_pct = round((exit_price - entry_price) / entry_price * 100, 4)
        duration_sec = int(pd.Timedelta(exit_time - entry_time).total_seconds()) if exit_time != entry_time else 0

        def _format_time(td):
            """timedelta → HH:MM:SS"""
            total_sec = int(pd.Timedelta(td).total_seconds())
            h, rem = divmod(total_sec, 3600)
            m, s = divmod(rem, 60)
            return f"{h:02d}:{m:02d}:{s:02d}"

        trades.append({
            'bond_code': code,
            'bond_name': sig.get('bond_name', ''),
            'signal_time': _format_time(entry_time),
            'entry_price': round(entry_price, 3),
            'exit_price': round(exit_price, 3),
            'exit_time': _format_time(exit_time),
            'exit_type': exit_type,
            'profit_pct': profit_pct,
            'duration_sec': duration_sec,
            'max_price': round(max_price, 3),
            'min_price': round(min_price, 3),
        })

    # ====== 统计汇总 ======
    if not trades:
        return {'total_signals': 0, 'tp_count': 0, 'sl_count': 0,
                'timeout_count': 0, 'win_rate': 0}, []

    tp_trades = [t for t in trades if t['exit_type'] == 'tp']
    sl_trades = [t for t in trades if t['exit_type'] == 'sl']
    timeout_trades = [t for t in trades if t['exit_type'] == 'timeout']
    all_profits = [t['profit_pct'] for t in trades]

    avg_profit = float(np.mean([t['profit_pct'] for t in tp_trades])) if tp_trades else 0
    avg_loss = float(np.mean([t['profit_pct'] for t in sl_trades])) if sl_trades else 0

    summary = {
        'total_signals': len(trades),
        'tp_count': len(tp_trades),
        'sl_count': len(sl_trades),
        'timeout_count': len(timeout_trades),
        'win_rate': round(len(tp_trades) / len(trades) * 100, 2),
        'avg_profit_pct': round(avg_profit, 4),
        'avg_loss_pct': round(avg_loss, 4),
        'profit_factor': round(abs(avg_profit / avg_loss), 2) if avg_loss != 0 else 999,
        'max_profit_pct': round(max(all_profits), 4) if all_profits else 0,
        'max_loss_pct': round(min(all_profits), 4) if all_profits else 0,
        'total_return_pct': round(sum(all_profits), 2),
        'avg_duration_sec': int(np.mean([t['duration_sec'] for t in trades])),
    }

    return summary, trades
```

## 七、异常处理

| 场景 | 处理方式 |
|------|---------|
| 日期表不存在 | 后端 catch SQL异常 → 返回 "该日期无数据" |
| 条件筛选0条信号 | 返回 `total_signals: 0` + 前端提示"无命中信号，请调整条件" |
| 字段不存在（旧表无min1字段） | 后端 catch Column not found → 返回具体提示 |
| 查询超时（>15秒） | 后端 SQL timeout + 前端 loading 动画 + abort 按钮 |
| 非法字段/操作符 | 后端白名单校验，返回 400 |
