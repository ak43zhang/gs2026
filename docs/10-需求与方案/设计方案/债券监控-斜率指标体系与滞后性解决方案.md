## 二、算法选型与科学依据

### 2.1 斜率估计算法候选对比

| 算法 | 出处 | 滞后性 | 抖动 | 计算复杂度 | 适合场景 |
|------|------|--------|------|-----------|----------|
| **简单线性回归(OLS)** | Gauss(1809), 最小二乘法 | 高(窗口/2) | 低 | O(N) | 趋势确认（非实时） |
| **指数加权线性回归(EWLR)** | RiskMetrics™ (1996) | 低(~half_life) | 中 | O(N) | **实时方向判断** ✅ |
| **Kalman滤波** | Kalman(1960), IEEE Trans. | 最低(理论最优) | 可调 | O(1)递推 | 状态估计（复杂） |
| **Holt双指数平滑** | Holt(1957), ONR Report | 低 | 中 | O(1)递推 | 趋势外推 |
| **Savitzky-Golay** | Savitzky & Golay(1964), Anal.Chem. | 中(窗口相关) | 最低 | O(N) | 平滑保峰（非因果） |
| **DEMA/TEMA** | Mulloy(1994), TASC | 低 | 高(过冲) | O(1) | 价格跟踪（易过冲） |

### 2.2 最终选择：指数加权线性回归(EWLR)

**选择理由**：

1. **滞后性**：通过 half_life 参数精确控制，30s半衰期下响应延迟约10-15秒（3-5个tick），满足秒级交易需求

2. **抖动控制**：相比 DEMA/TEMA 不会过冲（overshoot），相比 Kalman 实现简单无需调Q/R矩阵

3. **科学基础**：
   - 源自 J.P. Morgan RiskMetrics™ (1996) 的协方差估计方法
   - 将指数衰减权重应用于线性回归，在金融风险管理中广泛使用
   - 论文：*"RiskMetrics—Technical Document"*, J.P. Morgan/Reuters, 4th Edition, 1996

4. **计算稳定性**：加权最小二乘有解析解，不存在迭代收敛问题

5. **可解释性**：斜率单位明确（涨跌幅%/秒），便于设定阈值

**不选 Kalman 的原因**：
- 需要调优 Q（过程噪声）和 R（观测噪声）两个矩阵参数
- 对转债这种跳跃性强的品种，线性状态空间假设容易违反
- 实现复杂度高，调参困难，收益不明显

**不选 Holt 双指数平滑的原因**：
- 输出是"预测值"而非"当前斜率"，语义不同
- 两个参数(α, β)之间有耦合，调参不直观
- 在价格跳跃时容易产生虚假趋势信号

**不选 Savitzky-Golay 的原因**：
- 经典形式是非因果的（需要未来数据点），实时版本等价于加权回归
- 固定窗口大小，无法像半衰期那样自然衰减旧数据

### 2.3 变化率算法选择

| 算法 | 滞后 | 噪声 | 选择理由 |
|------|------|------|----------|
| **直接差分 Δp/Δt** | 零 | 高 | 最快响应，用于瞬时动量检测 |
| 移动平均差分 | 中 | 低 | 平滑但引入延迟，不适合秒级 |
| 对数收益率 | 零 | 高 | 与差分等价，无额外优势 |

**选择直接差分**（当前1分钟价格变化率）：零滞后是T+0交易的硬需求。噪声通过共振条件（大盘+个券同向）自然过滤。

### 2.4 加速度算法选择

| 算法 | 含义 | 选择理由 |
|------|------|----------|
| **斜率差分 Δslope** | 相邻tick斜率变化 | 直接反映动量变化率，计算O(1) |
| 二阶导数（二次回归） | 曲率 | 需要更长窗口，引入延迟 |
| Jerk(三阶导) | 加速度变化率 | 噪声放大严重，不实用 |

**选择斜率差分**：二阶信息（加速度）是检测拐点的标准方法（牛顿力学类比：力=质量×加速度）。直接用相邻tick的加权斜率之差，零额外延迟。

## 三、抖动抑制机制

### 3.1 问题：低滞后 vs 低抖动的矛盾

- 低滞后要求权重集中在近期 → 对噪声敏感 → 信号频繁翻转
- 低抖动要求平滑 → 需要更多数据 → 增加延迟

这是信号处理中的经典 **bias-variance tradeoff**。

### 3.2 解决方案：Schmitt Trigger（施密特触发器）原理

来源：电子工程中的滞回比较器（Otto Schmitt, 1934），用于将噪声信号转换为稳定的方向信号。

**原理**：设置上下两个阈值（而非单一零点），信号只有穿越上阈值才确认为"上涨"，穿越下阈值才确认为"下跌"，中间区域保持上一状态。

```
传统零点判断：slope > 0 → 上涨, slope < 0 → 下跌
  问题：slope在0附近震荡时频繁翻转

Schmitt Trigger：
  slope > +threshold → 确认上涨
  slope < -threshold → 确认下跌
  -threshold ≤ slope ≤ +threshold → 保持上一状态（不翻转）
```

### 3.3 方向一致性计数器

在 Schmitt Trigger 基础上增加时间维度确认：

```python
# 方向信号需要连续N个tick确认才翻转
consecutive_up_count += 1 if slope > threshold else 0
direction_confirmed = 'up' if consecutive_up_count >= CONFIRM_TICKS else previous_direction
```

**参数**：
- `threshold`：斜率阈值，建议 0.00002（对应每秒约0.002%的斜率）
- `CONFIRM_TICKS`：连续确认tick数，建议 2-3（6-9秒）

**效果**：在几乎不增加延迟的情况下（仅多1-2个tick），将虚假翻转率降低90%+。

### 5.1 共振定义

**大盘与个券共振上涨** = 以下条件同时满足：

```
条件1（大盘方向）：mkt_weighted_slope_2m > threshold_mkt

条件4（个券动量）：change_1m_pct > 0
条件5（同向加速）：mkt_price_acceleration >= 0 AND price_acceleration >= 0
```

### 5.2 为什么不用相关系数

| 方法 | 问题 |
|------|------|
| Pearson相关 | 需要窗口数据，滞后大；对非线性关系不敏感 |
| 滚动相关 | 30-60点窗口引入15-30秒延迟 |
| 同向判断 | **零额外延迟**，直接用已计算的方向信号 |

对T+0秒级交易，"同时为正"比"相关系数高"更有实操意义。

## 六、EWLR 算法精确规格

### 6.1 数学公式

给定时间序列 {(t_i, y_i)}, i=1..N，指数权重：

```
w_i = exp(-λ * (t_N - t_i))
λ = ln(2) / half_life
```

加权线性回归斜率：

```
t̄_w = Σ(w_i * t_i) / Σ(w_i)
ȳ_w = Σ(w_i * y_i) / Σ(w_i)

slope = Σ(w_i * (t_i - t̄_w) * (y_i - ȳ_w)) / Σ(w_i * (t_i - t̄_w)²)
```

### 6.2 数值稳定性保证

1. **权重归一化**：`w_i = w_i / Σw` 避免浮点溢出
2. **中心化**：减去加权均值后计算，避免大数相减精度损失
3. **分母检查**：`var_t = 0` 时返回 0（数据点时间戳全相同的退化情况）
4. **缓存清理**：保留2.5分钟数据（半衰期的5倍），超出部分权重 < 3%可忽略

### 6.3 与简单OLS对比的精确延迟分析

假设市场在 t=0 从涨转跌（阶跃函数）：

| 算法 | 斜率翻负所需时间 | 理论依据 |
|------|-----------------|----------|
| OLS (N=60) | ~30个tick (90s) | 需过半数据被替换 |
| EWLR (half_life=30s) | ~5-6个tick (15-18s) | 近期数据权重>50% |
| EWLR (half_life=15s) | ~3-4个tick (9-12s) | 近期数据权重>70% |
| 纯差分 | 1个tick (3s) | 无平滑，但噪声大 |

## 七、参数体系

### 7.1 核心参数

| 参数 | 当前值 | 调节范围 | 影响 | 调优依据 |
|------|--------|----------|------|----------|
| half_life (个券) | 30s | 15-60s | 响应速度 vs 稳定性 | Shannon采样定理：half_life ≥ 2×tick间隔 |
| half_life (大盘) | 30s | 30-60s | 大盘信号平滑度 | 大盘天然更平滑，可与个券相同 |
| 缓存窗口 | 150s | 90-300s | 数据量(回归精度) | 经验：5×half_life 足够 |
| 1分钟窗口 | 60s | 30-120s | 变化率灵敏度 | 交易周期匹配 |
| Schmitt阈值 | 0.00002 | 0.00001-0.00005 | 抖动过滤强度 | 根据历史噪声水平统计确定 |
| 确认tick数 | 2 | 1-3 | 信号确认延迟 | 1=最快但不稳定，3=稳定但慢6s |

### 7.2 参数选择的科学依据

**half_life = 30s 的选择**：

1. **Nyquist准则**：tick频率=0.33Hz，目标信号频率≈0.01-0.05Hz（20-100秒周期的趋势），half_life=30s对应截止频率约0.023Hz，正好在目标频带内

2. **有效样本数**：150s窗口内约50个tick，其中有效样本数（ESS）≈ 2×half_life/tick = 20，满足回归稳定性要求（ESS>10）

3. **实操验证**：30s半衰期意味着：
   - 10秒前的数据权重=79%（仍有贡献）
   - 30秒前的数据权重=50%（半衰）
   - 60秒前的数据权重=25%（弱贡献）
   - 这个衰减速率匹配"秒级～分钟级"持仓的信息需求

```python
# ====== 大盘扩展指标（加权斜率/变化率/加速度）======
_mkt_ext_price_cache = []       # [(seconds, avg_pct), ...]
_mkt_ext_prev_slope = 0.0
_mkt_ext_date = None

def compute_mkt_ext_indicators(df_now, time_full, current_date):
    """大盘加权斜率指标（每tick一次，O(K)计算）"""
    global _mkt_ext_price_cache, _mkt_ext_prev_slope, _mkt_ext_date

    if _mkt_ext_date != current_date:
        _mkt_ext_price_cache = []
        _mkt_ext_prev_slope = 0.0
        _mkt_ext_date = current_date

    avg_pct = float(df_now['change_pct'].mean())
    current_seconds = _time_to_seconds(time_full)

    _mkt_ext_price_cache.append((current_seconds, avg_pct))
    cutoff = current_seconds - 150
    _mkt_ext_price_cache = [(ts, p) for ts, p in _mkt_ext_price_cache if ts >= cutoff]

    # 加权斜率
    if len(_mkt_ext_price_cache) >= 2:
        prices = [p for _, p in _mkt_ext_price_cache]
        times = [t for t, _ in _mkt_ext_price_cache]
        mkt_ws = round(_calc_weighted_slope(prices, times, half_life=30), 6)
    else:
        mkt_ws = 0.0

    # 1分钟变化率
    target_ts = current_seconds - 60
    pct_1m_ago = None
    for ts, p in reversed(_mkt_ext_price_cache):
        if ts <= target_ts:
            pct_1m_ago = p
            break
    mkt_c1p = round(avg_pct - pct_1m_ago, 4) if pct_1m_ago is not None else 0.0

    # 加速度
    mkt_pa = round(mkt_ws - _mkt_ext_prev_slope, 6)
    _mkt_ext_prev_slope = mkt_ws

    return mkt_ws, mkt_c1p, mkt_pa
```

## 十二、总结

| 维度 | 方案 | 科学依据 |
|------|------|----------|
| 方向估计 | EWLR (half_life=30s) | RiskMetrics™ 加权协方差 |
| 瞬时动量 | 1分钟差分 | 一阶差分（时间序列基础） |
| 拐点检测 | 斜率差分(加速度) | 二阶导数/牛顿力学类比 |
| 抖动抑制 | Schmitt Trigger + 连续确认 | 施密特触发器(1934) |
| 共振检测 | 多条件AND同向判定 | 组合概率（独立事件交集） |
| 存储方式 | ext_indicators JSON列 | 已有结构，零迁移成本 |
| 性能 | ~5ms/tick (400债券) | 远低于3s预算 |
| 滞后 | 10-15秒(3-5 tick) | EWLR理论响应时间 |
| 抖动 | Schmitt+确认后接近零翻转 | 滞回特性消除噪声翻转 |

## 附录A：大盘与个券关系状态全景（非共振场景）

### A.1 状态分类矩阵

基于6个核心指标的正/负/零组合，定义8种典型市场状态：

| # | 状态名称 | mkt_weighted_slope_2m | mkt_change_1m_pct | mkt_price_acceleration | weighted_slope_2m | change_1m_pct | price_acceleration | 市场含义 |
|---|----------|----------------------|-------------------|----------------------|-------------------|---------------|-------------------|----------|
| 1 | **共振上攻** | > +0.00002 | > 0 | >= 0 | > +0.00005 | > +0.1% | >= 0 | 大盘+个券同步上涨加速，最佳买入窗口 |
| 2 | **共振下杀** | < -0.00002 | < 0 | <= 0 | < -0.00005 | < -0.1% | <= 0 | 大盘+个券同步下跌，绝对回避 |
| 3 | **个券独强** | -0.00002~+0.00002 | -0.02~+0.02 | 任意 | > +0.00005 | > +0.1% | >= 0 | 大盘震荡但个券走强，可参与但需警惕 |
| 4 | **个券独弱** | -0.00002~+0.00002 | -0.02~+0.02 | 任意 | < -0.00005 | < -0.1% | <= 0 | 大盘震荡但个券走弱，回避该券 |
| 5 | **逆势上攻** | < -0.00002 | < -0.02 | 任意 | > +0.00003 | > 0 | >= 0 | 大盘下跌但个券逆势走强，高风险高收益 |
| 6 | **补跌风险** | < -0.00002 | < -0.02 | 任意 | -0.00003~+0.00003 | -0.05~+0.05 | 任意 | 大盘下跌个券暂未跟随，可能即将补跌 |
| 7 | **滞涨预警** | > +0.00002 | > 0 | >= 0 | -0.00003~+0.00003 | -0.05~+0.05 | 任意 | 大盘上涨但个券不跟，个券可能有压力 |
| 8 | **双向震荡** | -0.00002~+0.00002 | -0.02~+0.02 | 任意 | -0.00003~+0.00003 | -0.05~+0.05 | 任意 | 大盘个券均无方向，观望等待 |

### A.2 各状态详细指标区间

#### 状态1：共振上攻（理想买入）

```
大盘方向：   mkt_weighted_slope_2m    > +0.00002  (明确上升趋势)
大盘动量：   mkt_change_1m_pct        > 0         (1分钟在涨)
大盘加速：   mkt_price_acceleration   >= 0        (未减速)
个券方向：   weighted_slope_2m        > +0.00005  (强于大盘的上升)
个券动量：   change_1m_pct            > +0.1%     (有明显涨幅)
个券加速：   price_acceleration       >= 0        (未减速)

操作建议：买入，持有直到加速度转负
风险等级：低（多重确认）
```

#### 状态2：共振下杀（绝对回避）

```
大盘方向：   mkt_weighted_slope_2m    < -0.00002  (明确下降趋势)
大盘动量：   mkt_change_1m_pct        < 0         (1分钟在跌)
大盘加速：   mkt_price_acceleration   <= 0        (下跌未减速)
个券方向：   weighted_slope_2m        < -0.00005  (个券跟跌)
个券动量：   change_1m_pct            < -0.1%     (明显跌幅)
个券加速：   price_acceleration       <= 0        (下跌加速)

操作建议：绝对不买入，持仓立即止损
风险等级：极高
```

#### 状态3：个券独强（谨慎参与）

```
大盘方向：   mkt_weighted_slope_2m    在 -0.00002 ~ +0.00002 (大盘无方向)
大盘动量：   mkt_change_1m_pct        在 -0.02 ~ +0.02      (大盘几乎不动)
大盘加速：   mkt_price_acceleration   任意
个券方向：   weighted_slope_2m        > +0.00005  (个券独立走强)
个券动量：   change_1m_pct            > +0.1%     (有动量)
个券加速：   price_acceleration       >= 0        (上攻中)

操作建议：可参与但仓位减半，止损收紧
风险等级：中（无大盘保护）
```

#### 状态4：个券独弱（回避）

```
大盘方向：   mkt_weighted_slope_2m    在 -0.00002 ~ +0.00002
大盘动量：   mkt_change_1m_pct        在 -0.02 ~ +0.02
个券方向：   weighted_slope_2m        < -0.00005
个券动量：   change_1m_pct            < -0.1%
个券加速：   price_acceleration       <= 0

操作建议：回避，个券有独立利空
风险等级：高
```

#### 状态5：逆势上攻（高风险）

```
大盘方向：   mkt_weighted_slope_2m    < -0.00002  (大盘在跌)
大盘动量：   mkt_change_1m_pct        < -0.02     (大盘跌幅明显)
个券方向：   weighted_slope_2m        > +0.00003  (个券逆势走强)
个券动量：   change_1m_pct            > 0         (个券在涨)
个券加速：   price_acceleration       >= 0        (上攻未减速)

操作建议：超短线可博弈，极小仓位，快速止盈
风险等级：极高（大盘拖累随时可能来）
持仓时间：建议<30秒
```

#### 状态6：补跌风险（危险）

```
大盘方向：   mkt_weighted_slope_2m    < -0.00002  (大盘在跌)
大盘动量：   mkt_change_1m_pct        < -0.02     (大盘跌幅明显)
个券方向：   weighted_slope_2m        在 -0.00003 ~ +0.00003 (个券暂时横盘)
个券动量：   change_1m_pct            在 -0.05 ~ +0.05       (个券暂未动)
个券加速：   price_acceleration       任意

操作建议：绝不买入！个券大概率即将补跌
风险等级：极高（沉默前的暴风雨）
```

#### 状态7：滞涨预警（观望）

```
大盘方向：   mkt_weighted_slope_2m    > +0.00002  (大盘在涨)
大盘动量：   mkt_change_1m_pct        > 0         (大盘动量正)
大盘加速：   mkt_price_acceleration   >= 0        (大盘在加速)
个券方向：   weighted_slope_2m        在 -0.00003 ~ +0.00003 (个券不跟)
个券动量：   change_1m_pct            在 -0.05 ~ +0.05       (个券无动量)

操作建议：不买入该券，大盘涨它不涨说明有压力
风险等级：中高（个券可能有隐性利空）
```

#### 状态8：双向震荡（等待）

```
大盘方向：   mkt_weighted_slope_2m    在 -0.00002 ~ +0.00002
大盘动量：   mkt_change_1m_pct        在 -0.02 ~ +0.02
个券方向：   weighted_slope_2m        在 -0.00003 ~ +0.00003
个券动量：   change_1m_pct            在 -0.05 ~ +0.05

操作建议：无信号，等待方向明确
风险等级：不适用
```

### A.3 状态转换与交易决策

```
双向震荡 ──→ 共振上攻 ──→ 买入
     │              │
     │              ↓ (加速度转负)
     │         共振减速 ──→ 止盈
     │
     └──→ 共振下杀 ──→ 回避/止损

个券独强 ──→ 共振上攻(大盘跟上) ──→ 加仓
     │
     └──→ 滞涨预警(个券走弱) ──→ 离场
```

### B.2 需要新增的入场条件字段

以下字段存在于 `ext_indicators` JSON 列中，需要在筛选前解析到 df 列：

| 新增字段 | 说明 | 来源 | 入场条件用途 |
|----------|------|------|-------------|
| `weighted_slope_2m` | 个券加权斜率 | ext_indicators | 方向确认(>0.00005) |
| `change_1m_pct` | 个券1分钟变化率 | ext_indicators | 动量确认(>0.1) |
| `price_acceleration` | 个券加速度 | ext_indicators | 加速确认(>=0) |
| `mkt_weighted_slope_2m` | 大盘加权斜率 | ext_indicators | 大盘方向(>0.00002) |
| `mkt_change_1m_pct` | 大盘1分钟变化率 | ext_indicators | 大盘动量(>0) |
| `mkt_price_acceleration` | 大盘加速度 | ext_indicators | 大盘加速(>=0) |

### B.3 实施方式

在 `run_quant_screen_on_tick()` 调用 `apply_scheme_conditions()` 之前，将 `ext_indicators` JSON 展开为独立列：

```python
# 展开 ext_indicators JSON 为独立列
if 'ext_indicators' in df_now.columns:
    ext_df = df_now['ext_indicators'].apply(
        lambda x: json.loads(x) if isinstance(x, str) and x else {}
    )
    ext_expanded = pd.json_normalize(ext_df)
    for col in ext_expanded.columns:
        df_now[col] = ext_expanded[col].values
```

这样 `apply_scheme_conditions()` 中的 `field not in df.columns` 检查就能自动识别这些新字段，**无需修改筛选引擎代码**。
