## 三、四道关卡（为什么不能直接访问 111.201.225.177:8080）

外网访问需数据包穿过完整链路：
```
外网设备 → 111.201.225.177(路由器WAN) → [路由器NAT转发] → 192.168.0.102:8080
```

| 关卡 | 状态 |
|------|------|
| ① Web服务监听0.0.0.0 | ✅ 已就绪 |
| ② Windows防火墙放行 | ✅ 已就绪 |
| ③ 路由器端口映射 | ❌ 未配置（传统方案需要） |
| ④ 运营商是否封端口 | ❓ 联通家宽常封80/8080 |

内网穿透方案的价值：**绕过③④两道关卡**，无需碰路由器、不怕运营商封端口。

## 五、方案A：ngrok 实施记录

### 5.1 安装历程与踩坑

| 步骤 | 结果 | 问题 |
|------|------|------|
| winget安装ngrok 3.3.1 | ✅装上 | ❌版本太旧(要求≥3.20) |
| ngrok update升级到3.39.10 | ✅升级 | ❌自更新导致exe损坏 |
| 官方zip重新下载 | ✅下载 | ❌**被Defender删除(误报Trojan:Win32/Kepavll!rfn)** |
| 提权加Defender排除项 | ⏳ | UAC交互受限，需手动 |

### 5.2 关键坑：Windows Defender 误报

ngrok被Defender识别为木马 `Trojan:Win32/Kepavll!rfn` 并自动删除。这是**已知误报**（内网穿透工具行为特征触发），ngrok是2000万+开发者使用的合法工具。

**解决**：需管理员权限关闭Defender实时监控 + 加白名单排除项。

### 5.3 手动修复命令（管理员PowerShell执行）

```powershell
Set-MpPreference -DisableRealtimeMonitoring $true
Add-MpPreference -ExclusionPath "C:\ngrok"
irm https://bin.equinox.io/c/bNyj1mQVY4c/ngrok-v3-stable-windows-amd64.zip -OutFile C:\ngrok\ngrok.zip
Expand-Archive C:\ngrok\ngrok.zip C:\ngrok -Force
C:\ngrok\ngrok.exe config add-authtoken <你的token>
```

### 5.4 日常使用

**开启外网访问**：
```powershell
C:\ngrok\ngrok.exe http 8080
```
→ 显示 `https://xxxx.ngrok-free.app`，任意设备浏览器打开

**关闭**：命令窗口按 `Ctrl+C` 或关窗口 → 立即恢复纯局域网状态

**查看当前网址**：浏览器开 `http://127.0.0.1:4040`（ngrok本地控制台）

## 六、方案B：Cloudflare Tunnel（备选/推荐长期用）

### 6.1 优势
- 大厂Cloudflare出品，**不被杀软误报**
- 快速模式**无需域名、无需注册**

### 6.2 安装
```powershell
winget install --id Cloudflare.cloudflared
```

### 6.3 快速模式使用（免域名免注册）
```powershell
cloudflared tunnel --url http://localhost:8080
```
→ 得到临时网址 `https://xxx-xxx-xxx.trycloudflare.com`

### 6.4 固定网址模式（需域名，长期用）
```powershell
cloudflared tunnel login                          # 浏览器授权
cloudflared tunnel create gs2026                  # 创建隧道
cloudflared tunnel route dns gs2026 gs.你的域名.com # 绑定域名
cloudflared tunnel run gs2026                     # 运行
```

### 6.5 关闭
命令窗口 `Ctrl+C` 即停，恢复原样。

## 十一、实施结果记录（v1.1 补充）

### 最终环境
| 项目 | 值 |
|------|-----|
| ngrok版本 | 3.39.10（官方zip，非winget旧版） |
| 安装路径 | `C:\ngrok\ngrok.exe` |
| authtoken | 已配置（`%LOCALAPPDATA%\ngrok\ngrok.yml`） |
| Defender实时监控 | 已关闭（DisableRealtimeMonitoring=true） |
| Defender白名单 | `C:\ngrok` 已加入排除项 |
| 隧道目标 | http://localhost:8080 |
| 验证结果 | HTTP 200，页面"登录-GS2026"，外网可访问 |

### 完整踩坑记录（重要经验）

| # | 问题 | 现象 | 解决 |
|---|------|------|------|
| 1 | winget版本过旧 | ngrok 3.3.1，账号要求≥3.20 报ERR_NGROK_121 | `ngrok update`升级 |
| 2 | 自更新损坏exe | 更新后exe"无法执行" | 官方zip重新下载 |
| 3 | **Defender误报** | ngrok被识别`Trojan:Win32/Kepavll!rfn`并删除 | 关实时监控+加白名单 |
| 4 | 自动提权掉线 | `Start-Process -Verb RunAs -Wait`阻塞等UAC导致会话超时 | 改用户手动管理员执行 |
| 5 | UAC框不可见 | 远程会话触发的UAC用户看不到 | 用户本地手动运行PowerShell |

**核心教训**：
- ngrok被主流杀软误报是普遍现象（内网穿透行为特征），需加白名单
- **敏感安全操作（关杀软/改防护）必须用户本地管理员权限手动执行**，远程自动提权会因UAC交互失败并导致会话掉线
- winget装的ngrok版本旧且自更新易损坏，**推荐直接用官方zip**

### 一次性修复命令（管理员PowerShell，备查）
```powershell
Set-MpPreference -DisableRealtimeMonitoring $true; Add-MpPreference -ExclusionPath "C:\ngrok"; irm https://bin.equinox.io/c/bNyj1mQVY4c/ngrok-v3-stable-windows-amd64.zip -OutFile C:\ngrok\ngrok.zip; Expand-Archive C:\ngrok\ngrok.zip C:\ngrok -Force; C:\ngrok\ngrok.exe config add-authtoken <token>; echo OK_DONE
```
