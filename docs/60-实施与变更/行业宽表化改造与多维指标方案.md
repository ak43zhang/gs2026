## 一、需求理解（请确认）

### 1.1 两个独立需求

| 需求 | 维度 | 说明 |
|------|------|------|
| **需求A：上攻排行** | 行业上攻强度 | 现有功能，用 final_score 验证行业强度（保持不变）|
| **需求B：涨幅验证** | 行业涨幅 | 新需求，用 avg_change_pct 验证行业涨幅作用 |

**你的核心思路**：
- 不改之前的区间测算设计（两个需求并存）
- **改造上攻排行存储的表**：存所有行业（而非只top5）
- 这样一张"时间×行业"宽表可以：
  - 基于行业做上攻排行筛选（需求A）
  - 基于涨跌幅或其他指标计算其他需求（需求B）
  - 维度 = 行业，或 时间×行业
  - 在此基础上完善区间最强行业指标

### 1.2 关键约束

```
【约束1】保证兼容之前的上攻排行（不能破坏现有功能）
【约束2】表存所有行业（支持多维度筛选）
【约束3】在宽表基础上增加区间最强/最弱行业指标
```

## 三、改造方案

### 3.1 设计原则

```
1. 兼容优先：上攻排行（final_score + top5）逻辑完全不动
2. 宽表已在：monitor_hy_top30 已存全部行业，无需大改存储
3. 增量扩展：在宽表上增加"涨幅维度"的排名字段和排行统计
4. 统一数据源：区间测算、涨幅排行都查这张宽表
```

### 3.2 方案总览

```
┌─────────────────────────────────────────────────────────────────┐
│  monitor_hy_top30_{date}（宽表，已存全部行业，改造：加涨幅排名）  │
│  现有字段（不动）:                                                │
│    code, name, count, total, avg_change_pct, final_score,        │
│    industry_cumulative_main_net, rank(按final_score), time...    │
│  【新增字段】:                                                    │
│    rank_by_change_pct    按涨幅排名（1=涨幅最高）                 │
│    change_pct_percentile 涨幅分位（可选）                        │
└─────────────────────────────────────────────────────────────────┘
                    │                          │
        ┌───────────┘                          └───────────┐
        ▼                                                   ▼
┌──────────────────────┐                    ┌──────────────────────┐
│ 需求A：上攻排行       │                    │ 需求B：涨幅排行/区间   │
│ （现有，不动）        │                    │ （新增）              │
│ - final_score top5    │                    │ - avg_change_pct排序  │
│ - 进top5次数统计      │                    │ - 最强(rank1)/最弱(末) │
│ - update_rank_redis   │                    │ - 区间当选次数聚合    │
└──────────────────────┘                    └──────────────────────┘
```

### 3.3 存储层改造（monitor_stock.py）

#### 改造1：宽表增加涨幅排名字段

```python
# calculate_industry_topn 第8步后，增加按涨幅的排名
# 现有：all_industries 已按 final_score 排序并有 rank

def _add_change_pct_rank(result_df: pd.DataFrame) -> pd.DataFrame:
    """在行业宽表中增加按涨幅的排名（不影响现有final_score排名）"""
    if result_df is None or result_df.empty:
        return result_df
    if 'avg_change_pct' in result_df.columns:
        # rank_by_change_pct: 1=涨幅最高，N=涨幅最低（最弱）
        result_df['rank_by_change_pct'] = (
            result_df['avg_change_pct']
            .rank(ascending=False, method='first')
            .astype(int)
        )
    return result_df

# INDUSTRY_RESULT_COLUMNS 增加 'rank_by_change_pct'
```

**效果**：宽表每tick的90个行业，既有 `rank`（上攻）又有 `rank_by_change_pct`（涨幅）。
- `rank_by_change_pct == 1` → 该tick涨幅最强板块
- `rank_by_change_pct == N`（最大）→ 该tick涨幅最弱板块

#### 改造2：上攻排行保持不动（兼容）

```python
# industry_attack 完全不动
hy_all_df = calculate_industry_topn(...)  # 现在多了rank_by_change_pct列
save_dataframe_async(hy_all_df, hy_top30_table)  # 存全部行业（含新列）
hy_top5_df = hy_all_df.head(5)              # 上攻top5不变
update_rank_redis(hy_top5_df, 'industry')   # 上攻排行不变
```

**关键**：`hy_all_df.head(5)` 仍是按 final_score 的top5，上攻排行**语义完全不变**。

#### 改造3（可选）：涨幅排行也存Redis rank

```python
# 若需要"涨幅进top5次数"排行（类似上攻排行），增加：
hy_top5_by_change = hy_all_df.nlargest(5, 'avg_change_pct')
update_rank_redis(hy_top5_by_change, 'industry_change', date_str=date_str)
# 新增 rank_name='industry_change'，与'industry'并存
```

### 3.4 区间测算数据源（基于宽表）

**无需APQD表扩展**（v2.0方案里的APQD扩展可以取消），直接查宽表：

```python
# services/range_analysis_service.py

def query_range_industry(date, start_time, end_time):
    """区间最强/最弱行业聚合（基于宽表 monitor_hy_top30）"""
    table = f"monitor_hy_top30_{date}"
    
    # 查区间内每个tick的涨幅最强(rank_by_change_pct=1)和最弱(=max)
    # 方式1：SQL直接取每tick的最强最弱
    sql_strongest = f"""
        SELECT time, code, name, avg_change_pct
        FROM {table}
        WHERE time >= %s AND time <= %s AND rank_by_change_pct = 1
        ORDER BY time
    """
    # 最弱：每tick rank_by_change_pct 最大的
    sql_weakest = f"""
        SELECT t1.time, t1.code, t1.name, t1.avg_change_pct
        FROM {table} t1
        INNER JOIN (
            SELECT time, MAX(rank_by_change_pct) as max_rank
            FROM {table}
            WHERE time >= %s AND time <= %s
            GROUP BY time
        ) t2 ON t1.time = t2.time AND t1.rank_by_change_pct = t2.max_rank
        WHERE t1.time >= %s AND t1.time <= %s
    """
    
    # 聚合：统计每个行业当选最强/最弱的次数
    from collections import Counter
    strongest_rows = execute_query(sql_strongest, (start_time, end_time))
    weakest_rows = execute_query(sql_weakest, (start_time, end_time, start_time, end_time))
    
    strongest_counter = Counter()
    weakest_counter = Counter()
    # ... 统计次数、均涨幅、名称（同v2.0聚合逻辑）
    
    return {
        'strongest_rank': [...],  # 区间最强（当选rank1次数最多）
        'weakest_rank': [...],    # 区间最弱
        'total_ticks': ...,
    }
```

**优势**：
- 宽表已有全部行业+涨幅+排名，一次查询搞定
- 上攻排行、涨幅排行、区间测算共用一张表
- 未来加"主力净额区间排行"等，同样查这张表

## 四、与之前v2.0区间测算方案的关系

### 4.1 调整说明

| v2.0方案（区间测算文档）| 本方案（宽表化）| 结论 |
|------------------------|----------------|------|
| 最强/最弱存APQD表 | 改为查宽表rank_by_change_pct | **本方案更优**（一表多用）|
| calc_strongest_weakest独立函数 | 改为宽表加rank_by_change_pct列 | 简化 |
| APQD扩展8字段 | **取消**，不动APQD | 减少改动 |

### 4.2 两方案协同

```
本方案（宽表化）= 数据基础层
  → 宽表存全部行业 + 涨幅排名
  
v2.0区间测算 = 应用层
  → 前端页面、区间聚合API（数据源改为查宽表）
  → 需求B（涨幅验证）落地
```

**建议**：先做本方案（宽表化改造），再做区间测算前端（v2.0应用层，数据源改为宽表）。
