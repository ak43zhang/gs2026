# 债券攻排行自动刷新问题 - 最终分析与修复方案

## 一、问题确认

用户确认：
1. 股票攻排行确实没有刷新或刷新的就是指定时间 → **自动刷新已正确停止**
2. 债券攻排行确实刷新了且刷新的不是时间轴点击的时间 → **自动刷新未停止**

## 二、代码对比分析

### 股票攻排行加载流程
1. 滑块事件 → `loadDataAtTime(ts)`
2. `loadDataAtTime` 设置 `_isLive = false` + `stopAutoRefresh()`
3. 调用 `loadStockRankingAtTime(timeStr)` → 使用固定时间
4. 自动刷新定时器检查 `if (_isLive && ...)` → **不执行**（因为 `_isLive=false`）

### 债券攻排行加载流程
1. 滑块事件 → `loadDataAtTime(ts)`
2. `loadDataAtTime` 同样设置 `_isLive = false` + `stopAutoRefresh()`
3. 调用 `loadRankingAtTime('bond', timeStr)` → 使用固定时间
4. 自动刷新定时器检查 `if (_isLive && ...)` → **理论上也不执行**

**矛盾**：理论上债券和股票应该行为一致，但用户观察到债券会刷新。

## 三、可能的原因

### 原因1：_isLive 被意外重置
某些操作可能将 `_isLive` 重置为 `true`，导致自动刷新恢复。

### 原因2：债券有独立的刷新机制
债券可能有其他代码路径触发了刷新。

### 原因3：页面可见性变化
用户离开页面后回来，`handleVisibilityChange` 可能错误地恢复了刷新。

## 四、解决方案

### 方案1：强化自动刷新检查（推荐）

修改自动刷新定时器，增加对 `_userFixedTime` 的检查：

```javascript
_autoRefreshTimer = setInterval(() => {
    // 实时模式且页面可见时才刷新
    if (_isLive && !document.hidden) {
        // 【修复】如果用户固定了时间，不自动刷新
        if (_userFixedTime) {
            console.log('[AutoRefresh] 用户固定了时间，跳过自动刷新');
            return;
        }
        
        // 【v3.0】二次检查：防止刷新中途进入非交易时段
        if (!shouldStartAutoRefresh()) {
            console.log('[AutoRefresh] 进入非交易时段，停止自动刷新');
            stopAutoRefresh();
            updateTradingStatusHint();
            return;
        }
        loadTimestamps();
        loadAllData();
    }
}, REFRESH_INTERVAL);
```

### 方案2：统一使用 loadDataAtTime

确保所有时间轴操作都通过 `loadDataAtTime`，而不是直接调用 `loadRankingAtTime`。

### 方案3：后端也检查时间参数

后端 `get_bond_ranking` 在没有 `time_str` 时，检查是否有其他方式确定时间（如session）。

## 五、推荐方案

**方案1（前端强化检查）**

理由：
1. 不依赖 `_isLive` 状态，直接检查 `_userFixedTime`
2. 即使 `_isLive` 被意外重置，也不会错误刷新
3. 改动小，风险低

## 六、验证方法

修复后：
1. 用户选择时间 09:45:24
2. 等待30秒（自动刷新周期）
3. 观察日志：应看到 "[AutoRefresh] 用户固定了时间，跳过自动刷新"
4. 债券数据保持不变
