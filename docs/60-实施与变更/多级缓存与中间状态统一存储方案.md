## 一、整体设计目标

### 1.1 核心问题背景

#### 问题1：中间结果缺失导致计算错误（根本原因）

**现象**：服务重启后，累积型指标计算结果错误

| 指标 | 正常值 | 重启后值 | 错误原因 |
|------|--------|----------|----------|
| `mkt_vwap_bias` | -0.3% | 0% | VWAP累积值 `_mkt_trend_vwap_sum_pv/v` 未恢复，从零开始 |
| `mkt_shape` | "低开高走" | "横盘" | 形态历史 `_mkt_shape_history` 未恢复，数据不足 |
| `weighted_slope_2m` | 1.5 | 0.0 | 斜率缓存 `_slope_buf_short` 未恢复，无法计算 |
| `peak_vol_bias` | -2.1% | 0% | 放量状态 `_peak_vol_state` 未恢复，max_amount丢失 |

**根本原因**：
```python
# 当前代码只存储结果字段，不存储中间累积状态
ext_indicators = {
    "mkt_vw_bias": -0.3,  # 只存结果
    # 不存 _mkt_trend_vwap_sum_pv/v（中间累积值）
    # 不存 _mkt_shape_history（历史列表）
}

# 数学上不可逆：从结果无法反推中间累积值
# 例：VWAP = sum_pv / sum_v，知道VWAP无法反推 sum_pv 和 sum_v
```

**影响**：
- 服务重启后需要10-15分钟才能恢复稳定
- 重启期间交易信号可能错误
- 回填数据与实时数据不一致

#### 问题2：中间字段膨胀与重复存储

| 字段 | 存储方式 | 问题 |
|------|----------|------|
| `_mkt_shape_history` | 每个tick的ext_indicators都存全量 | 4800次重复存储，150KB→720MB/天 |
| `_slope_buf_short/long` | 仅内存，无持久化 | 重启丢失，斜率计算错误 |

#### 问题3：实时与回填不一致

- 实时：从内存计算
- 回填：从MySQL恢复（仅部分指标）
- 结果：同一时间点，实时和回填计算的指标值不同

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **解决计算错误** | 持久化中间累积状态，重启后恢复，确保计算正确 |
| **解决膨胀问题** | 累积型历史独立存储，ext_indicators固定大小 |
| **实时回填一致** | 同一套存储架构，同一套恢复逻辑 |

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **分离存储** | 累积型历史独立存储，ext_indicators只存固定大小结果 |
| **通用架构** | 单表支持多指标，通过`indicator`字段区分 |
| **四级缓存** | L1内存→L2Redis→L3MySQL→L4重新计算 |
| **实时回填一致** | 同一套恢复逻辑，同一套存储架构 |
| **零侵入** | 不影响现有计算逻辑，失败自动降级 |

## 二、架构概览

### 2.1 存储分离架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        存储分离架构                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌─────────────────────┐        ┌─────────────────────────────┐ │
│  │  ext_indicators     │        │  IntermediateCache          │ │
│  │  （每tick存储）      │        │  （累积型历史独立存储）       │ │
│  ├─────────────────────┤        ├─────────────────────────────┤ │
│  │  结果字段：          │        │  支持指标：                  │ │
│  │  - mkt_vw_bias      │        │  - mkt_shape（大盘形态）      │ │
│  │  - mkt_shp          │        │  - bond_slope_{code}         │ │
│  │  - ...              │        │  - mkt_vwap                  │ │
│  │                     │        │  - ...（可扩展）              │ │
│  │  固定大小中间状态：  │        │                             │ │
│  │  - _m_vwap_pv       │        │  四级缓存：                  │ │
│  │  - _m_high/low      │        │  - L1: 内存                  │ │
│  │  （无大list）        │        │  - L2: Redis（12h过期）       │ │
│  │                     │        │  - L3: MySQL单表              │ │
│  │                     │        │  - L4: 重新计算               │ │
│  └─────────────────────┘        └─────────────────────────────┘ │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 四级缓存流程

```
实时运行（每tick）：
  ├─ 1. 计算当前指标值
  ├─ 2. IntermediateCache.append(indicator, date, time, value)
  │   ├─ L1: 内存追加（<1μs）
  │   ├─ L2: 标记待写入Redis（异步批量）
  │   └─ L3: 标记待写入MySQL（异步批量）
  ├─ 3. 从L1内存获取历史，计算结果
  └─ 4. 存储ext_indicators（固定大小，无大list）

重启恢复：
  ├─ 1. IntermediateCache.get_range(indicator, date, start, end)
  │   ├─ L1: 内存？无（刚重启）
  │   ├─ L2: Redis HGETALL → 内存筛选区间
  │   ├─ L3: MySQL SELECT ... WHERE time_sec BETWEEN
  │   └─ L4: 返回空list（从0开始）
  └─ 2. 恢复正常运行

回填（data_recovery.py）：
  ├─ 1. 从L2/L3加载历史到L1内存
  ├─ 2. 计算当前tick
  ├─ 3. IntermediateCache.append（更新L1/L2/L3）
  └─ 4. 存储结果到monitor_zq_sssj
```

```sql
-- 表名: day_history_intermediate
-- 用途: 通用中间过程缓存，单表支持所有指标

CREATE TABLE day_history_intermediate (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    indicator VARCHAR(64) NOT NULL COMMENT '指标名，如mkt_shape、bond_slope_123456',
    trading_date VARCHAR(8) NOT NULL COMMENT '交易日YYYYMMDD',
    time_sec INT NOT NULL COMMENT '时间（秒，从0点开始）',
    value_json JSON NOT NULL COMMENT '该时间点的值',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    -- 核心索引：支持区间查询
    UNIQUE KEY uk_indicator_date_time (indicator, trading_date, time_sec),
    KEY idx_indicator_date (indicator, trading_date),
    KEY idx_date (trading_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='中间过程缓存表（通用）';

-- 查询示例：获取mkt_shape全天历史形成list
SELECT time_sec, value_json 
FROM day_history_intermediate 
WHERE indicator = 'mkt_shape' 
  AND trading_date = '20260726'
  AND time_sec BETWEEN 32400 AND 54000
ORDER BY time_sec;
```

## 四、核心模块：IntermediateCache

### 4.1 类设计

```python
class IntermediateCache:
    """
    通用中间过程缓存模块
    
    职责：
    1. 累积型历史的四级缓存管理
    2. 区间查询形成list
    3. 实时/回填统一接口
    """
    
    # L1: 内存缓存 {(indicator, date): [(time_sec, value), ...]}
    _memory_cache = {}
    
    @staticmethod
    def append(indicator: str, date: str, time_sec: int, value: dict):
        """
        追加单点（每tick调用）
        
        流程：
        1. L1内存追加
        2. 标记异步写入L2/L3
        """
        key = (indicator, date)
        
        # L1: 内存追加
        if key not in IntermediateCache._memory_cache:
            IntermediateCache._memory_cache[key] = []
        IntermediateCache._memory_cache[key].append((time_sec, value))
        
        # 异步批量写入L2/L3（每30秒或每100点）
        IntermediateCache._async_persist(indicator, date, time_sec, value)
    
    @staticmethod
    def get_range(indicator: str, date: str, 
                  start_time: int = None, 
                  end_time: int = None) -> list:
        """
        获取区间数据形成list（四级缓存）
        
        返回: [{'t': time_sec, **value}, ...] 按时间排序
        """
        key = (indicator, date)
        start_time = start_time or 32400  # 默认09:30:00
        end_time = end_time or 54000       # 默认15:00:00
        
        # L1: 内存查询
        if key in IntermediateCache._memory_cache:
            result = [{'t': t, **v} for t, v in IntermediateCache._memory_cache[key]
                     if start_time <= t <= end_time]
            if result:
                return sorted(result, key=lambda x: x['t'])
        
        # L2: Redis查询
        result = IntermediateCache._get_from_redis(indicator, date, start_time, end_time)
        if result:
            IntermediateCache._fill_memory(key, result)
            return result
        
        # L3: MySQL查询
        result = IntermediateCache._get_from_mysql(indicator, date, start_time, end_time)
        if result:
            IntermediateCache._fill_memory(key, result)
            IntermediateCache._fill_redis(indicator, date, result)
            return result
        
        # L4: 无数据
        return []
```

### 4.2 四级缓存实现

```python
    @staticmethod
    def _get_from_redis(indicator: str, date: str,
                        start_time: int, end_time: int) -> Optional[list]:
        """L2: Redis HGETALL获取全天，内存筛选区间"""
        try:
            r = redis_util._get_redis_client()
            key = f"day_hist:{indicator}:{date}"
            data = r.hgetall(key)
            if not data:
                return None
            
            result = []
            for t_bytes, v_bytes in data.items():
                t = int(t_bytes.decode())
                if start_time <= t <= end_time:
                    result.append({'t': t, **json.loads(v_bytes.decode())})
            
            return sorted(result, key=lambda x: x['t'])
        except Exception as e:
            logger.warning(f"[L2] Redis失败: {e}")
            return None
    
    @staticmethod
    def _get_from_mysql(indicator: str, date: str,
                        start_time: int, end_time: int) -> Optional[list]:
        """L3: MySQL区间查询"""
        try:
            sql = """
                SELECT time_sec, value_json 
                FROM day_history_intermediate
                WHERE indicator = %(indicator)s
                  AND trading_date = %(date)s
                  AND time_sec BETWEEN %(start)s AND %(end)s
                ORDER BY time_sec
            """
            df = pd.read_sql(sql, engine, params={
                'indicator': indicator, 'date': date,
                'start': start_time, 'end': end_time
            })
            
            if df.empty:
                return None
            
            return [{'t': row['time_sec'], **json.loads(row['value_json'])}
                    for _, row in df.iterrows()]
        except Exception as e:
            logger.warning(f"[L3] MySQL失败: {e}")
            return None
```

```python
def compute_mkt_trend_indicators_v7(df_now, time_full, current_date):
    """v7.0: 使用IntermediateCache"""
    global _mkt_shape_date, _mkt_shape_history
    
    current_seconds = _time_to_seconds(time_full)
    mkt_vs_open_pct = round(float(df_now['change_pct'].mean()), 4)
    
    # 日期切换 → 从四级缓存恢复
    if _mkt_shape_date != current_date:

            date=current_date,
            start_time=32400,
            end_time=current_seconds

        indicator='mkt_shape',
        date=current_date,
        time_sec=current_seconds,
        value={'p': mkt_vs_open_pct}
    )
    
    # 更新内存list
    _mkt_shape_history.append({'t': current_seconds, 'p': mkt_vs_open_pct})

    # 返回结果（ext_indicators不再包含大list）

    }
```

## 八、个券中间字段存储优化（v8.0）

### 8.1 当前个券中间字段现状

| 字段 | 结构 | maxlen | 恢复机制 | 问题 |
|------|------|--------|----------|------|
| `_slope_buf_short` | `{code: deque(maxlen=60)}` | ✅ 60 | ❌ 无恢复 | 重启后斜率计算错误 |
| `_slope_buf_long` | `{code: deque(maxlen=300)}` | ✅ 300 | ❌ 无恢复 | 重启后斜率计算错误 |
| `_peak_vol_state` | `{code: {'max_amount': float}}` | - | ✅ 有恢复 | 从MySQL重新计算 |
| `_high_state` | `{code: {'max_cpct': float}}` | - | ✅ 有恢复 | 从MySQL重新计算 |

**当前恢复逻辑**：
```python

    # _slope_buf_short/long 保持为空，重启后斜率计算错误
```

### 8.2 问题分析

**问题1：斜率缓存无恢复**
```python
# 重启后
_slope_buf_short = {}  # 空！

# 计算斜率时
if code not in _slope_buf_short:
    _slope_buf_short[code] = deque(maxlen=60)  # 新建空deque

# 结果：需要60个tick才能填满，前60个tick斜率计算错误
```

**问题2：400只债券 × 2个deque = 800个对象**
- 内存占用：400 × (60+300) × 8B = 1.15MB（可接受）
- 但Redis/MySQL存储：400个key × 2 = 800个key（过多）

### 8.3 优化方案：个券中间字段分级存储

#### 方案A：全量存储（不推荐）

```python
# 为每只债券的每个中间字段都存Redis/MySQL
# 400只 × 2个字段 = 800个Redis key
```

### 8.4 个券中间字段优化设计（v8.0）

#### 存储架构

```
┌─────────────────────────────────────────────────────────────┐
│                    个券中间字段存储架构                      │
├─────────────────────────────────────────────────────────────┤
│  L1内存: _slope_buf_short/long = {code: deque(maxlen=60/300)}│
│  L2Redis: day_hist:bond_slopes:{date} → Hash{code_type: list}│
│  L3MySQL: day_history_intermediate (indicator='bond_slopes') │
│  L4重新计算: 从原始数据重新累积                              │
└─────────────────────────────────────────────────────────────┘
```

#### 代码实现

```python
class IntermediateCache:
    """增强版：支持个券批量存储"""
    
    @staticmethod
    def append_bond_slopes(date: str, 
                          slopes_data: Dict[str, Dict[str, list]]):
        """
        批量追加个券斜率（每tick调用一次，存储所有债券）
        
        Args:
            slopes_data: {
                "123456": {"short": [1.0, 1.1, ...], "long": [0.9, ...]},
                "123457": {"short": [2.0, ...], "long": [1.9, ...]},
                ...
            }
        """
        # L1: 已在内存中更新
        
        # L2: 批量写入Redis（1个key）
        r = redis_util._get_redis_client()
        key = f"day_hist:bond_slopes:{date}"
        for code, data in slopes_data.items():
            r.hset(key, f"{code}_short", json.dumps(data['short']))
            r.hset(key, f"{code}_long", json.dumps(data['long']))
        r.expire(key, 43200)  # 12小时
        
        # L3: 批量写入MySQL（1行，indicator='bond_slopes'）
        sql = """
            INSERT INTO day_history_intermediate 
            (indicator, trading_date, time_sec, value_json)
            VALUES (%s, %s, %s, %s)
            ON DUPLICATE KEY UPDATE value_json = VALUES(value_json)
        """
        # value_json = json.dumps(slopes_data)
    
    @staticmethod
    def get_bond_slopes(date: str, code: str) -> Optional[Dict]:
        """
        获取单只债券的斜率缓存（四级缓存）
        
        Returns:
            {"short": [1.0, 1.1, ...], "long": [0.9, 1.0, ...]} 或 None
        """
        # L1: 内存命中
        if code in _slope_buf_short:
            return {
                "short": list(_slope_buf_short[code]),
                "long": list(_slope_buf_long[code])
            }
        
        # L2: Redis查询（从批量key中获取）
        r = redis_util._get_redis_client()
        key = f"day_hist:bond_slopes:{date}"
        short_data = r.hget(key, f"{code}_short")
        long_data = r.hget(key, f"{code}_long")
        if short_data and long_data:
            return {
                "short": json.loads(short_data),
                "long": json.loads(long_data)
            }
        
        # L3: MySQL查询（从批量数据中筛选）
        sql = """
            SELECT value_json FROM day_history_intermediate
            WHERE indicator = 'bond_slopes' AND trading_date = %s
            ORDER BY time_sec DESC LIMIT 1
        """
        # 解析value_json，提取code对应的数据
        
        # L4: 无数据
        return None
```
