## 一、用户场景确认

### 场景1：简单定时任务
```
用户操作: 前端设置 "A进程每周五执行"
系统行为: 
  - 配置保存到MySQL
  - Windows服务读取配置
  - 每周五自动执行（无论app.py是否启动）
```

### 场景2：调度链（依赖执行）
```
用户操作: 前端设置 "A→B→C调度链"
系统行为:
  - A执行成功 → 自动触发B
  - B执行成功 → 自动触发C
  - 任意步骤失败 → 链停止/按条件继续
```

### 场景3：混合调度
```
用户操作: 
  - 设置独立任务X（每天执行）
  - 设置调度链Y（A→B→C，每周执行）
系统行为:
  - Windows服务统一管理所有任务
  - 按各自触发器独立调度
  - 链式任务按依赖顺序执行
```

## 二、当前调度链实现分析

### 当前已实现功能

```python
# scheduler_service.py 已实现:

1. 任务类型支持:
   - 'function'      - 执行Python函数
   - 'script'        - 执行Shell脚本
   - 'scheduler'     - 执行调度器任务
   - 'redis_cache'   - Redis缓存任务
   - 'dashboard_task'- Dashboard任务
   - 'python_script' - 执行Python脚本文件
   - 'chain'         - 调度链（已支持）

2. 触发器类型:
   - 'cron'          - 定时触发（如每周五）
   - 'interval'      - 间隔触发
   - 'date'          - 一次性触发
   - 'once'          - 立即执行一次

3. 调度链实现（已有）:
   - _execute_chain_job()      - 执行链
   - _trigger_next_jobs()      - 触发子任务
   - chain_condition支持:      - 触发条件
     - 'always'                - 总是触发
     - 'on_success'            - 成功时触发（默认）
     - 'on_failure'            - 失败时触发
   - next_job_ids              - 下一个任务ID列表
```

### 当前调度链数据模型

```sql
-- scheduler_jobs 表
CREATE TABLE scheduler_jobs (
    job_id VARCHAR(64) PRIMARY KEY,
    job_name VARCHAR(128),
    job_type VARCHAR(32),        -- 'chain' 表示调度链
    job_config JSON,           -- 链配置: {"steps": [{"job_id": "a"}, ...]}
    trigger_type VARCHAR(32),    -- 'cron'
    trigger_config JSON,       -- {"hour": 9, "minute": 30, "day_of_week": "fri"}
    next_job_ids JSON,         -- 链式: ["b", "c"]
    chain_condition VARCHAR(32), -- 'on_success'
    status VARCHAR(32),        -- 'enabled'
    ...
);
```

### 当前调度链执行流程

```
1. 触发器触发调度链任务
2. _execute_chain_job() 依次执行 steps
3. 每个 step 执行完成
4. _trigger_next_jobs() 检查 chain_condition
5. 条件满足则调度 next_job_ids
6. 子任务延迟2秒执行（避免阻塞）
```

#### 改造2：调度链增强

```python
# scheduler_service.py - 链式执行增强

class SchedulerService:
    def _execute_chain_job(self, config: Dict, execution_id: str) -> str:
        """执行调度链（增强版）"""
        steps = config.get('steps', [])
        parallel = config.get('parallel', False)
        continue_on_error = config.get('continue_on_error', False)
        
        results = []
        
        if parallel:
            # 并行执行所有步骤
            results = self._execute_chain_parallel(steps, execution_id)
        else:
            # 串行执行（默认）
            for step in steps:
                job_id = step.get('job_id')
                timeout = step.get('timeout', 3600)
                
                # 执行步骤
                result = self._execute_chain_step(job_id, execution_id, timeout)
                results.append(result)
                
                # 检查是否继续
                if result['status'] == 'failed' and not continue_on_error:
                    logger.error(f"Chain step failed: {job_id}, stopping chain")
                    break
        
        return f"Chain executed: {len(results)} steps"
    
    def _execute_chain_step(self, job_id: str, parent_execution_id: str, timeout: int) -> Dict:
        """执行链中的一个步骤"""
        # 创建子执行记录
        execution_id = self._create_execution(job_id, 'chain', parent_execution_id)
        
        try:
            # 同步执行（等待完成）
            self._execute_job_by_id(job_id, execution_id)
            
            # 查询执行结果
            result = self._get_execution_result(execution_id)
            return result
            
        except Exception as e:
            logger.error(f"Chain step execution failed: {job_id}, {e}")
            return {'status': 'failed', 'error': str(e)}
```

#### 改造4：MySQL触发机制

```python
# 方案A: 轮询检测（简单可靠）
class SchedulerService:
    def __init__(self):
        self._last_check_time = 0
        
    def start(self):
        # 添加轮询任务，每30秒检查一次新任务
        self.scheduler.add_job(
            func=self._check_new_jobs,
            trigger='interval',
            seconds=30,
            id='__check_new_jobs',
            replace_existing=True
        )
    
    def _check_new_jobs(self):
        """检查是否有新任务或配置变更"""
        sql = "SELECT job_id, updated_at FROM scheduler_jobs WHERE status = 'enabled'"
        jobs = execute_query(sql)
        
        for job in jobs:
            job_id = job['job_id']
            updated_at = job['updated_at']
            
            # 检查是否需要重新加载
            if self._needs_reload(job_id, updated_at):
                self._reload_job(job_id)

# 方案B: 数据库触发器（高级）
-- MySQL触发器，任务变更时通知服务
DELIMITER //
CREATE TRIGGER trg_job_changed
AFTER UPDATE ON scheduler_jobs
FOR EACH ROW
BEGIN
    IF OLD.status != NEW.status OR OLD.trigger_config != NEW.trigger_config THEN
        -- 写入变更通知表
        INSERT INTO scheduler_notifications (job_id, action, created_at)
        VALUES (NEW.job_id, 'reload', NOW());
    END IF;
END//
DELIMITER ;
```

## 五、关键问题解答

### Q1: app.py不启动能调度吗？
**能**。Windows服务独立进程，不依赖app.py。

### Q2: 前端设置后立即生效吗？
**30秒内生效**。服务轮询检测新任务，或可通过触发器立即通知。

### Q3: 调度链A→B→C如何确保顺序？
**串行执行**。`_execute_chain_step()` 同步等待A完成，成功后再调度B。

### Q4: A失败时B还会执行吗？
**默认不会**。`continue_on_error: false` 时链停止；设为true则继续。

### Q5: 如何查看链式执行状态？
**执行记录表**。每个步骤都有独立execution_id，通过parent_execution_id关联。
