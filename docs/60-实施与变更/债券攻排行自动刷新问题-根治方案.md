# 债券攻排行自动刷新问题 - 根治方案

## 一、问题本质

**依赖关系错误**：当前实现依赖 `_isLive` 全局变量来控制自动刷新，但 `_isLive` 可能被意外重置。

**正确的设计**：每个加载函数应该自己决定是否使用固定时间，而不是依赖外部状态。

## 二、根治方案

### 方案：每个加载函数自检 `_userFixedTime`

**核心思想**：无论 `_isLive` 是什么状态，只要 `_userFixedTime` 存在，就使用固定时间加载。

**修改 `loadBondRanking`**：

```javascript
async function loadBondRanking(timeStr) {
    showRefreshIndicator('bond');
    try {
        // 【根治】如果用户固定了时间，强制使用固定时间（无视传入的timeStr）
        const effectiveTime = _userFixedTime || timeStr;
        
        const r = await (await fetch(buildRankUrl('bond', effectiveTime))).json();
        if (r.success) {
            _rankRawData['bond-ranking'] = r.data;
            _bpBondRank = r.data || [];
            // 如果开启了前N筛选，先更新前N行业
            if (_bondTopNFilterEnabled) {
                await updateTopNSectors();
            }
            rerenderBondRanking();
            runBuyPoints();
        }
    } catch(e){}
}
```

**同样修改 `loadStockRanking`**：

```javascript
async function loadStockRanking(timeStr) {
    showRefreshIndicator('stock');
    try {
        // 【根治】如果用户固定了时间，强制使用固定时间
        const effectiveTime = _userFixedTime || timeStr;
        
        const url = buildRankUrl('stock', effectiveTime);
        console.log('[loadStockRanking] 请求URL:', url);
        const response = await fetch(url);
        const r = await response.json();
        // ... 其余逻辑不变
    }
}
```

**同样修改 `loadIndustryRanking`**：

```javascript

    try {

        const r = await (await fetch(buildRankUrl('industry', effectiveTime))).json();
        // ... 其余逻辑不变
    }
}
```

## 三、为什么这是根治方案

### 防御性编程

即使：
- `_isLive` 被意外重置为 `true`
- `loadAllData` 被错误地调用
- 自动刷新定时器没有正确停止

**每个加载函数都会自检 `_userFixedTime`**，确保使用固定时间。

### 单一职责

每个函数负责自己的时间管理，不依赖外部状态。

### 易于维护

不需要跟踪 `_isLive` 的变化，代码更清晰。

## 四、验证方法

修复后：
1. 用户选择时间 09:45:24
2. 等待自动刷新（即使 `_isLive` 被重置）
3. 观察债券数据：应该保持 09:45:24，不会变成最新时间

## 五、实施范围

修改三个函数：
1. `loadBondRanking`（债券攻排行）
2. `loadStockRanking`（股票攻排行）
3. `loadIndustryRanking`（行业攻排行）

确保所有攻排行都使用相同的机制。
