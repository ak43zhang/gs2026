# 股票×债券上攻交集功能 - 设计方案

## 一、需求理解

在股票上攻排行和债券上攻排行都各自筛选后，点击一个「交集」按钮，**只展示两个榜单都有的标的**——通过"债券代码"关联：
- 股票数据的 `bond_code`（关联债券代码）
- 债券数据的 `code`（债券代码本身）
- **关联规则**：`股票.bond_code === 债券.code`

举例：
- 股票榜筛出5条（各自有 bond_code）
- 债券榜筛出3条（各自有 code）
- 点击交集 → 只保留 `bond_code` 与债券榜 `code` 能对上的标的

---

## 二、关键设计问题（需确认交集后如何展示）

交集后**展示什么、展示在哪**，有三种方案：

### 方案A：双榜联动过滤（推荐）
点击「交集」后：
- **股票榜**：只显示 `bond_code ∈ 债券榜code集合` 的股票
- **债券榜**：只显示 `code ∈ 股票榜bond_code集合` 的债券
- 两个榜单同时收缩到交集部分，**各自保留原有列和排序**
- 再次点击「交集」关闭，恢复各自独立筛选

✅ 优点：直观，两边对照看；复用现有渲染；实现干净
✅ 符合你说的"只展示两个都有的数据"

### 方案B：单独合并结果区
新开一个区域，展示交集的"股票+债券"配对表（一行含股票信息+债券信息）
❌ 需新建表格渲染逻辑，列设计复杂，成本高

### 方案C：只过滤其中一个榜
只收缩股票榜（或只债券榜）
❌ 信息不完整，不如A

**我推荐方案A**（双榜联动），下面按A设计。

---

## 三、方案A 详细设计

### 3.1 数据留存
当前 `rerenderStockRanking`/`rerenderBondRanking` 的 `filtered` 是局部变量，渲染后丢弃。
需**留存最终展示数据**，供交集计算：
```javascript
let _stockDisplayed = [];   // 股票最终展示数据
let _bondDisplayed = [];    // 债券最终展示数据
let _intersectionMode = false;  // 交集开关（持久化）
```

在 `rerenderStockRanking` 末尾：`_stockDisplayed = filtered;`
在 `rerenderBondRanking` 末尾：`_bondDisplayed = filtered;`

### 3.2 交集计算
```javascript
function applyIntersection(stockData, bondData) {
    // 债券榜的 code 集合
    const bondCodes = new Set(bondData.map(b => String(b.code)));
    // 股票榜的 bond_code 集合
    const stockBondCodes = new Set(
        stockData.filter(s => s.bond_code && s.bond_code !== '-')
                 .map(s => String(s.bond_code))
    );
    // 股票：保留 bond_code 在债券榜的
    const stockResult = stockData.filter(s =>
        s.bond_code && s.bond_code !== '-' && bondCodes.has(String(s.bond_code))
    );
    // 债券：保留 code 在股票榜 bond_code 的
    const bondResult = bondData.filter(b =>
        stockBondCodes.has(String(b.code))
    );
    return { stockResult, bondResult };
}
```

### 3.3 管道集成（关键）
交集是**在各自过滤管道之后**的额外一层。改造 `rerenderStockRanking`/`rerenderBondRanking`：

```javascript
function rerenderStockRanking() {
    const rawData = _rankRawData['stock-ranking'];
    if (!rawData) { renderRanking('stock-ranking', []); updateStockFilterBadge(); return; }
    let filtered = runPipeline(STOCK_PIPELINE, rawData);
    _stockDisplayed = filtered;   // 留存(交集前)
    if (_intersectionMode) {
        // 需要债券的最终数据做交集
        filtered = intersectStockWithBond(filtered);
    }
    renderRanking('stock-ranking', filtered);
    updateStockFilterBadge();
}
```

**难点：互相依赖**。股票交集需要债券最终数据，债券交集需要股票最终数据。
解决：分两步——先各自算出"过滤后（交集前）"结果存起来，再统一做交集渲染。

新增协调函数：
```javascript
function refreshBothWithIntersection() {
    // 1. 各自跑管道，得到交集前结果
    const stockFiltered = _rankRawData['stock-ranking']
        ? runPipeline(STOCK_PIPELINE, _rankRawData['stock-ranking']) : [];
    const bondFiltered = _rankRawData['bond-ranking']
        ? runPipeline(BOND_PIPELINE, _rankRawData['bond-ranking']) : [];
    _stockDisplayed = stockFiltered;
    _bondDisplayed = bondFiltered;

    if (_intersectionMode) {
        const { stockResult, bondResult } = applyIntersection(stockFiltered, bondFiltered);
        renderRanking('stock-ranking', stockResult);
        renderRanking('bond-ranking', bondResult);
    } else {
        renderRanking('stock-ranking', stockFiltered);
        renderRanking('bond-ranking', bondFiltered);
    }
    updateStockFilterBadge();
    updateBondFilterBadge();
}
```

**改造原则**：
- `rerenderStockRanking()` / `rerenderBondRanking()` 内部，若 `_intersectionMode` 开启，则调用 `refreshBothWithIntersection()`（保证联动）
- 关闭时各自独立渲染（现状逻辑）

### 3.4 交集按钮 UI
在股票榜和债券榜之间（或某个显眼位置）加一个按钮：
```
[🔗 交集]   ← 点击切换，激活时高亮
```
- 位置建议：股票/债券榜的公共头部区域，或各自过滤按钮旁
- 激活态：按钮变色 + 显示"交集中(N条)"
- 点击切换 `_intersectionMode`，调用 `refreshBothWithIntersection()`

### 3.5 持久化
`_intersectionMode` 纳入现有 `saveFilterState`/`restoreFilterState`：
- 存入 `attack_filter_state_v1` 的 `intersection_mode` 字段
- 隔天/刷新保留，符合你之前的持久化要求

## 四、边界情况处理

| 情况 | 处理 |
|------|------|
| 股票 bond_code 为空/'-' | 不参与交集（视为无关联）|
| 债券榜为空 | 交集结果为空（两边都清空）|
| 一只债券对应多只股票 | 都保留（多对一正常）|
| 自动刷新时 | 交集模式下每次刷新都重新联动计算 |
| 交集模式 + 各自过滤条件变化 | 先各自过滤，再交集（管道顺序正确）|
