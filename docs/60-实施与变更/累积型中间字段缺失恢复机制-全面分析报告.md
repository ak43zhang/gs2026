# 累积型中间字段缺失恢复机制 - 全面分析报告

**文档版本**: v1.0  
**生成时间**: 2026-07-26 03:51  
**分析对象**: monitor_bond.py 所有累积型变量  
**状态**: 🔴 发现系统性问题 - 需修复

---

## 一、核心结论

**这是一个系统性设计缺陷**：
- 程序大量使用**累积型中间变量**（求和、缓存、历史序列）
- 但**绝大多数没有宕机恢复机制**
- 只存储**结果字段**到 MySQL/Redis，不存储**中间状态**
- 服务重启后，所有累积变量从0/空开始，导致**数据失真**

**影响范围**：🔴 **高** - 涉及12+个关键累积变量

## 三、存储现状分析

### 3.1 存储了什么？

```
DataFrame (df_now) 每tick存储到 MySQL/Redis：
├── bond_code, name, price, change_pct ... (原始字段)
├── slope_short, slope_long, peak_vol_bias, high_distance (计算结果)
├── ext_indicators (JSON字符串，含mkt_vwap_bias等结果)
└── 其他指标...
```

### 3.2 没有存储什么？

| 未存储内容 | 后果 |
|------------|------|
| `_mkt_trend_vwap_sum_pv/v` | VWAP从0开始重新累积 |
| `_mkt_trend_day_high/low` | 日内高低点从当前值开始 |
| `_mkt_trend_slope_10m_cache` | 10分钟斜率历史丢失 |
| `_mkt_shape_history` | 形态历史丢失，无法识别形态 |
| `_slope_buf_short/long` | 个券斜率缓存清空 |
| `_ext_price_cache` | 扩展指标缓存清空 |

### 3.3 为什么无法从结果反推？

以 VWAP 为例：
```python
# 存储的是：
mkt_vwap_bias = current_pct - (sum_pv / sum_v)  # 结果值

# 需要恢复的是：
sum_pv = Σ(pct_i × amount_i)  # 累积值
sum_v = Σ(amount_i)            # 累积值

# 问题：从 bias 无法反推 sum_pv 和 sum_v
# 因为：bias = current_pct - sum_pv/sum_v
#       一个方程，两个未知数
```

## 四、影响评估

### 4.1 按严重程度分类

| 严重程度 | 变量 | 重启后影响 | 恢复时间 |
|----------|------|------------|----------|
| 🔴 **高** | VWAP相关 | VWAP/Bias完全错误，需重新累积全天 | 全天 |
| 🔴 **高** | `_mkt_shape_history` | 形态识别失效，无法判断单边/低开高走等 | 全天 |
| 🟡 **中** | 斜率缓存(10m/300点) | 斜率计算短期失真，约10-15分钟 | 10-15分钟 |
| 🟡 **中** | 日内高低点 | 高低点从重启时刻开始，非真正日内极值 | 逐渐收敛 |
| 🟢 **低** | 单点状态(prev_slope) | 仅影响1个tick | 1个tick |

### 4.2 业务场景影响

| 场景 | 影响描述 |
|------|----------|
| 盘中重启(9:30-14:30) | 🔴 **严重** - VWAP/形态/斜率全部失真，信号质量下降 |
| 早盘重启(9:30-10:00) | 🔴 **极严重** - 几乎全天数据都错 |
| 尾盘重启(14:30-15:00) | 🟡 **中等** - 影响最后30分钟 |
| 每日首次启动 | 🟢 **无影响** - 本来就从0开始 |
| 回测 | 🟢 **无影响** - 回测用历史数据重新计算 |

## 五、修复方案（推荐）

### 5.1 方案概述

**核心思路**：每30秒将关键累积状态写入 Redis，重启时读取恢复

**存储策略**：
- Redis Hash：`mkt_state:{date}` 存储大盘级状态
- Redis Hash：`bond_state:{date}:{code}` 存储个券级状态（可选）
- 过期时间：当日收盘后自动过期

### 5.2 具体修复步骤

#### 步骤1：新增状态存储函数

```python
def _save_mkt_state(current_date: str, current_time: str):
    """保存大盘趋势状态到Redis"""
    try:
        r = redis_util._get_redis_client()
        key = f"mkt_state:{current_date}"
        state = {
            'vwap_sum_pv': _mkt_trend_vwap_sum_pv,
            'vwap_sum_v': _mkt_trend_vwap_sum_v,
            'day_high': _mkt_trend_day_high,
            'day_low': _mkt_trend_day_low,
            'last_new_low_time': _mkt_trend_last_new_low_time or 0,
            'shape_history': json.dumps(_mkt_shape_history[-100:]),  # 最近100点
            'slope_10m_cache': json.dumps(list(_mkt_trend_slope_10m_cache)[-100:]),
            'saved_at': current_time,
        }
        r.hset(key, mapping=state)
        r.expire(key, 86400)  # 24小时过期
    except Exception as e:
        logger.warning(f"[mkt_state] 保存失败: {e}")


def _recover_mkt_state(current_date: str):
    """从Redis恢复大盘趋势状态"""
    global _mkt_trend_vwap_sum_pv, _mkt_trend_vwap_sum_v
    global _mkt_trend_day_high, _mkt_trend_day_low
    global _mkt_trend_last_new_low_time, _mkt_shape_history
    global _mkt_trend_slope_10m_cache
    
    try:
        r = redis_util._get_redis_client()
        key = f"mkt_state:{current_date}"
        state = r.hgetall(key)
        
        if not state:
            logger.info("[mkt_state] 无历史状态，从0开始")
            return False
        
        _mkt_trend_vwap_sum_pv = float(state.get(b'vwap_sum_pv', b'0'))
        _mkt_trend_vwap_sum_v = float(state.get(b'vwap_sum_v', b'0'))
        _mkt_trend_day_high = float(state.get(b'day_high', b'-999'))
        _mkt_trend_day_low = float(state.get(b'day_low', b'999'))
        _mkt_trend_last_new_low_time = int(state.get(b'last_new_low_time', b'0')) or None
        
        # 恢复形态历史
        shape_hist = state.get(b'shape_history', b'[]')
        _mkt_shape_history = json.loads(shape_hist)
        
        # 恢复斜率缓存
        slope_cache = state.get(b'slope_10m_cache', b'[]')
        cache_list = json.loads(slope_cache)
        _mkt_trend_slope_10m_cache.clear()
        for item in cache_list:
            _mkt_trend_slope_10m_cache.append(tuple(item))
        
        logger.info(f"[mkt_state] 恢复成功: VWAP_SUM=({_mkt_trend_vwap_sum_pv:.2f}, {_mkt_trend_vwap_sum_v:.2f}), "
                   f"High={_mkt_trend_day_high:.2f}, Low={_mkt_trend_day_low:.2f}")
        return True
    except Exception as e:
        logger.warning(f"[mkt_state] 恢复失败(从0开始): {e}")
        return False
```

#### 步骤2：修改日期切换逻辑

# 在 compute_mkt_trend_indicators 函数中

#### 步骤3：定期保存状态

```python
# 在主循环中，每30秒保存一次
last_save_time = 0

def main_loop():
    global last_save_time
    current_seconds = _time_to_seconds(time_full)
    
    # 每30秒保存一次状态
    if current_seconds - last_save_time >= 30:
        _save_mkt_state(current_date, time_full)
        last_save_time = current_seconds
```

## 九、结论

**问题确认**：这是一个系统性设计缺陷，影响12+个累积变量，其中VWAP和形态历史影响最大。

**根本原因**：
- 设计时只考虑了"结果存储"，未考虑"状态恢复"
- 只有 `_peak_vol_state` 和 `_high_state` 有恢复（因为需要从历史数据反算）
- 其他累积变量被遗漏

**建议**：按优先级P0→P1→P2分阶段实施修复，先解决VWAP和形态历史。
