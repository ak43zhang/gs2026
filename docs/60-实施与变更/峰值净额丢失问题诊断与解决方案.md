# 峰值净额丢失问题 - 完整诊断与解决方案

**问题现象**: monitor_stock.py 运行中，main_net 日志一直显示 L1 命中，但 10:58:51 峰值净额 240.7万，下一个 tick 前端显示为 "-"（应延续 240.7万）  
**诊断时间**: 2026-07-27 12:55  
**状态**: 🔴 待审核（仅诊断，未改代码）

---

## 一、根本原因（已确认）

### 🔴 核心问题：monitor_stock.py 存在双进程并发，抢写同一张表

通过进程树分析，确认**每个监控程序都在双实例运行**：

```
monitor_stock.py:
  PID 48800 (.venv\Scripts\python.exe)   ← 父进程: pycharm64.exe（手动启动）
  PID 32664 (F:\python312\python.exe)    ← 父进程: PID 48800（dashboard进程管理器启动）

monitor_bond / monitor_industry / monitor_dp_signal:
  同样都是 2 个进程！
```

**两个进程的行为**：
1. 各自独立采集数据（同一时刻可能拿到**略有差异**的股票集合）
2. 各自维护**独立的内存缓存**（`_MAIN_NET_TICK_CACHE`，进程隔离）
3. 都写入**同一张表** `monitor_gp_sssj_{date}`（Redis + MySQL，仅按日期命名，无进程隔离）

### 为什么会丢失峰值？

```
时间线（两进程都在跑 10:58:51 → 10:59:06 这个tick）：

进程A (PID 48800):
  10:58:51 算出 股票X 峰值=240.7万 → 写表 ✓
  10:59:06 内存有X的峰值 → L1命中 → 继承240.7万 → 写表 ✓

进程B (PID 32664):
  10:59:06 这个tick，X股票【恰好这次采集缺失】或【B的内存无X】
           → 继承不到X的峰值 → X的峰值=0/NaN → 写表 ❌覆盖

结果：谁最后写，谁说了算。
      B在A之后写 → X的峰值被覆盖为0 → 前端显示 "-"
```

**关键**：用户看到的 "L1命中" 是**进程A自己视角**——它确实命中了。但**进程B**用它的（可能残缺的）状态覆盖了共享表。前端读的是共享表，所以看到峰值丢失。

### 为什么是"下一个tick"就丢？

因为两进程的 tick 是**交错写入**的。A 写对了，紧接着 B 写错了覆盖，就在下一个 tick 观察到。这也解释了"时有时无"的诡异现象。

## 二、问题推导链（完整证据）

| 步骤 | 证据 | 结论 |
|------|------|------|
| 1 | `Get-CimInstance` 查到 monitor_stock 有 **2个PID** | 双进程确认 |
| 2 | 两进程启动时间都是 08:58:49 | 同期启动 |
| 3 | PID 48800 父进程=pycharm64.exe | 手动启动（venv） |
| 4 | PID 32664 父进程=PID 48800 | 间接由dashboard启动（python312） |
| 5 | `process_manager.py`: `self.python_exe = r"F:\python312\python.exe"` | dashboard用系统python启动 |
| 6 | `start_monitor` 只检查 `self.processes['monitor']`（自己的记录） | **不检测外部已启动的进程** |
| 7 | sssj表名 `monitor_gp_sssj_{date_str}` 仅按日期 | **无进程隔离，共享写入** |
| 8 | `_MAIN_NET_TICK_CACHE` 是模块级全局变量 | **进程隔离，两进程内存独立** |
| 9 | `_carry_forward_cumulative_fields` 用 `how='left'` merge | **本tick缺失的股票不会继承峰值** |

**根因**：**双进程 + 共享表 + 无写入协调 = 后写覆盖先写，峰值随机丢失**

## 三、次要风险（同时存在，但非本次主因）

### 风险2：单进程下的"股票瞬时缺失"级联丢失

即使只有1个进程，若某tick数据源**漏采**了某只股票：
```
T0: 股票X 存在, 峰值=240.7万 → put_current存内存(含X)
T1: 股票X 漏采(不在df_now) → carry_forward的how='left'不会补X行
    → 该tick df_now无X → put_current存内存(无X)
T2: 股票X 恢复采集 → 但内存已无X的峰值 → 从0开始 → 峰值永久丢失
```

**验证**（test_peak_loss.py 场景1）：股票不在df_now中，峰值确实丢失。

### 风险3：NaN 传播

若 `cumulative_main_net` 和 `max_cumulative_main_net` 同时为 NaN，`.max(axis=1)` 结果为 NaN → 前端 "-"。
（test_peak_loss.py 场景3 验证）

## 四、完整解决方案

### 🔴 方案1（必须）：消除双进程 —— 治本

**1A. 立即处理**：杀掉重复进程，只保留1个

```powershell
# 保留 dashboard 管理的 python312 进程，杀掉 PyCharm 手动启动的 venv 进程
# （或反之，二选一，统一入口）
```

**1B. 根治：加单例锁**（防止重复启动）

在 `monitor_stock.py`（及其他监控）启动入口加**文件锁/端口锁单例检查**：
```python
import os, sys, tempfile

def _acquire_singleton_lock(name: str):
    """单例锁：已有实例运行则退出"""
    import msvcrt
    lock_file = os.path.join(tempfile.gettempdir(), f"{name}.lock")
    try:
        fp = open(lock_file, 'w')
        msvcrt.locking(fp.fileno(), msvcrt.LK_NBLCK, 1)
        return fp  # 持有锁，进程存活期间不释放
    except OSError:
        logger.error(f"[{name}] 已有实例在运行，本进程退出")
        sys.exit(1)

# main入口调用
_lock = _acquire_singleton_lock("monitor_stock")
```

**1C. dashboard 启动前检测外部进程**

修改 `process_manager.start_monitor`，用 `psutil` 扫描命令行是否已有 monitor_stock 在跑：
```python
def _find_running_by_cmdline(self, keyword: str):
    for p in psutil.process_iter(['pid', 'cmdline']):
        try:
            if p.info['cmdline'] and keyword in ' '.join(p.info['cmdline']):
                return p.info['pid']
        except (psutil.NoSuchProcess, psutil.AccessDenied):
            pass
    return None

def start_monitor(self):
    existing = self._find_running_by_cmdline("monitor_stock.py")
    if existing:
        return {'success': False, 'message': f'监控已在运行(PID {existing})'}
    ...
```

### 🟡 方案2（加固）：单进程下的峰值保护

**2A. carry_forward 改进**：对"本tick缺失但上tick有累计值"的股票，补齐行

当前 `how='left'` 只保留 df_now 的股票。改为：对有非零累计值但本tick缺失的股票，**保留其累计状态**（不算增量，仅延续）。

**2B. 增加峰值单调性保护**：从Redis hash读取历史峰值兜底
```python
# put_current前，用Redis hash的历史峰值兜住（peak只增不减）
df_now['max_cumulative_main_net'] = df_now[['max_cumulative_main_net', redis_hist_peak]].max(axis=1)
```

**2C. NaN 防护**：peak更新后 fillna
```python
df_now['max_cumulative_main_net'] = df_now['max_cumulative_main_net'].fillna(
    df_now['cumulative_main_net']).fillna(0)
```
