## ⚠️ v2.0 关键纠正（用户指出的问题）

### 问题1：排序依据错误

| | v1.0（错误）| v2.0（纠正）|
|--|--|--|
| 最强/最弱依据 | `final_score`（上攻评分）| **`avg_change_pct`（纯涨幅）**|
| 原因 | 误以为top30排名=涨幅排名 | final_score = smooth_ratio×confidence×price_quality，是**上攻强度**，不是涨幅 |

**证据**（`calculate_industry_topn` 第8步）：
```python
# 现有排序：按 final_score（上攻评分）排序，不是涨幅
all_industries = good.sort_values('final_score', ascending=False)
```
- `final_score` 反映"上涨股票占比 × 置信度 × 价格质量"
- 某板块涨幅大但股票少 → smooth_ratio低 → final_score可能不高
- **所以不能用现有排名当最强板块**

### 问题2：最弱板块从未保存

- 现有 `monitor_hy_top30` 虽存全部行业，但**按final_score降序**
- 取尾部≠最弱涨幅（尾部是"上攻最弱"，不是"涨幅最低"）
- **最弱板块（avg_change_pct最小）需要独立计算和存储**

### 问题3：monitor_hy_top30 表实际内容

**已确认**：`hy_all_df` 存的是**所有行业**（不是只top30），表名有误导。
- 每tick存所有行业的 `avg_change_pct` + `final_score` + 排名
- 排名字段 `rank` 是按 final_score，**不是按涨幅**

## 一、需求理解（v2.0 修正版）

### 1.1 核心需求（修正）

在 `monitor_stock.py` 计算大盘数据时，**新增两个tick级指标**：
- **最强板块**：当前tick所有行业中，**平均涨幅（avg_change_pct）最大**的板块
- **最弱板块**：当前tick所有行业中，**平均涨幅（avg_change_pct）最小**的板块

**明确**：
- 排序依据是 **纯涨幅 avg_change_pct**，**不是** final_score（上攻评分）
- 最强和最弱都要**独立计算并存储**
- 与上一tick同板块的涨幅做**环比对比**（Δ涨幅）

### 1.2 后续扩展（预留）

- **区间涨幅最强板块**：时间区间内，某板块当选"最强板块"的**次数**最多
- **区间涨幅最弱板块**：同理，当选"最弱"次数最多
- 其他区间×板块维度指标

### 1.3 应用场景

- 前端滑动时间区间 → 展示该区间最强/最弱板块
- **判断大盘上涨/下跌被哪个板块带动**

### 1.4 功能位置

智能选股页面，「交叉行概选股」「涨停行概选股」之后，新增「**区间测算**」。

## 二、需求复述确认（v2.0）

```
【确认1】最强板块 = 当前tick所有行业按 avg_change_pct（纯涨幅）排序，
         最大的是最强，最小的是最弱。
         ★ 不用 final_score（上攻评分），用纯涨幅。对吗？

【确认2】"与上一tick平均涨幅对比" 的作用：
         记录同板块环比涨幅变化量（Δ = 本tick涨幅 - 上tick涨幅）
         用于展示板块动能（涨幅在加速还是减速）
         ★ 主排序仍用 avg_change_pct 本身，Δ只是附加信息。对吗？

【确认3】区间最强板块 = 区间内每个tick选一个"最强板块"，
         统计哪个板块当选"最强"次数最多 = 区间最强。
         ★ 按"当选次数"，不是"区间累计涨幅"。对吗？

【确认4】板块粒度：用行业（industry）。概念（concept）是否也要？

【确认5】小样本过滤：板块股票太少（如1-2只）涨幅噪声大，
         是否设最少股票数阈值（如≥3只才纳入最强/最弱评选）？
```

## 三、现有基础分析（v2.0 修正）

### 3.1 可复用的基础

| 数据 | 现状 | 可用性 |
|------|------|--------|
| 行业平均涨幅 avg_change_pct | ✅ 每tick已算 | ✅ **可用**（这就是最强/最弱的依据）|
| 所有行业数据存储 | ✅ monitor_hy_top30存全部行业 | ✅ 可用（区间聚合数据源）|
| 行业映射 | ✅ Redis已有 | ✅ 可用 |
| 大盘强度表APQD | ✅ 每tick一行 | ✅ 可用（存最强/最弱）|

### 3.2 需要新增的

| 新增 | 说明 |
|------|------|
| **按涨幅重排** | 现有按final_score，需**额外按avg_change_pct取max/min** |
| **最弱板块计算** | 现有无，需新增 |
| **最强/最弱存储** | APQD表新增字段 |
| **区间聚合逻辑** | 新增API |

### 3.3 关键澄清：为什么不能直接用现有排名

```
现有 monitor_hy_top30 排序（按final_score上攻评分）:
  rank1: 半导体   final_score=0.85  avg_change_pct=2.1%
  rank2: 消费电子 final_score=0.82  avg_change_pct=3.5%  ← 涨幅更高但排第2
  rank3: 军工     final_score=0.78  avg_change_pct=1.8%

按涨幅重排（区间测算需要的）:
  最强: 消费电子 avg_change_pct=3.5%  ← 涨幅最高才是最强
  ...
  最弱: 某板块   avg_change_pct=-2.3% ← 需扫描全部行业找最小
```

**结论**：必须在现有 `industry_stats` 基础上，**按 avg_change_pct 重新取 max/min**。

### 4.2 指标计算层（核心，v2.0修正）

```python
# monitor_stock.py 新增

# 上一tick各行业涨幅缓存（用于环比对比）
_prev_industry_change_pct = {}  # {industry_code: avg_change_pct}

def calc_strongest_weakest_by_change_pct(industry_stats: pd.DataFrame, 
                                          time_full: str,
                                          min_total: int = 3) -> dict:
    """
    从行业统计中按【纯涨幅 avg_change_pct】计算最强/最弱板块（tick级）
    
    ★ 与 final_score（上攻评分）无关，纯粹按平均涨幅排序
    
    Args:
        industry_stats: 含 industry_code, industry_name, avg_change_pct, total
                        （calculate_industry_topn 内部的 groupby 结果，
                         或从 result_df 用 code/name/avg_change_pct/total）
        time_full: 当前时间
        min_total: 最少股票数（过滤小样本噪声，默认3）
    
    Returns:
        dict: {
            'strongest_code', 'strongest_name', 'strongest_change_pct', 'strongest_delta',
            'weakest_code', 'weakest_name', 'weakest_change_pct', 'weakest_delta'
        }
    """
    global _prev_industry_change_pct
    result = {
        'strongest_code': '', 'strongest_name': '', 
        'strongest_change_pct': 0.0, 'strongest_delta': 0.0,
        'weakest_code': '', 'weakest_name': '',
        'weakest_change_pct': 0.0, 'weakest_delta': 0.0
    }
    
    if industry_stats is None or industry_stats.empty:
        return result
    
    try:
        # 字段兼容（industry_stats 可能用 code/name 或 industry_code/industry_name）
        code_col = 'industry_code' if 'industry_code' in industry_stats.columns else 'code'
        name_col = 'industry_name' if 'industry_name' in industry_stats.columns else 'name'
        
        # 小样本过滤：至少min_total只股票才纳入评选
        valid = industry_stats[industry_stats['total'] >= min_total].copy()
        if valid.empty:
            valid = industry_stats.copy()
        
        # ★ 按纯涨幅 avg_change_pct 取 max/min（不是 final_score）
        strongest = valid.loc[valid['avg_change_pct'].idxmax()]
        weakest = valid.loc[valid['avg_change_pct'].idxmin()]
        
        s_code = str(strongest[code_col])
        s_name = str(strongest[name_col])
        s_pct = float(strongest['avg_change_pct'])
        w_code = str(weakest[code_col])
        w_name = str(weakest[name_col])
        w_pct = float(weakest['avg_change_pct'])
        
        # 环比上一tick（同板块涨幅变化量，反映动能）
        s_delta = s_pct - _prev_industry_change_pct.get(s_code, s_pct)
        w_delta = w_pct - _prev_industry_change_pct.get(w_code, w_pct)
        
        result.update({
            'strongest_code': s_code, 'strongest_name': s_name,
            'strongest_change_pct': round(s_pct, 4), 'strongest_delta': round(s_delta, 4),
            'weakest_code': w_code, 'weakest_name': w_name,
            'weakest_change_pct': round(w_pct, 4), 'weakest_delta': round(w_delta, 4)
        })
        
        # 更新缓存（供下一tick环比）
        _prev_industry_change_pct = dict(zip(
            valid[code_col].astype(str), 
            valid['avg_change_pct'].astype(float)
        ))
        
    except Exception as e:
        logger.warning(f"[{time_full}] 计算最强/最弱板块失败: {e}")
    
    return result
```

### 4.5 后端层（区间聚合API）

```python
# services/range_analysis_service.py

def query_range_industry(date, start_time, end_time):
    """区间最强/最弱板块聚合"""
    apqd_table = f"monitor_gp_apqd_{date}"
    
    # 1. 查区间内每个tick的最强/最弱板块
    sql = f"""
        SELECT time, strongest_industry_code, strongest_industry_name, 
               strongest_change_pct, weakest_industry_code, 
               weakest_industry_name, weakest_change_pct
        FROM {apqd_table}
        WHERE time >= %s AND time <= %s
        ORDER BY time
    """
    rows = execute_query(sql, (start_time, end_time))
    total_ticks = len(rows)
    
    # 2. 聚合：统计每个板块当选最强/最弱的次数
    from collections import Counter
    strongest_counter = Counter()
    weakest_counter = Counter()
    strongest_pct_sum = {}  # 累计涨幅（用于展示均值）
    weakest_pct_sum = {}
    name_map = {}
    
    for r in rows:
        sc = r['strongest_industry_code']
        if sc:
            strongest_counter[sc] += 1
            strongest_pct_sum[sc] = strongest_pct_sum.get(sc, 0) + r['strongest_change_pct']
            name_map[sc] = r['strongest_industry_name']
        wc = r['weakest_industry_code']
        if wc:
            weakest_counter[wc] += 1
            weakest_pct_sum[wc] = weakest_pct_sum.get(wc, 0) + r['weakest_change_pct']
            name_map[wc] = r['weakest_industry_name']
    
    # 3. 构建榜单（按次数降序）
    strongest_rank = [
        {
            'code': code, 'name': name_map.get(code, code),
            'count': cnt,  # 当选最强次数
            'ratio': round(cnt / total_ticks, 4) if total_ticks else 0,
            'avg_change_pct': round(strongest_pct_sum[code] / cnt, 4)  # 当选时均涨幅
        }
        for code, cnt in strongest_counter.most_common(10)
    ]
    weakest_rank = [
        {
            'code': code, 'name': name_map.get(code, code),
            'count': cnt,
            'ratio': round(cnt / total_ticks, 4) if total_ticks else 0,
            'avg_change_pct': round(weakest_pct_sum[code] / cnt, 4)
        }
        for code, cnt in weakest_counter.most_common(10)
    ]
    
    return {
        'strongest_rank': strongest_rank,
        'weakest_rank': weakest_rank,
        'total_ticks': total_ticks,
        'time_range': [start_time, end_time]
    }
```

## 六、性能与风险

| 风险 | 解决 |
|------|------|
| tick计算增耗时 | max/min极小开销，可忽略 |
| APQD加字段影响建表 | 沿用建表完整性机制（防consecutive_attacks事故重演）|
| 区间查询慢 | APQD表按time索引，聚合在Python层（tick数有限，一天~4800）|
| 小样本板块噪声 | min_total过滤（≥3只）|
| 执行顺序依赖 | 确认 industry_attack 先于 APQD 存储 |
