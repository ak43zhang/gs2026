## 一、需求

给"行业上攻排行"加入与"债券上攻排行"一致的**列设置功能**：
- **仅纯列显隐 + 排序**（不做"仅前N行业"等过滤）
- 在原有 `次数`、`主力净额` 基础上，新增 `平均涨幅` 列（默认显示）
- 分析并一并加入其他重要行业上攻字段，**默认隐藏**

---

## 二、现状

- 行业排行当前**固定硬编码 2 列**：`次数`(count) + `主力净额`(industry_cumulative_main_net)，外加固定的 `#`、`行业名` 列
- 表头和数据行都是写死的 if/else 分支，无列配置系统
- 债券排行已有完整列设置框架可复刻：`BOND_COLUMNS` + `getBondColConfig`/`saveBondColConfig`（localStorage）+ 列设置面板（勾选+拖拽）+ `getVisibleBondCols` + 数据驱动渲染 `renderBondCell`

## 三、字段调研（实测 monitor_hy_top30_20260731）

行业表全部字段及分析价值评估：

| 字段 | 含义 | 决策 |
|------|------|------|
| `count` | 上攻入选次数 | **显示**（原有） |
| `industry_cumulative_main_net` | 主力累计净额 | **显示**（原有） |
| `avg_change_pct` | 平均涨幅 | **显示**（新增，用户要求） |
| `final_score` | 上攻综合评分 = smooth_ratio×confidence×price_quality^α | **隐藏**（新增，最核心强度指标） |
| `delta_change_pct` | 环比涨幅（较上一tick） | **隐藏**（新增，动量/加速度） |
| `total` | 行业成分/上攻股票基数 | **隐藏**（新增，上攻广度） |
| `smooth_ratio` | 平滑后上攻占比 | **隐藏**（新增，占比维度） |
| `confidence` | 评分置信度 | 不纳入（final_score 分解因子，避免过度技术化） |
| `price_quality` | 价格质量分 | 不纳入（同上） |
| `raw_ratio` | 原始上攻比（未平滑） | 不纳入（smooth_ratio 已够） |
| `avg_price` | 平均绝对价 | 不纳入（无横向可比意义） |
| `rank`/`rank_by_change_pct`/`rank_by_delta_pct` | 各种排名 | 不纳入（渲染顺序/排序结果，不必单列） |
| `rq`/`time`/`code` | 元数据 | 不纳入 |

### 最终列清单（7 列）

**默认显示（3）**：次数、平均涨幅、主力净额
**默认隐藏（4）**：上攻评分(final_score)、环比涨幅(delta_change_pct)、成分股数(total)、上攻占比(smooth_ratio)

维度覆盖：频次(count)、涨幅(avg_change_pct)、资金(主力净额)、强度(final_score)、动量(delta_change_pct)、广度(total)、占比(smooth_ratio)。

## 四、数据链路（关键前提，已验证）

- 后端服务：dashboard2 复用 `dashboard/services/data_service.py` 的 `DataService`（monitor.py 第33/41行导入）
- 主力净额补充方式：在行业分支从同一份 JSON（`all_industries`）逐行取字段
- **新增字段与主力净额同源**（Redis JSON / MySQL 表都含全部字段），可用完全相同方式补充，无需新建查询
- 行业数据补充路径共 3 条，均需补新增字段：
  1. `get_rising_ranking` Redis 分支（前端默认走这条）
  2. `get_ranking_at_time` Redis 分支（时间轴/历史）
  3. `get_ranking_at_time` MySQL fallback

## 五、改造方案

### 后端（data_service.py，3 处）

在每处补充 `industry_cumulative_main_net` 的位置，一并补充：`avg_change_pct`、`final_score`、`delta_change_pct`、`total`、`smooth_ratio`。

- Redis 分支：`net_map`/`latest_net` 旁增加各字段 map，或直接一次性把整行需要的字段带出
- MySQL fallback：`net_map` 旁增加对应字段 map（同一 JOIN 最新时间点结果里取）

### 前端（monitor.html）

1. 新增 `INDUSTRY_COLUMNS` 列定义数组（7 列，default 按上表）
2. 新增 `getIndustryColConfig`/`saveIndustryColConfig`（localStorage key: `industry_ranking_columns_v1`，采用已验证的"读缓存+新列default补齐+无缓存回落"正确写法）
3. 新增 `getVisibleIndustryCols`
4. 新增行业列设置面板（`renderIndustryColSettingsPanel` + `onIndustryColVisibleChange` + 拖拽 `bindIndustryColDragEvents`），复用债券 UI/交互
5. `renderRanking` 行业分支改数据驱动：表头按可见列生成 + 新增 `renderIndustryCell`
6. 排序：`sortRankData` 已通用（按 `st.field`），点表头传字段名即自动生效
7. 触发按钮：行业排行标题区增加"列设置"入口（参照债券）

### 渲染样式约定
- `avg_change_pct`/`delta_change_pct`：>0 红 `+x.xx%`，<0 绿，0 显示 `0.00%`
- `final_score`/`smooth_ratio`：保留 2~3 位小数
- `total`：整数
- `count`：整数居中；`主力净额`：formatMoney + 红绿

## 六、影响范围与风险

- 后端：`data_service.py` 3 处各加数行字段补充，不动查询结构、不动股票/债券逻辑
- 前端：`monitor.html` 新增行业列配置体系并改行业渲染分支，不动股票/债券列配置
- 生效：后端改动需重启；前端刷新即可
- 风险：低。后端"顺带多取已存在字段"；前端复刻已验证债券框架。注意行业排行无代码列（仅 #、行业名），面板/渲染沿用其固定列结构
