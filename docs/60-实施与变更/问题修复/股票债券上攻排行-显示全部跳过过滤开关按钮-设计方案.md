# 股票/债券上攻排行「显示全部（跳过过滤）」开关按钮 — 设计方案

## 一、需求

- 新增一个功能按钮：点击后**直接展示全部数据，跳过所有过滤条件**；取消则**恢复按过滤条件正常筛选**。
- 作用范围：**股票上攻排行 + 债券上攻排行**。
- 按钮位置：股票上攻排行 header 中，**放在交集按钮（🔗）之前**（即第一个）。

## 二、现有架构（已读代码确认）

### 2.1 渲染 / 过滤链路
- 每个榜单原始数据存 `_rankRawData['stock-ranking']` / `_rankRawData['bond-ranking']`。
- 重渲染入口：`rerenderStockRanking()` / `rerenderBondRanking()`。
- 过滤核心：`runPipeline(PIPELINE, rawData)` —— 谓词型串行 + 排名型取交集，返回过滤后数据。
- 最终 `renderRanking(id, filtered)` 渲染。

```
rerenderStockRanking():
    rawData = _rankRawData['stock-ranking']
    if _intersectionMode: refreshBothWithIntersection(); return
    filtered = runPipeline(STOCK_PIPELINE, rawData)   ← 过滤发生在这里
    renderRanking('stock-ranking', filtered)
```

### 2.2 交集模式（参照物）
- `_intersectionMode`（布尔，**不持久化**）+ `toggleIntersection()` + `stock-intersect-btn` 按钮。
- 按钮点亮时背景变黄 `#ffd54f`。
- 开启走 `refreshBothWithIntersection()`（两榜跑管道后取交集），关闭走各自 `rerender`。

### 2.3 过滤状态持久化
- `PERSIST_CONTROLS` + `saveFilterState()`/`restoreFilterState()` 持久化各过滤控件到 localStorage。
- **交集开关 `_intersectionMode` 明确不持久化**（临时视图开关）。

## 三、设计方案

### 3.1 核心思路（最小侵入，复刻交集按钮范式）

新增一个全局开关 `_showAllMode`（布尔），作用于股票+债券两榜：
- **开启**：`rerenderStockRanking`/`rerenderBondRanking` **跳过 `runPipeline`，直接渲染 `_rankRawData` 全量**。
- **关闭**：走现有正常过滤逻辑（零改动）。

在两个 rerender 函数**最前面**插入一行短路判断即可：

```javascript
function rerenderStockRanking() {
    const rawData = _rankRawData['stock-ranking'];
    if (!rawData) { renderRanking('stock-ranking', []); updateStockFilterBadge(); return; }
    // 【新增】显示全部：跳过所有过滤（含交集）
    if (_showAllMode) {
        renderRanking('stock-ranking', rawData);
        updateStockFilterBadge();
        return;
    }
    if (_intersectionMode) { refreshBothWithIntersection(); return; }
    const filtered = runPipeline(STOCK_PIPELINE, rawData);
    renderRanking('stock-ranking', filtered);
    updateStockFilterBadge();
}
```
债券侧 `rerenderBondRanking` 同理（保留其 `window._bondRankRawData = [...rawData]` 那行，仅在其后加 `_showAllMode` 短路）。

### 3.2 开关函数

```javascript
let _showAllMode = false;   // 显示全部开关（不持久化，与交集开关一致）

function toggleShowAll(e) {
    e && e.stopPropagation();
    _showAllMode = !_showAllMode;
    const btn = document.getElementById('stock-showall-btn');
    if (btn) btn.style.background = _showAllMode ? '#81c784' : '';  // 绿色点亮
    // 显示全部与交集互斥：开启显示全部时自动关闭交集
    if (_showAllMode && _intersectionMode) {
        _intersectionMode = false;
        const ibtn = document.getElementById('stock-intersect-btn');
        if (ibtn) ibtn.style.background = '';
    }
    // 两榜都重渲染
    rerenderStockRanking();
    rerenderBondRanking();
}
```

### 3.3 交集按钮联动（互斥）

- 「显示全部」与「交集」逻辑互斥（一个要全量、一个要交集缩小）。
- 方案：**开启显示全部 → 自动关闭交集**（见上）；同理在 `toggleIntersection` 开头加：开启交集时若 `_showAllMode` 为真，自动关闭显示全部。
- 这样两个按钮不会同时点亮，语义清晰。

### 3.4 按钮 HTML（股票 header，放交集按钮前）

在 `stock-intersect-btn` **之前**插入：
```html
<span class="filter-settings-btn" id="stock-showall-btn" onclick="toggleShowAll(event)" title="显示全部数据（跳过所有过滤条件）">📋</span>
```
放置后股票 header 按钮顺序：**📋显示全部 → 🔗交集 → 🔍过滤 → ⚙️列设置 → ●刷新**

> 债券 header 不加按钮（与交集一致，由股票侧统一控制两榜）。图标 📋 可换，你定（备选：👁️/🔓/∀/"全"）。

### 3.5 数据自动刷新时的行为

- 实时/时间轴刷新最终都会调用 `rerenderStockRanking`/`rerenderBondRanking`，短路判断在其内部，**刷新后仍保持"显示全部"状态**，无需额外改动。

## 四、持久化选择（待你确认）

参照交集开关，**默认不持久化** `_showAllMode`（刷新页面后回到正常过滤）。
- 理由：这是"临时查看全部"的操作，与交集同属临时视图开关，不宜跨会话记忆。
- 若你希望**持久化**（刷新后仍显示全部），我再加：控件状态存 localStorage + `restoreFilterState` 恢复。

## 五、改动清单（方案确认后实施）

1. HTML：股票 header 交集按钮前加 `stock-showall-btn`（1 处）。
2. JS 新增：`_showAllMode` 变量 + `toggleShowAll()` 函数。
3. JS 改动：`rerenderStockRanking` / `rerenderBondRanking` 各加 1 段 `_showAllMode` 短路（2 处）。
4. JS 改动：`toggleIntersection` 开头加互斥处理（1 处）。
5. （可选）持久化：若需要，改 `PERSIST_CONTROLS` + restore。

## 六、影响评估

- **零破坏**：不改 `runPipeline`、不改过滤器注册表、不改 `renderRanking`。
- 关闭「显示全部」→ 完全回到现有逻辑，行为不变。
- 与交集互斥，不产生歧义状态。
- 徽章 `updateStockFilterBadge`/`updateBondFilterBadge` 仍调用（显示全部时可正常反映"无过滤"或全部条数，如需特殊提示可加）。

## 七、待确认问题

1. **持久化**：默认不持久化（同交集），可否？还是要刷新后保持？
2. **按钮图标**：📋 可否？还是换其他（👁️/🔓/"全"）？
3. **与交集互斥**：认可"两者互斥、开一个自动关另一个"吗？还是允许并存（不建议，语义冲突）？
4. **徽章提示**：显示全部时，过滤徽章是否需要显示"已跳过过滤"字样提醒？（可选增强）
