## 【v2.0 补漏】非交易时段仍刷新问题诊断与修复

### 问题现象（2026-07-28 09:12 用户报告）
页面刷新后仍持续刷新，后端报错：
```
查询 bond 上攻排行失败: (pymysql.err.ProgrammingError) (1146, 
"Table 'gs.monitor_zq_top30_20260728' doesn't exist")
```
非交易时段（09:12，未到09:25）仍访问今日未生成的数据表。

### 根因：页面存在两套独立刷新机制，v1.0只改了一套

| 定时器 | 位置 | 触发函数 | 刷新内容 | v1.0是否处理 |
|--------|------|----------|----------|-------------|
| `_pollingTimer` | 第2012行 `adjustPollingInterval` | `loadMarketStats`+`loadCombineSignals` | 仅大盘概览+组合信号 | ✅ 已加判断 |
| **`_autoRefreshTimer`** | **第1500行 `startAutoRefresh`** | **`loadTimestamps`+`loadAllData`** | **stock/bond/industry全部排行** | ❌ **遗漏** |

**真凶**：`startAutoRefresh` → `loadAllData`（第4474行）
```javascript
async function loadAllData(timeStr) {
    await loadMarketStats(timeStr);
    await loadStockRanking(timeStr);
    await loadBondRanking(timeStr);      // ← 访问 monitor_zq_top30_今日
    await loadIndustryRanking(timeStr);  // ← 访问 monitor_hy_top30_今日
    await loadCombineSignal(timeStr);
}
```

`startAutoRefresh` 现有启动条件（第1488行）只判断"历史日期"和"页面可见"，**没有"交易时段"判断** → 非交易时段照常每3秒刷新。调用点有5处（初始化、可见性恢复、回放切实时等），只要当日就无条件启动。

**为什么v1.0没拦住**：v1.0在 `adjustPollingInterval`（`_pollingTimer`）加了判断，但 `_autoRefreshTimer` 是另一套独立机制，走 `startAutoRefresh`，没经过判断逻辑。两套定时器并存，只关了次要的一套，主力那套继续跑。

### 修复方案

**方案A（推荐，最小改动）**：在 `startAutoRefresh` 加交易时段判断，复用v1.0已有函数（`isNonTradingHours`/`isAuctionHours`/`loadAuctionMarketOverview`）

```javascript
function startAutoRefresh() {
    if (getSelectedDate()) return;   // 历史日期（原有）
    stopAutoRefresh();
    if (document.hidden) return;     // 页面不可见（原有）
    
    // 【v2.0新增】非交易时段不启动
    if (isNonTradingHours()) {
        console.log('[AutoRefresh] 非交易时段，不启动自动刷新');
        updateTradingStatusHint();
        if (isAuctionHours() && !_auctionDataLoaded) {
            loadAuctionMarketOverview();  // 集合竞价只加载一次大盘概览
        }
        return;
    }
    
    _autoRefreshTimer = setInterval(() => {
        if (_isLive && !document.hidden) {
            if (isNonTradingHours()) {  // 二次检查防中途进入
                stopAutoRefresh();
                updateTradingStatusHint();
                return;
            }
            loadTimestamps();
            loadAllData();
        }
    }, REFRESH_INTERVAL);
}
```

**并且** `startTradingCheckTimer`（第2025行，每10秒）需能恢复 `_autoRefreshTimer`：
```javascript
if (isTradingHours() && !_autoRefreshTimer) {
    console.log('[Monitor] 进入交易时段，恢复自动刷新');
    startAutoRefresh();
}
```

**方案B（重构合并两套定时器）**：改动大、回归风险高，暂不推荐。

### 我的倾向
- **方案A**：最小改动、直击真凶、复用已有逻辑
- 非交易时段完全停止 `loadAllData`（含stock/bond/industry）
- 集合竞价09:25-09:30只加载大盘概览一次（与v1.0决策一致）

# 【v1.0 原始方案存档】

---

## 一、问题分析（v1.0）

### 现状
| 项目 | 现状 |
|------|------|
| 刷新机制 | `adjustPollingInterval(3000)` 每3秒调用 `loadMarketStats()` + `loadCombineSignals()` |
| 数据表 | 按日期命名（如 `monitor_gp_sssj_20260728`），00:00-09:25 时段表不存在或为空 |
| 影响 | 每3秒发起无效请求 → 后端查空表/异常 → 浪费数据库连接 + 网络资源 + 前端CPU |

### 交易时段定义（A股）
- **早盘**: 09:30 - 11:30
- **午盘**: 13:00 - 15:00
- **无效时段**: 00:00 - 09:25（集合竞价前无任何数据）

---

## 二、优化方案（三层防护）

### 方案概述
采用"**前端为主、后端兜底、配置兜底**"的三层防护策略，确保任何一层失效仍有保护。

```
┌─────────────────────────────────────────────────────────┐
│  第1层（前端）: 交易时间判断，非交易时段停止轮询              │
│  第2层（后端）: API返回空数据/特定状态码，不查数据库         │
│  第3层（配置）: 可开关、可调整时段，紧急情况下可关闭优化      │
└─────────────────────────────────────────────────────────┘
```

---

## 三、详细设计

### 3.1 第1层：前端交易时间判断（主防护）

**位置**: `monitor.html` 的 `adjustPollingInterval` 函数

**逻辑**:
```javascript
// 交易时间判断工具函数
function isTradingHours() {
    const now = new Date();
    const hour = now.getHours();
    const minute = now.getMinutes();
    const timeVal = hour * 100 + minute; // 如 925 表示 09:25
    
    // 早盘: 09:30-11:30, 午盘: 13:00-15:00
    const isMorning = (timeVal >= 930 && timeVal <= 1130);
    const isAfternoon = (timeVal >= 1300 && timeVal <= 1500);
    
    return isMorning || isAfternoon;
}

// 修改 adjustPollingInterval
function adjustPollingInterval(interval) {
    if (_pollingTimer) {
        clearInterval(_pollingTimer);
    }
    
    // 非交易时段：延长到60秒检查一次（或完全停止）
    if (!isTradingHours()) {
        console.log('[Monitor] 非交易时段，暂停高频刷新');
        // 方案A：完全停止（推荐）
        return;
        
        // 方案B：60秒检查一次（如需保持"在线"状态）
        // _pollingTimer = setInterval(() => {
        //     if (!document.hidden && isTradingHours()) {
        //         // 进入交易时段，恢复高频
        //         adjustPollingInterval(3000);
        //     }
        // }, 60000);
        // return;
    }
    
    // 交易时段：正常3秒刷新
    _pollingTimer = setInterval(() => {
        if (!document.hidden) {
            loadMarketStats();
            loadCombineSignals();
        }
    }, interval);
}

// 新增：每分钟检查一次是否进入交易时段（从非交易恢复）
setInterval(() => {
    if (!_pollingTimer && isTradingHours()) {
        console.log('[Monitor] 进入交易时段，恢复刷新');
        adjustPollingInterval(3000);
    }
}, 60000); // 每分钟检查
```

**效果**:
- 00:00-09:25: 完全停止轮询，零请求
- 09:25-09:30: 保持停止（集合竞价期间通常也无数据或数据不全）
- 09:30: 自动恢复3秒刷新

### 3.2 第2层：后端API快速返回（兜底防护）

**位置**: `monitor.py` 的数据查询API

**逻辑**:
```python
from datetime import datetime

# 交易时间判断工具（后端复用）
def is_trading_hours() -> bool:
    """判断当前是否为A股交易时段"""
    now = datetime.now()
    hour, minute = now.hour, now.minute
    time_val = hour * 100 + minute
    
    # 早盘 09:30-11:30, 午盘 13:00-15:00
    is_morning = 930 <= time_val <= 1130
    is_afternoon = 1300 <= time_val <= 1500
    return is_morning or is_afternoon

# 在数据查询API入口使用
@monitor_bp.route('/market-stats', methods=['GET'])
def get_market_stats():
    # 非交易时段快速返回空数据，不查数据库
    if not is_trading_hours():
        return jsonify({
            'status': 'non_trading_hours',
            'message': '当前非交易时段',
            'data': None,
            'next_open': get_next_open_time()  # 可选：返回下次开盘时间
        }), 200  # 200避免前端报错，但明确标记状态
    
    # 正常查询...
    data = DataService.get_market_stats(...)
    return jsonify({'status': 'ok', 'data': data})
```

**效果**:
- 即使前端判断失效，后端也不查数据库，直接返回
- 可扩展：返回"下次开盘时间"用于前端显示倒计时

### 3.3 第3层：配置开关（紧急兜底）

**位置**: `config.yaml` 或前端 `localStorage`

```yaml
# config.yaml 新增
monitor:
  enable_trading_hours_optimization: true  # 总开关
  trading_hours:
    morning_start: "09:30"
    morning_end: "11:30"
    afternoon_start: "13:00"
    afternoon_end: "15:00"
  non_trading_poll_interval: 0  # 0=完全停止, 60000=60秒检查一次
```

**前端读取**:
```javascript
// 启动时读取配置
const CONFIG = {
    enableOptimization: localStorage.getItem('monitor_trading_opt') !== 'false',
    morning: { start: 930, end: 1130 },
    afternoon: { start: 1300, end: 1500 }
};

function isTradingHours() {
    if (!CONFIG.enableOptimization) return true;  // 关闭优化时全天交易
    // ...正常判断
}
```

**紧急关闭**: 若优化导致问题，用户可执行 `localStorage.setItem('monitor_trading_opt', 'false')` 立即关闭。

## 六、风险与回退

| 风险 | 应对 |
|------|------|
| 时间判断错误（如夏令时） | 使用本地时间，A股无夏令时；后端兜底 |
| 节假日误判为交易日 | 优化仅判断"时段"不判断"日期"，节假日无数据是预期行为 |
| 需要紧急查看历史数据 | 手动选择历史日期，绕过实时刷新逻辑 |
| 优化导致功能异常 | 配置开关 `enable_trading_hours_optimization: false` 立即回退 |

**回退方法**:
1. 前端：执行 `localStorage.setItem('monitor_trading_opt', 'false')` 刷新即恢复
2. 后端：修改配置重启服务
3. Git 回退：已打 tag，可快速回滚
