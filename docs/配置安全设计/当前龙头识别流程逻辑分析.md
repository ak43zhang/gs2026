# 当前确定龙头的流程逻辑分析

## 当前流程梳理

### 阶段1：单只股票基础分析（Phase 1）

**流程**：
```
stock_anomaly表（ai_status='pending'）
    ↓
analyze_one() 函数
    ↓
build_anomaly_prompt() → AI分析（单只股票）
    ↓
_update_result() → 更新 ai_analysis, ai_status='analyzed'
```

**Prompt**：`build_anomaly_prompt()`
- 输入：单只股票的异动数据
- 输出：异动原因、板块消息、概念消息、龙头股消息等
- **问题**：单只股票分析，**无同主线横向比较**

### 阶段2：主线关联分析（Phase 2）

**流程**：
```
stock_anomaly表（ai_status='analyzed'）
    ↓
analyze_correlation() 函数
    ↓
build_correlation_prompt() → AI分析（关联主线）
    ↓
_update_mainlines() → 更新 stock_anomaly_mainline + stock_anomaly_mainline_rel
```

**Prompt**：`build_correlation_prompt()`
- 输入：
  - 当前股票
  - 当日所有涨停股票（_get_today_all_zt）
  - 已识别主线（_get_existing_mainlines）
- 输出：主线归属（type: existing/new/independent）+ role（龙头/跟风/补涨）
- **关键JSON结构**：
```json
{
  "主线归属": [{
    "type": "existing/new/independent",
    "mainline_name": "主线名称",
    "role": "龙头/跟风/补涨",
    "evidence": "归属证据"
  }]
}
```

### 阶段3：数据存储

**存储位置**：
- `stock_anomaly_mainline`：主线信息（mainline_name, related_stocks, confidence）
- `stock_anomaly_mainline_rel`：股票-主线关系（anomaly_id, mainline_id, **role**, evidence）

## 当前问题诊断

### 问题1：龙头识别不准确

**现状**：
- AI应用与智能体主线今日32只涨停
- `stock_anomaly_mainline_rel.role` 分布：跟风6条、补涨24条
- **龙头：0条**（或极少）

**根本原因**：
1. **Phase 2是增量分析**：每只股票分析时，主线可能还未完全形成
2. **role判定时机问题**：
   - 第1只股票分析时，主线只有1只，无法判定为"龙头"
   - 第2只股票分析时，主线有2只，可能判定为"补涨"
   - 后续股票分析时，主线已成型，但早期股票role已固定
3. **无横向比较**：AI没有将同主线所有股票放在一起比较

**证据**：
```python
# _update_mainlines() 中的逻辑
if existing:  # 主线已存在
    # 更新已有主线，添加当前股票
    related.append(stock_info)  # 当前股票加入
    # 但之前股票的role不会重新计算！
```

### 问题2：无龙头强度评分

**现状**：
- 只有 role（龙头/跟风/补涨）
- **无 0-100 评分**
- 无法区分"真龙头"和"边缘龙头"

### 问题3：数据分散

**现状**：
- 龙头信息分散在 `stock_anomaly_mainline_rel`
- 需要JOIN查询
- 无统一视图

## 当前Prompt中的role定义

```python
# prompts.py 中的JSON模板
"主线归属": [{
    "type": "existing/new/independent",
    "mainline_name": "主线名称",
    "mainline_reason": "驱动逻辑",
    "catalyst": "具体催化事件",
    "confidence_delta": 15,
    "role": "龙头/跟风/补涨",  # ← 这里定义
    "evidence": "归属证据"
}]
```

**AI判定role的依据**（来自Prompt）：
- 当前股票与主线的关联度
- 当前股票在主线中的"预期"地位
- **但不是基于同主线所有股票的横向比较**

## 结论

### 当前流程可行性评估

| 维度 | 评估 | 说明 |
|------|------|------|
| **龙头识别准确性** | ❌ 不可行 | 增量分析导致早期股票role判定错误 |
| **横向比较** | ❌ 缺失 | 无同主线所有股票一起比较的环节 |
| **评分体系** | ❌ 缺失 | 无0-100龙头强度评分 |
| **数据存储** | ⚠️ 可优化 | 分散在多表，可集中到stock_anomaly |

### 根本问题

**当前流程是"增量分析"，而非"批量比较"**：
- 每只股票独立分析，role判定基于"当前已知信息"
- 当主线成型后，早期股票的role不会重新计算
- 导致：主线32只股票，可能没有一只被正确识别为龙头

### 必须改进

1. **新增Phase 3**：主线成型后，批量重新计算role
2. **增加评分**：0-100龙头强度评分
3. **扩展字段**：在stock_anomaly表存储分析结果

## 改进方案（最终版）

### 新增Phase 3：主线龙头重新识别

**触发时机**：
- 主线股票数 >= 3 且 最后一只涨停后5分钟
- 或 每日收盘后（15:00后）

**流程**：
```
stock_anomaly_mainline（stock_count >= 3）
    ↓
identify_mainline_leaders() 新函数
    ↓
同主线所有股票横向比较AI分析
    ↓
更新 stock_anomaly.leader_analysis
     stock_anomaly.leader_score
     stock_anomaly_mainline_rel.role（重新计算）
```

### 数据存储优化

**在 stock_anomaly 表新增字段**：
```sql
ALTER TABLE stock_anomaly
ADD COLUMN leader_analysis JSON NULL,  -- 完整分析结果
ADD COLUMN leader_score INT NULL;      -- 龙头强度评分
```

### AI Prompt改进

**新增**：`build_leader_identification_prompt()`
- 输入：同主线所有涨停股票（按时间排序）
- 输出：每只股票的地位 + 评分 + 依据
- 核心：横向比较，识别真龙头

## 总结

**当前流程不可行**，原因：
1. 增量分析导致role判定时机错误
2. 无同主线横向比较
3. 无龙头强度评分

**必须实施改进方案**（约2小时）：
1. 新增Phase 3批量重新识别
2. 扩展stock_anomaly表字段
3. 新增横向比较Prompt
