## 四、文件命名规范

### 4.1 命名规则

```
{功能模块}-{具体内容}-{版本}.md

示例：
✓ 可转债分时图查询性能优化方案-v1.0.md
✓ MySQL连接中断问题排查-20260423.md
✓ 股票分时图查询性能优化方案-v1.0.md
✗ stock-ticks-query-opt.md          (英文)
✗ 20260423-bug-fix.md               (无意义前缀)
✗ 新文档.md                         (无描述)
```

### 4.2 命名要素

| 要素 | 说明 | 示例 |
|------|------|------|
| 功能模块 | 所属业务/技术领域 | 可转债、MySQL、前端、API |
| 具体内容 | 文档核心主题 | 分时图查询、连接中断、性能优化 |
| 版本/日期 | 版本号或日期 | v1.0、20260423 |

## 五、整合实施步骤

### 阶段1：准备（0.5天）

1. 备份当前docs目录
2. 创建新目录结构
3. 制定详细文件映射表

### 阶段2：迁移（1天）

1. 按新结构创建目录
2. 移动文件到新位置
3. 重命名文件（英文→中文）
4. 更新文件内交叉引用链接

### 阶段3：验证（0.5天）

1. 检查所有文件已迁移
2. 验证链接有效性
3. 更新README和目录说明

### 阶段4：清理（0.5天）

1. 删除旧目录
2. Git提交变更
3. 通知团队成员

1. **Git历史**：移动文件会保留历史，但重命名会显示为删除+新增
