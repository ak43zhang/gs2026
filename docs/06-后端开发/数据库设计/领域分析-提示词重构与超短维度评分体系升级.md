# 领域分析提示词重构 + 超短维度评分体系升级

**日期**: 2026-06-10  
**范围**: 领域事件驱动分析（`deepseek_analysis_event_driven.py`）  
**回退点**: `git reset --hard 34827a7`

---

## 一、改动背景

### 问题1：提示词内联重复
- 60+行内联prompt散落在 `deepseek_analysis_event_driven.py` 中
- 12维度评分说明、JSON结构、字段定义在4个模块（deepseek/volcengine/news_cls/news_combine/ztb/notice）中高度重复
- 修改评分规则需要改4~8处，极易遗漏

### 问题2：评分不准
- AI先填评分再补深度分析，导致评分与维度脱节
- 缺少"分数必须等于各维度加总"的强约束
- JSON结构顺序（先评分后分析）导致因果倒置

### 问题3：综合评分公式不合理
- 原公式：`重要程度×4 + 业务影响`
- 未纳入超短线决策的核心因素（情绪、资金、筹码等）
- 阈值设计不合理：最高235分但100分即利好，导致利好占比过高

---

## 二、解决方案总览

### 2.1 提示词拆分重组（`prompts.py`）

新建 `src/gs2026/analysis/worker/message/prompts.py`，三部分结构：

| 部分 | 内容 | 示例 |
|------|------|------|
| **常量区** | 固定提示词文本 | ROLE_PROMPT, DIMENSION_GUIDE, CHAODUAN_GUIDE |
| **数据结构区** | 固定JSON结构模板 | JSON_STRUCTURE_EVENT, JSON_STRUCTURE_NEWS |
| **构造函数区** | 组装完整prompt | build_event_driven_prompt, build_news_cls_prompt |

### 2.2 超短维度评分体系（CHAODUAN_GUIDE）

新增10维度超短线评分（-5至5分，总分-50至50）：

| # | 维度 | 核心判断 |
|---|------|---------|
| 13 | 供需格局 | 原料断供/产能收缩/缺货涨价 vs 内卷降价 |
| 14 | 事件催化强度 | 顶级重磅催化 vs 致命暴雷 |
| 15 | 筹码持仓情绪 | 筹码锁仓无抛压 vs 筹码溃散恐慌 |
| 16 | 主力资金行为 | 合力抢筹封单坚硬 vs 主力出逃砸盘 |
| 17 | 板块联动效应 | 龙头带动全场 vs 板块崩盘拖累 |
| 18 | 标的替代逻辑 | 竞品暴雷唯一标的 vs 被竞品替代边缘化 |
| 19 | 日内流动性与盘口承接 | 炸板秒回封 vs 无量阴跌 |
| 20 | 题材溢价高度 | 市场绝对主线 vs 题材彻底结束 |
| 21 | 风险对冲属性 | 双赛道对冲 vs 多重利空叠加 |
| 22 | 预期差与消息兑现 | 利空出尽反转 vs 利好出尽兑现 |

### 2.3 综合评分公式

```
综合评分 = 重要程度评分 × 5 + 业务影响维度评分 × 1 + 超短维度评分 × 2
```

| 维度 | 范围 | 权重 | 加权后范围 | 设计 rationale |
|------|------|------|-----------|----------------|
| 重要程度评分 | 0~15 | ×5 | 0~75 | 门槛权重，确保只有足够重要的消息才值得交易 |
| 业务影响维度评分 | -60~60 | ×1 | -60~60 | 基本面影响，权重适中 |
| 超短维度评分 | -50~50 | ×2 | -100~100 | 超短核心决策因子，权重最高 |

**综合评分范围：-85 ~ 235**

### 2.4 衍生字段阈值

| 字段 | 判定逻辑 |
|------|---------|
| **消息大小** | 重大：≥ 120 / 大：60~120 / 中：30~60 / 小：< 30 |
| **消息类型** | < 20 → 利空 / 20~100 → 中性 / ≥ 100 → 利好 |
| **利空利好** | 同消息类型 |

## 四、评分准确性优化

### 4.1 JSON结构重排

**改前**（先评分后分析 → AI先编分再凑理由）：
```json
"重要程度评分": "", "业务影响维度评分": "", "超短维度评分": "", "综合评分": "",
"深度分析": [""]
```

**改后**（先分析后评分 → AI先逐维度打分再算总分）：
```json
"深度分析": [""],
"重要程度评分": "", "业务影响维度评分": "", "超短维度评分": "", "综合评分": "",
"利空利好": "", "消息大小": "", "原因分析": ""
```

### 4.2 评分计算规则（强约束）

```
【评分计算规则 - 严格遵守】
1. 先逐一分析22个维度，写入"深度分析"数组，每条必须带明确的+/-分数
2. 业务影响维度评分 = 深度分析中第1~12维度的分数之和（范围-60至60）
3. 超短维度评分 = 深度分析中第13~22维度的分数之和（范围-50至50）
4. 综合评分 = 重要程度评分×5 + 业务影响维度评分 + 超短维度评分×2
5. 如计算结果与直觉不符，以计算结果为准，不要人为调整
```

### 4.3 后端校验

`_extract_domain_record` 中：
- `composite = importance * 5 + business_impact + chaoduan_score * 2`（后端正算）
- `news_size = _map_news_size(composite)`（覆盖AI返回值）
- `news_type = _map_news_type(composite)`（覆盖AI返回值）
