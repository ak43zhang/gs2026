# GS2026 文档管理规范 v1.0

---

## 一、问题诊断

### 1.1 当前问题

| 问题 | 现状 | 影响 |
|------|------|------|
| **版本分散** | `xxx-v2.md`, `xxx-v2.1.md` 多个文件 | 难以追溯，文件过多 |
| **分类模糊** | `01-需求与设计` 混杂各类文档 | 查找困难 |
| **命名混乱** | 中英文混杂，无统一规范 | 可读性差 |
| **无版本沿革** | 无法追踪文档演进历史 | 维护困难 |

### 1.2 设计目标

1. **单文件多版本**：一个文档包含完整版本历史
2. **清晰分类**：按文档类型明确划分目录
3. **统一命名**：中英文规范，易读易找
4. **可追溯**：版本沿革一目了然

## 三、文档版本管理规范

### 3.1 单文件多版本模式

**禁止**：`xxx-v2.md`, `xxx-v2.1.md` 等多文件
**强制**：单文件内包含完整版本历史

### 3.2 文档模板

每个文档必须包含以下结构：

```markdown
# 文档标题

---

## 版本沿革

| 版本 | 日期 | 更新内容 | 作者 |
|------|------|----------|------|
| v1.0 | 2026-07-20 | 初始版本 | - |
| v1.1 | 2026-07-22 | 补充异常处理逻辑 | - |
| v2.0 | 2026-07-25 | 重构：改为异步架构 | - |

---

## 一、当前版本（v2.0）

### 1.1 概述
...

### 1.2 详细内容
...

---

## 附录：历史版本

### v1.1（2026-07-22）
...

### v1.0（2026-07-20）
...
```

### 3.3 版本号规则

| 版本 | 含义 | 示例 |
|------|------|------|
| v1.0 | 初始版本 | 首次发布 |
| v1.1 | 小修订 | 补充、修正、优化 |
| v1.2 | 小修订 | 同上 |
| v2.0 | 大重构 | 架构变更、重大调整 |
| v2.1 | 小修订 | ... |

**规则**：
- 小数点后：小修订（+0.1）
- 整数位：大重构（+1.0）
- 当前版本放在文档最前面
- 历史版本放在附录

## 六、长期维护规范

### 6.1 新增文档流程

```
1. 确定文档类型 → 选择对应目录
2. 使用文档模板 → 创建新文档
3. 填写版本沿革 → v1.0
4. 标注状态 → 🟡 草稿
5. 审核通过 → 🟢 已审核
6. 实施完成 → 🔵 已实施
```

### 6.2 文档更新流程

```
1. 查看版本沿革 → 确定当前版本
2. 判断变更类型 → 小修订(v1.1) / 大重构(v2.0)
3. 更新版本沿革 → 添加新行
4. 更新当前版本内容 → 替换或补充
5. 旧版本移至附录 → 保留历史
6. 更新状态 → 相应标签
```

### 6.3 禁止事项

| 禁止 | 说明 | 正确做法 |
|------|------|----------|
| ❌ 创建 `xxx-v2.md` | 版本分散 | ✅ 合并到 `xxx.md` |
| ❌ 创建 `xxx-v2.1.md` | 版本过多 | ✅ 使用版本沿革表格 |
| ❌ 英文目录名 | 不易读 | ✅ `10-需求与方案/` |
| ❌ 拼音文件名 | 不专业 | ✅ `自动止盈止损需求.md` |
| ❌ 无版本沿革 | 无法追溯 | ✅ 强制版本表格 |
| ❌ 删除旧版本内容 | 丢失历史 | ✅ 移至附录保留 |
