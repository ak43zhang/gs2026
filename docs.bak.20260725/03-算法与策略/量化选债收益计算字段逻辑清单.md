# 量化选债收益计算 - 全字段计算逻辑清单

## 一、数据库表结构字段分类

表: `quant_screen_hits`

### 1.1 入场信息字段（写入后不变）
| 字段 | 类型 | 说明 | 计算逻辑 |
|------|------|------|---------|
| `trade_date` | VARCHAR(8) | 交易日期 | 当前日期 YYYYMMDD |
| `tick_time` | VARCHAR(6) | 入场时间 | 命中时刻 HHMMSS |
| `scheme_name` | VARCHAR(100) | 方案名称 | 命中的策略方案 |
| `bond_code` | VARCHAR(10) | 债券代码 | 命中债券 |
| `bond_name` | VARCHAR(50) | 债券名称 | 债券名称 |
| `entry_price` | DECIMAL(10,3) | **入场价格** | 命中时刻的当前价格 |
| `entry_change_pct` | DECIMAL(6,2) | 入场时涨跌幅% | 命中时刻的涨跌幅 |
| `entry_amount` | DECIMAL(15,2) | 入场时成交金额 | 命中时刻的成交金额 |
| `stop_loss_pct` | DECIMAL(5,2) | 止损百分比 | 方案参数 |
| `take_profit_pct` | DECIMAL(5,2) | 止盈百分比 | 方案参数 |
| `max_hold_time` | INT | 最大持仓时间(分钟) | 方案参数，NULL=收盘前持续 |

### 1.2 预计算字段（入场时计算，不变）
| 字段 | 计算逻辑 |
|------|---------|
| `stop_loss_price` | `entry_price * (1 - stop_loss_pct/100)` |
| `take_profit_price` | `entry_price * (1 + take_profit_pct/100)` |

## 二、字段更新策略（前端计算方案）

> **方案变更**: 采用前端计算方案，数据库只存储静态数据和最终结算数据

### 2.1 前端计算字段（实时，不入库）

| 字段 | 计算逻辑 | 计算位置 |
|------|---------|---------|
| `current_price` | 从实时行情API获取 | **前端** |
| `current_return_pct` | `(current_price - entry_price) / entry_price * 100` | **前端** |
| `display_status` | 触发判断：holding/profited(stopped/timeout | **前端** |

### 2.2 数据库更新字段（仅状态变更时）

| 字段 | 更新时机 | 说明 |
|------|---------|------|
| `exit_price` | **触发时**写入 | 止盈用`take_profit_price`，止损用`stop_loss_price`，超时用`current_price` |
| `exit_time` | **触发时**写入 | 触发时刻 |
| `final_return_pct` | **触发时**写入 | `(exit_price - entry_price) / entry_price * 100` |
| `signal_status` | **触发时**写入 | profited/stopped/timeout |
| `is_locked` | **触发时**写入 | 1（锁定） |
| `locked_at` | **触发时**写入 | 当前时间戳 |
| `lock_reason` | **触发时**写入 | take_profit/stop_loss/max_time |

### 2.3 不再每tick更新的字段

| 字段 | 原因 |
|------|------|
| ~~`current_price`~~ | 前端实时获取，不存数据库 |
| ~~`current_return_pct`~~ | 前端实时计算，不存数据库 |

### 2.2 信号状态字段 `signal_status`（状态机）

**状态流转**:
```
entry（入场）→ holding（持仓中）→ {profited(止盈) | stopped(止损) | timeout(超时)}
```

| 状态值 | 触发条件 | 计算确认时机 |
|--------|---------|-------------|
| `entry` | 刚写入记录 | 写入时设置 |
| `holding` | 持仓中，未触发任何条件 | **每tick**判断，无触发则保持holding |
| `profited` | `current_price >= take_profit_price` | **首次触发时**确定，不再变更 |
| `stopped` | `current_price <= stop_loss_price` | **首次触发时**确定，不再变更 |
| `timeout` | `当前时间 >= 入场时间 + max_hold_time分钟` | **首次触发时**确定，不再变更 |

**关键规则**: 一旦从holding变为profited/stopped/timeout，**状态锁定不再变更**

## 三、平仓/结算字段（触发时计算，确定后不变）

### 3.1 平仓信息字段（触发时一次性计算）

| 字段 | 计算逻辑 | 触发条件 |
|------|---------|---------|
| `exit_price` | **止盈触发**: `take_profit_price`<br>**止损触发**: `stop_loss_price`<br>**超时触发**: `current_price`（当时最新价） | 首次触发对应条件时确定 |
| `exit_time` | **止盈/止损触发**: 首次触及阈值的时间<br>**超时触发**: `entry_time + max_hold_time` | 首次触发时确定 |
| `final_return_pct` | `(exit_price - entry_price) / entry_price * 100` | 触发时计算 |

### 3.2 锁定字段（触发时设置）

| 字段 | 计算逻辑 |
|------|---------|
| `is_locked` | 触发止盈/止损/超时时设为 `1` |
| `locked_at` | 触发时刻的当前时间戳 |
| `lock_reason` | `take_profit` / `stop_loss` / `max_time` |

## 四、统计字段（派生计算，不入库，每tick实时统计）

### 4.1 用户要求的统计指标

| 统计项 | 计算逻辑 | 说明 |
|--------|---------|------|
| **持仓数** | `COUNT(*) WHERE is_locked=0` | 浮动未结算的数量 |
| **损数** | `COUNT(*) WHERE (lock_reason='stop_loss') OR (lock_reason='max_time' AND final_return_pct<0)` | 止损 + 超时亏损 |
| **盈数** | `COUNT(*) WHERE (lock_reason='take_profit') OR (lock_reason='max_time' AND final_return_pct>=0)` | 止盈 + 超时盈利/持平 |

### 4.2 时长计算

| 场景 | 时长计算 |
|------|---------|
| 止盈触发 | `触发时间 - 入场时间`（首次触及止盈价的时间） |
| 止损触发 | `触发时间 - 入场时间`（首次触及止损价的时间） |
| 超时触发 | `max_hold_time * 60` 秒（固定） |
| 持仓中 | `当前时间 - 入场时间`（实时变化） |

## 五、完整计算流程（前端计算方案）

### 5.1 后端流程（每tick执行）

```
【后端：只处理触发判定，不计算浮动】

1. 查询未结算记录（is_locked=0）
   SELECT id, bond_code, entry_price, take_profit_price, stop_loss_price, 
          max_hold_time, tick_time
   FROM quant_screen_hits 
   WHERE trade_date = :today AND is_locked = 0

2. 判断触发条件（只检测，不UPDATE持仓中）
   
   for each row in pending:
       current_price = 从df_now获取
       
       ├─ 止盈？current_price >= take_profit_price
       │   └─ 加入 updates_profited
       │       {id, exit_price=take_profit_price, exit_time=now, 
       │        final_return_pct=计算, signal_status='profited',
       │        is_locked=1, lock_reason='take_profit'}
       │
       ├─ 止损？current_price <= stop_loss_price
       │   └─ 加入 updates_stopped
       │       {id, exit_price=stop_loss_price, exit_time=now,
       │        final_return_pct=计算, signal_status='stopped',
       │        is_locked=1, lock_reason='stop_loss'}
       │
       └─ 超时？current_time >= entry_time + max_hold_time
           └─ 加入 updates_timeout
               {id, exit_price=current_price, exit_time=now,
                final_return_pct=计算, signal_status='timeout',
                is_locked=1, lock_reason='max_time'}

3. 批量UPDATE（只更新新触发的，通常0-5条/天）
   UPDATE quant_screen_hits SET ... WHERE id IN (新触发的IDs)

4. 【关键】持仓中的记录：不UPDATE，前端自己算
```

### 5.2 前端流程（实时计算）

```
【前端：实时计算浮动收益和触发状态】

1. 获取静态数据（一次性或轮询）
   GET /api/hits?date=today
   返回: [{id, bond_code, entry_price, take_profit_price, stop_loss_price, 
          max_hold_time, tick_time, is_locked, exit_price, final_return_pct, ...}]

2. 获取实时行情（WebSocket或轮询）
   prices = {bond_code: current_price, ...}

3. 实时计算每条记录
   for each hit in hits:
       if hit.is_locked:
           // 已结算：直接显示最终收益
           hit.display_return = hit.final_return_pct
           hit.display_status = hit.lock_reason  // '止盈'/'止损'/'超时'
       else:
           // 持仓中：实时计算
           currentPrice = prices[hit.bond_code]
           hit.display_return = ((currentPrice - hit.entry_price) / hit.entry_price * 100).toFixed(4)
           
           // 触发状态（展示用，最终以后端为准）
           if currentPrice >= hit.take_profit_price:
               hit.display_status = '止盈(待确认)'
           else if currentPrice <= hit.stop_loss_price:
               hit.display_status = '止损(待确认)'
           else if 超时:
               hit.display_status = '超时(待确认)'
           else:
               hit.display_status = '持仓中'
           
           // 时长计算
           hit.display_hold_time = 当前时间 - hit.tick_time

4. 实时统计
   stats = {
       holding: hits.filter(h => !h.is_locked).length,
       profited: hits.filter(h => h.lock_reason === 'take_profit' || 
                                   (h.lock_reason === 'max_time' && h.final_return_pct >= 0)).length,
       stopped: hits.filter(h => h.lock_reason === 'stop_loss' || 
                                 (h.lock_reason === 'max_time' && h.final_return_pct < 0)).length
   }
```

## 七、关键规则确认（待用户审核）

### 7.1 触发判定优先级
按此顺序判断（一旦触发一个，后续不再检查）：
1. **止盈**（最高优先级）
2. **止损**
3. **超时**（最低优先级）

### 7.2 触发价格使用规则
| 触发类型 | exit_price取值 | 理由 |
|---------|---------------|------|
| 止盈 | `take_profit_price`（预设阈值） | 用户要求：触发价计算收益 |
| 止损 | `stop_loss_price`（预设阈值） | 同上 |
| 超时 | `current_price`（当时最新价） | 无预设阈值，用实际价格 |

### 7.3 盈/损统计规则
| 统计项 | 包含条件 |
|--------|---------|
| **盈数** | `lock_reason='take_profit'` **OR** (`lock_reason='max_time'` AND `final_return_pct >= 0`) |
| **损数** | `lock_reason='stop_loss'` **OR** (`lock_reason='max_time'` AND `final_return_pct < 0`) |

### 7.4 时长计算规则
| 场景 | 时长计算方式 |
|------|-------------|
| 止盈/止损 | `触发时刻 - 入场时刻`（精确到秒） |
| 超时 | `max_hold_time * 60` 秒（固定值） |
| 持仓中 | `当前时刻 - 入场时刻`（实时变化） |

**现象**：重启服务刷新页面后，收益仍显示为"--"

**排查过程**：
1. 检查后端数据：final_return_pct都有值，数据正确

**根本原因**：前端代码字段名错误

**修复**（`src/gs2026/dashboard2/templates/monitor.html`）：
```javascript
// 正确代码
var retVal = item.final_return_pct != null ? item.final_return_pct : 
            (item.current_return_pct != null ? item.current_return_pct : null);
// 同时修复显示格式
var returnDisplay = retVal != null ? (returnSign + parseFloat(retVal).toFixed(2) + '%') : '--';
```

#### 问题5：前端统计逻辑错误（2026-07-23 21:15）
**现象**：统计数字不正确

**原因**：原统计只按`signal_status`分类，未正确处理超时盈/损

**修复**（`src/gs2026/dashboard2/templates/monitor.html`）：
```javascript
// 按用户要求统计：盈=止盈+(超时且>=0)，损=止损+(超时且<0)
if (item.is_locked) {
    if (item.lock_reason === 'take_profit') {
        stats[name].profited++;  // 止盈
    } else if (item.lock_reason === 'stop_loss') {
        stats[name].stopped++;   // 止损
    } else if (item.lock_reason === 'max_time') {
        // 超时：根据收益判断盈/损
        if (item.final_return_pct != null && parseFloat(item.final_return_pct) >= 0) {
            stats[name].profited++;  // 超时盈
        } else {
            stats[name].stopped++;   // 超时损
        }
    }
} else {
    stats[name].holding++;  // 持仓中
}
```

### 10.3 实时分析tick数据逻辑确认

#### 后端逻辑（`_track_pending_exits`函数）

**每tick执行流程**：
```
1. 查询未结算记录（is_locked=0）
2. 获取当前tick价格
3. 对每个记录判断触发：
   ├─ 止盈？current_price >= take_profit_price
   │   └─ 计算收益：(take_profit_price - entry_price) / entry_price * 100
   │   └─ 加入更新队列
   ├─ 止损？current_price <= stop_loss_price
   │   └─ 计算收益：(stop_loss_price - entry_price) / entry_price * 100
   │   └─ 加入更新队列
   ├─ 超时？current_time >= entry_time + max_hold_time
   │   └─ 计算收益：(current_price - entry_price) / entry_price * 100
   │   └─ 加入更新队列
   └─ 未触发：跳过（前端自己算）
4. 批量UPDATE新触发的记录
```

**关键逻辑确认**：
| 项目 | 实现 | 状态 |
|------|------|------|
| 触发优先级 | 止盈 > 止损 > 超时 | ✅ 正确 |
| 止盈exit_price | take_profit_price（预设阈值） | ✅ 正确 |
| 止损exit_price | stop_loss_price（预设阈值） | ✅ 正确 |
| 超时exit_price | current_price（当时最新价） | ✅ 正确 |
| 超时hold_seconds | max_hold_time * 60（固定值） | ✅ 正确 |
| 止盈/止损hold_seconds | 实际触发时长 | ✅ 正确 |
| 收益计算 | (exit - entry) / entry * 100 | ✅ 正确 |
