# 时间分片读取优化分析

## 当前问题

```
[LOAD] 共 4522 个时间点, 每批 100 个
```

**计算**：4522 / 100 = ~46次查询

**耗时预估**：
- 每次查询：~2-5秒（取决于数据量）
- 总耗时：46 × 3秒 = ~138秒 = **2.3分钟**

## 瓶颈分析

### 1. 查询次数过多

| 参数 | 当前 | 优化空间 |
|------|------|---------|
| 时间点总数 | 4522 | 固定（全天） |
| 每批时间点 | 100 | **可增大** |
| 查询次数 | ~46次 | **可减少** |

### 2. 每次查询的数据量

假设：400只债券 × 100个时间点 = **4万行/查询**

**问题**：
- 单次查询数据量适中，但查询次数太多
- 网络往返开销累积

## 优化方案

### 方案1：增大每批时间点数量（最简单）

```python
# 当前

# 优化后

```

**效果**：

- 单次数据量：4万行 → 20万行

**风险**：
- 单次查询数据量增大，内存占用增加
- 但20万行 ≈ 50MB，可接受

### 方案2：并行查询（推荐）

```python
from concurrent.futures import ThreadPoolExecutor

def load_table_data_parallel(engine, table_name, needed_columns, 
                              chunk_time_count=500, max_workers=4):
    """并行时间分片读取"""
    
    # 1. 获取所有时间点
    all_times = get_all_times(engine, table_name)
    
    # 2. 分片
    chunks = [all_times[i:i+chunk_time_count] 
              for i in range(0, len(all_times), chunk_time_count)]
    
    # 3. 并行查询
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        futures = [executor.submit(fetch_chunk, chunk) 
                   for chunk in chunks]
        
        for future in futures:
            df = future.result()
            if not df.empty:
                yield df
```

**效果**：
- 4个并行查询，理论速度 **4x**
- 实际速度：2-3x（受数据库连接限制）

    """单次全量读取（仅依赖列）"""
    
    cols_str = ", ".join([f"`{c}`" for c in sorted(needed_columns)])
    sql = f"SELECT {cols_str} FROM `{table_name}` ORDER BY `time`, `bond_code`"

- 1次查询，无时间分片开销
- 但数据量大（20万行 × 全天）

**适用场景**：
- 内存充足（>1GB）
- 网络带宽充足

### 方案4：混合方案（推荐）

```python
def load_table_data_optimized(engine, table_name, needed_columns):
    """优化版时间分片读取"""
    
    # 1. 预估总行数
    total_rows = get_total_rows(engine, table_name)
    
    # 2. 根据数据量选择策略
    if total_rows < 100000:
        # 小数据量：单次全量读取
        yield from load_table_data_full(engine, table_name, needed_columns)
    else:
        # 大数据量：并行时间分片
        yield from load_table_data_parallel(engine, table_name, needed_columns,
                                           chunk_time_count=500, max_workers=4)
```
