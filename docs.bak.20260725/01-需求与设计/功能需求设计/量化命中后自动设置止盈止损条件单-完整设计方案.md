## 一、需求背景

### 1.1 当前系统现状

当前 monitor_bond.py 实时监控可转债行情(每3秒一个tick),通过量化方案筛选命中信号后,调用华泰委托系统填充买入表单。

**现有流程:**
```
monitor_bond tick -> 量化选债命中 -> trader_on_hit(code, name, scheme_name)
                                          |
                                trader_adapter -> HTTP -> 华泰xiadan.exe填充买入表单
```

**存在的问题:**

| # | 问题 | 说明 |
|---|------|------|
| 1 | 买入价未使用偏移 | scheme中的price_offset已加载但未传入交易调用 |
| 2 | 无止盈止损机制 | 买入后无自动TP/SL,完全依赖人工盯盘 |
| 3 | 成交确认不明确 | 多个命中信号时,系统无法确定用户实际操作了哪一单 |

### 1.2 目标

实现: **量化命中 -> 计算买入价(含偏移) -> 买入确认后 -> 自动提交华泰止盈止损条件单**

关键要求:
- 买入价格 = 命中价格 + 方案设置的价格偏移
- 止盈止损价格基于实际成交价(买入价)计算
- 通过华泰xiadan.exe的止盈止损条件单功能提交
- 支持串行处理多个命中信号,明确区分每一单

## 二、架构设计

### 2.1 整体流程图

```
+------------------------------------------------------------------+
|                    完整订单生命周期                                  |
+------------------------------------------------------------------+
|                                                                    |
|  (1) 量化筛选命中                                                   |
|      -> 计算买入价 = hit_price + price_offset                       |
|      -> 填充华泰买入表单 -> 人工确认点击[买入]                        |
|                                                                    |
|  (2) 买入确认(热键 或 自动扫描当日成交)                               |
|      -> 获取实际成交价                                               |
|      -> 计算 TP价 = 成交价 x (1 + tp_pct/100)                      |
|      -> 计算 SL价 = 成交价 x (1 - sl_pct/100)                      |
|                                                                    |
|  (3) 自动提交华泰xiadan.exe止盈止损条件单                                  |
|      -> 一个表单同时设置止盈和止损                                    |
|      -> 券商服务器自动监控执行                                        |
|                                                                    |
|  (4) 券商侧自动触发卖出                                              |
|      -> 触发条件满足 -> 自动委托卖出 -> 完成                          |
|                                                                    |
+------------------------------------------------------------------+
```

### 2.2 核心设计: 串行订单管道

**解决的核心问题:** 多个命中信号时,系统如何确定用户实际操作了哪一单?

**方案: 任何时刻只有一个订单处于PENDING状态**

```
命中队列: [hitA, hitB, hitC, ...]
      | (每次只取1个处理)
      v
+-------------------------------+
| 当前活跃单 (PENDING)           |
| 123456 某转债 @105.5 买入已填充 |
+-------------------------------+
      |
      | <- 用户确认(热键/自动扫描)
      v
确认成交 -> 计算TP/SL -> 提交条件单 -> DONE
      |
      v (处理下一个)
从队列取下一个命中 -> 填充买入表单 -> 等待确认...
```

**规则:**
- 任何时刻最多1个订单处于PENDING状态
- 新命中信号进入队列排队,不立刻填充表单
- 用户确认/跳过当前订单后,才处理下一个
- 队列上限5个,满时丢弃最旧的
- 超时30秒未确认自动跳过,处理下一个

### 2.3 成交确认方式(双通道)

同时支持两种确认方式,任一触发即确认:

| 方式 | 触发条件 | 优先级 |
|------|---------|--------|
| **全局热键** | Ctrl+Shift+Y = 确认成交, Ctrl+Shift+N = 跳过 | 主(最快) |
| **HTTP面板** | 浏览器小面板点击[已成交]/[跳过] | 辅(直观) |
| **自动扫描** | 扫描当日成交,三元组匹配(code+price+time) | 兜底(自动) |

**三元组匹配策略(解决同一转债多次交易的区分问题):**

```
匹配条件 = (证券代码 完全匹配)
         AND (委托价格 与 target_buy_price 差值 <= 0.01元)
         AND (委托时间 在 提交时间后 0~30秒内)
```

### 3.3 Tab顺序（实测确认）

```
证券代码 → Tab → 基准价 → Tab → 止盈(%) → Tab → 止损(%) → Tab → 委托数量
```

**注意：**
- 委托价、截止时间不在Tab路径上（Tab直接跳过）
- Tab从止损直接到委托数量

### 3.4 自动化方式（实测确认）

**方案：纯Win32 API + 相对坐标**

| 对比项 | 最初设想 | 实际方案 |
|--------|---------|---------|
| 操控方式 | pywinauto | 纯win32 API (无第三方依赖) |
| 定位方式 | 控件查找 | 窗口相对坐标 + Tab键 |
| 坐标类型 | 绝对坐标 | **相对坐标**(相对窗口左上角) |
| 窗口移动 | 坐标失效 | **不影响**(运行时动态计算) |
| 32/64位 | 有兼容问题 | 无问题(纯API) |

**为何用相对坐标：**
- 弹窗位置可能被用户移动
- 存储相对于窗口左上角的偏移
- 运行时: 绝对坐标 = GetWindowRect().left + 相对偏移X

### 3.5 价格计算规则（修正版）

```python
# 买入价计算（命中时）
if offset_mode == 'percent':
    target_buy_price = hit_price * (1 + price_offset / 100)
elif offset_mode == 'fixed':
    target_buy_price = hit_price + price_offset

# 止盈止损 —— 直接使用方案中的百分比
# 不需要计算绝对价格！华泰表单接受百分比
tp_pct = scheme.take_profit_pct   # 如 3.0
sl_pct = scheme.stop_loss_pct     # 如 2.0
base_price = actual_buy_price     # 如 105.300

# 填入表单:
#   基准价 = 105.300
#   止盈 = 3.0 (表示>=基准价*(1+3%)时卖出)
#   止损 = 2.0 (表示<=基准价*(1-2%)时卖出)
```

### 4.3 订单状态机

```
CREATED ──> PENDING ──> FILLED ──> TP_SL_SET ──> CLOSED
   |            |           |          |
   |            |           |          └──> TP_SL_FAILED(重试/人工)
   |            |           |
   |            └──> SKIPPED(超时30秒/用户跳过)
   |
   └──> QUEUED(当前有PENDING单时入队等待)
```

**状态说明:**

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| CREATED | 命中信号已生成 | 量化筛选命中 |
| QUEUED | 在队列中等待 | 当前已有PENDING订单 |
| PENDING | 买入表单已填充,等待用户确认 | 华泰表单填充成功 |
| FILLED | 买入已确认成交 | 热键确认/自动扫描匹配 |
| TP_SL_SET | 止盈止损条件单已提交 | 条件单提交成功 |
| TP_SL_FAILED | 条件单提交失败 | 重试耗尽 |
| SKIPPED | 已跳过 | 超时30秒/用户按跳过键 |
| CLOSED | 已完结 | TP/SL执行完毕 或 手动关闭 |

### 5.1 OrderPipeline (串行订单管道)

```python
class OrderPipeline:
    """
    串行订单管道
    
    设计原则:
    - 任何时刻最多1个PENDING订单
    - 队列上限5个,满时丢弃最旧
    - 超时30秒自动跳过
    - 状态持久化到JSON(防重启丢单)
    """
    
    MAX_QUEUE_SIZE = 5
    PENDING_TIMEOUT_SECONDS = 30
    STATE_FILE = "pipeline_state.json"
    
    def __init__(self, config, trader, cond_placer):
        self.queue = []              # 等待处理的命中信号
        self.current = None          # 当前PENDING订单(最多1个)
        self.history = []            # 已完成订单(用于当日统计)
        self.trader = trader         # HuaTaiTrader实例
        self.cond_placer = cond_placer  # 条件单提交器
    
    def on_new_hit(self, hit_info: dict):
        """
        新命中到达
        
        Args:
            hit_info: {
                'bond_code': str,
                'bond_name': str,
                'hit_price': float,    # 命中时市场价
                'scheme_name': str,
                'scheme_detail': {
                    'price_offset': float,
                    'offset_mode': str,     # 'fixed' / 'percent'
                    'stop_loss': float,     # 止损百分比
                    'take_profit': float,   # 止盈百分比
                    'max_hold_time': int,   # 最大持仓分钟(条件单截止时间参考)
                },
                'lots': int,
            }
        """
        if self.current is None:
            # 无等待中的订单,立即处理
            self._process_hit(hit_info)
        else:
            # 有订单在等确认,入队
            if len(self.queue) >= self.MAX_QUEUE_SIZE:
                dropped = self.queue.pop(0)  # 丢弃最旧的
                logger.info(f"[Pipeline] 队列满,丢弃最旧: {dropped['bond_name']}")
            self.queue.append(hit_info)
            logger.info(f"[Pipeline] 入队: {hit_info['bond_name']} (队列={len(self.queue)})")
    
    def on_confirm(self, actual_price: float = None):
        """
        用户确认成交(热键或HTTP面板触发)
        
        Args:
            actual_price: 实际成交价,None则使用target_buy_price
        """
        if not self.current:
            return
        
        order = self.current
        order.actual_buy_price = actual_price or order.target_buy_price
        order.status = "filled"
        order.filled_at = datetime.now().isoformat()
        
        # 提交止盈止损条件单
        self._submit_tp_sl(order)
        
        # 处理下一个
        self.current = None
        self._process_next()
    
    def on_skip(self):
        """用户跳过当前订单"""
        if self.current:
            self.current.status = "skipped"
            self.history.append(self.current)
            self.current = None
            self._process_next()
    
    def check_timeout(self):
        """每tick调用: 检查当前PENDING订单是否超时"""
        if self.current and self.current.status == "pending":
            elapsed = (datetime.now() - self.current.pending_since).total_seconds()
            if elapsed >= self.PENDING_TIMEOUT_SECONDS:
                logger.info(f"[Pipeline] 超时跳过: {self.current.bond_name} ({elapsed:.0f}秒)")
                self.on_skip()
```

### 5.2 ConditionalOrderPlacer (条件单提交器) — 已验证方案

**文件:** `scripts/huatai_trader/conditional_order.py`

**技术方案:** 纯Win32 API + 相对坐标 + Tab键填充（已通过测试验证）

```python
class ConditionalOrderPlacer:
    """
    华泰止盈止损条件单自动化
    
    技术栈: 纯Win32 API (ctypes.windll)
    定位方式: 窗口相对坐标(校准一次,永久使用)
    填充方式: 点击证券代码框 + Tab切换字段 + 剪贴板粘贴输入
    
    已验证的Tab顺序:
        证券代码 → Tab → 基准价 → Tab → 止盈(%) → Tab → 止损(%) → Tab → 数量
    """
    
    MAX_RETRIES = 3
    RETRY_INTERVAL = 2
    
    XIADAN_TITLE = "网上股票交易系统5.0"
    POPUP_TITLE = "华泰理财通"
    POPUP_CLASS = "Chrome_WidgetWin_1"
    
    def __init__(self, positions_file: str):
        """
        Args:
            positions_file: 校准文件路径(tp_sl_positions.json)
                包含所有元素相对于窗口左上角的坐标偏移
        """
        self.positions = self._load_positions(positions_file)
    
    def place_tp_sl(self, bond_code: str, base_price: float,
                    tp_pct: float, sl_pct: float, 
                    quantity: int) -> dict:
        """
        提交止盈止损条件单
        
        Args:
            bond_code: 证券代码
            base_price: 基准价(买入成交价,元)
            tp_pct: 止盈百分比(如3.0表示涨3%触发)
            sl_pct: 止损百分比(如2.0表示跌2%触发)
            quantity: 委托数量(股/张)
        
        Returns:
            {'success': bool, 'message': str, 'retries': int}
        """
        for attempt in range(self.MAX_RETRIES):
            try:
                result = self._execute(bond_code, base_price, tp_pct, sl_pct, quantity)
                if result['success']:
                    result['retries'] = attempt
                    return result
            except Exception as e:
                logger.warning(f"[条件单] 第{attempt+1}次失败: {e}")
            
            if attempt < self.MAX_RETRIES - 1:
                time.sleep(self.RETRY_INTERVAL)
        
        self._alert_manual_intervention(bond_code, base_price, tp_pct, sl_pct)
        return {'success': False, 'message': f'重试{self.MAX_RETRIES}次失败', 'retries': self.MAX_RETRIES}
    
    def _execute(self, bond_code, base_price, tp_pct, sl_pct, quantity):
        """
        完整执行序列(已验证):
        
        1. 找到xiadan.exe → 激活 → 点击[条件单]
        2. 等待华泰理财通弹窗出现 → 激活
        3. 点击: 卖出条件单 → 止盈止损
        4. 点击证券代码框 → 输入代码
        5. Tab → 输入基准价
        6. Tab → 输入止盈百分比
        7. Tab → 输入止损百分比
        8. Tab → 输入数量
        9. 滚动到提交按钮 → 点击提交
        """
        # 1. 找到并激活xiadan
        hwnd_x = find_window(self.XIADAN_TITLE)
        if not hwnd_x:
            return {'success': False, 'message': 'xiadan.exe未找到'}
        activate(hwnd_x)
        
        # 2. 点击条件单,等待弹窗
        self._abs_click(hwnd_x, 'condition_btn', wait=2.5)
        hwnd_p = self._wait_popup(timeout=5)
        if not hwnd_p:
            return {'success': False, 'message': '条件单弹窗未出现'}
        activate(hwnd_p)
        
        # 3. 导航: 卖出条件单 → 止盈止损
        self._abs_click(hwnd_p, 'sell_condition', wait=1.0)
        self._abs_click(hwnd_p, 'tp_sl', wait=1.5)
        
        # 4-8. 填充表单(Tab模式)
        self._abs_click(hwnd_p, 'code', wait=0.5)
        self._type_value(bond_code)
        time.sleep(1.0)
        
        press_tab()
        self._type_value(f"{base_price:.3f}")
        
        press_tab()
        self._type_value(f"{tp_pct:.3f}")
        
        press_tab()
        self._type_value(f"{sl_pct:.3f}")
        
        press_tab()
        self._type_value(str(quantity))
        
        # 9. 滚动 + 提交
        self._abs_scroll(hwnd_p)
        time.sleep(0.5)
        self._abs_click(hwnd_p, 'submit_btn', wait=1.5)
        press_enter()  # 确认弹窗(如有)
        
        return {'success': True, 'message': '条件单已提交'}
```

```python
class HotkeyListener:
    """
    全局热键监听器
    
    快捷键:
    - Ctrl+Shift+Y: 确认当前订单已成交
    - Ctrl+Shift+N: 跳过当前订单
    - Ctrl+Shift+I: 显示当前订单信息(控制台打印)
    
    实现: 使用 pynput 或 keyboard 库注册全局热键
    """
    
    def __init__(self, pipeline: OrderPipeline):
        self.pipeline = pipeline
        self._running = False
    
    def start(self):
        """启动热键监听(独立线程)"""
        import keyboard  # pip install keyboard
        
        keyboard.add_hotkey('ctrl+shift+y', self._on_confirm)
        keyboard.add_hotkey('ctrl+shift+n', self._on_skip)
        keyboard.add_hotkey('ctrl+shift+i', self._on_info)
        
        self._running = True
        logger.info("[Hotkey] 热键监听已启动: Ctrl+Shift+Y=确认 N=跳过 I=信息")
    
    def stop(self):
        """停止监听"""
        import keyboard
        keyboard.unhook_all()
        self._running = False
    
    def _on_confirm(self):
        """确认成交"""
        if self.pipeline.current:
            logger.info(f"[Hotkey] 用户确认成交: {self.pipeline.current.bond_name}")
            self.pipeline.on_confirm()
            # 播放确认音
            self._play_confirm_sound()
    
    def _on_skip(self):
        """跳过当前"""
        if self.pipeline.current:
            logger.info(f"[Hotkey] 用户跳过: {self.pipeline.current.bond_name}")
            self.pipeline.on_skip()
    
    def _on_info(self):
        """打印当前订单信息"""
        if self.pipeline.current:
            o = self.pipeline.current
            print(f"\n{'='*50}")
            print(f"当前订单: {o.bond_name}({o.bond_code})")
            print(f"目标买入价: {o.target_buy_price}")
            print(f"止盈: +{o.take_profit_pct}% = {o.tp_price_preview}")
            print(f"止损: -{o.stop_loss_pct}% = {o.sl_price_preview}")
            print(f"等待时间: {o.pending_elapsed:.0f}秒 / 30秒超时")
            print(f"队列中: {len(self.pipeline.queue)}个")
            print(f"{'='*50}\n")
        else:
            print("[Pipeline] 当前无活跃订单")
```

### 6.2 trader_adapter.py 修改

**修改内容:** on_hit() 方法改为接收完整信息并转发给Pipeline

```python
def on_hit(self, bond_code: str, bond_name: str, price: float = None,
           scheme_name: str = '', lots: int = None,
           scheme_detail: dict = None, **extra) -> bool:
    """
    命中回调 - 转发给OrderPipeline
    (保留原有过滤逻辑: 方案过滤/风控/去重)
    """
    if not self.config['enabled']:
        return False
    
    self._reset_daily_count_if_needed()
    
    # 方案过滤(不变)
    if not self._check_scheme_filter(scheme_name):
        return False
    
    # 交易时段检查(不变)
    if self.config.get('check_trading_time', True):
        if not self._is_trading_time():
            return False
    
    # 风控检查(不变)
    passed, reason = self._check_risk_limits(bond_code, price, lots)
    if not passed:
        self._send_notification("风控拦截", reason, success=False)
        return False
    
    # 转发给Pipeline
    from gs2026.monitor.order_pipeline import get_pipeline
    pipeline = get_pipeline()
    pipeline.on_new_hit({
        'bond_code': bond_code,
        'bond_name': bond_name,
        'hit_price': price or 0,
        'scheme_name': scheme_name,
        'scheme_detail': scheme_detail or {},
        'lots': lots or self.config.get('default_lots', 1),
    })
    
    self._daily_count += 1
    return True
```

## 八、错误处理与容错

### 8.1 条件单提交失败处理流程

```
条件单提交
    |
    v
第1次尝试 ──失败──> 等待2秒 ──> 第2次尝试 ──失败──> 等待2秒 ──> 第3次尝试
    |                                   |                              |
    成功                                成功                          失败
    |                                   |                              |
    v                                   v                              v
  完成                                完成                      触发告警流程
                                                                       |
                                                         +-------------+-------------+
                                                         |                           |
                                                    声音告警x3                  控制台红色警告
                                                    (急促蜂鸣)              "[!!! 需要人工干预 !!!]"
                                                         |                           |
                                                         +-------------+-------------+
                                                                       |
                                                                       v
                                                              订单标记为 TP_SL_FAILED
                                                              (不自动重试,等待人工处理)
```

### 8.2 各环节容错策略

| 环节 | 可能的错误 | 处理方式 |
|------|-----------|---------|
| 买入表单填充 | 华泰窗口未连接 | 自动重连1次,失败则跳过此单 |
| 华泰Web页面 | 未登录/session过期 | 告警提示重新登录 |
| 条件单提交 | 网络超时/页面卡顿 | 重试3次,间隔2秒 |
| 条件单提交 | 证券代码不存在 | 记录错误,跳过(数据异常) |
| 条件单提交 | 数量超过持仓 | 告警,需人工确认 |
| 热键监听 | 库冲突/权限不足 | 降级为仅HTTP面板模式 |
| 状态文件 | JSON损坏 | 备份损坏文件,从空状态重启 |
| 进程重启 | 有未完成的PENDING单 | 从state文件恢复,继续倒计时 |

### 8.3 进程重启恢复策略

```
启动时:
1. 读取 pipeline_state.json
2. 检查是否有 status="pending" 的订单
   - 有: 检查创建时间
     - 已超过30秒: 自动标记skipped
     - 未超过30秒: 恢复为PENDING,继续倒计时
3. 检查是否有 status="filled" 但 tp_sl未提交 的订单
   - 有: 重新执行条件单提交
4. 队列中的订单: 保留,继续处理
```
