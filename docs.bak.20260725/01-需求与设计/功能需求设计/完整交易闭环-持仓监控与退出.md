## 二、交易模式

### 2.1 模式配置

```python
config = {
    'mode': 'full',              # "buy_only" | "full"
    'signal_expire_seconds': 120, # 信号有效期(秒)
    'fill_timeout_seconds': 30,   # 等待成交弹窗超时(秒)
    'popup_poll_ms': 100,         # 弹窗检测轮询间隔
}
```

### 2.2 buy_only 模式（半自动）

```
命中 → 面板显示 → 用户点[买] → 填表 → 等弹窗(30s)
  ├─ 检测到弹窗 → 买入成交确认 → 播放提示音 → 交易结束
  └─ 超时 → F3全撤 → 交易结束
```

**适用场景**: 用户希望只执行买入，后续止盈止损自己操作。

### 2.3 full 模式（全自动）

```
命中 → 面板显示 → 用户点[买] → 填表 → 等弹窗(30s)
  ├─ 超时 → F3全撤 → 交易结束
  └─ 检测到弹窗 → 买入成交确认
        │
        ├─ 清理旧条件单 (防止残留干扰)
        ├─ 设置止盈止损条件单
        │
        ├─ 等第二次弹窗 (max_hold_minutes)
        │   ├─ 检测到弹窗 → 止盈/止损触发成交
        │   │   └─ 清理剩余条件单 → 交易完成
        │   └─ 超时 → 强制平仓
        │       └─ 清理条件单 → 交易完成
        │
        └─ 回到IDLE → 准备下一轮
```

## 三、状态机

### 3.1 状态定义

```
IDLE ─── 空闲，等待命中信号
  │
  ▼ (用户点[买])
TRADING ─── 交易执行中
  │
  ├─► 成交 ──► MONITORING ─── 持仓监控中 (仅full模式)
  │                │
  │                ├─► 止盈/止损触发 ──► IDLE
  │                └─► 超时强平 ──► IDLE
  │
  └─► 未成交 ──► 撤单 ──► IDLE
```

### 3.2 状态数据

```python
@dataclass
class TradeState:
    state: str = "IDLE"          # IDLE / TRADING / MONITORING
    hit_list: List[HitSignal]    # 待处理命中列表
    current: HitSignal = None    # 当前交易的命中信号
    fill_time: float = 0         # 买入成交时间
    tp_level: float = 0          # 止盈价位
    sl_level: float = 0          # 止损价位
    max_hold_seconds: int = 0    # 最大持仓时间
    history: List[dict]          # 今日交易历史
```

## 五、关键操作实现

### 5.1 买入表单填充

```
F1(买入快捷键) → 填code → 填price → 填lots → 用户手动确认买入
```
- 坐标来源: `trade_flow.py` 内部配置
- 用户仍需手动点"买入确认"（安全设计）

### 5.2 止盈止损条件单设置

```
打开条件单弹窗 → 填充TP价格/SL价格 → 确认提交
```
- 坐标来源: `tp_sl_config.json` + `tp_sl_positions.json`
- 使用键盘填充方式 (`tp_sl_placer_keyboard.py`)
- **已测试验证通过**

### 5.3 F3撤单（买入超时）

```
F3 → 打开撤单页 → 点击"全撤"按钮(1259,780) → Enter确认
```
- 坐标来源: `cancel_config.json`
- 策略: 全撤（一轮只做一笔，不需要精确选行）

### 5.4 条件单清理（终止旧条件单）

```
打开条件单界面 → 我的条件单 → 当前监控中 → 全选 → 终止
```
- 坐标来源: `tp_sl_cancel_config.json` (待校准)
- 调用时机:
  1. 设新TP/SL之前（清旧单）
  2. 强平之后（清无效单）
  3. TP/SL触发后（清剩余另一个）

### 5.5 强制平仓（持仓超时）

```
切换到卖出界面 → 填code → 填market_price → 填lots → 提交
```
- 坐标来源: `sell_config.json`
- 触发条件: max_hold_minutes 到期无二次弹窗

## 六、信号链路

### 6.1 命中推送

```
monitor_bond.py 命中检测
  → POST http://127.0.0.1:8081/api/auto_trade/hit
    body: {code, name, price, scheme, lots}
    timeout: 3s
  → server 接收:
    ├─ hit_store.save_hit() → MySQL (status='pending')
    └─ auto_trader.on_hit() → 内存 hit_list
```

### 6.2 信号有效期

- `signal_expire_seconds = 120`（2分钟）
- 过期后从内存hit_list移除
- MySQL记录永久保留（status更新为'expired'）

### 6.3 持久化表结构

```sql
CREATE TABLE auto_trade_hits (
    id INT AUTO_INCREMENT PRIMARY KEY,
    bond_code VARCHAR(10),
    bond_name VARCHAR(30),
    hit_price DECIMAL(10,4),
    scheme_json TEXT,
    lots INT DEFAULT 1,
    status ENUM('pending','trading','filled','cancelled','expired','force_sold'),
    mode VARCHAR(10),
    tp_level DECIMAL(10,4),
    sl_level DECIMAL(10,4),
    fill_price DECIMAL(10,4),
    sell_price DECIMAL(10,4),
    hit_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    note VARCHAR(200)
);
```

## 八、条件单生命周期管理

### 8.1 核心原则

> **每轮交易结束时，必须确保无残留条件单。**

华泰条件单独立于持仓——即使卖出，条件单不会自动消失。

### 8.2 清理时机

| # | 时机 | 代码位置 | 说明 |
|---|------|----------|------|
| 1 | 设新TP/SL之前 | `_on_filled()` | 清旧单，防止上轮残留 |
| 2 | TP/SL触发成交后 | `_on_filled()` 第二次弹窗后 | TP触发→清SL；SL触发→清TP |
| 3 | 强平之后 | `_force_sell()` 末尾 | 本轮条件单已无意义 |

## 九、异常处理

| 异常场景 | 处理方式 |
|----------|----------|
| server未启动，命中推送失败 | monitor静默跳过(info日志) |
| 买入表单填充失败 | 不进入TRADING，保持IDLE |
| 弹窗检测超时(买入) | F3全撤，回到IDLE |
| 弹窗检测超时(卖出) | 强制平仓 + 清条件单 |
| 条件单设置失败 | 记录warning，继续监控(降级运行) |
| 强平失败 | 记录error，播放警报音，需人工介入 |
| 条件单清理失败 | 记录warning，不阻塞主流程 |
| server重启 | 从MySQL加载pending记录恢复 |
