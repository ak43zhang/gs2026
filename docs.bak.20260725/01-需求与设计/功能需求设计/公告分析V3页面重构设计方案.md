# 公告分析V3 — 页面重构设计方案

> **版本**: V3.0  
> **日期**: 2026-05-11  
> **状态**: 待用户审核  
> **基于**: 公告分析V2设计方案 + 评分优化方案 + 当前工程实现

---

## 一、设计目标

在公告分析V2设计基础上，重构**分析中心的公告分析页面**，核心目标：

1. **顶级信号一眼定位** — 高+利好/高+利空置顶展示，快速识别隔夜机会
2. **评分体系可视化** — S/A/B/C/D五档卡片分流，取代平淡列表
3. **查询-展示-深潜三层架构** — 从快速筛选到沉浸式报告流畅体验
4. **充分利用全部字段** — 公告原文、核心内容、超短策略等AI分析结果不再被埋没
5. **导航完全保留** — 顶部全局导航栏 + 分析中心子导航栏不变

## 三、顶级信号快览区

### 3.1 规格

- **位置**：分析中心子导航栏正下方
- **高度**：自适应（约 220-400px）
- **显示逻辑**：4个Tab切换，每个Tab显示 TopN 公告（建议 Top5，超过该数量显示"+N 更多"链接）

### 3.2 4个信号组合

| Tab | 筛选条件 | Emoji | 优先级 | 配色方案 |
|-----|---------|------|--------|---------|
| 🚀 高+利好 | risk_level='高' AND notice_type='利好' | 🚀 | 最高 | 红色系边框 `#fee2e2`，背景 `#fff5f5`，标签 `#dc2626` |
| 🔴 高+利空 | risk_level='高' AND notice_type='利空' | 🔴 | 最高 | 暗红系边框 `#d1fae5`→`#a7f3d0`，背景 `#f0fdf4`，标签 `#b91c1c` |

## 四、日期选择器 + 查询条件

### 4.1 布局

三行排列：

```
行1: [📅 2026-05-11] [🔍 股票搜索…] [⚡ 全部影响力度 ▼] [📢 全部类型 ▼]
行2: [📂 公告分类 ▼] [📊 市场预期 ▼] [📈 开盘预判 ▼] [⏱ 持续性 ▼]
行3: [⭐ 评分档位 ▼] [排序: 综合评分↓ ▼] [🔄 重置] [✅ 查询] [⚡ 切四象限]
```

**设计原则**：
- 行1每日必用，放显眼位置
- 行2-3（高级条件）默认收起到一个 `[更多筛选 ∨]` 折叠区，点击展开

### 4.2 9个筛选条件

| # | 条件 | 绑定参数 | 数据来源 | 默认值 |
|---|------|---------|---------|--------|
| 1 | 📅 日期 | `date` | 日历控件 | 今日 |
| 2 | 🔍 股票搜索 | `stock_code`/`stock_name` | 输入框模糊匹配 | 空 |
| 3 | ⚡ 影响力度 | `risk_level` | 高/中/低 | 全部 |
| 4 | 📢 消息类型 | `notice_type` | 利好/利空/中性 | 全部 |
| 5 | 📂 公告分类 | `notice_category` | 动态读取（当前约272个） | 全部 |
| 6 | 📊 市场预期 | `market_expectation` | 超预期/符合预期/低于预期 | 全部 |
| 7 | 📈 开盘预判 | `open_prediction` | 7档 | 全部 |
| 8 | ⏱ 持续性 | `duration` | 一日游/2-3日/一周以上/持续发酵 | 全部 |
| 9 | ⭐ 评分档位 | `overnight_score` 范围 | S/A/B/C/D | 全部 |

### 4.3 排序

| 选项 | 参数值 | 实际排序 |
|------|--------|---------|
| 综合评分↓（默认） | `score_desc` | `overnight_score DESC` |
| 综合评分↑ | `score_asc` | `overnight_score ASC` |
| 影响力度 | `risk_desc` | `risk_score DESC` |
| 时间最新 | `time_desc` | `analysis_time DESC` |

### 4.4 公告分类动态读取

首次加载页面时调用 `/api/notice/categories`，缓存到 `localStorage`（过期时间5小时）。

```json
// /api/notice/categories 响应
{ "code": 0, "data": {
  "categories": ["业绩暴增超预期", "季度扭亏", "重大资产重组", ...],
  "updated_at": "2026-05-11T10:00:00"
}}
```

当前数据库实际分布（述值前20）：
```
业绩暴增超预期   一季报下降   一季报亏损  ...
（共约272个类型，请以动态读取为准）
```

如果 `/api/notice/categories` 失败，fallback到本地静态列表。

### 4.5 四象限按钮

- **位置**：查询栏同排右侧
- **功能**：切换主视图模式：`列表模式` ⇄ `四象限图模式`
- **初始状态**：隐藏，点击后显示

## 十二、技术约束与兼容性

### 12.1 当前数据库环境约束

- **MySQL 5.7**，不支持 JSON_TABLE，可能不支持 `INTERSECT`、`WITH`
- **跨年分表**：表名为 `analysis_notice_detail_2026`（年份拼接到表后缀），切勿硬编码为固定表名
- **配置文件**：`config/settings.yaml` — `common.url` 连接参数
- **前缀冲突**：`settings.yaml` 表前缀是 `data_gs`，如全局表名以 `data_gs` 开头 ≠ 当前直接SQL查询的 `analysis_notice_detail_2026`
- `fields` 应对235的；MyISAM vs InnoDB：如蹈全局表使用MyISAM或阻塞
- **阿拉伯风格注意**：Booster风格

> ⚠️ 以上约束来自系统工程师（stedctheq 3节信息）

### 12.2 Redis缓存策略

已有 `DETAIL_TTL = 48h`，`TIMELINE_TTL = 72h`，深潜报告继承此策略，无需新增。

### 12.3 前端技术栈约束

- 当前页面纯 HTML+内联 JavaScript（无 React/Vue）
- CSS 使用 `base.css` / `components.css` / `pages.css` / `analysis_center.css`
- 不引入新框架，继续用原生 JS + fetch 保持一致性

### 12.4 性能注意事项

- 顶级信号区：`overnight_score` 有索引（已有），4个组合各LIMIT5，4条SQL → 合并为1条SQL优化
- 列表区：新增5个筛选条件，SQL WHERE 排名，注意文本 LIKE %xx% 无索引
- `notice_category` 动态读取缓存到 localStorage（5小时）
