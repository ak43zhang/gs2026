## 问题1: 无效条件单是否影响下次同code交易?

### 分析

```
场景:
t=0s  命中127045 → 你没买 → 30秒超时 → 保守设了TP/SL条件单
      条件单内容: 127045 基准价=105.3 止盈3% 止损2%
      
t=5min 再次命中127045 → 你买了! 成交价=108.0
      系统设新条件单: 127045 基准价=108.0 止盈3% 止损2%

现在存在两个条件单:
  旧(无效): 基准价=105.3 → 止盈>=108.459, 止损<=103.194
  新(有效): 基准价=108.0 → 止盈>=111.24, 止损<=105.84

问题: 旧条件单的止盈价108.459 可能接近当前价格!
     如果价格涨到108.459 → 旧条件单触发卖出!
     但你是在108.0买的,108.459才涨了0.4% → 不是你想要的止盈!
```

### 结论: ⚠️ 无效条件单会干扰! 不能保守设置!

**旧条件单不会"自动消失"——它一直有效直到触发或手动删除或到期。**

如果下次买了同一只,旧条件单的止盈/止损价可能先触发,导致被错误卖出。

### 解决: 放弃"保守设TP/SL"策略

```
超时后F3找不到的处理:
  ✗ 旧方案: 保守假设成交 → 设TP/SL (会留下垃圾条件单!)
  ✓ 新方案: 不设TP/SL, 只告警(声音+日志)
  
  如果真的成交了但没设TP/SL → 你听到告警 → 手动检查 → 手动设
  如果没买过 → 告警提示但无影响
```

这是概率极低的场景(弹窗漏检), 用告警替代自动操作更安全。

## 问题2: 多条命中只买了一条,其他超时会很久吗?

### 分析

```
当前设计: state!=IDLE时,新命中全部跳过(不记录)

tick1: 命中127045 → state=WATCHING → 只跟踪这1个
tick2: 命中127011 → state!=IDLE → return(根本没记录)
tick3: 命中127123 → state!=IDLE → return(根本没记录)

你买了127045 → 成交 → 设TP/SL → state=IDLE

结果: 127011和127123根本不存在于系统中!
      没有"其他超时"的问题!
      因为根本没有"其他"!
```

### 结论: ✅ 不存在多个超时问题

只有1个current在跟踪,其他全部被跳过(丢弃)。不存在"等其他超时"的时间开销。

```
唯一的超时: 当前这1个(127045)
  → 30秒后如果没成交弹窗 → 撤单(F3操作3-5秒) → IDLE → 完
  → 不会有"多个排队撤单"的情况
```

## 问题3: 交易操作会不会阻塞monitor_bond.py的3秒tick?

### 分析

```
monitor_bond.py 主循环:
  while True:
      df = fetch_data()        # 采集(必须3秒完成)
      process(df)              # ETL转换
      check_hits(df)           # 命中检测
      trade_hook.on_hit(...)   # ← 这里如果阻塞,tick就延迟了!
      sleep(remaining)
```

**如果on_hit()内部做了耗时操作(如fill_buy_form 2-3秒), 会直接阻塞tick!**

### 解决: on_hit()必须是非阻塞的

```python
# trade_hook.py
def on_hit(self, code, name, price, scheme, lots):
    """保证: 绝不阻塞, 瞬间返回"""
    if not self.enabled:
        return
    try:
        self._trader.on_hit_async(code, name, price, scheme, lots)
    except Exception as e:
        logger.warning(f"[TradeHook] {e}")

# auto_trader.py  
def on_hit_async(self, code, name, price, scheme, lots):
    """非阻塞: 只设状态+启动线程"""
    if self.state != "IDLE":
        return
    
    self.state = "WATCHING"
    self.current = {... }
    
    # 所有耗时操作都在独立线程
    Thread(target=self._trade_loop, daemon=True).start()

def _trade_loop(self):
    """独立线程: 填表 → 等弹窗 → 设TP/SL 或 撤单"""
    # 1. 填充买入表单(2-3秒, 不阻塞主线程)
    fill_buy_form(...)
    
    # 2. 监听弹窗(每100ms)
    while ...:
        if detect_popup(): ...
        if timeout: ...
        sleep(0.1)
    
    # 3. 设TP/SL或撤单(5-7秒)
    ...
    
    # 4. 完成
    self.state = "IDLE"
```

### 线程模型(最终版)

```
┌──────────────────────────────────────┐
│  主线程 (monitor_bond.py)             │
│  每3秒tick: 采集 → ETL → 命中检测    │
│  on_hit(): 只改state + 启动线程       │
│  耗时: <1ms (瞬间返回)               │
│  绝不阻塞 ✓                          │
└──────────────────────┬───────────────┘
                       │ 启动(state=IDLE时)
                       ▼
┌──────────────────────────────────────┐
│  交易线程 (1个, daemon)               │
│  顺序执行:                            │
│    1. fill_buy_form (2-3秒)          │
│    2. 监听弹窗 (每100ms, 最多30秒)    │
│    3. set_tp_sl (5-7秒) 或 cancel    │
│    4. state=IDLE → 线程结束           │
│                                      │
│  下次命中时启动新线程                  │
└──────────────────────────────────────┘

并发安全:
- 主线程只读state(判断是否IDLE)
- 交易线程写state
- state只有两个写入点:
  · on_hit_async中 IDLE→WATCHING (主线程, 只在IDLE时)
  · _trade_loop末尾 →IDLE (交易线程)
- 不会同时写 → 无竞态 ✓
```

## 最终修正方案(完整版)

### 状态机

```
IDLE ──→ WATCHING ──→ FILLED ──→ SETTING_TP_SL ──→ IDLE
              │                                      ↑
              └──→ TIMEOUT ──→ 撤单                  │
                      ├── 撤成功 → IDLE              │
                      └── 找不到 → 告警 → IDLE       │
                            (不设TP/SL,避免垃圾条件单)│
```

### 完整代码逻辑

```python
class AutoTrader:
    """
    极简全仓交易: 单线程执行, 非阻塞接入
    
    规则:
    - state=IDLE时才接受命中
    - 同一时间只有1笔交易在处理
    - 所有UI操作在独立线程(不阻塞tick)
    - 超时后不盲设TP/SL(避免垃圾条件单)
    """
    
    def __init__(self, config):
        self.state = "IDLE"
        self.current = None
        self.config = config
        self.timeout_seconds = config.get('timeout_seconds', 30)
        self.tp_sl_placer = TpSlPlacer(config['positions_file'])
    
    def on_hit_async(self, code, name, price, scheme, lots):
        """
        主线程调用(非阻塞, <1ms返回)
        state!=IDLE → 直接跳过
        """
        if self.state != "IDLE":
            return
        
        # 计算买入价
        offset = scheme.get('price_offset', 0)
        mode = scheme.get('offset_mode', 'fixed')
        if mode == 'percent':
            buy_price = round(price * (1 + offset / 100), 3)
        else:
            buy_price = round(price + offset, 3)
        
        # 设置状态(主线程写, 此时无交易线程)
        self.state = "WATCHING"
        self.current = {
            'code': code,
            'name': name,
            'buy_price': buy_price,
            'tp_pct': scheme.get('take_profit', 3.0),
            'sl_pct': scheme.get('stop_loss', 2.0),
            'quantity': lots * 10,
            'hit_time': time.time(),
        }
        
        # 启动交易线程(所有耗时操作在这里)
        Thread(target=self._trade_loop, daemon=True).start()
    
    def _trade_loop(self):
        """交易线程: 填表→等弹窗→设TP/SL或撤单→结束"""
        try:
            # 阶段1: 填充买入表单(2-3秒)
            fill_buy_form(
                self.current['code'],
                self.current['buy_price'],
                self.current['quantity'] // 10,  # lots
            )
            play_sound("hit")
            
            # 阶段2: 监听成交弹窗(每100ms, 最多30秒)
            start = time.time()
            filled = False
            
            while time.time() - start < self.timeout_seconds:
                popup_code = detect_fill_popup()
                if popup_code == self.current['code']:
                    filled = True
                    break
                time.sleep(0.1)
            
            # 阶段3: 根据结果处理
            if filled:
                # 成交了! 设止盈止损
                self.state = "SETTING_TP_SL"
                play_sound("filled")
                
                result = self.tp_sl_placer.place(
                    bond_code=self.current['code'],
                    base_price=self.current['buy_price'],
                    tp_pct=self.current['tp_pct'],
                    sl_pct=self.current['sl_pct'],
                    quantity=self.current['quantity'],
                )
                
                if result['success']:
                    play_sound("done")
                    log_trade("TP_SL_SET", self.current)
                else:
                    play_sound("error")
                    log_trade("TP_SL_FAILED", self.current, result['message'])
            
            else:
                # 超时! 尝试撤单
                self.state = "CANCELLING"
                cancelled = try_cancel_order(self.current['code'])
                
                if cancelled:
                    # 撤成功 → 买了但没成交 → 正常结束
                    play_sound("timeout")
                    log_trade("CANCELLED", self.current)
                else:
                    # F3找不到 → 可能没买过, 也可能已成交(弹窗漏了)
                    # 不盲设TP/SL(避免垃圾条件单), 只告警
                    play_sound("alert")
                    log_trade("ALERT_CHECK", self.current, 
                             "超时且无法撤单,请手动检查是否已成交")
        
        except Exception as e:
            logger.error(f"[AutoTrader] 交易线程异常: {e}")
            play_sound("error")
        
        finally:
            # 无论如何, 恢复IDLE
            self.state = "IDLE"
            self.current = None
```

## 关键问题答案汇总

| 问题 | 答案 |
|------|------|
| 无效条件单影响下次交易? | **会!** 所以超时后不盲设TP/SL, 改为告警 |
| 多条命中其他超时很久? | **不存在!** state!=IDLE时新命中直接跳过, 只有1个在处理 |
| 交易操作阻塞tick? | **不会!** on_hit <1ms返回, 所有操作在独立daemon线程 |
| 线程冲突? | **不会!** 同一时间只有1个交易线程, 且主线程不做UI操作 |

## 完整线程安全证明

```
时刻T1: state=IDLE
  主线程: on_hit() → state="WATCHING" → 启动交易线程
  (此时只有主线程写state, 安全)

时刻T2: state=WATCHING, 交易线程运行中
  主线程: on_hit() → state!="IDLE" → return(不写任何东西)
  交易线程: 独占执行, 无人干扰
  (只有交易线程在工作, 安全)

时刻T3: 交易线程完成
  交易线程: state="IDLE" → current=None → 线程结束
  (写完后线程消亡, 安全)

时刻T4: state=IDLE, 无交易线程
  回到T1状态, 等待下一次命中
  
任何时刻, state只有1个写入者 → 零竞态 ✓
```
