## 二、目标架构（统一到 auto_trader，单票串行）

```
monitor_bond.py 命中
   │  (只推送，不下单)
   ▼
HTTP POST /api/auto_trade/hit  ──►  auto_trader (唯一状态机引擎)
                                      状态: IDLE→TRADING→MONITORING→IDLE
   ┌──────────────────────────────────────────────────────┐
   │ 前端面板 auto_trader_panel.html                        │
   │  - 轮询 /api/auto_trade/status 显示命中列表+当前交易   │
   │  - [买入]按钮 → POST /api/auto_trade/buy               │
   └──────────────────────────────────────────────────────┘
   ▼ 用户点买入
auto_trader._trade_thread_worker (单票串行):
   1. _fill_buy_form()      → HTTP /api/prepare_buy (trader.py 真实现)
   2. _wait_for_fill_popup()→ Afx成交弹窗检测
   3a. 成交 + full模式  → _place_tp_sl() → TpSlPlacer.place() 【抽取的独立模块】
                          → MONITORING → 等第二次弹窗(卖出成交)/超时强平
   3b. 成交 + buy_only  → 直接结束
   3c. 未成交(30s)      → _try_cancel_order() F3全撤 → 结束
```

**核心原则**：状态机非 IDLE 时拒绝新命中（`on_hit` 已实现该逻辑）→ 天然"每次只买一只"。

## 三、关键改动清单

### 改动1：抽取 TpSlPlacer 为独立模块（消除跨引擎耦合）★

**问题**：`auto_trader._place_tp_sl()` 现在 `from trade_flow import get_trade_flow_manager`，
会实例化整个引擎B（含Pipeline、状态文件），耦合且有副作用。

**方案**：
- 新建 `tp_sl_placer.py`，把 `trade_flow.py` 里的 `TpSlPlacer` 类**原样搬过去**（逻辑不改）
- `auto_trader._place_tp_sl()` 改为 `from tp_sl_placer import TpSlPlacer` 直接用
- `trade_flow.py` 改为 `from tp_sl_placer import TpSlPlacer`（保持它自己还能用，不破坏）

**收益**：auto_trader 不再依赖 trade_flow；两边共用同一份下单器。

### 改动2：避免双重下单 ★

**问题**：monitor_bond 命中时有**两条并行推送**：
- line 1601 `trader_on_hit()`（trader_adapter → prepare_buy，直接下单！）
- line 1625 HTTP `/api/auto_trade/hit`（auto_trader）

两条都会触发买入 → **双重下单风险**。

**方案**：
- **关闭 line 1601 的 `trader_on_hit` 自动下单**（用开关 `_trader_enabled=False`，或删调用）
- 只保留 HTTP `/api/auto_trade/hit` → auto_trader 单一路径
- auto_trader 内部：填买单由**人工点击**触发，不是命中即下单 → 双重保险

> 注意：`_track_pending_exits()`（quant_screen_hits结算）是纯数据记录，不下单，**保留不动**。

### 改动3：buy_only / full 模式（已实现，确认配置）

`auto_trader.py` 已支持 `mode: buy_only|full`（`_on_filled` 里已分支）。
- 当前上线：`mode='full'`
- 配置位置：monitor_bond 的 `AUTO_TRADER_CONFIG` 传入
- 保留 buy_only：面板加一个模式切换（可选，或配置文件改）

### 改动4：补齐前端面板 [买入] 交互

确认 `auto_trader_panel.html` + `auto_trader_routes.py` 的 buy 接口通路：
- `/api/auto_trade/hit`（monitor推送 → hit_store存MySQL + on_hit）✅ 已实现
- `/api/auto_trade/status`（轮询）✅ 已实现
- `/api/auto_trade/buy/<code>`（点买入 → on_buy_click）✅ 已实现
- `/api/auto_trade/cancel`、`/skip` ❌ 仍是TODO空壳
  → **但单票流程不依赖它们**（未成交撤单在交易线程内 `_try_cancel_order` F3全撤自动完成）
  → 可选补齐（面板手动撤当前单/跳过命中）
- `/api/auto_trade/history`（今日历史）✅ 已实现

### 改动5：monitor_bond 的 on_tick 推送（更新持仓现价）

full模式 MONITORING 时，第二次弹窗检测在交易线程阻塞等待，
on_tick 仅更新前端展示现价（auto_trader.on_tick 已实现）。
→ **需确认 monitor 每tick是否推送现价给交易server**（当前推送是HTTP，
   但 on_tick 需要 df_now，跨进程较难；MONITORING现价展示可降级为次要项）
