# 全自动交易流程分析 - 无面板+弹窗检测方案

> 日期: 2026-07-17
> 思路: 命中→买入→弹窗检测成交→自动设TP/SL, 全程无面板无人工确认

---

## 一、方案概述

```
量化命中
  → 自动填充买入表单
  → 你在xiadan点买入(唯一人工操作)
  → 系统自动检测成交弹窗
      ├── 检测到成交 → 自动设止盈止损 → 完成
      └── 超时(N秒) → 自动撤单 → 完成
  → 期间所有命中: 直接放走(不处理)
  → 持有债券时: 同一债券命中跳过
```

**极简: 你只需做一件事 — 点买入。其余全自动。**

---

## 二、详细流程时间线

```
[t+0.0s] 量化命中 127045 @105.0
         系统: 计算买入价=105.3, 设置状态=TRADING
         系统: 自动填充xiadan买入表单(F1)
         系统: 开始弹窗监听 + 30秒超时计时
         系统: 所有新命中信号 → 跳过(状态=TRADING)

[t+1~2s] 你: 看了一眼价格,点击[买入]
         xiadan: 委托提交

[t+2~3s] 成交(秒成交情况)
         xiadan: 弹出"成交回报"窗口
         系统: 检测到弹窗! 读取信息确认是127045
         系统: 状态=FILLED

[t+3~8s] 系统: 自动打开条件单弹窗 → 填充止盈止损 → 提交
         系统: 状态=TP_SL_SET

[t+8s]   完成!
         系统: 状态=IDLE, 恢复接收命中信号
         系统: 记录127045到持仓列表(后续同code命中跳过)

---

[另一种情况: 未成交]

[t+0s]   命中, 填充买入表单, offset=-0.5, 买入价=104.5(低于市价)
[t+2s]   你: 点了买入(挂单中)
[t+2~30s] 系统: 每秒检测弹窗... 没有成交弹窗...
[t+30s]  超时!
         系统: 自动执行撤单(F3)
         系统: 状态=IDLE, 恢复接收命中
```

| 优点 | 说明 |
|------|------|
| **极简操作** | 你只需点买入,其余全自动 |
| **无面板依赖** | 不用开浏览器,不用切窗口 |

## 四、逻辑分析 - 潜在漏洞

### 漏洞1: 成交弹窗检测不可靠 ⚠️ 核心风险

| 问题 | 影响 | 严重度 |
|------|------|--------|
| 弹窗标题不确定 | 找不到窗口 | 高 |
| 弹窗停留时间短(1-2秒就消失) | 来不及检测 | 高 |
| 你手动关了弹窗 | 系统漏检 | 中 |
| 别的委托也弹窗 | 误判为当前单成交 | 中 |
| 华泰版本更新改了弹窗 | 检测失效 | 低 |

**解决方案:**
```
优先: 实测弹窗行为(标题/持续时间/内容)
备选: 如果弹窗不可靠,改用"提交后N秒自动视为成交"策略
      (正偏移3秒自动确认, 负偏移等弹窗或超时撤单)
```

### 漏洞2: "你决定不买"的情况

```
命中 → 填充表单 → 你看了一眼觉得不好 → 不点买入
系统: 30秒后超时撤单

问题: 这30秒内所有新命中都丢了!
      但你根本没买,本应可以接收新命中

解决: 
  方案A: 接受(30秒内丢信号是可接受的代价)
  方案B: 加一个"放弃"快捷键(如Esc),你按了立刻恢复
  方案C: 如果检测到xiadan买入表单被手动清空→恢复
```

**建议: 方案A即可(30秒丢信号影响小,简化设计)**

### 漏洞3: 撤单时发现已成交

```
场景: 30秒超时 → 系统去撤单 → 但其实刚好在29.9秒成交了
      撤单API返回"无法撤单,已成交"

这不是bug,是正常情况!

处理: 
  撤单失败(已成交) → 视为成交 → 继续设TP/SL
  撤单成功 → 确实没成交 → 状态恢复IDLE
```

### 漏洞4: 止盈止损设置期间的命中

```
[t+3~8s] 系统正在设置TP/SL(操作华泰界面)
         此时如果命中新信号 → 必须跳过
         因为华泰界面正在被操作,不能并行

现有设计已覆盖: 状态=TRADING/FILLED期间所有命中跳过 ✓
```

### 漏洞5: 持仓检测的准确性

```
"实时监听是否持有" — 怎么实现?

方式A: 内部状态跟踪
  - 成交 → 标记holding[127045]=True
  - 条件单触发卖出(止盈/止损) → holding[127045]=False
  - 问题: 条件单触发是券商服务器执行的,本地不知道什么时候卖了
  
方式B: 定时查询持仓(xiadan资金股份面板)
  - 切到F4/持仓面板读取
  - 问题: 干扰操作,实现复杂
  
方式C: 简化版 — 只管"今日已买入的code"
  - 维护一个set: today_traded_codes
  - 成交了某code → 加入set → 后续同code命中跳过
  - 当日结束清空
  - 不精确(卖出后仍会跳过),但足够安全

建议: 方式C(简化,当日不重复买同一只)
```

### 漏洞6: 弹窗检测 vs 正偏移秒成交

```
正偏移(买入价>=市价): 几乎100%秒成交
  → 弹窗在你点买入后0.x秒就出现
  → 系统能检测到(只要轮询够快,如100ms一次)

负偏移(买入价<市价): 不确定何时成交
  → 可能5秒,可能20秒,可能不成交
  → 弹窗在某个时刻出现(或不出现)
  → 超时撤单是安全网

两种情况都能用同一套弹窗检测逻辑 ✓
不需要分两条路径了!
```

## 七、最终方案(完整)

### 7.1 状态机(极简)

```
IDLE ──→ TRADING ──→ SETTING_TP_SL ──→ IDLE
            │                              ↑
            ├── 成交弹窗检测到 ─────────────┤
            │                              │
            └── 超时 → 撤单 ───────────────┘
```

只有3个状态!

### 7.2 完整逻辑(伪代码)

```python
class AutoTrader:
    state = "IDLE"
    current_code = None
    today_traded = set()  # 当日已交易代码
    
    def on_hit(self, bond_code, bond_name, hit_price, scheme_detail, lots):
        """monitor_bond.py调用"""
        # 跳过条件
        if self.state != "IDLE":
            return  # 正在处理中,跳过
        if bond_code in self.today_traded:
            return  # 今天已买过,跳过
        
        # 开始处理
        self.state = "TRADING"
        self.current_code = bond_code
        
        # 计算买入价
        buy_price = hit_price + offset
        
        # 1. 填充买入表单
        fill_buy_form(bond_code, buy_price, lots)
        play_sound("hit")  # 提示音:有新单
        
        # 2. 启动异步监控线程
        Thread(target=self._monitor_fill, args=(
            bond_code, buy_price, scheme_detail, lots, timeout
        )).start()
    
    def _monitor_fill(self, code, price, scheme, lots, timeout):
        """后台: 等待成交或超时"""
        start = time.time()
        
        while time.time() - start < timeout:
            # 检测成交弹窗
            if detect_fill_popup(code):
                # 成交了!
                self._on_filled(code, price, scheme, lots)
                return
            time.sleep(0.1)  # 100ms轮询
        
        # 超时,尝试撤单
        cancel_result = cancel_order(code)
        if cancel_result == "already_filled":
            # 撤单失败=其实成交了
            self._on_filled(code, price, scheme, lots)
        else:
            # 确实没成交
            self.state = "IDLE"
            play_sound("timeout")
            log("[TIMEOUT] 撤单完成")
    
    def _on_filled(self, code, price, scheme, lots):
        """成交后: 设置止盈止损"""
        self.state = "SETTING_TP_SL"
        self.today_traded.add(code)
        
        # 设置止盈止损
        result = tp_sl_placer.place(
            code, base_price=price,
            tp_pct=scheme['take_profit'],
            sl_pct=scheme['stop_loss'],
            quantity=lots*10
        )
        
        if result['success']:
            play_sound("success")
            log(f"[TP_SL] 设置成功")
        else:
            play_sound("alert")
            log(f"[FAIL] TP/SL设置失败: {result['message']}")
        
        self.state = "IDLE"
```

## 八、风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 弹窗检测不到 | 中 | 超时撤单(误撤已成交单) | 正偏移兜底+撤单返回"已成交"时补救 |
| 弹窗误检测 | 低 | 未成交就设TP/SL(条件单不触发,无实际损失) | 检测时匹配code |
| 30秒丢太多信号 | 中 | 错过机会 | 可调短(如20秒),或止盈止损设置更快 |
| xiadan未打开 | 低 | 流程全失败 | 启动时检测,失败则disable |
