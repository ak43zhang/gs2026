# 华泰证券可转债半自动交易助手 - 设计文档

## 一、系统概述

### 1.1 设计目标
为量化交易系统提供一个**安全、合规、半自动**的交易辅助工具：
- 接收量化信号，自动填充委托单
- **人工最终确认**（只需点击华泰软件中的"买入"按钮）
- 完整的风控、日志管理

### 1.2 核心原则
| 原则 | 说明 |
|------|------|
| **不自动提交** | 系统只填充证券代码，最终点击"买入"由人工完成 |
| **不存储密码** | 交易密码不落地，由用户在华泰软件中输入 |
| **本地运行** | 所有操作仅在本地执行，不联网传输交易信息 |
| **单次确认** | 无中间弹窗，只保留华泰软件中的一次人工确认 |
| **新信号覆盖** | 每个新命中直接覆盖前一个，不管前一个是否已操作 |

## 三、交易行为配置

### 3.1 配置项说明

```yaml
# ==================== 交易行为配置 ====================
trading_behavior:
  # 价格填充模式：
  #   "auto"   - 不填价格，由软件默认（通常是卖1价）【默认】
  #   "manual" - 使用API传入的价格填充
  price_mode: "auto"
  
  # 数量填充模式：
  #   "auto"    - 不填数量，由软件默认
  #   "fixed"   - 使用固定数量（default_quantity）
  #   "manual"  - 使用API传入的数量
  quantity_mode: "auto"
  
  # 固定数量（张数），仅在 quantity_mode="fixed" 时生效
  # 10张=1手, 20张=2手
  default_quantity: 10

  # 提示音（成功/失败时播放不同音效）
  sound_enabled: true
```

### 3.2 填充模式对照表

| price_mode | quantity_mode | 键盘操作 | 说明 |
|---|---|---|---|
| auto | auto | F1 → 代码 → 完成 | **极简模式（默认）** |
| auto | fixed | F1 → 代码 → Tab → Tab → 数量 → 完成 | 固定数量 |
| manual | auto | F1 → 代码 → Tab → 价格 → 完成 | 指定价格 |
| manual | fixed | F1 → 代码 → Tab → 价格 → Tab → 数量 → 完成 | 全指定（固定量）|
| manual | manual | F1 → 代码 → Tab → 价格 → Tab → 数量 → 完成 | 全指定（API传入）|

### 3.3 API参数优先级

```
POST /api/prepare_buy
{
  "code": "123257",       // 必填 - 证券代码
  "name": "美诺转债",     // 可选 - 名称（仅日志）
  "price": 105.20,        // 可选 - 显式传入时覆盖配置
  "lots": 1              // 可选 - 显式传入时覆盖配置
}
```

**优先级规则**：
- API 显式传入 `price` → 无论 `price_mode` 配置如何，填充价格
- API 未传 `price` + `price_mode="auto"` → 不填价格，由软件自动处理
- API 显式传入 `lots` → 无论 `quantity_mode` 配置如何，填充数量
- API 未传 `lots` + `quantity_mode="fixed"` → 填充 `default_quantity`
- API 未传 `lots` + `quantity_mode="auto"` → 不填数量

### 3.4 配置示例

**极简模式（推荐）**：
```yaml
trading_behavior:
  price_mode: "auto"       # 价格由软件填（卖1/卖2）
  quantity_mode: "auto"    # 数量由软件默认
  sound_enabled: true      # 提示音开启
```

**固定1手**：
```yaml
trading_behavior:
  price_mode: "auto"
  quantity_mode: "fixed"
  default_quantity: 10     # 1手=10张
  sound_enabled: true
```

## 四、键盘驱动方案（核心技术）

### 4.1 为什么使用键盘驱动

华泰证券 `网上股票交易系统5.0`（进程 `xiadan.exe`）的UI有一个特殊结构：

> **买入面板和卖出面板的所有Edit控件位置完全重叠、始终同时存在。**
> F1/F2只改变哪个面板在视觉上置顶，但两套控件始终可被pywinauto枚举到。

如果用控件名称（如 `"证券代码Edit"`）查找，pywinauto会找到**排在前面的那个**（通常是卖出面板的），导致数据填入错误面板。

### 4.2 解决方案

改用**纯键盘驱动**，完全不依赖控件名称查找：

```python
# 买入填充
send_keys('{F1}')          # F1 切到买入面板，焦点自动落在代码框
send_keys('^a')            # 全选
send_keys(bond_code)       # 输入代码
time.sleep(1.0)            # 等待软件查询债券
# 如需填价格：
send_keys('{TAB}')         # Tab到价格框
send_keys('^a')
send_keys(price_str)
# 如需填数量：
send_keys('{TAB}')         # Tab到数量框
send_keys('^a')
send_keys(quantity_str)
```

### 4.3 快捷键对照

| 快捷键 | 功能 |
|--------|------|
| F1 | 切换到买入面板（焦点→代码框） |
| F2 | 切换到卖出面板（焦点→代码框） |
| Tab | 下一个输入框（代码→价格→数量） |
| Ctrl+A | 全选当前输入框内容 |
| 买入[B] | 买入确认按钮（人工点击） |
| 卖出[S] | 卖出确认按钮（人工点击） |

## 五、连接方案与踩坑记录

### 5.1 窗口信息

| 属性 | 值 |
|------|-----|
| 进程路径 | `D:\华泰证券网上交易委托系统\xiadan.exe` |
| 窗口标题 | `网上股票交易系统5.0` |
| 窗口类名 | `Afx:002B0000:b:00010003:00000006:523A0961` |
| 架构 | **32位程序**（使用64位Python操作，需win32后端） |
| pywinauto后端 | `win32`（兼容32位软件） |

### 5.2 踩坑1：连接状态始终False

**现象**：服务启动日志显示"自动连接华泰软件成功"，但 `/api/status` 返回 `connected: False`。

**根因**：Flask 多线程模式下，HTTP请求在工作线程处理。原代码在 `is_connected()` 中调用 `self.main_window.exists()` 进行窗口验证，但 pywinauto 的 `exists()` 跨线程调用会失败。

**修复**：`is_connected()` 只检查连接标志，不再跨线程调用 `exists()`：
```python
def is_connected(self) -> bool:
    return self._connected and self.main_window is not None
```

### 5.3 踩坑2：通过标题连接失败

**现象**：`Application().connect(title="网上股票交易系统5.0")` 偶尔失败。

**根因**：标题匹配在某些情况下不稳定（可能与编码或窗口状态有关）。

**修复**：改为通过进程路径连接，更稳定：
```python
app = Application(backend='win32').connect(
    path=r'D:\华泰证券网上交易委托系统\xiadan.exe',
    timeout=5
)
main_window = app.window(title='网上股票交易系统5.0')
```

### 5.4 踩坑3：买入数据填入卖出面板

**现象**：调用 `prepare_buy_order` 后，数据出现在卖出界面。

**根因**：华泰软件的买入/卖出面板所有Edit控件位置完全重叠、始终共存。用 `main_window['证券代码Edit']` 查找时，pywinauto找到的是排在前面的卖出面板控件。

**修复**：改用纯键盘驱动（F1/F2 + Tab），完全不依赖控件名称查找。详见第四节。

### 5.5 踩坑4：旧进程占用端口

**现象**：重启服务后行为未更新。

**根因**：旧进程未杀掉，两个进程同时监听8081端口。新请求被路由到旧进程。

**修复**：重启前先确认端口空闲：
```bash
netstat -ano | findstr "8081"
taskkill /PID <旧PID> /F
```

## 六、风控机制

| 层级 | 检查项 | 默认值 | 说明 |
|------|--------|--------|------|
| 1 | 方案过滤 | 全部允许 | 白名单/黑名单 |
| 2 | 交易时段 | 09:30-11:30, 13:00-15:00 | 可通过配置关闭（测试用） |
| 3 | 价格范围 | 50-200元 | 超出范围拦截 |
| 4 | 单笔金额 | 1000-100000元 | 异常金额拦截 |
| 5 | 同一债券去抖 | 10秒 | 仅防止同一tick重复触发 |
| 6 | 单日次数 | 50次 | 日内熔断 |

**覆盖逻辑**：新命中直接覆盖前一个，不管前一个是否已操作。去抖间隔仅10秒（防同一tick重复）。
